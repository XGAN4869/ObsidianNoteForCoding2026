# 测试、调试与工程规范

## 1. 学习目标

建立从单元测试到端到端测试的验证体系，并使用 Go 工具链保持代码质量。

## 2. 表驱动测试

~~~go
func TestValidateTitle(t *testing.T) {
	tests := []struct {
		name    string
		input   string
		wantErr bool
	}{
		{"正常标题", "Go 入门", false},
		{"空标题", " ", true},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			err := validateTitle(tt.input)
			if (err != nil) != tt.wantErr {
				t.Fatalf("wantErr=%v, got=%v", tt.wantErr, err)
			}
		})
	}
}
~~~

测试名称应说明场景，失败信息应包含输入和期望值。

## 3. Mock 与依赖注入

Service 依赖接口，测试时注入内存实现或 Mock。不要为了测试把所有代码都改成复杂抽象；只对外部系统和变化频繁的依赖使用接口。

## 4. HTTP 测试

~~~go
req := httptest.NewRequest(http.MethodGet, "/healthz", nil)
rec := httptest.NewRecorder()
router.ServeHTTP(rec, req)

if rec.Code != http.StatusOK {
	t.Fatalf("status=%d", rec.Code)
}
~~~

测试成功、参数错误、未登录、无权限、资源不存在和内部错误。

## 5. 集成测试

Repository 集成测试使用独立数据库或 Testcontainers，测试迁移、真实 SQL 和事务。测试结束后清理数据，避免测试相互依赖。

## 6. Benchmark 与诊断

~~~go
func BenchmarkUniqueTags(b *testing.B) {
	tags := []string{"go", "sql", "go"}
	for i := 0; i < b.N; i++ {
		_ = uniqueTags(tags)
	}
}
~~~

先用基准测试建立基线，再优化。发生 panic 时保留堆栈、请求 ID、输入摘要和版本号。

## 7. Race Detector

~~~powershell
go test -race ./...
go test -cover ./...
go tool pprof
~~~

不要在日志中打印密码、完整 JWT 或数据库密码。

## 8. 工程检查

提交前执行：

~~~powershell
gofmt -w .
go test ./...
go vet ./...
go test -race ./...
go mod tidy
~~~

团队可以在 CI 中固定 Go 版本、运行测试、检查格式化差异和构建镜像。

## 9. 博客项目测试矩阵

| 模块 | 成功场景 | 失败场景 |
| --- | --- | --- |
| 注册 | 新用户名创建 | 重复用户名、弱密码 |
| 登录 | 正确凭据返回 Token | 密码错误、用户不存在 |
| 文章 | 作者创建并发布 | 非作者修改、草稿不可见 |
| 评论 | 已登录用户发布 | 空内容、未审核不可展示 |
| 管理 | 管理员审核 | 普通用户越权 |
| 缓存 | 命中后返回 | Redis 失败回源数据库 |

## 10. 常见问题与练习

常见问题：测试只测成功路径、共享全局状态、忽略时间导致测试不稳定、依赖真实外部服务、只看覆盖率数字。

练习：

1. 为 ParsePagination 写表驱动测试。
2. 为认证中间件写 401、403 测试。
3. 运行 race detector 并修复一个竞态。
4. 写一条 Repository 集成测试并清理数据。

## 11. 小结与下一章

测试不是项目末尾的补丁，而是设计反馈。接口边界清晰、依赖可注入，测试就会自然变简单。
