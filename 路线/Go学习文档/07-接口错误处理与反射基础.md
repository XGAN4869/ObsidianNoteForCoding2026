# 接口、错误处理与反射基础

## 1. 学习目标

使用小接口隔离依赖，建立可判断、可包装的错误体系，并了解反射的适用边界。

## 2. 接口与隐式实现

~~~go
type PostRepository interface {
	FindByID(ctx context.Context, id int64) (*Post, error)
	Save(ctx context.Context, post *Post) error
}
~~~

类型只要拥有接口要求的方法就自动实现接口，不需要声明 implements。

接口应由使用方定义，并保持小而专一。Service 只依赖自己需要的方法，测试时更容易替换为假实现。

## 3. 接口值与 nil

接口值由动态类型和动态值组成。装入一个 nil 指针后，接口本身可能不等于 nil：

~~~go
var repo *SQLPostRepository = nil
var value any = repo
fmt.Println(value == nil) // false
~~~

避免返回带类型的 nil 指针作为接口；构造阶段应尽早拒绝 nil 依赖。

## 4. 类型断言和类型 switch

~~~go
text, ok := value.(string)
if !ok {
	return errors.New("不是字符串")
}
~~~

不接收 ok 的断言失败会 panic。外部数据或不确定接口值应使用安全写法。

## 5. error

error 是一个只有 Error 方法的接口：

~~~go
type error interface {
	Error() string
}
~~~

哨兵错误：

~~~go
var ErrPostNotFound = errors.New("文章不存在")
~~~

包装错误并保留错误链：

~~~go
return fmt.Errorf("查询文章 %d：%w", id, err)
~~~

判断错误链：

~~~go
if errors.Is(err, ErrPostNotFound) {
	// 返回 HTTP 404
}
~~~

读取自定义错误：

~~~go
var validation *ValidationError
if errors.As(err, &validation) {
	// 返回字段错误
}
~~~

## 6. 自定义业务错误

~~~go
type AppError struct {
	Code    string
	Message string
	Err     error
}

func (e *AppError) Error() string { return e.Message }
func (e *AppError) Unwrap() error { return e.Err }
~~~

Message 可以安全返回客户端，Err 保留内部原因用于日志。不要把 SQL、文件路径或密钥信息直接返回用户。

## 7. panic 与 recover

普通业务错误使用 error，不使用 panic。panic 适合程序无法继续的不变量破坏。HTTP 服务可在最外层 Recovery 中间件记录并返回 500，但不能把 recover 当作日常流程控制。

## 8. 反射基础

反射可以在运行时查看类型和值：

~~~go
t := reflect.TypeOf(value)
v := reflect.ValueOf(value)
fmt.Println(t.Kind(), v.IsValid())
~~~

JSON、校验器和 ORM 会使用反射。业务代码优先使用明确类型和接口，因为反射错误往往到运行时才暴露。

## 9. 博客错误映射

| 业务错误 | HTTP 状态 | 对外错误码 |
| --- | --- | --- |
| 参数校验失败 | 400 | VALIDATION_ERROR |
| 未登录 | 401 | UNAUTHORIZED |
| 无权限 | 403 | FORBIDDEN |
| 文章不存在 | 404 | POST_NOT_FOUND |
| 用户名冲突 | 409 | USERNAME_CONFLICT |
| 未知内部错误 | 500 | INTERNAL_ERROR |

Handler 负责把 Service 错误映射为 HTTP，Repository 不应该返回 HTTP 状态码。

## 10. 常见错误与练习

常见错误：接口过大、到处使用 any、用字符串比较错误、包装错误时使用 %v 导致错误链丢失、把内部错误直接暴露给客户端。

练习：

1. 定义只含 FindByID 的 Reader 接口。
2. 创建 ValidationError 并用 errors.As 判断。
3. 把 sql.ErrNoRows 映射成 ErrPostNotFound。
4. 编写错误到 HTTP 状态码的映射函数测试。
