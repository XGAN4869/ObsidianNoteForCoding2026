# 流程控制与程序结构

## 1. 学习目标

完成本章后，你能够：

- 使用 if、for、switch 表达业务分支。
- 理解 break、continue 和 return 的控制范围。
- 使用 defer 管理资源释放。
- 解释 init、变量初始化和 main 的执行顺序。
- 为博客接口编写参数校验、状态判断和资源清理逻辑。

## 2. if 条件

Go 的 if 不需要括号，但必须有大括号：

~~~go
if age >= 18 {
	fmt.Println("成年人")
}
~~~

可以在条件前声明只在 if/else 范围内使用的变量：

~~~go
if length := len(title); length == 0 {
	return errors.New("标题不能为空")
} else if length > 100 {
	return errors.New("标题不能超过 100 个字符")
}
~~~

length 在 if 语句结束后不可见，这能缩小变量作用域。

### 提前返回减少嵌套

不推荐：

~~~go
if user != nil {
	if user.IsAdmin {
		// 业务逻辑
	}
}
~~~

更清晰的写法：

~~~go
if user == nil {
	return errors.New("用户不存在")
}
if !user.IsAdmin {
	return errors.New("没有管理员权限")
}
// 这里直接处理管理员逻辑
~~~

在 Handler 和 Service 中，优先验证失败条件并提前返回，可以让正常路径保持在最外层。

## 3. for 循环

### 类似 while 的写法

~~~go
attempts := 0
for attempts < 3 {
	attempts++
	fmt.Println("尝试次数", attempts)
}
~~~

### 经典三段式

~~~go
for i := 0; i < 5; i++ {
	fmt.Println(i)
}
~~~

### 无限循环与退出

~~~go
for {
	item, ok := <-jobs
	if !ok {
		break
	}
	fmt.Println(item)
}
~~~

无限循环必须有明确的退出条件，否则会造成 Goroutine 或进程无法结束。

### 遍历切片和 Map

~~~go
titles := []string{"Go", "SQL", "HTTP"}
for index, title := range titles {
	fmt.Println(index, title)
}

counts := map[string]int{"go": 2, "sql": 1}
for name, count := range counts {
	fmt.Println(name, count)
}
~~~

Map 的遍历顺序不保证稳定，不要依赖它进行排序或生成固定快照。

只需要值时使用下划线忽略索引：

~~~go
for _, title := range titles {
	fmt.Println(title)
}
~~~

## 4. break、continue 和标签

continue 跳过当前轮次，进入下一轮：

~~~go
for _, post := range posts {
	if post.Status != "published" {
		continue
	}
	fmt.Println(post.Title)
}
~~~

break 只退出当前所在的循环。嵌套循环需要标签时要谨慎：

~~~go
outer:
for _, user := range users {
	for _, post := range posts {
		if user.ID == post.AuthorID {
			fmt.Println("找到作者的文章")
			break outer
		}
	}
}
~~~

标签能解决特殊控制流，但过多使用会让代码难读。通常优先拆成函数或使用返回值。

## 5. switch

### 基础 switch

~~~go
switch status {
case "draft":
	fmt.Println("草稿")
case "published":
	fmt.Println("已发布")
default:
	fmt.Println("未知状态")
}
~~~

Go 的 case 默认不会自动贯穿，不需要手工写 break。

### 多个值共用分支

~~~go
switch role {
case "admin", "editor":
	fmt.Println("可以进入管理端")
case "visitor":
	fmt.Println("只能浏览")
}
~~~

### 无表达式 switch

可以把多个条件集中到一个结构中：

~~~go
switch {
case age < 0:
	return errors.New("年龄不能为负数")
case age < 18:
	return errors.New("必须年满 18 岁")
default:
	return nil
}
~~~

### 类型 switch

接口值可以通过类型 switch 处理：

~~~go
func describe(value any) string {
	switch v := value.(type) {
	case string:
		return "字符串：" + v
	case int:
		return fmt.Sprintf("整数：%d", v)
	default:
		return fmt.Sprintf("其他类型：%T", v)
	}
}
~~~

## 6. defer 延迟执行

defer 会把函数调用放入当前函数的延迟队列，在当前函数返回前执行，常用于释放资源：

~~~go
file, err := os.Open("data.txt")
if err != nil {
	return err
}
defer file.Close()
~~~

### defer 的执行顺序

多个 defer 按后进先出执行：

~~~go
defer fmt.Println("first")
defer fmt.Println("second")
// 输出 second、first
~~~

defer 参数会在声明时求值：

~~~go
value := 1
defer fmt.Println(value)
value = 2
// 输出 1
~~~

如果希望延迟读取最新值，使用闭包：

~~~go
defer func() {
	fmt.Println(value)
}()
~~~

不要在高频循环中无边界地 defer 打开文件。defer 会等整个外层函数返回才执行；应把单次处理抽到独立函数中。

## 7. init、变量初始化与 main

一个包的大致执行顺序是：

~~~text
导入依赖包
  ↓
依赖包的包级变量初始化
  ↓
依赖包的 init
  ↓
当前包的包级变量初始化
  ↓
当前包的 init
  ↓
main.main
~~~

init 适合非常少量且确定的初始化，不适合连接数据库、读取复杂配置或启动后台任务。博客项目会在 main 中显式初始化配置、数据库、Redis 和路由，便于测试和处理错误。

同一个包中，包级变量按照源文件的依赖关系和编译器确定的文件顺序初始化。不要依赖文件名顺序来表达业务逻辑。

## 8. 错误处理中的控制流

Go 通常在错误返回后立即处理：

~~~go
post, err := postService.FindByID(ctx, id)
if err != nil {
	if errors.Is(err, repository.ErrNotFound) {
		return nil, ErrPostNotFound
	}
	return nil, fmt.Errorf("查询文章：%w", err)
}
return post, nil
~~~

这种写法让错误边界清晰，也能保留原始错误供日志和测试判断。

## 9. 参数校验示例

~~~go
func validateCreatePost(title, content string) error {
	title = strings.TrimSpace(title)
	if title == "" {
		return errors.New("标题不能为空")
	}
	if utf8.RuneCountInString(title) > 100 {
		return errors.New("标题最多 100 个字符")
	}
	if strings.TrimSpace(content) == "" {
		return errors.New("正文不能为空")
	}
	return nil
}
~~~

校验函数只负责判断，不应该偷偷修改数据库或发送消息。把副作用放在 Service 中，测试会更简单。

## 10. 常见错误

### 忘记大括号

Go 不支持把大括号放到下一行：

~~~go
// 错误示例
if ok
{
	fmt.Println("ok")
}
~~~

### switch 误以为会贯穿

Go 的 case 默认自动结束。如果需要继续执行下一个 case，必须显式使用 fallthrough，但业务代码中应少用。

### defer 放在错误检查之前

~~~go
// 错误：file 可能是 nil
file, err := os.Open(path)
defer file.Close()
if err != nil {
	return err
}
~~~

必须先判断 err，再注册 Close。

### 循环变量闭包问题

在启动 Goroutine 或保存闭包时，注意循环变量的作用域和捕获方式。可以在循环体内创建局部副本，或使用当前 Go 版本推荐的循环变量语义，并为行为写测试。

1. 写一个函数，接收文章状态并返回可读的中文提示。
2. 遍历文章列表，只打印已发布文章。
3. 编写带重试次数上限的函数，失败三次后返回错误。
4. 打开文件并统计行数，确保无论成功还是失败都能正确关闭文件。
5. 把一个多层嵌套的 if 改写为“提前返回”的形式。

## 12. 小结

- if 负责条件判断，for 负责重复，switch 负责多分支。
- 提前返回能显著降低业务代码的嵌套深度。
- defer 适合资源释放，但要先检查资源获取错误。
- init 应保持轻量，复杂初始化应显式放在 main 或构造函数中。
- 控制流设计直接影响 Handler 和 Service 的可读性与可测试性。
