# 博客项目部署与扩展

## 1. Dockerfile

推荐多阶段构建：

~~~dockerfile
FROM golang:1.22 AS builder
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o /out/server ./cmd/server

FROM gcr.io/distroless/static-debian12
COPY --from=builder /out/server /server
EXPOSE 8080
ENTRYPOINT ["/server"]
~~~

构建阶段和运行阶段分离，减少最终镜像体积和攻击面。

## 2. Docker Compose

服务至少包含：

- api：Go 博客服务。
- db：MySQL 或 PostgreSQL。
- redis：缓存和限流。
- migrate：执行数据库迁移的临时任务。

API 通过服务名连接数据库，例如 db:3306，而不是 localhost。localhost 在容器中指向当前容器。

## 3. 生产配置

必须通过环境变量或 Secret 注入：

- DATABASE_DSN
- REDIS_PASSWORD
- JWT_SECRET
- APP_ENV=production

生产禁用 Gin DebugMode，限制 CORS 来源，设置请求体上限和合理超时。

## 4. 反向代理

Nginx 或云负载均衡负责：

- TLS 终止。
- /api 转发到 Go 服务。
- 传递 X-Request-ID。
- 限制上传大小。
- 静态资源缓存。
- 健康检查 /healthz 和 /readyz。

应用仍应校验 Host、Origin 和 Authorization，不把安全责任全部交给代理。

## 5. 发布流程

~~~text
提交代码
  ↓
CI 格式化、测试、构建镜像
  ↓
执行向前兼容迁移
  ↓
部署新版本实例
  ↓
检查 readyz 和 smoke test
  ↓
逐步切流
  ↓
观察错误率、延迟和数据库连接
~~~

回滚应用版本前，确认数据库迁移仍兼容旧代码。

## 6. 备份与恢复

- 每日全量备份数据库。
- 定期验证备份可恢复，不只检查文件存在。
- Redis 主要作为缓存，不把唯一业务数据只放在 Redis。
- 附件存储使用对象存储并开启版本或生命周期策略。
- 备份文件加密并限制访问。

## 7. 监控指标

至少观察：

- HTTP 请求总数、错误率、P95/P99 延迟。
- 数据库连接池使用率、慢查询和锁等待。
- Redis 命中率、连接错误和内存。
- Goroutine 数量和进程内存。
- 文章列表、登录和评论接口的业务成功率。

## 8. 扩展路线

### 全文搜索

数据量较小时使用数据库全文索引；规模增大后接 Elasticsearch 或 OpenSearch，并通过异步事件同步。

### 对象存储

文章图片上传到对象存储，数据库只保存 URL、大小、类型和所有者。

### 消息队列

将浏览量聚合、邮件通知和审计扩展为消息任务；必须设计重试、幂等和死信处理。

### 定时任务

定期清理过期 Refresh Token、刷新热门文章缓存和生成站点地图。任务要有分布式锁，避免多实例重复执行。

## 9. 最终项目验收清单

- [ ] 可以通过 Docker Compose 启动。
- [ ] 迁移可重复执行且有回滚文件。
- [ ] 注册、登录、刷新和退出完整可用。
- [ ] 文章草稿、发布、列表、详情和删除可用。
- [ ] 分类、标签和评论审核可用。
- [ ] 普通用户和管理员权限边界正确。
- [ ] 核心 Service 和 Handler 有测试。
- [ ] go test -race 和 go vet 通过。
- [ ] 日志不泄露密码和 Token。
- [ ] 有健康检查、优雅关闭和备份方案。

## 10. 结课复习

用自己的话回答：

1. 为什么 Handler 不应该写 SQL？
2. 为什么 Refresh Token 需要撤销机制？
3. 文章发布为什么需要事务？
4. Redis 不可用时哪些功能可以降级？
5. 如何从 request_id 定位一次失败请求？
6. 如果文章表达到千万级，分页和搜索如何演进？
