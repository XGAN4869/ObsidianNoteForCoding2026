# 评论与内容审核模块

## 1. 评论模型

~~~go
type Comment struct {
	ID        int64
	PostID    int64
	UserID    int64
	ParentID  *int64
	Content   string
	Status    string
	CreatedAt time.Time
	UpdatedAt time.Time
	DeletedAt *time.Time
}
~~~

状态：pending、approved、rejected、deleted。客户端不能直接指定 approved。

## 2. 发布评论

流程：

1. 从认证 Context 获取 user_id。
2. 校验文章存在且对外可见。
3. 校验 parent_id 属于同一文章且未删除。
4. 清理首尾空白并限制长度。
5. 进行敏感词和频率检查。
6. 写入 pending 评论。
7. 返回评论摘要，不立即对游客展示。

## 3. 评论树组装

Repository 返回按时间排序的平铺评论。Service 使用 Map 建立 id → node，再把节点挂到 parent.Children：

~~~go
nodes := make(map[int64]*CommentNode, len(rows))
for _, row := range rows {
	nodes[row.ID] = &CommentNode{Comment: row}
}
for _, node := range nodes {
	if node.ParentID == nil {
		roots = append(roots, node)
		continue
	}
	if parent, ok := nodes[*node.ParentID]; ok {
		parent.Children = append(parent.Children, node)
	}
}
~~~

遇到孤儿 parent_id 时记录数据异常，不要让整个请求 panic。

## 4. 审核接口

管理员接口：

- GET /api/v1/admin/comments?status=pending
- POST /api/v1/admin/comments/{id}/approve
- POST /api/v1/admin/comments/{id}/reject
- DELETE /api/v1/admin/comments/{id}

审核操作记录 reviewer_id、comment_id、旧状态、新状态和时间。状态更新应检查当前状态，避免重复审核覆盖结果。

## 5. 防刷策略

初版可以按 user_id + post_id + 时间窗口限流；游客评论则按 IP 和设备标识限流。Redis 不可用时采用保守降级或拒绝高风险写入，避免完全失去保护。

## 6. 敏感内容

敏感词过滤应有明确策略：

- 命中后进入人工审核，还是直接拒绝。
- 是否保存原文供管理员查看。
- 词库如何更新。
- 日志是否脱敏。

不要把完整评论正文写入普通访问日志。

## 7. 删除与展示

评论删除采用软删除，游客查询过滤 deleted_at。管理员可查看删除记录但不能把已删除内容误展示为正常评论。

## 8. 测试场景

- 登录用户发布正常评论。
- 空评论、过长评论被拒绝。
- 回复其他文章的评论被拒绝。
- pending 评论对游客不可见。
- 管理员批准后可见。
- 普通用户审核返回 403。
- 重复审核具有幂等或明确冲突行为。
- 评论树的根节点和子节点顺序正确。
