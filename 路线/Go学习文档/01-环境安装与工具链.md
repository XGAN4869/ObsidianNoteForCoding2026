# Go 环境安装与工具链

## 1. 学习目标

完成本章后，你能够：

- 确认 Go 是否安装成功以及版本是否符合要求。
- 理解 GOROOT、GOPATH 和模块模式的作用。
- 创建一个带 go.mod 的项目。
- 使用常用 Go 命令运行、构建、测试和格式化代码。
- 配置 VS Code 或 GoLand 获得补全、跳转和调试能力。

## 2. 安装 Go

### Windows

1. 打开 Go 官方下载页面，选择 Windows 的 MSI 安装包。
2. 按默认选项安装，通常不需要手动修改安装目录。
3. 重新打开 PowerShell，让新的 PATH 配置生效。
4. 执行：

~~~powershell
go version
go env GOROOT GOPATH GOMOD
~~~

预期能看到类似：

~~~text
go version go1.22.x windows/amd64
C:\Program Files\Go
C:\Users\你的用户名\go
~~~

GOMOD 如果当前目录不在 Go 项目中，可能为空；这不是安装失败。

### macOS 和 Linux

可使用官方压缩包或系统包管理器安装。安装结束后，在终端执行：

~~~bash
go version
go env GOROOT GOPATH GOMOD
~~~

不要同时维护多个来源不明的 Go 安装，否则容易出现 PATH 指向旧版本的问题。

## 3. 三个容易混淆的环境变量

### GOROOT

Go 编译器、标准库和工具链的安装目录。正常情况下由安装程序设置，不建议手动修改。

### GOPATH

Go 的工作区目录，默认用于缓存下载的模块、编译缓存和通过 go install 安装的工具。模块项目不要求代码必须放在 GOPATH/src 中。

### GOMOD

当前项目使用的 go.mod 文件路径。只要项目目录或父目录存在 go.mod，Go 就会以模块模式工作。

查看完整环境：

~~~powershell
go env
~~~

只查看单项：

~~~powershell
go env GOPATH
go env GOPROXY
go env GOMOD
~~~

## 4. 创建第一个模块

新建一个练习目录并初始化模块：

~~~powershell
mkdir hello-go
cd hello-go
go mod init example.com/hello-go
~~~

创建 main.go：

~~~go
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go!")
}
~~~

运行：

~~~powershell
go run .
~~~

go run . 会临时编译并运行当前模块，不会留下最终可执行文件。

## 5. 常用命令速查

| 命令 | 用途 | 典型场景 |
| --- | --- | --- |
| go mod init | 创建模块 | 新项目开始时 |
| go mod tidy | 整理依赖 | 增删 import 后 |
| go run . | 编译并运行 | 本地开发 |
| go build ./... | 编译所有包 | 提交前检查 |
| go install | 编译并安装工具 | 安装开发工具 |
| go fmt ./... | 格式化代码 | 保存或提交前 |
| go test ./... | 运行全部测试 | 日常验证 |
| go test -race ./... | 检查数据竞争 | 并发代码 |
| go vet ./... | 静态分析 | 发现可疑写法 |
| go list -m all | 查看模块依赖 | 排查版本问题 |

### go build 和 go run 的区别

go run 适合快速验证；go build 会生成可交付的二进制文件。生产环境通常先构建，再运行二进制，而不是使用 go run。

## 6. 格式化与导入整理

Go 的格式化规则是统一的：

~~~powershell
go fmt ./...
~~~

编辑器保存时可以自动执行 gofmt。不要手工调整 Tab、空格或 import 顺序来追求自己的风格，优先遵循工具输出。

## 7. VS Code 配置

1. 安装 VS Code。
2. 安装官方 Go 扩展。
3. 用 VS Code 打开包含 go.mod 的项目根目录。
4. 如果提示安装工具，允许安装 gopls、dlv 等开发工具。
5. 在设置中开启保存时格式化：editor.formatOnSave。

建议的工作区检查：

- gopls 能提供跳转、补全和错误提示。
- 按 F5 能启动调试。
- 测试文件旁边能出现运行测试按钮。

## 8. GoLand 配置

1. 打开项目根目录，而不是只打开某一个 .go 文件。
2. 在 Settings → Go → GOROOT 中确认 SDK。
3. 确认 Go Modules 已启用。
4. 为 main.go 创建 Run/Debug Configuration。
5. 在测试函数旁运行单个测试，确认断点可命中。

## 9. 一个最小测试

创建 main_test.go：

~~~go
package main

import "testing"

func TestAlwaysPass(t *testing.T) {
	if 1+1 != 2 {
		t.Fatal("数学规律被破坏了")
	}
}
~~~

执行：

~~~powershell
go test ./...
~~~

如果测试失败，先看失败函数名、文件行号和实际值，再修改代码；不要只重复运行命令。

## 10. 常见问题

### go 不是内部或外部命令

通常是终端没有重新打开，或 Go 安装目录没有加入 PATH。重新打开终端后再次执行 go version；仍失败时检查系统环境变量。

### go: cannot find main module

当前目录及其父目录不存在 go.mod。进入正确项目根目录，或执行 go mod init。

### 依赖下载很慢

检查 go env GOPROXY。团队项目应统一代理配置，避免每个人的依赖来源不同。

### 编辑器没有代码提示

确认打开的是项目根目录、gopls 已安装，并查看编辑器的 Go 扩展日志。
