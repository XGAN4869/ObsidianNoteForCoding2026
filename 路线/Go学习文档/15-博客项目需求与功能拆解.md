# 个人博客项目：需求与功能拆解

## 1. 项目目标

go-blog 是一个以 Go 后端为核心的个人博客系统。它的目标不是堆砌功能，而是把 HTTP、数据库、认证、缓存、测试和分层架构串成一个可运行项目。

第一版完成后，用户可以注册登录、浏览文章、发表评论；作者可以写作和发布文章；管理员可以审核评论、管理内容和用户。

## 2. 角色与权限

| 角色 | 未登录 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 查看已发布文章 | ✓ | ✓ | ✓ |
| 搜索文章 | ✓ | ✓ | ✓ |
| 发布评论 | × | ✓ | ✓ |
| 修改自己的资料 | × | ✓ | ✓ |
| 创建文章 | × | ✓ | ✓ |
| 修改自己的文章 | × | ✓ | ✓ |
| 修改他人文章 | × | × | ✓ |
| 审核评论 | × | × | ✓ |
| 管理用户 | × | × | ✓ |

权限判断放在 Service 层，不把“是不是管理员”散落在各个 Handler 中。

## 3. 前台功能

- 文章列表按发布时间倒序。
- 只有 published 状态的文章对游客可见。
- 支持分类、标签和关键词筛选。
- 详情页返回标题、摘要、正文、作者、标签、发布时间和浏览量。
- 浏览量采用最终一致性策略，避免每次请求都阻塞主查询。
- 登录用户可以评论，评论先进入 pending 状态。
- 支持回复已有评论，形成 parent_id 树。
- 只有 approved 评论展示给游客。

## 4. 用户功能

- 注册：校验用户名、邮箱和密码强度。
- 登录：返回 Access Token 和 Refresh Token。
- 刷新：校验 Refresh Token 后签发新 Access Token。
- 退出：撤销 Refresh Token。
- 资料：修改头像、昵称和简介。
- 密码：验证旧密码后修改新密码。

密码只保存 Argon2id 或 bcrypt 哈希，绝不保存明文。

## 5. 管理功能

- 文章：创建、编辑、发布、归档、删除、恢复。
- 分类：新增、重命名、删除前检查文章引用。
- 标签：新增、合并、删除。
- 评论：审核、拒绝、删除、批量处理。
- 用户：查看、禁用、恢复、调整角色。
- 审计：记录操作者、目标和时间。

## 6. 非功能需求

### 安全

- 所有写操作校验输入。
- 使用参数化 SQL。
- JWT Secret 从环境变量读取。
- 登录失败返回模糊错误，避免暴露用户是否存在。
- 设置 CORS、请求体大小和基础限流。

### 可靠性

- 数据库和 Redis 初始化失败时快速退出。
- HTTP Server 有读写超时。
- 收到终止信号时优雅关闭。
- 错误日志包含 request_id，但不包含敏感信息。

### 可维护性

- Handler 不写 SQL。
- Repository 不返回 HTTP 状态码。
- Service 通过接口依赖外部资源。
- DTO 和数据库模型分离。
- 核心规则必须有单元测试。

## 7. 用户故事与验收条件

### 游客浏览文章

Given 数据库有已发布文章，When 游客请求文章列表，Then 返回分页结果和总数；草稿不应出现。

### 作者发布文章

Given 用户已登录且是文章作者，When 提交发布请求，Then 状态改为 published 并记录发布时间；非作者返回 403。

### 管理员审核评论

Given 评论状态为 pending，When 管理员批准，Then 状态变为 approved；普通用户调用同一路由返回 403。

## 8. 迭代顺序

1. 健康检查和项目启动。
2. 用户注册、登录和鉴权。
3. 分类、标签和文章 CRUD。
4. 文章发布、列表、详情和搜索。
5. 评论与审核。
6. Redis 缓存、限流和审计。
7. 测试、Docker 和部署。
