# 个人博客项目：总体架构与完整目录结构

## 1. 技术选型

- Go 1.22+
- Gin：HTTP 路由和中间件
- MySQL 8 或 PostgreSQL 16：关系数据
- Redis 7：缓存、限流和 Refresh Token 撤销
- JWT：Access Token
- Docker Compose：本地依赖编排
- golang-migrate：数据库迁移
- slog 或 zap：结构化日志

## 3. 依赖方向

~~~text
cmd/server
    ↓
app + router
    ↓
handler → service → repository interface
              ↓              ↑
           cache        SQL repository
~~~

- handler 可以依赖 service、dto、response。
- service 可以依赖 model、repository 接口、cache 接口。
- repository 实现可以依赖 database 和 model。
- model 不依赖 handler。
- repository 不依赖 Gin。
- main 负责组装具体实现。

## 4. 一次请求的执行流程

~~~text
客户端
  ↓
Gin Router
  ↓
Recovery / RequestID / Logger / CORS
  ↓
Auth Middleware（需要登录的路由）
  ↓
Handler 绑定和校验 DTO
  ↓
Service 校验权限并执行业务规则
  ↓
Repository 查询数据库，Cache 读写 Redis
  ↓
Service 组装结果 DTO
  ↓
统一 Response 输出 JSON
~~~

## 5. main 的组装顺序

1. 读取并校验配置。
2. 初始化日志。
3. 初始化数据库连接池并 Ping。
4. 初始化 Redis 并 Ping。
5. 创建 Repository 实现。
6. 创建 Service，并注入 Repository/Cache。
7. 创建 Handler。
8. 注册路由和中间件。
9. 启动 HTTP Server。
10. 监听信号并按 Server → Redis → DB 顺序关闭。

## 6. 为什么需要 DTO

数据库 Post 模型可能包含 deleted_at、内部审核字段；API 响应只应暴露 id、title、summary、author 和 published_at。DTO 还能兼容数据库字段名与 JSON 字段名的差异。
