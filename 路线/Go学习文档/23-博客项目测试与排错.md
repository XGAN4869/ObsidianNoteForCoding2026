# 博客项目测试与排错

## 1. 测试分层

~~~text
纯函数单元测试
      ↓
Service + fake repository
      ↓
Handler + httptest
      ↓
Repository + 临时数据库
      ↓
端到端 API + Docker Compose
~~~

越靠上越快，越靠下越接近真实环境。日常开发优先运行快速测试，CI 再运行完整套件。

## 2. 单元测试重点

- 分页参数边界：page=0、负数、超大 page_size。
- 状态转换：draft → published → archived。
- 权限规则：作者、管理员、普通用户。
- 错误映射：errors.Is 和 errors.As。
- 标签去重、slug 生成和敏感词过滤。

## 3. Service 测试

使用 fake repository 记录调用：

~~~go
type fakePostRepo struct {
	found *Post
	updated *Post
	err error
}

func (f *fakePostRepo) FindByID(ctx context.Context, id int64) (*Post, error) {
	return f.found, f.err
}
~~~

断言不仅要看返回值，还要检查权限失败时 Repository 没有被错误调用，发布时更新字段和事务行为正确。

## 4. Handler 测试

使用 httptest 检查：

- 路由匹配。
- JSON 请求绑定。
- 参数错误返回 400。
- 鉴权失败返回 401。
- Service 错误映射为正确状态码。
- 成功响应字段不泄露内部信息。
- request_id 出现在响应和日志上下文。

## 5. Repository 集成测试

每个测试准备自己的数据，测试后回滚或清理。重点验证：

- SQL 参数顺序。
- NULL 字段扫描到指针。
- 事务提交和回滚。
- 软删除过滤。
- 分页总数和列表一致。

## 6. 端到端场景

推荐按业务旅程测试：

1. 注册普通用户。
2. 登录取得 Token。
3. 创建草稿。
4. 发布文章。
5. 游客查询文章。
6. 普通用户发表评论。
7. 管理员登录并审核评论。
8. 游客再次查询并看到评论。
9. 非作者尝试修改文章并被拒绝。

## 7. 故障排查路径

### 返回 500

1. 查看 request_id。
2. 查结构化日志中的 error_code。
3. 判断是配置、数据库、Redis 还是业务异常。
4. 用最小请求复现。
5. 检查最近迁移和依赖变化。
6. 增加针对失败分支的测试。

### 数据库超时

检查连接池耗尽、慢 SQL、事务未提交、Context deadline 和数据库锁等待。

### Redis 缓存脏数据

先确认写入成功后是否删除缓存，再检查 key 命名、序列化版本和过期时间。必要时提供按文章 ID 清理缓存的运维命令。

## 8. CI 检查清单

~~~powershell
gofmt -l .
go test ./...
go test -race ./...
go vet ./...
go build ./cmd/server
~~~

构建镜像前运行迁移验证和 API smoke test。

## 9. 本章练习

1. 为发布文章写成功、非作者、重复发布三组测试。
2. 模拟 Redis 返回错误，验证文章仍能从数据库读取。
3. 模拟数据库超时，验证请求不会无限等待。
4. 写一份从 request_id 定位 500 的排错记录。
