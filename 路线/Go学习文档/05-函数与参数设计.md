# 函数与参数设计

## 1. 学习目标

掌握函数声明、多返回值、可变参数、函数值、闭包和递归，并能围绕业务含义设计清晰的输入输出。

## 2. 基础声明

~~~go
func add(a, b int) int {
	return a + b
}
~~~

同类型相邻参数可以合并。函数应完成一个清晰任务，名称描述动作，例如 CreatePost、FindUserByID。

## 3. 多返回值

Go 常用“结果 + 错误”：

~~~go
func parsePage(raw string) (int, error) {
	page, err := strconv.Atoi(raw)
	if err != nil {
		return 0, fmt.Errorf("页码不是整数：%w", err)
	}
	if page < 1 {
		return 0, errors.New("页码必须大于 0")
	}
	return page, nil
}
~~~

调用者必须明确处理错误：

~~~go
page, err := parsePage(input)
if err != nil {
	return err
}
~~~

命名返回值适合短函数或 defer 修改返回值的场景，长函数中过度使用会让数据来源不清晰。

## 4. 可变参数

~~~go
func joinTags(separator string, tags ...string) string {
	return strings.Join(tags, separator)
}

joinTags(",", "go", "sql")
joinTags(",", existingTags...)
~~~

可变参数在函数内部是切片。不要用它替代结构化配置；参数很多时使用配置结构体。

## 5. 函数作为值

~~~go
type Validator func(string) error

func validate(value string, rules ...Validator) error {
	for _, rule := range rules {
		if err := rule(value); err != nil {
			return err
		}
	}
	return nil
}
~~~

函数值适合策略、回调和中间件。核心业务依赖较复杂时优先使用接口，便于表达多个方法。

## 6. 闭包

~~~go
func sequence() func() int {
	current := 0
	return func() int {
		current++
		return current
	}
}
~~~

闭包会捕获外部变量。被长期保存的闭包也会延长捕获对象的生命周期；并发调用闭包时还要考虑数据竞争。

## 7. 参数传递

Go 只有值传递。传入结构体会复制结构体；传入指针会复制指针值，但双方指向同一对象。

~~~go
func rename(user *User, name string) {
	user.Name = name
}
~~~

切片和 Map 的描述符被复制，但通常仍引用同一底层数据。函数是否修改入参应通过名称、文档或返回新值表达清楚。

## 8. Options 模式

可选项很多时可以使用函数选项：

~~~go
type Server struct {
	addr    string
	timeout time.Duration
}

type Option func(*Server)

func WithTimeout(d time.Duration) Option {
	return func(s *Server) { s.timeout = d }
}

func NewServer(addr string, options ...Option) *Server {
	s := &Server{addr: addr, timeout: 5 * time.Second}
	for _, option := range options {
		option(s)
	}
	return s
}
~~~

简单业务函数不必套用 Options 模式，避免过度设计。

## 9. 递归

递归适合树结构，例如输出评论树：

~~~go
func countComments(node *Comment) int {
	total := 1
	for _, child := range node.Children {
		total += countComments(child)
	}
	return total
}
~~~

必须有终止条件。外部输入形成的深树可能造成栈过深，必要时改为显式队列或栈。

## 10. 博客实战：函数边界

Handler 负责解析 HTTP，Service 负责业务规则，Repository 负责持久化：

~~~go
func (s *PostService) Publish(ctx context.Context, authorID, postID int64) error {
	post, err := s.posts.FindByID(ctx, postID)
	if err != nil {
		return err
	}
	if post.AuthorID != authorID {
		return ErrForbidden
	}
	post.Status = "published"
	return s.posts.Update(ctx, post)
}
~~~

## 11. 常见错误与练习

常见错误：函数过长、布尔参数语义不明、忽略 error、在工具函数中偷偷修改全局状态、返回过多彼此相关的值。

练习：

1. 编写 ParsePagination，返回 page、pageSize 和 error。
2. 使用 Validator 类型组合用户名校验。
3. 用闭包实现调用次数统计器。
4. 把一个超过 50 行的函数按职责拆分，并说明拆分理由。
