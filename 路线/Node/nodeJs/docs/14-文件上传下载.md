# 14 文件上传、下载与大文件处理

## 1. 上传的安全边界

上传不是“把文件保存到一个目录”这么简单。至少限制：单文件大小、总请求大小、文件数量、允许的类型和用户权限。`Content-Type` 由客户端提供，不能单独当作真实类型；需要检查文件签名或使用可信解析库。

保存时使用随机文件名，不使用用户原名作为路径；上传目录不应直接执行脚本；病毒扫描、图片解码等耗时工作可以异步处理。

## 2. 分片上传

大文件可拆成分片：客户端先申请 upload id，再上传带序号的分片，服务端校验大小和 checksum，全部到齐后按顺序合并。合并必须防止重复、乱序和并发写入；未完成的 upload id 要有过期清理任务。

## 3. 安全下载

下载前检查用户是否有权限。文件 ID 应映射到服务端保存的路径，不能让用户直接提交任意路径。预签名 URL 要设置短有效期、限定对象和方法，密钥只放服务端。

## 4. Range 下载

视频、音频和大文件常需要 `Range: bytes=start-end`。服务端应校验范围，成功返回 `206 Partial Content`、`Content-Range` 和正确长度；不支持或范围非法时返回恰当状态码。不要自己猜所有浏览器行为，优先使用成熟静态文件中间件，并在代理层配置缓存。

## 5. 图片、压缩与 FFmpeg

图片压缩、转码可以通过 `spawn` 调用 pngquant、FFmpeg 等外部程序。参数必须使用数组，不要把用户输入拼成 shell 命令；检查退出码、标准错误、超时和临时文件清理。

## 动手题与检查

设计一个“上传头像”接口的检查表：类型、大小、随机名、目录权限、病毒扫描、失败清理、下载鉴权。只写设计，不要拿真实用户文件测试。

- [ ] 没有路径穿越和命令注入。
- [ ] 大文件不会一次性读入内存。
- [ ] 临时文件和过期分片会清理。
