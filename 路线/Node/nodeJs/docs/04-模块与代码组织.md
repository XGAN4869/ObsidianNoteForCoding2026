# 04 模块系统与代码组织

## 1. CommonJS 与 ES Modules

CommonJS：

```js
// math.cjs
function add(a, b) { return a + b }
module.exports = { add }

// main.cjs
const { add } = require('./math.cjs')
console.log(add(2, 3))
```

ES Modules：

```js
// math.js
export function add(a, b) { return a + b }

// main.js（package.json 中设置 "type": "module"）
import { add } from './math.js'
console.log(add(2, 3))
```

同一个项目可以使用 `.cjs` 和 `.mjs` 明确指定格式，但初学时最好选一种并保持一致。ESM 的相对导入通常需要写文件扩展名。

## 2. `__dirname` 与 `import.meta.url`

CommonJS 可用 `__dirname`；ESM 没有这个变量。ESM 读取当前文件附近资源时可这样写：

```js
import { fileURLToPath } from 'node:url'
import path from 'node:path'

const currentFile = fileURLToPath(import.meta.url)
const currentDir = path.dirname(currentFile)
const configPath = path.join(currentDir, 'config.json')
```

## 3. 导出边界

一个模块最好只负责一个清楚的职责：计算、读取文件、处理 HTTP 请求不要全部混在一个文件。导出公开函数，隐藏内部变量：

```js
const notes = []

export function listNotes() {
  return [...notes]
}
```

返回副本可以避免调用者直接修改模块内部数组。

## 4. 推荐的初学者目录

```text
project/
├─ src/
│  ├─ server.js       # 启动服务
│  ├─ routes/         # 路径和 HTTP 方法
│  ├─ services/        # 业务规则
│  └─ repositories/    # 文件或数据库读写
├─ test/
├─ package.json
└─ README.md
```

目录不是越多越专业。代码少时可以先放在 `src/server.js`，出现重复或职责混乱时再拆分。
