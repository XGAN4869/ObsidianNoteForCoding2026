# 工具函数写作规则

模块标题格式：

```markdown
## parseMoney（工具函数）
```

节内必须严格使用以下三级标题，顺序不能调整。

## 一句话说明

说明函数做什么、输入是什么、输出是什么、适合什么场景。不要在“一句话说明”中塞入完整调用步骤。

## 函数签名

使用 TypeScript 代码块：

```ts
export function parseMoney(value: string | number | null, fallback?: number): number
```

签名必须与源码一致。泛型、重载、可选参数和联合类型不能省略。

## 参数

必须使用表格：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `value` | `string \| number \| null` | 是 | 待转换的值 |

## 返回值

说明：

- 返回类型
- 正常返回什么
- 失败或空值时返回什么
- 是否可能抛出异常

## 示例

先给最小示例，再给两个进阶示例。

```ts
import { parseMoney } from '@/utils/money'

// 最小使用：字符串金额转数字
const price = parseMoney('128.50')
console.log(price)
```

进阶示例必须来自真实使用方式，例如表单提交转换、接口响应归一化、批量处理数组。

## 边界情况

必须明确列出：

- `null`
- `undefined`
- 空字符串
- 空数组
- 非数字字符串
- 负数或超大数字，如果适用

如果源码行为无法确认，使用：

```markdown
<!-- TODO: 待作者确认 -->
```

## 常见坑

至少说明两个错误认知或错误写法，例如：

- 把 `null` 和 `0` 当成同一种情况
- 把格式化结果再次传给计算函数
- 忽略异常或 NaN
- 对数组直接原地修改
