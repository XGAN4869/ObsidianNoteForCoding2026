# Vue Module README

目标是把用户给出的前端模块写成一份能让 3～6 个月经验的前端开发者独立接入、正确调用、避开常见错误的
`README.md`。重点写“怎么用”，不是解释实现细节，也不是复制源码。

## 硬性规则

1. 全中文，语气像带新人的资深工程师；直接、具体，不写官腔、不抒情、不扩写无关背景。
2. 每个模块独立成节，严格使用对应类型的规定结构，不把多个模块混写。
3. 所有示例必须能直接复制运行。禁止 `...`、`…`、伪代码、省略参数或自造不存在的 API。
4. 代码注释只解释关键行为，例如调用时机、必填参数、避免踩坑的原因。
5. 不复制大段源码。只保留理解和调用所必需的签名、类型、少量关键实现事实。
6. 源码语义不明确时，原位置写 `<!-- TODO: 待作者确认 -->`，不要猜业务含义、默认值或返回值。
7. 标题最多三级：文档标题用一级，模块或模块关系用二级，节内固定小节用三级。

## 工作流程

### 1. 建立模块清单

先按用户提供的类型和文件名建立清单。每个模块必须记录：

- 类型：Vue 组件、组合式 Hook、工具函数或其他
- 文件路径
- 主要职责
- 使用它的现有调用点
- 是否存在类型定义、默认值或运行时校验

无法判断模块类型或职责时，不要继续编造，直接在对应节中标记待确认。

### 2. 核对真实接口

阅读模块文件、同目录类型文件以及至少一个真实调用点。必须核对：

- 组件的 Props、Emits、Slots、`v-model`
- Hook 的选项、返回值、生命周期依赖和并发行为
- 工具函数的签名、返回值、空值和异常行为
- import 路径、必填配置、Provider 或全局注册要求

只按当前代码和调用点写文档。不要在 README 中发明新参数、别名或兼容层。

### 3. 读取对应规则

- Vue 组件：读 [references/vue-component.md](references/vue-component.md)
- 组合式 Hook：读 [references/composable.md](references/composable.md)
- 工具函数：读 [references/utility.md](references/utility.md)
- 最后统一读 [references/module-relations.md](references/module-relations.md)

### 4. 组装 README

以 [assets/README.template.md](assets/README.template.md) 为骨架，但必须替换所有占位内容。
最终结构只能是：

```text
# README
## 模块名（类型）
### 固定小节
### 固定小节
## 模块名（类型）
### 固定小节
## 模块之间的关系
### 调用关系
### 综合示例
```

模块顺序优先跟随用户粘贴顺序；用户要求按依赖顺序时，按依赖顺序排列。

### 5. 校验后输出

生成后运行：

```bash
python3 scripts/validate_readme.py <生成的README.md>
```

校验失败必须修复后重新校验。最终回复直接输出完整 Markdown 正文，从一级标题开始；
不要先解释、不要附加“下面是 README”、不要再包一层 Markdown 代码围栏。

## 写作重点

- 每个模块开头先告诉新人“什么时候该用、什么时候不要用”。
- 表格写事实，示例写完整调用过程。
- “常见坑”必须使用错误写法与正确写法对照，并解释后果。
- 综合示例必须真的把这些模块串起来，不能只是并列展示。
- 没有真实信息的位置使用待确认注释，宁可留缺口，也不要把猜测写成契约。

## 质量门禁

- 每个模块都有固定小节，且没有四级及以上标题。
- Props、Emits、Slots、选项、返回值、参数表覆盖实际公开接口。
- 组件至少 2 个场景示例；Hook 至少 3 个场景示例；工具函数至少 3 个示例。
- 所有代码块闭合，代码块内没有 `...`、`…` 或伪代码。
- 不复制大段源码，不出现未说明的新 API。
- 最后包含“模块之间的关系”和可运行的综合示例。
- 所有不确定信息都使用 `<!-- TODO: 待作者确认 -->`。
