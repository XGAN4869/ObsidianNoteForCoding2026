# 03 · 功能模块详细设计

> 这一篇把每个模块"拆到骨头"：要做什么、怎么交互、状态怎么变、有哪些边界情况。
> 读完后你会对每个功能了如指掌，写代码只是"照着填空"。

## 模块一：随笔（Notes）

### 目的
随手记录文字、想法、心情，是博客最核心的内容载体。

### 功能清单

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 新建随笔 | 标题 + 正文（Markdown）+ 心情 + 标签 | P0 |
| 编辑随笔 | 修改已有随笔 | P0 |
| 删除随笔 | 二次确认后删除 | P0 |
| 列表浏览 | 按时间倒序，支持分页/懒加载 | P0 |
| 草稿 | 未完成的可存草稿，列表里标记 | P1 |
| 标签筛选 | 点标签过滤随笔 | P1 |
| 全文搜索 | 搜标题和正文 | P1 |
| 心情筛选 | 按心情过滤 | P2 |

### 交互流程

```
列表页 → 点"写一篇" → 写作页
                    → 输入标题/正文/选心情/加标签
                    → 点"保存"
                    → 调 POST /api/notes
                    → 返回列表页（新随笔在顶部）
```

### 状态机（一篇文章的生命周期）

```
[draft 草稿] ──保存──> [published 已发布] ──编辑──> [published]
     │                                             │
     └──────────────── 删除 ────────────> [已删除]
```

### 边界情况（写代码前必须想清楚）

- 标题为空怎么办？→ 自动用正文前 20 字当标题，或提示"写个标题吧"。
- 正文为空能保存吗？→ 允许存草稿，不允许发布。
- 标签重复？→ 自动去重。
- 删除后能恢复吗？→ 第一版不做回收站，但删除前二次确认。**建议加"软删除"字段，将来可恢复**（师傅会在教程里留这个扩展点）。

## 模块二：时光胶囊（Time Capsule）

### 目的
写给未来的自己，设定一个未来的日期，到期前"密封"，到期后才能打开。

### 功能清单

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 埋胶囊 | 标题 + 内容 + 心情 + 打开日期 | P0 |
| 查看列表 | 区分"未到期(密封)"和"已到期(可打开)" | P0 |
| 打开胶囊 | 到期后点击打开，有拆封动画 | P0 |
| 删除胶囊 | 二次确认 | P1 |

### 核心规则（务必记住）

1. **`openAt` 必须晚于现在**，埋的时候校验，早于现在的日期不允许选。
2. **未到期不能打开**：前端隐藏内容，后端 API 也校验（防止绕过前端）。
3. **打开是一次性的**：打开后 `isOpened = true`，记录 `openedAt`。
4. **到期判断**：`now >= openAt` 即为"可打开"，由后端判断并返回 `canOpen` 字段，**不要在前端用本地时间判断**（时区坑）。

### 交互流程

```
胶囊页 → 点"埋一个"
       → 输入内容 + 选打开日期（日期选择器，只能选未来）
       → 保存 → POST /api/capsules
       → 列表里显示"🔒 还有 N 天"
       
到期后 → 卡片显示"🔓 可以打开了"
       → 点击 → 拆封动画 → POST /api/capsules/:id/open
       → 显示内容，标记已打开
```

### 状态机

```
[sealed 密封] ──到期──> [ready 可打开] ──点击──> [opened 已打开]
     │                      │
     └────── 删除 ──────────┘
```

### 边界情况

- 打开日期选了过去？→ 前端禁止，后端也校验。
- 打开日期是"今天"？→ 允许，算作立即到期。
- 已打开的胶囊能再改吗？→ 不能改内容，只能删除。
- 时间到时区问题？→ 所有日期存 UTC，展示时转本地时区。

## 模块三：待办清单（Todos）

### 目的
管理日常任务，轻量、快速、有"完成"的爽感。

### 功能清单

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 添加待办 | 输入框 + 回车/按钮 | P0 |
| 勾选完成 | 划掉 + 动画 | P0 |
| 取消勾选 | 恢复未完成 | P0 |
| 删除待办 | 单个删除 | P0 |
| 截止日期 | 可选，今天/明天/自定义 | P1 |
| 拖拽排序 | 调整顺序 | P2 |
| 分组显示 | 今天 / 未来 / 已完成 | P2 |
| 清空已完成 | 一键清空 | P2 |

### 交互流程

```
待办页
  ├─ 顶部输入框 → 回车添加 → POST /api/todos → 追加到列表
  ├─ 点击勾选框 → PATCH /api/todos/:id {done:true} → 划掉 + 动画
  ├─ 点击删除 → 确认 → DELETE
  └─ 拖拽 → PATCH 更新 order
```

### 关键交互细节

- **勾选动画**：打勾的 SVG stroke 用 `stroke-dasharray` + `stroke-dashoffset` 做"手绘打勾"动画，文字同时划线。
- **乐观更新（Optimistic Update）**：点勾选立即生效（本地先改），再同步后端；失败就回滚。这样手感最顺。师傅会在教程里教这个"高级但必要"的技巧。

### 边界情况

- 空标题不能添加。
- 连续快速点击勾选？→ 防抖，避免请求错乱。
- 待办数量多？→ 第一版不做分页，几百条足够；以后加"已完成折叠"。

## 模块四：自定义模块（Widgets）

### 目的
像布置房间一样，在首页摆一些实用小部件，让博客"活"起来。

### 内置模块类型（第一版提供这些）

| 类型 | 名称 | 说明 | 配置项 |
|------|------|------|--------|
| clock | 时钟 | 显示当前时间，手绘表盘 | 无 |
| weather | 天气 | 显示某城市天气 | 城市名（用免费天气 API） |
| pomodoro | 番茄钟 | 25 分钟专注计时 | 时长 |
| quote | 一句话 | 随机/收藏的一句话 | 无 |
| calendar | 心情日历 | 月视图展示心情色块 | 无 |
| countdown | 倒计时 | 距离某个日子的天数 | 目标日期 |

### 交互流程

```
布置页
  ├─ 显示已添加的模块（网格排列）
  ├─ 点"+ 添加模块" → 弹出类型选择 → 选类型 → 配置
  ├─ 拖拽调整位置 → PATCH order
  └─ 每个模块有删除/编辑按钮
```

### 模块的通用结构

每个模块组件都实现一个统一接口：

```ts
interface WidgetProps {
  widget: Widget;           // 模块数据
  onUpdate: (config) => void; // 更新配置
  onDelete: () => void;     // 删除
}
```

这样添加新模块时，只要写一个符合接口的新组件 + 注册到类型列表即可。

### 边界情况

- 天气 API 请求失败？→ 显示"天气加载失败"，不阻塞其他模块。
- 时钟要实时刷新 → 用 `setInterval`，但记得清理，避免内存泄漏。
- 模块配置保存失败 → 提示重试。

## 模块五：心情系统（Mood，贯穿所有模块）

### 目的
OMORI 是讲情绪的游戏，心情是博客的"灵魂标记"，串联随笔、胶囊、首页、日历。

### 功能

1. **7 种心情**（枚举 + 颜色 + 手绘图标），见 01 章。
2. **每日心情记录（MoodLog）**：首页每天选一次当天心情，形成"心情日历"。
3. **心情日历**：月视图，每一天一个心情色块，hover 显示详情。
4. **心情筛选**：随笔/胶囊可按心情过滤。

### 心情图标设计（手绘 SVG）

| 心情 | 图形创意（对应 OMORI） |
|------|----------------------|
| 平静 Calm | 水母（游戏里白色水母是"平静"意象） |
| 开心 Happy | 一朵小花 |
| 难过 Sad | 一滴雨 / 眼泪 |
| 愤怒 Angry | 红色手（游戏标志性元素） |
| 害怕 Afraid | 蜘蛛 |
| 疲惫 Tired | 一朵打盹的云 |
| 孤独 Lonely | 单只眼睛 |

> 这些图标会做成一个可复用的 `<MoodIcon mood="happy" size={32} />` 组件，全站通用。

## 模块六：补充闭环功能

### 6.1 首页聚合（白空间 Home）

把散落各处的信息聚合到一屏：
- 当天心情（可改）
- 三个功能"门"（随笔/胶囊/待办入口）
- 今日待办精简版
- 随机回忆
- 用户自定义的模块（Widgets）

### 6.2 随机回忆（Memories）

- 从历史随笔里随机抽一篇，展示一句话。
- 每次进首页刷新，或手动点"再换一个"。
- 目的是制造"偶然重逢过去自己"的惊喜。

### 6.3 搜索（Search）

- 全文搜索随笔的标题 + 正文。
- 用 SQLite 的 `LIKE`（简单）或 Prisma 的 `contains`。
- 第一版搜随笔即可，扩展可搜胶囊。

### 6.4 数据备份（Backup）

- **导出**：一键把所有数据（随笔/胶囊/待办/心情/模块/设置）打包成 JSON 下载。
- **导入**：上传 JSON 恢复数据。
- **这是"文字是你的命"的保险**，必须做，且要测试。

### 6.5 主题切换（Settings）

- 浅色（白空间）⇄ 深色（现实）切换。
- 存到 `Setting` 表 + 本地 `localStorage`，刷新不丢。

## 完整闭环回顾

```
你记录（随笔/胶囊/待办）
   ↓
打上心情标记（Mood）
   ↓
首页聚合 + 心情日历呈现（回顾）
   ↓
随机回忆制造惊喜（连接过去）
   ↓
一键备份（安全）
```

**一句话：这个博客不只是"记录工具"，而是"一个陪你的数字空间"。**

## 各模块优先级汇总（先做哪个）

按"价值 × 难度"排序，建议开发顺序：

1. **随笔**（P0，最高价值，教会你完整 CRUD 套路）
2. **待办**（P0，简单，练手 + 乐观更新）
3. **时光胶囊**（P0，复用随笔套路 + 新增定时逻辑）
4. **心情系统**（P1，贯穿性的，越早做越顺）
5. **首页聚合 + 白空间**（P1，把前面的串起来）
6. **自定义模块**（P2，最灵活也最复杂，放后面）
7. **搜索 + 随机回忆 + 备份 + 主题**（P1/P2，补闭环）

> 教程章节就是按这个顺序排的，你跟着走就行。
