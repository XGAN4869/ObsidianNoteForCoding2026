## 一、报错速查表

| 报错/现象 | 原因 | 解决 |
|-----------|------|------|
| `params is possibly undefined` / `params` 报错 | Next 15 的 `params` 是 Promise | 用 `const { id } = await params;` |
| `Module not found: Can't resolve '...'` | 路径写错 / 包没装 | 检查 import 路径；`npm install` 重装 |
| `PrismaClient is not configured` | 没跑 migrate | `npx prisma migrate dev` |
| `Error: P1001`（连不上数据库） | `DATABASE_URL` 没设或路径错 | 检查 `.env` 的 `DATABASE_URL` |
| `Hydration failed` | 服务端和客户端渲染不一致（常见：用了 `Date.now()`、`localStorage` 在服务端） | 把相关逻辑放 `useEffect`，或标 `"use client"` |
| `window is not defined` | 在服务端组件用了浏览器 API | 标 `"use client"` 或放 `useEffect` |
| `localStorage is not defined` | 同上 | 同上 |
| 访问 `/` 没被重定向到登录页 | `middleware.ts` 位置/命名错 | 确保在项目根目录，文件名 `middleware.ts` |
| 登录后刷新又回到登录页 | Cookie 没写成功 / JWT 校验失败 | 检查 `JWT_SECRET` 是否一致、Cookie 参数 |
| 中文乱码 | 文件编码问题 | 确保文件是 UTF-8 |
| `@prisma/client did not initialize` | 改了 schema 没重新 generate | `npx prisma generate` |

## 二、高频坑详解

### 1. Server Component vs Client Component（最容易晕）

Next.js App Router 里，**默认所有组件是服务端组件**，不能用 `useState`、`useEffect`、浏览器 API。

规则（记牢）：
- 要用 `useState` / `useEffect` / 事件 / 浏览器 API → 文件顶部写 `"use client"`。
- 纯展示、读数据（可 `await db.xxx`）→ 保持服务端组件。

师傅在本教程里，**所有有交互的页面都标了 `"use client"`**，你照着写就不会错。等熟练了再学"服务端组件优先"的高级用法。

### 2. `useEffect` 依赖数组

```tsx
useEffect(() => {
  fetchData(id);
}, [id]); // ← 依赖数组，id 变了才重新执行
```

- 忘了写依赖 → 可能每次渲染都跑，或永远不跑。
- 写了空的 `[]` → 只在挂载时跑一次。
- 用了 `id` 却没写进依赖 → 数据不更新。

### 3. 日期/时区

- 数据库存 UTC，展示用 `toLocaleDateString("zh-CN")` 自动转本地。
- "还有 N 天"用时间戳差值算，别手算年月日。
- `datetime-local` 返回本地时间字符串，`new Date()` 按本地解析，别加 `Z` 后缀。

### 4. Prisma 的 `findUnique` vs `findFirst`

- `findUnique`：只能用 `@unique` / `@id` 字段查，查不到返回 `null`。
- `findFirst`：可以加任意条件，查不到返回 `null`。
- 查详情用 `findUnique({ where: { id } })` 最快。

### 5. 乐观更新失败回滚

第 09 章待办的 `toggle` 函数里，失败要回滚。**别省略回滚逻辑**，否则断网时界面状态和数据库会不一致。

## 三、开发时的调试技巧

1. **看浏览器 Network 面板**：点 F12 → Network，看 API 请求的响应（状态码 + 返回体）。404 说明路径错，500 看后端报错。
2. **看终端**：`npm run dev` 的终端会打印后端报错堆栈，这是第一手线索。
3. **`console.log` 大法**：在 API 里 `console.log(body)` 看入参，在前端 `console.log(d)` 看返回。
4. **Prisma Studio**：可视化看数据库，超好用：

```bash
npx prisma studio
```

浏览器打开它给的地址，能直接看/改数据，排查数据问题神器。

## 四、性能与代码质量

1. **定时器要清理**：时钟/番茄钟的 `setInterval`，`useEffect` 返回清理函数，否则切页面会内存泄漏。
2. **列表 key**：`map` 渲染必须用唯一 `key`（用 `id`），否则 React 警告 + 渲染错乱。
3. **大文本不要全量渲染**：随笔列表只显示摘要（`.slice(0, 80)`），详情才渲染全文。
4. **图片懒加载**：以后加图片用 Next 的 `<Image>` 组件，自带懒加载和优化。

## 五、安全清单

- [ ] 密码用 bcrypt 哈希，绝不存明文
- [ ] JWT_SECRET 足够长且保密，`.env` 不进 Git
- [ ] 写操作 API 都有 `requireAuth` 校验
- [ ] 胶囊"未到期不能开"在后端也校验
- [ ] 生产环境 Cookie 的 `secure: true`
- [ ] `robots.txt` 禁止搜索引擎抓取（如果你不想被公开）

## 七、最后的师傅叮嘱

1. **先跑起来，再求完美**——丑没关系，能用最重要。
2. **理解比抄代码重要**——每段代码都带注释，你要读懂"为什么"。
3. **遇到报错先读最后一行**——90% 的答案就在报错信息里。
4. **你的文字是你的命**——养成定期备份的习惯。
5. **这个博客是"你的空间"**——OMORI 的精髓是真诚面对自己的情绪，别把它做成一个冷冰冰的工具。
