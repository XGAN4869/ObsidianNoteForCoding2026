## 一、这个博客要做什么

一个**只有你自己用的个人博客**，但它不是普通的文章列表，而是一个"数字心灵空间"。核心功能：

| 编号  | 模块                 | 一句话说明             |
| --- | ------------------ | ----------------- |
| 1   | 随笔（Notes）          | 随手记录想法、文字、心情      |
| 2   | 时光胶囊（Time Capsule） | 写给未来的自己，定时才能打开    |
| 3   | 待办清单（Todos）        | 管理日常任务，有勾选和完成动画   |
| 4   | 自定义模块（Widgets）     | 像布置房间一样，自己拖拽摆放小部件 |
| 5   | 补充闭环（见下）           | 让整个博客"活"起来、用得起来   |

### 为什么需要"补充功能"让它闭环？

只有"记录"没有"回顾"和"连接"，博客就是一潭死水。为了逻辑闭环，我建议补充以下能力（后面的文档会详细展开）：

1. **心情标记（Mood）** —— 每条随笔/胶囊都带一个情绪表情，长期积累形成"心情日历"，这是 OMORI 风格最契合的一点（游戏本身就是讲情绪的）。
2. **首页聚合（Home / 白空间）** —— 一个像 OMORI "White Space" 一样的首页，把随笔、待办、胶囊、心情全部聚合到一屏。
3. **标签/分类（Tags）** —— 随笔可以打标签，方便日后检索。
4. **搜索（Search）** —— 全文搜索所有内容。
5. **回忆（Memories / 随机回顾）** —— 随机弹出过去某天的随笔或照片，制造"偶然重逢"。
6. **设置与主题（Settings）** —— 切换深色/浅色、调整"白空间"氛围。
7. **数据导出/导入（Backup）** —— 你的文字是你的命，必须能一键备份成 JSON，也能导入恢复。

> 一句话闭环逻辑：**记录 → 标记 → 聚合 → 回顾 → 备份**。这样博客不只是"写"，而是"陪你过日子"。

## 二、技术选型（不给你过时的东西）

### 前端

| 技术                        | 版本基线             | 为什么选它                                         |
| ------------------------- | ---------------- | --------------------------------------------- |
| **Next.js**               | 15.x（App Router） | 你熟 React，Next 是 React 官方主推的全栈框架，SSR/SEO/路由一体化 |
| **React**                 | 19.x             | 随 Next 15 内置                                  |
| **Tailwind CSS**          | 4.x              | 原子化 CSS，最适合快速做出手绘风                            |
| **shadcn/ui**             | 最新（New York 风格）  | 不是 npm 包，是复制到你项目里的高质量组件源码，可随意改造成 OMORI 手绘风    |
| **TypeScript**            | 5.x              | 别裸写 JS，类型能救你无数次                               |
| **Zustand**               | 5.x              | 轻量状态管理，比 Redux 简单一百倍，适合你                      |
| **React Hook Form + Zod** | 最新               | 表单处理 + 数据校验，标准搭配                              |
| **Framer Motion**         | 11.x（现名 motion）  | 做 OMORI 那种"呼吸、漂浮、晕染"的动画                       |

### 关于 `style-vega`

你提到的 **`style-vega`** 我做了排查：目前 npm 上没有稳定、主流的 `style-vega` 包（"vega" 在生态里通常指 Vega/Vega-Lite 数据可视化库，和你的视觉风格无关）。**我判断这可能是你记错的名字，或者是某个很冷门的小众库。**

我的处理方案（后面文档会落地成代码）：

- **不强行引入一个不存在的库**，而是用 **Tailwind CSS 的自定义主题变量 + 少量 CSS 手绘效果（纸张纹理、手绘描边、抖动线条）** 来实现 OMORI 风格，这是最稳妥、最可控、可维护的做法。
- 如果你确实想用某个叫 `style-vega` 的具体库，把它的 GitHub 或 npm 链接发我，我再评估要不要替换进来。

> 师傅的忠告：**别为了"看起来高大上"引入一堆没人维护的库。** OMORI 风格的精髓是"手绘 + 情绪 + 留白"，这些用纯 CSS 完全能做出来，而且性能更好、更不容易坏。

### 后端

你偏向 **Node + Express**，我同意，但给你更现代、更省心的具体方案：

| 方案                                     | 说明                        | 我的推荐     |
| -------------------------------------- | ------------------------- | -------- |
| **Next.js API Routes（Route Handlers）** | 前后端都在一个项目里，不需要单独起后端进程     | ⭐ **首选** |
| 独立 Express 后端                          | 前后端分离，单独 `node server.js` | 备选       |

**我的最终建议**：**用 Next.js 自带的 Route Handlers 做 API**，而不是单独搭一个 Express。

理由（说人话）：
1. 你本来就要写 Next.js，API 直接写在 `app/api/xxx/route.ts` 里，**不用维护两个进程、两个端口、两套部署**。
2. 你的博客只有你自己用，API 量小，Next 的 Route Handlers 完全够。
3. 部署时一个命令搞定，不用额外配反向代理。

**但是**——你既然点名要 Express，我会在文档里**两种都讲清楚**：
- **路线 A（推荐）**：纯 Next.js，API 写 Route Handlers。
- **路线 B（你要的）**：独立 Express 后端，专门有一章教你写 `server.js` + 数据库访问 + 跨域。

你按需选择，两边教程都给全。

### 数据库

| 方案                     | 说明                            | 适合谁             |
| ---------------------- | ----------------------------- | --------------- |
| **SQLite（Prisma ORM）** | 单文件数据库，零部署，`prisma` 管理 schema | ⭐ **首选**，个人博客完美 |
| **PostgreSQL**         | 功能强，但要装服务或用云                  | 以后想上线多人用再换      |
| **JSON 文件**            | 最简单但容易乱                       | 不推荐做正事          |

**推荐：SQLite + Prisma。** 一个 `blog.db` 文件就搞定所有数据，Prisma 写 schema 像写 TS 类型一样直观，你对数据操作（增删改查）会有清晰的代码提示。
