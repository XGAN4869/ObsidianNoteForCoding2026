## 一、总体架构图

```
┌─────────────────────────────────────────────┐
│                   浏览器                      │
│         ( 你的博客界面，React 组件 )           │
└──────────────┬──────────────────────────────┘
               │  HTTP 请求 (fetch / API)
┌──────────────▼──────────────────────────────┐
│              Next.js 应用                     │
│  ┌────────────────────────────────────┐      │
│  │  前端页面 (app/ 目录，React)        │      │
│  └────────────────────────────────────┘      │
│  ┌────────────────────────────────────┐      │
│  │  API 层 (app/api/*/route.ts)       │      │
│  │   ← 路线A：直接用 Next Route        │      │
│  └────────────────────────────────────┘      │
│        │（可选路线B：独立 Express）            │
└────────┼─────────────────────────────────────┘
         │  Prisma ORM
┌────────▼─────────────────────────────────────┐
│              SQLite 数据库 (blog.db)          │
│   随笔 / 胶囊 / 待办 / 心情 / 部件 / 用户       │
└──────────────────────────────────────────────┘
```

**关键理解**：数据流是 **页面 → API → Prisma → SQLite → 返回页面**。

## 三、数据模型（Prisma Schema）

这是整个项目的"地基"，我们一条条定义。用 Prisma 的 schema 语言写，它很像 TypeScript 类型。

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}

// ── 用户（只有你一个人，但要登录保护）──
model User {
  id        String   @id @default(cuid())
  name      String
  password  String   // 存哈希后的密码，绝不存明文！
  createdAt DateTime @default(now())
}

// ── 心情枚举（7 种）──
enum Mood {
  CALM
  HAPPY
  SAD
  ANGRY
  AFRAID
  TIRED
  LONELY
}

// ── 随笔 ──
model Note {
  id        String   @id @default(cuid())
  title     String
  content   String          // 存 Markdown 原文
  mood      Mood     @default(CALM)
  tags      Tag[]
  isDraft   Boolean  @default(false)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

// ── 标签（随笔的）──
model Tag {
  id     String  @id @default(cuid())
  name   String  @unique
  notes  Note[]
}

// ── 时光胶囊 ──
model Capsule {
  id        String   @id @default(cuid())
  title     String
  content   String
  mood      Mood     @default(CALM)
  openAt    DateTime // 允许打开的时间（未来某天）
  isOpened  Boolean  @default(false)
  createdAt DateTime @default(now())
  openedAt  DateTime? // 实际打开时间
}

// ── 待办 ──
model Todo {
  id        String   @id @default(cuid())
  title     String
  done      Boolean  @default(false)
  dueDate   DateTime? // 可选：截止日期
  order     Int      @default(0) // 排序
  createdAt DateTime @default(now())
  completedAt DateTime?
}

// ── 每日心情记录（心情日历用）──
model MoodLog {
  id     String   @id @default(cuid())
  mood   Mood
  date   DateTime @unique // 每天一条
  note   String?  // 可选：当天的情绪备注
}

// ── 自定义模块（布置）──
model Widget {
  id        String   @id @default(cuid())
  type      String   // "clock" | "weather" | "pomodoro" | "quote" | ...
  title     String?
  config    String   // JSON 字符串，存模块的配置
  position  Int      @default(0) // 排列位置
  enabled   Boolean  @default(true)
}

// ── 设置（键值对，存主题等全局配置）──
model Setting {
  key   String @id
  value String // JSON 字符串
}
```

### 数据模型关系图

```
User (1)
Mood (枚举)
  ├─ Note (多) ─── Tag (多对多)
  ├─ Capsule (多)
  ├─ MoodLog (每天一条)
  ├─ Todo (多)
  └─ Widget (多)
```

**几个设计决策，师傅解释给你听：**

1. **`Mood` 用枚举**而不是字符串 —— 防止拼错（`HAPY`），类型安全。
2. **`Note.tags` 是多对多** —— 一篇随笔多个标签，一个标签多篇随笔。
3. **`Widget.config` 存 JSON 字符串** —— 因为不同模块配置差异大（时钟不需要配置，天气需要城市），用 JSON 字符串最灵活。
4. **`Setting` 是键值对** —— 以后加新设置不用改表结构。
5. **密码存哈希** —— 用 `bcrypt`，数据库泄露也不怕。

## 四、API 设计（REST 风格）

所有接口前缀 `/api`，返回 JSON。

### 通用返回格式

```ts
// 成功
{ "data": {...} }

// 错误
{ "error": "错误信息", "code": 404 }
```

### 接口清单

| 方法 | 路径 | 说明 | 入参 | 返回 |
|------|------|------|------|------|
| POST | `/api/auth/login` | 登录 | `{password}` | `{data:{ok:true}}` |
| POST | `/api/auth/logout` | 登出 | - | `{data:{ok:true}}` |
| GET | `/api/notes` | 随笔列表 | `?tag=&q=&page=` | `{data: Note[]}` |
| POST | `/api/notes` | 新建随笔 | `{title,content,mood,tags}` | `{data: Note}` |
| GET | `/api/notes/:id` | 随笔详情 | - | `{data: Note}` |
| PATCH | `/api/notes/:id` | 更新随笔 | 部分字段 | `{data: Note}` |
| DELETE | `/api/notes/:id` | 删除随笔 | - | `{data:{ok:true}}` |
| GET | `/api/capsules` | 胶囊列表 | - | `{data: Capsule[]}` |
| POST | `/api/capsules` | 埋胶囊 | `{title,content,mood,openAt}` | `{data: Capsule}` |
| POST | `/api/capsules/:id/open` | 打开胶囊 | - | `{data: Capsule}` |
| DELETE | `/api/capsules/:id` | 删除胶囊 | - | `{data:{ok:true}}` |
| GET | `/api/todos` | 待办列表 | - | `{data: Todo[]}` |
| POST | `/api/todos` | 新建待办 | `{title,dueDate}` | `{data: Todo}` |
| PATCH | `/api/todos/:id` | 更新（含勾选） | `{done?,title?,dueDate?}` | `{data: Todo}` |
| DELETE | `/api/todos/:id` | 删除 | - | `{data:{ok:true}}` |
| GET | `/api/moods` | 心情日历数据 | `?from=&to=` | `{data: MoodLog[]}` |
| POST | `/api/moods` | 记录当天心情 | `{mood,note?}` | `{data: MoodLog}` |
| GET | `/api/widgets` | 模块列表 | - | `{data: Widget[]}` |
| POST | `/api/widgets` | 添加模块 | `{type,config}` | `{data: Widget}` |
| PATCH | `/api/widgets/:id` | 更新模块 | 部分字段 | `{data: Widget}` |
| DELETE | `/api/widgets/:id` | 删除模块 | - | `{data:{ok:true}}` |
| GET | `/api/backup` | 导出所有数据 | - | `{data: {...全部}}` |
| POST | `/api/backup` | 导入数据 | 完整 JSON | `{data:{ok:true}}` |
| GET | `/api/random-note` | 随机回忆 | - | `{data: Note}` |

## 五、认证方案（登录保护）

你的博客只有你用，但要防止别人乱点。最简单可靠的方案：

- **单密码登录**：在 `.env` 里设一个 `BLOG_PASSWORD`。
- 登录成功后，写一个**加密的 httpOnly Cookie**（用 `jose` 库签名的 JWT）。
- 所有 API 和页面通过 `middleware.ts` 检查 Cookie，没有就跳登录页。

```
用户输密码 → 对比 .env 里的 BLOG_PASSWORD
  ├─ 对 → 发 JWT Cookie → 进入博客
  └─ 错 → 提示"密码不对"
```

> 为什么不用复杂的第三方登录（GitHub OAuth 等）？因为只有你一个人用，单密码最简单、最好维护。等以后想公开了再升级。

## 六、路线 B：独立 Express 后端（你要的）

如果你坚持前后端分离，这是独立 Express 的结构和要点：

```
server/
├── index.js          # Express 入口
├── routes/
│   ├── notes.js
│   ├── capsules.js
│   ├── todos.js
│   └── ...
├── prisma.js         # Prisma 客户端（复用同一个 prisma schema）
└── middleware/
    └── auth.js       # 登录校验中间件
```

关键点：
1. Express 和 Next 共用同一个 `prisma/schema.prisma` 和 SQLite 文件，**不要建两套数据库**。
2. Next 前端通过环境变量 `NEXT_PUBLIC_API_URL` 指向 Express 地址（如 `http://localhost:4000`）。
3. 需要处理跨域（CORS），用 `cors` 包。
4. 开发时同时起两个进程：`next dev` + `node server/index.js`。

**但师傅再啰嗦一次**：对单人博客，路线 A（纯 Next）更省心。路线 B 的唯一好处是"你想专门学 Express"。**推荐先用 A 把博客做完，A 学到的 API 写法几乎原样能搬到 Express。**
