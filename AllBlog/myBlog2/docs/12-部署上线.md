# 12 · 部署上线（手把手）

> 目标：把博客部署到云端，让它在公网上 24 小时可访问。
> 你的博客是"单机 + SQLite"，部署选择要特别注意：**SQLite 需要一个持久化磁盘**，不能用在会丢文件的无状态容器上。

---

## 一、部署前准备

1. **检查 `.env`**：确保 `BLOG_PASSWORD`、`JWT_SECRET`、`DATABASE_URL` 都设好了。
2. **本地跑通生产构建**：

```bash
npm run build
```

如果 build 报错，先解决再部署（常见：类型错误、未处理的 lint）。

---

## 二、方案 A：Vercel（推荐，最省心）

Vercel 是 Next.js 官方平台，免费额度个人用完全够。

**但 SQLite 的坑**：Vercel 是无状态的，文件系统是临时的，`dev.db` 会丢。

解决方案（三选一）：

| 方案 | 说明 | 适合 |
|------|------|------|
| **用 Turso（SQLite 云）** | 把 SQLite 放云端，Prisma 支持 | ⭐ 推荐 |
| 用 Vercel Postgres | 换 PostgreSQL，Prisma 改 provider | 备选 |
| 用 Neon（免费 Postgres） | 同上 | 备选 |

### 用 Turso 的步骤（SQLite 迁移到云）

1. 去 [turso.tech](https://turso.tech) 注册，创建数据库，拿到连接地址和 token。
2. 安装 Turso 的 Prisma 适配器：

```bash
npm install @prisma/adapter-libsql
```

3. 修改 `prisma/schema.prisma` 的 datasource：

```prisma
datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
  // 或用 libsql 直连：
  // url    = "file:./dev.db"
}
```

> 更准确的做法是改用 libsql 的 provider（`prisma` 官方文档有完整指引），这里给方向，具体以官方最新文档为准。

4. 在 Vercel 上：
   - 导入 GitHub 仓库（需要先把项目推到 GitHub）
   - 配置环境变量（`DATABASE_URL`、`BLOG_PASSWORD`、`JWT_SECRET`）
   - 部署命令保持默认（Vercel 自动识别 Next.js）

---

## 三、方案 B：自建服务器（Node + PM2）

如果你想完全自己掌控（也顺便学部署），用一台云服务器（阿里云/腾讯云轻量，几十块/年）：

1. **服务器装 Node**（用 nvm 装 Node 20 LTS）。

2. **上传项目**（git clone 或 scp）。

3. **装依赖 + 构建**：

```bash
npm install
npm run build
```

4. **用 PM2 常驻运行**：

```bash
npm install -g pm2
pm2 start npm --name "blog" -- start
pm2 save
```

5. **配反向代理**（Nginx 把 80 端口转发到 3000）：

```nginx
server {
    listen 80;
    server_name 你的域名;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

6. **SQLite 在这里没问题**——因为服务器有持久磁盘，`dev.db` 不会丢。这也是自建服务器的优势：**保留 SQLite，最省事**。

---

## 四、方案 C：Docker（可选，进阶）

如果你以后想规范部署，写一个 `Dockerfile`：

```dockerfile
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci

FROM node:20-alpine AS build
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npx prisma generate && npm run build

FROM node:20-alpine AS run
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/.next ./.next
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/package.json ./package.json
COPY --from=build /app/prisma ./prisma
EXPOSE 3000
CMD ["npm", "start"]
```

> Docker 不是必须的，先用方案 A 或 B 上线，以后再折腾。

---

## 五、上线后必做清单

- [ ] 访问公网地址，能正常登录、写随笔
- [ ] 检查 HTTPS（Vercel 自动；自建需配 SSL 证书，用 Let's Encrypt 免费）
- [ ] 改掉默认密码（如果之前用了弱密码）
- [ ] 测试备份导出能正常下载
- [ ] 手机浏览器访问一次，确认移动端正常
- [ ] 把 `robots.txt` 设好（个人博客不想被搜索引擎抓，可在 `public/robots.txt` 写 `User-agent: *\nDisallow: /`）

---

## 六、路线 B（Express）的部署差异

如果你走了独立 Express 后端，部署时：
1. Express 和 Next 是两个进程，都要用 PM2 常驻。
2. Next 的 `NEXT_PUBLIC_API_URL` 要指向 Express 的公网地址。
3. 配 CORS 允许你的前端域名。

**这也是师傅一直建议路线 A 的原因之一**：多一个进程，部署就多一堆麻烦。
