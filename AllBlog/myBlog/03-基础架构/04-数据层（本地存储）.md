# 04 · 数据层（本地存储）

> 博客文章怎么存、胶囊怎么存、代办怎么存。
> 选 JSON 还是 SQLite，**看场景**。

---

## 一、三种存储方式

| 方式 | 适用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **Markdown / MDX 文件** | 博客文章 | 版本可控、永久不丢、写起来像 Word | 不能被运行时增删 |
| **JSON 文件** | 少量动态数据 | 简单、可 commit、容易调试 | 多了性能差 |
| **SQLite** | 中等量动态数据 | 性能好、支持复杂查询 | 部署需要文件系统 |
| **数据库服务**（Supabase / PlanetScale） | 大型应用 | 多人协作 | **个人博客过度设计** |

**我们博客用前三种**：

```
博客文章  → MDX 文件（commit 到 Git）
时光胶囊  → JSON 文件（可前端增删）
代办清单  → JSON 文件（可前端增删）
友链      → JSON 文件（手写维护）
留言板    → GitHub Discussions（Giscus）
```

**不用数据库服务**——个人博客用云数据库是过度设计。

## 二、MDX 文件：博客文章

> 这一节只是**预览**，完整教程在 `04-模块开发/01-随笔博客（MDX）.md`。

### 文件位置

```
content/posts/hello-world.mdx
```

### 文件内容

```mdx
---
title: 'Hello, Pixel Blog'
date: '2026-09-08'
tags: ['随笔', '开篇']
description: '这是我的第一篇博客'

# 你好

这是我的第一篇像素风博客。

\```js
console.log('hello');
\```
```

### 怎么读

新建 `src/lib/posts.ts`：

```ts
import fs from 'node:fs/promises';
import path from 'node:path';
import matter from 'gray-matter';

export type PostMeta = {
  slug: string;
  title: string;
  date: string;
  tags: string[];
  description?: string;
};

const POSTS_DIR = path.join(process.cwd(), 'content/posts');

export async function getAllPosts(): Promise<PostMeta[]> {
  const files = await fs.readdir(POSTS_DIR);
  const mdxFiles = files.filter((f) => f.endsWith('.mdx'));

  const posts = await Promise.all(
    mdxFiles.map(async (file) => {
      const filePath = path.join(POSTS_DIR, file);
      const content = await fs.readFile(filePath, 'utf-8');
      const { data } = matter(content);
      const slug = file.replace(/\.mdx$/, '');
      return {
        slug,
        title: data.title ?? slug,
        date: data.date ?? new Date().toISOString().slice(0, 10),
        tags: data.tags ?? [],
        description: data.description,
      };
    }),
  );

  // 按日期倒序
  return posts.sort((a, b) => b.date.localeCompare(a.date));
}

export async function getPostBySlug(slug: string) {
  const filePath = path.join(POSTS_DIR, `${slug}.mdx`);
  const content = await fs.readFile(filePath, 'utf-8');
  const { data, content: body } = matter(content);
  return {
    meta: {
      slug,
      title: data.title ?? slug,
      date: data.date ?? '',
      tags: data.tags ?? [],
      description: data.description,
    },
    body,
  };
}
```

> 注意 `process.cwd()` = 当前工作目录 = 项目根目录。
> 在 `app/posts/page.tsx` 用 `await getAllPosts()` 就能拿到所有文章。

## 三、JSON 文件：动态数据

### 文件位置

```
data/capsules.json
data/todos.json
data/friends.json
```

### 优缺点

| 优点 | 缺点 |
| --- | --- |
| 简单 | 并发写可能丢数据 |
| 可 `git diff` | 上千条会变慢 |
| 部署简单（不用 DB） | **部署在 Serverless 上不能改文件** |

### 关键问题：Serverless 不能写文件

> **Vercel / Netlify 的部署是 Serverless 函数，每次请求都可能跑在新机器上**。
>
> 你写 `data/capsules.json` 时，可能**写到一台机器，但下次读的是另一台**。
> 结果：**写完就读不到**。

**解决方案**：

| 方案 | 适用 |
| --- | --- |
| **A. 用 GitHub API 把 JSON commit 回仓库** | 最简单，但慢（GitHub API 限流） |
| **B. 用 Vercel KV / Upstash Redis** | 免费额度够个人博客 |
| **C. 用 Supabase / Neon** | 免费额度够，SQL 强大 |
| **D. 用 IndexedDB（纯前端）** | 不依赖服务器，但用户换设备丢数据 |

**教程采用 A 方案**（最简单）：
- 写操作 → 用 GitHub API commit JSON 文件到 GitHub
- 读操作 → 用 Vercel 的 `fetch` + 缓存

> A 方案的"代价"是每次写有 1-2 秒延迟（GitHub API）。
> 个人博客**可以接受**——你不会每秒点一次"保存胶囊"。

### A 方案的详细代码

**写**（`src/app/api/capsules/route.ts`）：

```ts
import { NextResponse } from 'next/server';
import { Octokit } from '@octokit/rest';

const octokit = new Octokit({
  auth: process.env.GITHUB_TOKEN,
});

const REPO = process.env.GITHUB_REPO!; // 格式 "用户名/仓库名"
const FILE_PATH = 'data/capsules.json';

async function readJson(): Promise<unknown[]> {
  try {
    const { data } = await octokit.repos.getContent({
      owner: REPO.split('/')[0],
      repo: REPO.split('/')[1],
      path: FILE_PATH,
    });
    if (Array.isArray(data)) return [];
    const content = Buffer.from(data.content, 'base64').toString('utf-8');
    return JSON.parse(content);
  } catch {
    return [];
  }
}

async function writeJson(json: unknown[]): Promise<void> {
  const content = JSON.stringify(json, null, 2);
  // 先获取当前文件的 SHA
  const { data: currentFile } = await octokit.repos.getContent({
    owner: REPO.split('/')[0],
    repo: REPO.split('/')[1],
    path: FILE_PATH,
  });
  await octokit.repos.createOrUpdateFileContents({
    owner: REPO.split('/')[0],
    repo: REPO.split('/')[1],
    path: FILE_PATH,
    message: 'chore: 更新 capsules.json',
    content: Buffer.from(content).toString('base64'),
    sha: Array.isArray(currentFile) ? undefined : currentFile.sha,
  });
}

export async function GET() {
  const capsules = await readJson();
  return NextResponse.json(capsules);
}

export async function POST(request: Request) {
  const newCapsule = await request.json();
  const capsules = await readJson();
  capsules.push(newCapsule);
  await writeJson(capsules);
  return NextResponse.json({ success: true });
}
```

**环境变量**（`.env.local`，**不进 Git**）：

```env
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxx
GITHUB_REPO=your-name/pixel-blog
```

**GitHub Token 怎么来**：

1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. Generate new token
3. 勾选 `repo`（读写仓库）
4. 生成，**复制保存**（关了页面就没了）

**风险**：Token 暴露 = 别人能改你的仓库。**一定要 `.env.local`**，**不要 commit**。

## 四、SQLite：本地数据库（备选）

> 如果你**真的**想用 SQLite（数据多了，JSON 不够用），可以。

### 安装

```bash
pnpm add better-sqlite3
pnpm add -D @types/better-sqlite3
```

### 文件位置

```
data/blog.db    （二进制文件，**不进 Git**）
```

`.gitignore` 加：

```
data/*.db
data/*.db-journal
```

### 建表

```ts
// src/lib/db.ts
import Database from 'better-sqlite3';
import path from 'node:path';

const DB_PATH = path.join(process.cwd(), 'data/blog.db');

let db: Database.Database | null = null;

export function getDb() {
  if (!db) {
    db = new Database(DB_PATH);
    db.pragma('journal_mode = WAL'); // 提升并发性能
    initSchema(db);
  }
  return db;
}

function initSchema(db: Database.Database) {
  db.exec(`
    CREATE TABLE IF NOT EXISTS capsules (
      id TEXT PRIMARY KEY,
      title TEXT NOT NULL,
      content TEXT NOT NULL,
      unlockAt TEXT NOT NULL,
      createdAt TEXT NOT NULL
    );

    CREATE TABLE IF NOT EXISTS todos (
      id TEXT PRIMARY KEY,
      title TEXT NOT NULL,
      done INTEGER NOT NULL DEFAULT 0,
      createdAt TEXT NOT NULL,
      dueDate TEXT
    );

    CREATE TABLE IF NOT EXISTS comments (
      id TEXT PRIMARY KEY,
      author TEXT NOT NULL,
      content TEXT NOT NULL,
      createdAt TEXT NOT NULL
    );
  `);
}
```

> **警告** —— Vercel Serverless 上 SQLite 文件 **也不能跨请求保留**（跟 JSON 一样的问题）。
>
> SQLite 适合**自己跑服务器**（比如一台 VPS），**不适合 Vercel**。
> 在 Vercel 用，**还是用 A 方案（JSON + GitHub API）**。

## 五、IndexedDB：纯前端存储（备选）

> **最简单**：代办数据存浏览器本地。

### 优缺点

| 优点 | 缺点 |
| --- | --- |
| **不需要后端** | 换设备 = 数据丢 |
| 速度极快 | 不能跨设备同步 |
| 配额大（几十 MB） | 不能分享 |

### 用 Dexie 库

```bash
pnpm add dexie
```

```ts
// src/lib/dexie.ts
import Dexie, { Table } from 'dexie';
import type { Todo } from '@/types/todo';

export class BlogDexie extends Dexie {
  todos!: Table<Todo, string>;

  constructor() {
    super('PixelBlog');
    this.version(1).stores({
      todos: 'id, done, createdAt',
    });
  }
}

export const db = new BlogDexie();
```

```tsx
'use client';
import { db } from '@/lib/dexie';
import { useLiveQuery } from 'dexie-react-hooks';

export function TodoList() {
  const todos = useLiveQuery(() => db.todos.toArray(), []);
  if (!todos) return <PixelSpinner />;
  return (
    <ul>
      {todos.map((t) => (
        <li key={t.id}>{t.title}</li>
      ))}
    </ul>
  );
}
```

> 但 `useLiveQuery` 是 hooks，需要装 `dexie-react-hooks`。

### 用 localStorage：最最简单

```ts
// src/hooks/useLocalStorage.ts
import { useEffect, useState } from 'react';

export function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(initial);

  useEffect(() => {
    try {
      const stored = localStorage.getItem(key);
      if (stored) setValue(JSON.parse(stored));
    } catch {}
  }, [key]);

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch {}
  }, [key, value]);

  return [value, setValue] as const;
}
```

适合**代办、设置**这种少量数据。

## 六、各方案决策表

| 数据 | 推荐方案 | 原因 |
| --- | --- | --- |
| **博客文章** | MDX 文件 | 内容多、Markdown 写起来顺手 |
| **友链** | JSON 文件 | 几乎不改 |
| **关于我** | MDX 或 JSON | 看你想 |
| **时光胶囊** | JSON + GitHub API | 不频繁写 |
| **代办清单** | localStorage 或 IndexedDB | 高频写、不需要跨设备 |
| **留言板** | Giscus (GitHub Discussions) | 不自己存，省事 |
| **站点统计** | Plausible / Umami | 免费托管服务 |

## 七、数据层的"接口规范"

> 不管你用 JSON、SQLite、IndexedDB，**业务代码不应该关心底层**。

### 错误的写法

```tsx
// 直接在组件里读 JSON
'use client';
import data from '@/data/todos.json';

export function TodoList() {
  const todos = data; // ← 静态，不能改
  return <ul>{todos.map(...)}</ul>;
}
```

### 正确的写法

```ts
// src/lib/todos.ts （库）
import type { Todo } from '@/types/todo';

export async function getAllTodos(): Promise<Todo[]> {
  // 读 JSON / SQLite / API / IndexedDB ...
}

export async function addTodo(todo: Omit<Todo, 'id'>): Promise<Todo> {
  // ...
}

export async function deleteTodo(id: string): Promise<void> {
  // ...
}
```

```tsx
// 组件用接口
import { getAllTodos } from '@/lib/todos';

export default async function TodoList() {
  const todos = await getAllTodos();
  return <ul>{todos.map(...)}</ul>;
}
```

**好处**：将来换存储方式（JSON → SQLite），**只改 `lib/` 里的函数，组件不动**。

## 九、数据校验

> 用户输入 → 校验 → 存。**别信任何用户输入**。

### 用 zod 校验

```bash
pnpm add zod
```

```ts
// src/lib/capsules.ts
import { z } from 'zod';

export const capsuleInputSchema = z.object({
  title: z.string().min(1).max(100),
  content: z.string().min(1).max(10000),
  unlockAt: z.string().datetime(), // ISO 8601
});

export type CapsuleInput = z.infer<typeof capsuleInputSchema>;

export function validateCapsule(input: unknown): CapsuleInput {
  return capsuleInputSchema.parse(input);
}
```

API 路由里用：

```ts
export async function POST(request: Request) {
  try {
    const body = await request.json();
    const input = validateCapsule(body); // ← 校验失败会抛错
    // ... 存数据
  } catch (error) {
    return NextResponse.json({ error: '输入不合法' }, { status: 400 });
  }
}
```

## 十、错误处理

> "文件读不到"、"数据库连不上"、"用户输入非法" —— 都要处理。

### 错误统一格式

```ts
export class AppError extends Error {
  constructor(message: string, public code: string) {
    super(message);
  }
}
```

### API 返回格式

```ts
// 成功
{ success: true, data: {...} }

// 失败
{ success: false, error: '错误信息', code: 'VALIDATION_ERROR' }
```
