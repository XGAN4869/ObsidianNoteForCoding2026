## 1. 为什么选 Next.js 15，不用 Hexo

### 先说"博客生成器"是什么

博客生成器 = 把 **Markdown 文件** 自动变成 **HTML 网页** 的工具。
写文章时你只用关心内容，技术细节全交给工具。

### Hexo 是什么

- 老牌博客生成器（基于 Node.js）
- 主题多、生态成熟（中文社区尤其多）
- 一行命令 `hexo new "文章名"` 就能写博客
- 一键部署到 GitHub Pages

### 为什么**不**选 Hexo

| 痛点                 | 影响                                        |
| ------------------ | ----------------------------------------- |
| **主题是"模板"，改起来很痛苦** | 想做个像素风自定义模块？要改主题源代码，EJS / Pug 模板语言对新手不友好  |
| **没有"动态功能"**       | 留言板、待办清单这些**需要用户交互**的东西，Hexo 做不了或者很难做     |
| **不是 React 体系**    | 学 Hexo 等于学一套新东西（EJS、Hexo 配置），**没法锻炼前端能力** |
| **SEO 优势其实不大**     | 现在的 Next.js 通过 SSG（静态生成）一样做到，**且更现代**     |

### Next.js 是什么

- **React 框架**，Facebook/Meta 团队出品，全世界前端都在用
- 默认就是 **静态生成**（SSG），博客天生就快
- 想加交互？React 直接写，**无缝**
- 想自定义样式？Tailwind 直接写，**所见即所得**
- 部署？一行命令推到 Vercel，**全球 CDN**

### 结论

> Hexo 是"博客专用工具"。
> **Next.js 是"全栈框架，写博客只是它能干的事之一"**。
>
> 学 Next.js，将来你**能做的事**远超"写博客"。
> 学 Hexo，将来你**只能继续写博客**。
>
> ——选 Next.js。

### Hexo 主题的折中方案

> 你说"很多第三方主题比如 Hexo 主题很漂亮"。

如果你**真的只是想看效果，不想学编程**：
- 直接用 Hexo + 选一个顺眼的主题（比如 `hexo-theme-butterfly`、`hexo-theme-melody`、`hexo-theme-anzhiyu`）
- 半天就能跑起来一个好看的博客
- **但这就违背了"教智力障碍初级前端搭建"的目的**

我们这份教程的目标是"学"，不是"快"。

如果你**学了 Next.js 之后**，还是喜欢 Hexo 某个主题的设计——完全可以把那个主题的样式**搬**过来。Tailwind 写像素风比 Hexo 主题改模板**自由得多**。

## 2. 为什么选 Tailwind CSS，不用 shadcn / DaisyUI

### Tailwind 是什么

- **CSS 框架**，但不像 Bootstrap 那样"给你一个 .btn 按钮类"
- 它给你一堆**原子类**，比如 `bg-black text-white px-4 py-2`
- 你直接写 HTML class，不需要自己写 CSS 文件
- **像素风的硬边、没有圆角**等规则，用 Tailwind 写出来**最干净**

### shadcn/ui 是什么

- 基于 Tailwind 的 **"组件复制粘贴"** 方案
- 你 `npx shadcn@latest add button`，它把一个按钮的源代码**粘**到你的项目里
- 然后你可以改这个组件源代码

### 为什么不用 shadcn

| 痛点 | 影响 |
| --- | --- |
| **默认样式是"现代柔光"** | 圆角、模糊阴影、过渡动画——**跟像素风完全冲突** |
| 要改**每一个**组件源码 | 对新手来说"复制过来再改"比"自己写"还难 |
| 依赖 Radix UI | 又多一个学习成本 |
| 主题依赖 CSS 变量 | 像素风的硬边变量不好塞进去 |

### DaisyUI 是什么

- 基于 Tailwind 的**预制主题**（有"复古"、"像素"、"暗黑"主题）

### 为什么不用 DaisyUI

- 它的"复古"主题是 **80 年代霓虹色**，不是 1-bit 黑白像素
- 自定义程度低
- 加了一个**不必要**的抽象层

### 为什么不用 Ant Design / Material UI / Chakra UI

| 库 | 风格 | 跟像素风冲突程度 |
| --- | --- | --- |
| **Ant Design** | 阿里出品，企业级，蓝色边框 | ★★★★★ 完全冲突 |
| **Material UI** | Google Material，圆角+阴影 | ★★★★★ 完全冲突 |
| **Chakra UI** | 简约现代 | ★★★★ 大部分冲突 |
| **Bootstrap** | 老牌但偏商业 | ★★★★ 大部分冲突 |

### 我们怎么做

> **Tailwind + 自制少量组件**

- 80% 用 Tailwind 直接写 class（`<button class="bg-black text-white border-2 border-white px-4 py-2">`）
- 20% 抽成小组件（`<PixelButton>`、`<PixelCard>`），**降低重复**
- 组件自己写在自己项目里，**改起来最自由**

这就是为啥我让你用 `components/Pixel*` 这种目录命名——**像素风就意味着组件库是我们自己**。

## 3. 为什么不选"现成的博客 SaaS"

| SaaS               | 问题                      |
| ------------------ | ----------------------- |
| **WordPress.com**  | 不是你的，平台能封你号；定制受限于主题     |
| **Notion + Super** | 看起来简单，但 SEO 差、被墙风险、定制受限 |
| **博客园 / CSDN**     | 广告、UI 丑、不是"个人博客"        |
| **Ghost (Pro)**    | 收费、自己部署又劝退新手            |
| **Medium**         | 写作体验好，但你没有自己的域名         |

**自己搭 = 你的域名、你的代码、你的命运。**

### 必须装

| `@mdx-js/loader`       | `^3.x`   | 同上                      |

| `rehype-highlight`     | `^7.x`   | 代码高亮                    |
| `highlight.js`         | `^11.x`  | 代码高亮主题                  |

### 不装

| 不装的东西 | 原因 |
| --- | --- |
| ~~`shadcn-ui`~~ | 像素风冲突 |
| ~~`bootstrap`~~ | 商业风冲突 |
| ~~`antd`~~ | 企业风冲突 |
| ~~`hexo` / `hugo`~~ | 不灵活 |
| ~~`prisma` + 数据库服务~~ | 太重；本地 SQLite 就够 |
| ~~`redux` / `zustand`~~ | 不需要全局状态；React Context 足够 |

## 6. 跟"智力障碍初级前端"讲实话

> 你现在也许在想："师傅你推 Next.js 是因为它难，你学得会，我学不会。"

不会。

**Next.js 的学习曲线是这样的**：

```
HMTL/CSS 基础  →  React 基础  →  Next.js App Router  →  自定义
   1 周            1 周             1 周                  N 周
```

我们这份教程**默认你已经会 HTML/CSS 基础**。如果不会：

- 先看 MDN 的 HTML 教程：<https://developer.mozilla.org/zh-CN/docs/Learn/HTML>
- 看完 `<div>`、`<a>`、`<img>`、`<form>` 这些基础标签就够
- 别看完整本 MDN，**会浪费你一周**

学 React 的入门资料：
- React 官方教程（中文）：<https://zh-hans.react.dev/learn>
- 看到 "State" 那一节就够，剩下的边做边学

学 Next.js 的入门资料：
- Next.js 官方教程：<https://nextjs.org/learn>
- **我们这份教程本身就是官方教程的中文本地化版 + 像素风专项**
