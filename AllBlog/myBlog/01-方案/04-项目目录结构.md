> 项目长什么样，每个文件夹放什么，**新手不会迷路**。

## 二、每个文件夹的"职责"

### `/` 根目录

| 文件 | 作用 | 重要程度 |
| --- | --- | --- |
| `package.json` | 项目"身份证"：名字、版本、依赖、脚本 | 🔴 |
| `next.config.mjs` | Next.js 配置（MDX、图片优化、redirects） | 🔴 |
| `tailwind.config.ts` | Tailwind 配置（颜色、字体、阴影） | 🔴 |
| `tsconfig.json` | TypeScript 配置（路径别名、严格模式） | 🟡 |
| `.eslintrc.json` | 代码检查（找错） | 🟡 |
| `.prettierrc` | 代码格式化（统一风格） | 🟢 |
| `.env.local` | **环境变量**（GitHub token 等） | 🔴 别提交 |
| `.gitignore` | 告诉 Git 哪些文件**不要**入库 | 🟡 |

### `/src/app/` Next.js 路由

> **App Router 规则**：每个 `page.tsx` 文件 = 一个页面，文件夹名 = URL 段。

| 路径 | URL | 说明 |
| --- | --- | --- |
| `app/page.tsx` | `/` | 首页 |
| `app/posts/page.tsx` | `/posts` | 随笔列表 |
| `app/posts/[slug]/page.tsx` | `/posts/hello-world` | 随笔详情（`[slug]` = 动态参数） |
| `app/capsules/page.tsx` | `/capsules` | 胶囊列表 |
| `app/capsules/[id]/page.tsx` | `/capsules/xxx` | 胶囊详情 |
| `app/about/page.tsx` | `/about` | 关于我 |
| `app/layout.tsx` | （无） | 全局布局，必须 |
| `app/globals.css` | （无） | 全局 CSS，必须 |

**约定俗成**：每个文件夹下都有 `page.tsx`，没有就不是路由。

### `/src/components/` 你的组件库

> **拆分原则**：能用 = 抽组件；只用一次 = 不抽。

```
components/
├── pixel/        ← 像素风原子组件（按钮、卡片）
├── layout/       ← 布局相关（导航、底部）
├── blog/         ← 博客专用
├── capsule/      ← 胶囊专用
├── todo/         ← 代办专用
└── home/         ← 首页专用
```

| 命名规范 | 示例 |
| --- | --- |
| **文件名** | 大驼峰：`PixelButton.tsx` |
| **组件名** | 大驼峰：`export function PixelButton()` |
| **目录名** | 小写连字符或单数：`pixel/` `blog/` |
| **导入路径** | 用 `@/` 别名（`import { PixelButton } from '@/components/pixel'`） |

### `/content/posts/` 你的博客文章

> 每篇文章 = 一个 `.mdx` 文件。

```
posts/
├── hello-world.mdx
├── why-i-built-this.mdx
├── 2027-letter-to-myself.mdx
└── ...
```

**文件名 = URL slug**：
- `hello-world.mdx` → `/posts/hello-world`
- **永远不要用中文文件名**（URL 会乱码）

### `/data/` 动态数据

> 时光胶囊、代办、友链的"小数据库"。

```
data/
├── capsules.json
├── todos.json
└── friends.json
```

**为什么用 JSON 而不是数据库？**

- 个人博客，量小（最多几百条）
- JSON 文件可以**跟着代码一起 commit 到 Git**
- 出错了可以 `git diff` 看修改
- 不需要装数据库服务

**为什么不直接用 SQLite？** 也可以，但**初期不必**。后期真要换 SQLite，教程里有迁移步骤。

### `/public/` 静态资源

> 文件名 = URL，**直接对外可访问**。

| 路径 | URL |
| --- | --- |
| `public/sprites/cat.png` | `/sprites/cat.png` |
| `public/favicon.ico` | `/favicon.ico` |

**注意**：**不要放私密文件**在这里——任何人都能通过 URL 访问。

## 四、命名约定（重要）

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| **React 组件文件** | 大驼峰 | `PixelButton.tsx` |
| **工具函数文件** | 小写连字符或小驼峰 | `format-date.ts` 或 `formatDate.ts` |
| **页面文件** | 固定 `page.tsx` | `app/posts/page.tsx` |
| **布局文件** | 固定 `layout.tsx` | `app/layout.tsx` |
| **样式文件** | 小写连字符 | `globals.css` |
| **配置文件** | 点开头 | `.eslintrc.json` |
| **类型定义文件** | 大驼峰 | `Post.ts` |
| **常量** | 全大写下划线 | `MAX_TODO_LENGTH = 200` |
| **变量** | 小驼峰 | `const postTitle = ...` |
| **布尔变量** | 加 `is` / `has` / `can` | `isDark`、`hasMore` |
| **URL slug** | 小写连字符 | `hello-world` |

## 五、文件大小建议

| 类型 | 建议最大行数 |
| --- | --- |
| **页面文件** | 200 行 |
| **组件文件** | 150 行 |
| **工具函数** | 100 行 |
| **配置** | 50 行 |

**超过就拆**。新手最容易写出 500 行的"超级组件"，**难维护**。

## 六、哪些文件是"自动的"，哪些是"手写的"

| 文件 | 来源 |
| --- | --- |
| `package.json` | `npm init` / 手写 |
| `package-lock.json` / `pnpm-lock.yaml` | **自动**（不要手改） |
| `next.config.mjs` | 手写 |
| `tsconfig.json` | `npx create-next-app` 自动生成 / 手改 |
| `.eslintrc.json` | 自动 / 手改 |
| `.gitignore` | 自动 |
| `node_modules/` | **自动**（依赖，**不要 commit**） |
| `.next/` | **自动**（构建产物，**不要 commit**） |
| `public/` 下所有文件 | **手写 / 你的素材** |
| `content/posts/*.mdx` | **手写**（你的文章） |
| `data/*.json` | **手写 + 程序写**（你的数据） |
| `src/**/*` | **手写**（代码） |

## 七、目录结构变更历史

> 我们为什么**现在**这样组织，**将来可能**怎么变。

```
V0.1（教程当前）
├── pages/ 路由（如果是 Page Router）
└── 简单结构

V1.0（教程主线）
└── App Router，结构如上图

V2.0（你可能加）
├── /src/server/        后端工具
├── /src/db/            数据库 schema
├── /prisma/            Prisma schema（如果你换 Prisma）
├── /tests/             单元测试
└── /docker/            Docker 配置
```

**新手建议**：**先按当前结构来**，**别预先优化**。
