# 12 排错方法与练习计划

## 1. 固定排错顺序

1. **复现**：记录 URL、操作步骤、环境和完整错误。
2. **定位边界**：错误发生在浏览器、Next 服务器、数据库还是第三方服务？
3. **查看事实**：浏览器 Console/Network、服务器日志、数据库日志、构建输出。
4. **缩小范围**：用最小数据和最小组件验证假设。
5. **修复后回归**：重新跑原步骤和相关失败路径。

## 2. 高频错误对照

### “document/window is not defined”

代码在服务器执行，却访问了浏览器 API。把真正需要浏览器的部分放入 Client Component，并在事件或合适的 effect 中访问；不要为了消除错误把整棵页面树都改成客户端。

### “Hydration failed”

服务器 HTML 与浏览器第一次渲染结果不同。检查随机数、当前时间、仅浏览器可用值、非法 HTML 嵌套和不稳定排序。让首屏输出确定，客户端挂载后再更新。

### 数据过期

先确认请求是否被缓存、写入后是否重新验证了所有相关路径、详情页是否使用旧 slug。开发和生产缓存行为可能不同，要用生产构建验证。

### 页面 404

确认文件名必须是 `page.tsx`、目录层级和大小写正确、动态参数名称一致；检查 `notFound()` 是否被业务条件触发。

### 构建时数据库失败

确认构建环境是否有变量、数据库是否允许 CI 网络访问、构建阶段是否意外执行了只能运行时执行的查询。必要时调整静态/动态边界和部署流程。

## 3. 八周练习路线

1. 第 1 周：JSX、props、state、事件，做计数器和筛选列表。
2. 第 2 周：`app` 路由、layout、Link、动态路由，做文档站。
3. 第 3 周：服务端数据获取、loading、error、not-found。
4. 第 4 周：缓存、重新验证、并行请求和分页。
5. 第 5 周：表单、Server Action、Route Handler、输入校验。
6. 第 6 周：认证、授权、环境变量和安全测试。
7. 第 7 周：完成博客 MVP，补齐移动端和 SEO。
8. 第 8 周：部署、监控、性能分析和一次重构。

每周产出一个可运行的小功能、一份 README 和至少一个失败场景测试。

## 4. 学习验收标准

- 能解释每个路由文件的 URL 和渲染位置。
- 能准确说出一段代码为何必须在服务器或浏览器运行。
- 能为公开数据和私有数据选择安全的缓存策略。
- 能从错误日志定位到最小修复点。
- 能独立部署，并说明环境变量、数据库迁移和回滚步骤。
