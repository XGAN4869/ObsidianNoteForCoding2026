# 04 渲染、缓存与数据获取

## 1. 三种页面生成方式

- **静态渲染**：构建时或缓存命中时生成，适合不常变的内容，速度快。
- **动态渲染**：请求到达时在服务器生成，适合依赖用户、Cookie、请求头或实时数据的页面。
- **客户端渲染**：浏览器加载 JavaScript 后再请求和显示，适合强交互区域；不应成为默认选择。

现代 Next.js 会根据代码和所用 API 自动判断，并且版本演进中缓存默认值可能变化。不要死记某个默认值；显式表达意图并阅读当前版本文档。

## 2. Server Component 中直接获取数据

```tsx
async function getPosts() {
  const res = await fetch('https://example.com/api/posts', {
    next: { revalidate: 60 },
  })
  if (!res.ok) throw new Error('文章获取失败')
  return res.json() as Promise<Post[]>
}
```

不要在自己的服务器组件里为了读数据库再请求自己的 `/api`；直接调用数据层更简单、少一次网络跳转。API Route 更适合给浏览器、移动端或第三方调用。

## 3. 缓存与重新验证

缓存的三个问题：

1. **缓存什么**：请求结果、页面输出还是浏览器资源。
2. **多久有效**：时间重新验证，或数据变化后按标签/路径失效。
3. **谁能看到**：公共数据与用户私有数据不能共用缓存。

文章列表可按时间重新验证；用户个人资料通常应动态读取，并确认不会被公共缓存。写入数据后要让相关页面失效（使用当前版本提供的路径/标签重新验证 API）。

## 4. generateStaticParams

对已知的文章 slug 可在构建时预生成：

```tsx
export async function generateStaticParams() {
  const posts = await getPosts()
  return posts.map(post => ({ slug: post.slug }))
}
```

数据量很大或经常变化时，使用按需生成和合理缓存，避免构建时间失控。

## 5. 串行与并行请求

无依赖的请求应并行：

```tsx
const [post, related] = await Promise.all([getPost(slug), getRelated(slug)])
```

有依赖（必须先拿用户 ID 才能查订单）才串行。重复的相同请求在框架/运行时可能被去重，但不要把去重当成业务正确性的保证。

## 6. Suspense 与流式传输

把慢组件放进 `Suspense`，先发送页面骨架，数据准备好后流式补齐。`loading.tsx` 是路由级便捷方案；组件级细粒度场景使用 React `Suspense`。

## 7. 数据层分层

```text
页面/Server Component -> services/posts.ts -> 数据库或外部 API
                         -> lib/validation.ts（校验）
```

页面负责组合 UI，service 负责查询和错误转换，数据库凭据只存在服务端。这样测试和替换数据源都更容易。
