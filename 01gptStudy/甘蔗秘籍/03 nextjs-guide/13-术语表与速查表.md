# 13 术语表与速查表

## 术语

- **App Router**：以 `app/` 目录约定路由的 Next.js 路由系统。
- **Server Component**：在服务器执行的 React 组件，默认模式。
- **Client Component**：文件顶部有 `'use client'`，可使用交互 hooks 和浏览器 API。
- **Server Action**：文件/函数标记 `'use server'` 的服务端写入函数。
- **Route Handler**：`route.ts` 中实现 HTTP 方法的接口处理器。
- **静态渲染**：提前生成并缓存页面输出。
- **动态渲染**：请求到达时根据请求上下文生成页面。
- **重新验证**：让缓存数据在时间到期或写入后重新生成。
- **Hydration**：浏览器用 React 接管服务器生成 HTML 的过程。
- **slug**：用于 URL 的稳定、可读标识，如 `next-basics`。

## 看到需求时的决策表

| 需求 | 首选方案 |
|---|---|
| 页面导航 | `next/link` |
| 服务器查公开文章 | Server Component + service |
| 点击按钮改变局部 UI | 最小 Client Component + `useState` |
| 同应用表单写入 | Server Action |
| 给移动端/第三方的 HTTP API | Route Handler |
| URL 中的文章标识 | `[slug]` 动态路由 |
| 文章不存在 | `notFound()` + `not-found.tsx` |
| 慢区块先显示骨架 | `loading.tsx` 或 `Suspense` |
| 公开列表更新 | 重新验证路径/标签（按当前版本 API） |
| 密钥配置 | 服务端环境变量，不加 `NEXT_PUBLIC_` |

## 每个新页面都问自己

1. URL 是什么？需要哪些布局？
2. 数据从哪里来，是否公开，能否缓存？
3. 哪一小部分需要交互？
4. 加载、空数据、错误、404、未登录和无权限时显示什么？
5. 标题、描述、图片替代文本和键盘操作是否完整？
6. 如何测试并在生产构建中验证？
