# 01 学习方法与环境准备

## 1. Next.js 是什么

React 主要负责“如何描述界面”；Next.js 是建立在 React 之上的全栈 Web 框架。它补齐了路由、服务端渲染、静态生成、数据获取、图片优化、字体优化、接口、部署等应用级能力。

可以把它理解为：

```text
React 组件 + Next.js 约定(目录、渲染、构建、部署) = 可上线的 Web 应用
```

Next.js 不是 Vue，也不是把 React 换成另一种模板。你仍然写 JSX、props、state 和 hooks，只是多了一套“哪些代码在服务器运行、页面如何生成”的规则。

## 2. 建议环境

- Node.js：使用当前仍受支持的 LTS 版本。运行 `node -v` 检查。
- 包管理器：npm、pnpm、yarn 三选一，整个项目保持一致。
- 编辑器：VS Code，并启用 ESLint、Prettier、TypeScript。
- Git：每完成一个小目标就提交一次。

创建项目（命令会询问选项）：

```bash
npx create-next-app@latest my-blog
cd my-blog
npm run dev
```

浏览器访问 `http://localhost:3000`。如果团队固定版本，可把 `@latest` 换成明确版本，并把版本写入文档。

## 3. 推荐选项

新项目通常选择 TypeScript、ESLint、Tailwind（或你熟悉的 CSS 方案）、`src/` 目录、App Router。是否使用 Turbopack 由项目版本和团队规范决定，不要因为工具名字而改变业务代码。

## 4. 最小目录认知

```text
my-blog/
├─ app/                 # 路由、布局、页面、错误态
│  ├─ layout.tsx        # 根布局，必须存在
│  └─ page.tsx          # / 首页
├─ public/              # 可直接访问的静态文件
├─ src/                 # 可选，放业务源码
├─ package.json         # 脚本和依赖
├─ next.config.*        # Next 配置（按需）
└─ tsconfig.json        # TypeScript 配置
```

选择 `src/app` 后，只是把 `app` 放进 `src`，路由规则不变。不要同时维护 `app` 和 `src/app` 两套路由。

## 5. 必会脚本

```bash
npm run dev       # 开发服务器
npm run lint      # 静态检查（具体脚本由项目决定）
npm run build     # 生产构建
npm run start     # 启动生产构建
```

开发模式和生产模式的缓存、错误提示可能不同。发布前至少执行一次 `build`，不能只以 `dev` 正常为准。

## 6. 给初学者的学习规则

1. 先判断“这段代码在哪运行”，再学习语法。
2. 每次只引入一个新概念，并写一个最小例子。
3. 先看浏览器、终端和 Network 面板的事实，再猜原因。
4. 不复制不理解的配置；先问它解决什么问题。
5. 组件先保持小而直白，重复出现后再抽象。

## 7. 常见第一天问题

- **端口被占用**：换端口运行，例如 `npm run dev -- --port 3001`。
- **模块找不到**：确认安装命令成功、导入路径大小写正确、重启开发服务器。
- **页面没有更新**：检查是否编辑了实际运行的项目，确认保存成功。
- **环境变量为空**：只在服务端读取的变量不要加 `NEXT_PUBLIC_`；浏览器需要的变量必须显式加此前缀，但不要把密钥放进去。
