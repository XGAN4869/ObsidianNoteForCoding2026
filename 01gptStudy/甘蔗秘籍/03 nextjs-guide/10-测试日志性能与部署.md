# 10 测试、日志、性能与部署

## 1. 测试层次

- 单元：slug 生成、校验、权限判断等纯函数。
- 集成：service + 测试数据库。
- API：请求状态码、响应结构、鉴权和失败路径。
- 端到端：登录、发布、查看文章的完整流程。

Node 自带 `node:test` 和 `node:assert`，也可以按团队需要选择 Vitest/Jest。测试数据使用独立数据库或事务隔离，避免依赖执行顺序。

## 2. 结构化日志

日志包含时间、级别、requestId、路由、状态码和耗时；使用 JSON 便于检索。错误记录堆栈和上下文，但不记录密钥。生产环境使用集中式日志和错误监控。

## 3. 性能

先测量再优化：关注事件循环延迟、P95/P99 延迟、吞吐、错误率、内存和数据库耗时。避免同步文件/加密、超大 JSON、无上限分页和 N+1 查询。CPU 密集任务考虑 Worker Threads 或拆分服务。

## 4. 部署

```bash
npm ci
npm test
npm run build   # 若使用 TypeScript
npm start
```

确认 Node 版本、环境变量、迁移、端口绑定（通常 `0.0.0.0`）、健康检查、优雅关闭、备份和回滚。无状态应用才能安全水平扩展；会话/任务状态放共享存储。

## 5. 发布前检查

覆盖 404、401、403、422、429、500；压测关键接口；检查依赖漏洞、CORS、Cookie、日志脱敏和数据库索引；用生产构建而非开发模式验收。
