# 06 命令行参数、环境变量与配置

## 1. 读取命令行参数

```js
const [, , command, value] = process.argv

if (command === 'hello') {
  console.log(`你好，${value || '同学'}`)
} else {
  console.error('用法：node cli.js hello 姓名')
  process.exitCode = 1
}
```

`process.argv[0]` 通常是 Node 路径，`process.argv[1]` 是脚本路径，用户参数从下标 2 开始。参数多、类型复杂时使用经过维护的 CLI 解析库，并先阅读文档。

## 2. 环境变量

PowerShell 中临时设置：

```powershell
$env:PORT='3000'
node src/server.js
```

代码中读取：

```js
const port = Number(process.env.PORT || 3000)
if (!Number.isInteger(port) || port < 1 || port > 65535) {
  throw new Error('PORT 必须是 1 到 65535 的整数')
}
```

环境变量的值都是字符串，端口、开关、数字都要显式转换和校验。不要把密码硬编码到 JS，也不要把 `.env` 提交到公开仓库。开发时可使用 dotenv 等库加载本地文件，但生产环境应使用平台的密钥管理能力。

## 3. 配置分层

把“默认值、环境配置、用户输入”分开：

1. 默认值：例如开发端口 3000。
2. 环境变量：例如数据库地址和生产端口。
3. 请求输入：只能影响当前请求，不能偷偷改变全局配置。

启动时一次性读取并校验配置，之后把只读配置传给服务。不要在每个请求里反复读取文件或环境变量并改变含义。

## 4. 退出信号

部署时进程可能收到 `SIGTERM`。先停止接收新请求，再关闭数据库和其他连接，最后退出。完整示例见 [18-部署运维与性能](18-部署运维与性能.md)。
