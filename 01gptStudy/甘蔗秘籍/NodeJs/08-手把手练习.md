# 08 手把手练习：记事本 API（从零到可测试）

这份练习每一步都很小。只在上一小步能运行时进入下一步。数据先放内存，最后再讨论文件和数据库的差异。

## 第 1 步：创建项目

```powershell
mkdir notes-api
cd notes-api
npm init -y
npm install express
```

创建 `src/server.js`，并在 `package.json` 增加 `"type": "module"` 与 `"start": "node src/server.js"`。

## 第 2 步：健康检查

```js
import express from 'express'

const app = express()
app.use(express.json({ limit: '100kb' }))

app.get('/health', (req, res) => {
  res.json({ ok: true })
})

const port = Number(process.env.PORT || 3000)
app.listen(port, () => console.log(`Listening on ${port}`))
```

运行 `npm start`，浏览器打开 `http://localhost:3000/health`。停止服务使用 Ctrl+C。

## 第 3 步：内存数据和 GET

```js
const notes = [{ id: 1, title: '第一条', content: '开始学习' }]

app.get('/notes', (req, res) => {
  res.json({ data: notes })
})
```

此时重启会丢数据，这是故意的教学示例。

## 第 4 步：POST 和校验

```js
let nextId = 2

app.post('/notes', (req, res) => {
  const title = typeof req.body?.title === 'string' ? req.body.title.trim() : ''
  const content = typeof req.body?.content === 'string' ? req.body.content : ''
  if (!title || title.length > 100 || content.length > 5000) {
    return res.status(400).json({ error: 'INVALID_NOTE' })
  }
  const note = { id: nextId++, title, content }
  notes.push(note)
  res.status(201).json({ data: note })
})
```

请求头使用 `Content-Type: application/json`，正文例如 `{"title":"买牛奶","content":"周六购买"}`。

## 第 5 步：GET、DELETE 和 404

```js
app.get('/notes/:id', (req, res) => {
  const id = Number(req.params.id)
  if (!Number.isInteger(id)) return res.status(400).json({ error: 'INVALID_ID' })
  const note = notes.find(item => item.id === id)
  if (!note) return res.status(404).json({ error: 'NOT_FOUND' })
  res.json({ data: note })
})

app.delete('/notes/:id', (req, res) => {
  const id = Number(req.params.id)
  const index = notes.findIndex(item => item.id === id)
  if (index < 0) return res.status(404).json({ error: 'NOT_FOUND' })
  notes.splice(index, 1)
  res.status(204).end()
})

app.use((req, res) => res.status(404).json({ error: 'NOT_FOUND' }))
```

## 第 6 步：保存到 JSON 文件（可选）

把 `notes` 的读写放进单独的 repository，使用 `fs/promises` 和 `JSON.parse` 的错误处理。多人同时写文件会互相覆盖，正式项目应迁移到数据库。

## 第 7 步：主动测试

逐项测试并记录结果：

1. `GET /health` 得到 200。
2. 空标题 POST 得到 400。
3. 错误 JSON 得到 400，而不是进程崩溃。
4. 不存在的 ID 得到 404。
5. 连续两次 POST 得到两个不同 ID。
6. 超过 100KB 的正文被拒绝。

## 第 8 步：思考题

- 为什么重启后数据消失？
- 如果两个请求同时生成 ID，`nextId++` 还够可靠吗？
- 让所有用户看到同一数组有什么隐私问题？
- 把内存数组换成 MySQL 时，哪一层应该修改？
