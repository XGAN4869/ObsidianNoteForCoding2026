# 08 数据库与数据访问层

## 1. 为什么不用数组存生产数据

进程重启会丢失内存；多实例之间内存不共享；并发写入难以保证一致性。数据库提供持久化、索引、事务、约束和查询能力。

## 2. 关系型数据思维

博客可拆为 `users`、`posts`、`tags`、`post_tags`。主键标识记录，外键表达关系，唯一约束保证 slug 不重复，索引支持常用查询。设计时先画实体和关系，再写迁移。

## 3. 连接与迁移

数据库 URL 放环境变量；使用连接池，限制池大小。迁移文件纳入 Git，部署时按顺序执行；不要在应用启动时偷偷修改表结构。生产迁移前备份并准备回滚/前向修复方案。

## 4. Repository/Service 分层

```text
route/controller -> service（业务规则、权限） -> repository（SQL/ORM） -> database
```

Repository 不决定 HTTP 状态码；service 不依赖 Express 的 `req/res`。这样同一业务可以被 API、任务脚本和测试复用。

## 5. 查询安全与性能

- 始终使用参数化查询或 ORM 参数绑定。
- 列表必须分页并设置上限。
- 避免 N+1，必要时批量查询或 JOIN。
- 只选择需要字段，给排序/过滤字段建立合适索引。
- 事务覆盖必须一起成功的多步写入。

## 6. 一致性与并发

唯一 slug 冲突必须捕获数据库约束错误并返回可理解提示。库存、发布状态等关键写入要考虑乐观锁/事务，而不是先查后无条件覆盖。
