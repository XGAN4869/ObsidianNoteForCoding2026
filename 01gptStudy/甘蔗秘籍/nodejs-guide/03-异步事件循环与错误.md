# 03 异步、事件循环与错误

## 1. Promise 与 async/await

```js
async function loadUser(id) {
  const response = await fetch(`https://example.test/users/${id}`)
  if (!response.ok) throw new Error(`请求失败: ${response.status}`)
  return response.json()
}
```

`await` 只暂停当前异步函数，不会阻塞整个 Node 线程；但连续 `await` 会串行执行。无依赖的任务使用 `Promise.all`：

```js
const [user, posts] = await Promise.all([getUser(id), getPosts(id)])
```

## 2. 事件循环的直觉模型

Node 先执行当前同步代码，再处理已完成的异步回调。文件、网络等 I/O 由运行时和操作系统协作完成。微任务（Promise continuation）通常会在进入下一轮事件循环前执行；因此大量递归微任务也可能让定时器和请求“饿死”。

```js
console.log('A')
setTimeout(() => console.log('timer'), 0)
Promise.resolve().then(() => console.log('microtask'))
console.log('B')
// 常见顺序：A、B、microtask、timer
```

不要依赖边缘情况下的执行顺序；用文档和测试确认具体行为。

## 3. 超时、取消与重试

网络请求应有超时和取消机制：

```js
const controller = new AbortController()
const timer = setTimeout(() => controller.abort(), 5000)
try {
  const res = await fetch(url, { signal: controller.signal })
  return await res.json()
} finally {
  clearTimeout(timer)
}
```

重试只针对确定的临时错误，使用指数退避并设置上限；写操作必须考虑重复提交和幂等性。

## 4. 错误分类

- 预期错误：参数错误、未登录、资源不存在，转成稳定的业务响应。
- 依赖错误：数据库/第三方超时，记录上下文并返回通用提示。
- 编程错误：未定义变量、违反不变量，应尽快暴露、修复并让监控报警。

`try/catch` 只捕获其 `try` 内异步链的错误；忘记 `await` 可能导致错误在外层捕获不到。不要在每一层重复打印同一个错误，统一在边界记录。

## 5. 进程级事件

监听 `uncaughtException`/`unhandledRejection` 只能用于记录和触发优雅退出，不能把已经未知状态的进程当作健康服务继续运行。生产环境使用进程管理器或平台自动拉起新进程。
