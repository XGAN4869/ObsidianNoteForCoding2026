# 08 认证、授权与安全

## 认证和授权的区别

- 认证（Authentication）：你是谁？
- 授权（Authorization）：你能做什么？

登录成功只说明身份可信，不能自动说明可以编辑任何文章。

## 密码

密码只能保存哈希，不能保存明文。常用 `bcrypt` 或 `argon2`，选择其一并按官方建议设置成本参数：

```js
const bcrypt = require('bcrypt');
const hash = await bcrypt.hash(password, 12);
const ok = await bcrypt.compare(password, hash);
```

不要自行设计哈希算法，不要把密码写日志。

## JWT 的基本流程

1. 登录接口校验用户名和密码。
2. 服务端签发短期 access token（只放用户 ID、角色等非敏感声明）。
3. 客户端通过 `Authorization: Bearer <token>` 发送。
4. 认证中间件验证签名、过期时间和必要声明，设置 `req.user`。
5. 授权中间件检查资源归属和角色。

Token 密钥必须来自环境变量，且足够随机。生产环境要考虑刷新、撤销、泄露后的处理；不能把 JWT 当成“自动安全”。

## Cookie 会话

若使用 Cookie，设置 `httpOnly`、`secure`（HTTPS）、合适的 `sameSite` 和过期时间，并防范 CSRF。跨域请求还要正确配置 CORS，不能简单地把 `origin: *` 与凭据一起使用。

## 常见防护清单

- `helmet` 设置常见安全响应头。
- 登录和写接口限流。
- 严格校验请求体大小、字符串长度和 ID 格式。
- 输出 HTML 时防止 XSS；Markdown 要使用可信 sanitizer。
- 使用 HTTPS，依赖定期更新。
- 错误响应不暴露堆栈、SQL、密钥。
