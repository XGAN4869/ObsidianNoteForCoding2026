# 05 错误处理与异步

## 统一错误处理中间件

错误处理中间件有四个参数，顺序不能改：

```js
function errorHandler(err, req, res, next) {
  console.error(err);
  if (res.headersSent) return next(err);
  const status = Number.isInteger(err.status) ? err.status : 500;
  res.status(status).json({
    error: { code: err.code || 'INTERNAL_ERROR', message: status === 500 ? '服务器内部错误' : err.message }
  });
}
app.use(errorHandler); // 放在所有路由之后
```

## 自定义业务错误

```js
class AppError extends Error {
  constructor(status, code, message) {
    super(message);
    this.status = status;
    this.code = code;
  }
}
```

路由中：

```js
app.get('/demo', (req, res, next) => {
  next(new AppError(404, 'NOT_FOUND', '资源不存在'));
});
```

## Express 5 异步路由

Express 5 会把 Promise rejection 传给错误处理中间件：

```js
app.get('/posts', async (req, res) => {
  const posts = await repository.findAll();
  res.json({ data: posts });
});
```

如果项目仍使用 Express 4，建议使用 `try/catch` 或统一 `asyncHandler` 包装，不要假设 Express 4 自动捕获异步错误。升级后应运行测试确认行为。

## 资源清理

数据库连接、文件句柄、定时器需要在错误和关闭时清理。监听关闭信号：

```js
const server = app.listen(port);
process.on('SIGTERM', () => {
  server.close(() => process.exit(0));
});
```

## 不要做的事

- 不要 `catch` 后什么都不做。
- 不要把 `err.stack` 返回给生产环境用户。
- 不要在一个请求中发送两次响应。
- 不要用全局变量保存每个用户的登录状态。
