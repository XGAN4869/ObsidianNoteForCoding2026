# 07 认证、安全、错误处理与测试

## 1. 认证与授权不是一回事

- 认证（Authentication）：你是谁？登录、会话、Cookie、OAuth。
- 授权（Authorization）：你能做什么？角色、资源归属、权限检查。

只判断“有 Cookie”远远不够。每个读取和写入入口都要在服务端检查用户身份与资源权限。生产项目优先采用经过审计的认证库，按其当前文档配置 Session、CSRF、回调地址和密钥。

## 2. 环境变量

```env
DATABASE_URL=...
AUTH_SECRET=...
NEXT_PUBLIC_SITE_NAME=我的博客
```

不带 `NEXT_PUBLIC_` 的变量只应在服务端使用；带此前缀的值会进入浏览器，绝不能放密钥。将 `.env*` 加入 `.gitignore`，在部署平台单独配置并定期轮换。

## 3. 输入与输出安全

- 用 schema 校验类型、长度、枚举和必填项。
- 展示用户 Markdown/HTML 前进行可信解析和 XSS 防护；不要直接使用 `dangerouslySetInnerHTML` 渲染未清洗内容。
- 防止 SQL 注入：使用参数化查询/ORM，不拼接用户输入。
- 限制请求体、文件大小、频率和分页上限。
- 错误日志记录 request id，不记录密码、Token、完整 Cookie。

## 4. 错误边界

预期错误（参数不合法、文章不存在）应转成可理解的 UI 或 HTTP 响应；意外错误交给 `error.tsx` 和服务器日志。生产 UI 提供重试或返回入口，开发日志保留堆栈。

## 5. 测试层次

1. **静态检查**：TypeScript、ESLint、格式化。
2. **单元测试**：slug 生成、校验函数、权限判断等纯逻辑。
3. **集成测试**：Service 与测试数据库/API 的组合。
4. **端到端测试**：登录、创建文章、访问详情等关键用户流程。

测试应稳定、可重复，使用独立测试数据。不要只测“页面能打开”，还要测失败路径、未登录和无权限。

## 6. 发布前安全清单

- 生产环境没有调试密钥和真实数据副本。
- 关键 Action/接口从服务端重新鉴权。
- 依赖锁文件已提交并完成漏洞审查。
- 日志、监控、备份和回滚方案可用。
