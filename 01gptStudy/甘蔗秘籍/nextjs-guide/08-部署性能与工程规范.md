# 08 部署、性能与工程规范

## 1. 构建流程

```bash
npm ci
npm run lint
npm run build
npm run start
```

`npm ci` 根据锁文件安装，适合 CI。构建失败必须修复，不能用跳过检查的方式掩盖类型或 ESLint 问题。

## 2. 部署选择

Next.js 可部署到支持 Node.js 的服务器、容器或托管平台。选择时确认：运行时（Node/Edge）、文件系统是否持久化、缓存与 CDN、环境变量、定时任务、数据库网络和日志能力。不要假定本地磁盘写入在所有平台永久存在。

## 3. 性能原则

- 让页面尽量静态或缓存；用户私有内容保持正确的动态边界。
- 缩小 Client Component 范围，避免把大组件树标记为客户端。
- 并行获取无依赖数据，使用流式 UI 处理慢区域。
- 图片指定尺寸/响应式策略，字体只加载必要字重。
- 分析构建产物和客户端 bundle，不要凭感觉优化。
- 数据库查询有索引、分页和字段选择，避免 N+1。

## 4. 可观测性

生产环境至少需要错误监控、请求耗时、关键业务指标和健康检查。为一次请求保留关联 ID；记录路由、状态码、耗时和错误类别，不记录敏感数据。

## 5. Git 与代码组织

```text
app/                    # 页面和路由组合
components/             # 可复用 UI
lib/                    # 数据库、认证、校验、工具
services/               # 业务查询与写入
tests/                  # 测试
```

组件名用 PascalCase，函数名表达动作，服务端/客户端边界在文件顶部清楚可见。一个提交只解决一个主题，提交信息描述行为变化。

## 6. 发布检查表

- `lint`、类型检查、测试、`build` 全部通过。
- 关键页面在生产构建中验证，不只看开发模式。
- 404、错误页、加载态、无数据态、移动端布局已检查。
- 数据库迁移、环境变量、域名和回滚步骤有记录。
