# 11 小型博客项目：后台、部署与扩展

## 1. 管理表单

```tsx
// app/admin/posts/new/page.tsx
import { createPostAction } from '@/app/admin/posts/actions'

export default function NewPostPage() {
  return <form action={createPostAction}>
    <label>标题<input name="title" required maxLength={120} /></label>
    <label>摘要<textarea name="excerpt" maxLength={300} /></label>
    <label>正文<textarea name="content" required /></label>
    <label>Slug<input name="slug" required pattern="[a-z0-9-]+" /></label>
    <select name="status"><option value="draft">草稿</option><option value="published">发布</option></select>
    <button>保存</button>
  </form>
}
```

Action 内部顺序固定为：读取会话 → 检查角色/归属 → schema 校验 → 生成或校验 slug → 写入 → 重新验证相关路径 → 返回可展示结果。编辑和删除同样执行完整权限检查，不能只相信隐藏字段或页面入口。

## 2. 草稿预览

预览接口必须要求已登录作者，并使用不可猜测的短期 token 或同一会话；不要把草稿内容放入公开缓存。预览失败时只返回通用错误。

## 3. 数据库迁移与种子数据

把 schema 迁移文件纳入 Git；部署前先在临时环境执行迁移和回滚演练。种子脚本只插入明确的演示数据，禁止把真实用户数据写进仓库。生产数据库凭据通过平台密钥管理配置。

## 4. 部署步骤

1. 设置生产环境变量（数据库、认证密钥、站点 URL、图片域名）。
2. 执行依赖安装、迁移、`lint`、类型检查、测试和 `build`。
3. 部署并检查首页、详情、登录、写入和 404。
4. 配置日志、错误监控、数据库备份和健康检查。
5. 保留上一个可用版本，验证回滚路径。

如果使用 Serverless/Edge，确认 ORM 驱动和连接池兼容；如果使用容器，确认健康检查、优雅关闭和静态资源缓存。文件上传放对象存储，不依赖容器本地磁盘。

## 5. 最小端到端验收

- 未登录访问管理页会被重定向到登录页。
- 普通用户不能修改别人的文章。
- 草稿 URL 不会出现在公开列表和搜索元数据。
- 发布后首页、标签和详情都能看到最新内容。
- 删除后旧详情返回 404，缓存已失效。
- 非法 Markdown/HTML 不会执行脚本。
- 移动端键盘可完成登录和发布。

## 6. 后续扩展顺序

先做分页与全文搜索，再做评论、草稿协作、图片上传、RSS、站点地图和分析。每次扩展都重新评估数据模型、权限、缓存、SEO、性能和测试，不要为了“架构完整”提前引入复杂系统。

## 7. 独立开发能力自测

你能否不用复制文档回答：

1. 为什么首页可以是 Server Component，而编辑器需要 Client Component？
2. 文章发布后哪些路径需要重新验证？
3. 为什么 `NEXT_PUBLIC_` 变量不能放数据库密码？
4. 如何防止用户通过修改文章 ID 编辑别人的文章？
5. 生产环境为什么不能依赖本地文件系统保存图片？

如果每题都能结合自己的代码说明原因，说明已经从“会写页面”进入“能独立开发应用”的阶段。
