# 第 15 课：综合练习与毕业清单

## 本课目标

独立完成一个“学习任务卡”小项目，把前十四课连起来。练习使用原生 JavaScript 模板，不要求框架知识。完成标准是能够解释每一步，而不只是页面偶然出现。

## 任务说明

页面显示标题、学习阶段、三张任务卡和一张本地图片。开发模式标题为“Vite 学习任务”，staging 模式标题为“Vite 预发布检查”。源码至少拆成 `main.js` 与 `tasks.js` 两个模块，样式放独立 CSS，图片从 `src/assets` 导入。配置一个 `@` 指向 `src` 的别名。最后完成开发检查、生产构建、预览检查，并写一份不含秘密的 `.env.example`。

## 第一步：创建项目

```powershell
npm create vite@latest vite-task-board -- --template vanilla
cd vite-task-board
npm install
npm run dev
```

打开终端显示的地址，确认初始页面出现，再停止服务器。不要直接在脚手架还未成功时同时添加后续配置。

## 第二步：规划文件

保留根目录的 `index.html`、`package.json`。在 `src` 中准备 `main.js`、`tasks.js`、`style.css` 和 `assets` 图片目录。`tasks.js` 可以导出数组：

```js
export const tasks = [
  { id: 1, title: '启动开发服务器', done: true },
  { id: 2, title: '完成生产构建', done: false },
  { id: 3, title: '检查预览页面', done: false },
]
```

`main.js` 导入数组、CSS 和图片 URL，再用数组 `map` 生成卡片。初学时可使用 `textContent` 和 `createElement`，避免把未知字符串直接拼进 `innerHTML`。每完成一个小部分就保存并检查页面。

## 第三步：配置环境

根目录 `.env`：

```dotenv
VITE_APP_TITLE=Vite 学习任务
```

根目录 `.env.staging`：

```dotenv
VITE_APP_TITLE=Vite 预发布检查
```

再建立 `.env.example`，只写变量名和安全示例，不放密码。客户端用 `import.meta.env.VITE_APP_TITLE`。修改文件后重启服务器，确认开发标题。执行 staging 构建时再确认另一个标题。

## 第四步：配置别名

在 `vite.config.js` 使用 `fileURLToPath(new URL('./src', import.meta.url))` 建立 `@` 别名，然后把一个导入改为 `@/tasks.js`。重启开发服务器。若失败，先恢复相对导入证明文件存在，再检查别名，不要同时改文件名。

## 第五步：构建和预览

```powershell
npm run build
npm run preview
```

检查 `dist` 已生成；通过 preview 地址打开；刷新页面；查看 Console 和 Network；确认图片、样式、三张卡片都存在。然后执行：

```powershell
npm run build -- --mode staging
npm run preview
```

确认标题来自 `.env.staging`。如果 preview 端口变化，以终端为准。如果源码改过但页面还是旧内容，先重新 build。

## 毕业清单

你能解释 Vite 与 Vue/React 的区别；能检查 Node 与 npm；能创建、启动、停止项目；知道 `index.html` 是入口；会写相对导入；能区分 `src/assets` 和 `public`；知道 `VITE_*` 不是秘密；会读取 mode；能找到 `vite.config`；知道 server.proxy 只用于开发；会检查插件必要性；会 build 和 preview；能根据部署子路径设置 base；知道 Vite 不做完整 TS 类型检查；遇错会先分类而不是乱删文件。

## 自我评分

每项用 0、1、2 分：0 表示不会，1 表示看文档能做，2 表示不看文档能做。不要因为需要看文档而否定自己，真实工作本来就会查资料。总分不重要，低分项告诉你应该重读哪一课。隔一天从空目录再做一次，第二次仍能完成才表示流程开始稳定。

## 最后的安全检查

搜索项目中是否出现密码、令牌、真实私钥或公司内部地址；检查 `.env.local` 是否被 Git 忽略；确认没有提交 `node_modules`；确认没有把 localhost 当生产 API；确认构建命令成功；确认预览页面没有关键错误。若计划真实部署，再按照第 12 课核对目标平台，而不是把练习项目直接公开。
