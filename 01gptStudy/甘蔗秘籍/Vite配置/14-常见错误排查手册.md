# 第 14 课：Vite 常见错误排查手册

## 本课目标

遇到报错时不靠乱试，按“阶段、位置、第一条根因、最小修改、重新验证”的顺序排查。错误并不可怕，保留完整信息比马上清屏更重要。

## 固定五步法

第一步确认当前阶段：创建项目、安装依赖、启动开发、浏览器运行、生产构建、预览，还是正式部署。第二步确认终端当前目录，用 `Get-Location` 查看路径，并确认同一目录有 `package.json`。第三步复制完整错误，重点读最先出现的明确原因、文件路径和行号。第四步一次只改一个地方。第五步重新执行原命令，确认错误消失且没有产生新问题。

## 命令找不到

`node` 或 `npm` 无法识别：关闭并重新打开终端，再运行 `node --version` 与 `npm --version`。仍失败则检查 Node 安装。`vite` 无法识别但 `npm run dev` 可以：这通常是因为 Vite 安装在项目本地，直接在全局终端输入 `vite` 不一定可用，优先使用项目脚本。不要为了一个本地命令就盲目全局安装不同版本。

## npm install 失败

先看是网络超时、证书、权限、版本不兼容，还是包不存在。确认 Node 版本满足 Vite 与模板要求。确认 `package.json` 中包名真实存在且拼写正确。公司网络的代理与证书问题应遵守公司方案，不要通过关闭 SSL 校验绕过安全。不要把反复删除 lockfile 当第一步，因为这会改变依赖解析。

## 端口占用

Vite 默认可能自动选择下一个端口，所以先读终端实际 Local 地址。如果设置了 `strictPort: true`，占用会导致启动失败。停止重复的开发服务器，或明确换端口：

```powershell
npm run dev -- --port 3001
```

不要未经确认结束陌生系统进程。最简单的情况常常是你在另一个终端已经运行了一份项目。

## 无法解析导入

检查相对路径的 `./` 或 `../`；检查扩展名和文件真实位置；检查大小写完全一致；裸包导入则检查依赖是否已安装并记录在 `package.json`。别名导入失败时检查 `resolve.alias` 是否为正确绝对路径，并重启开发服务器。不要通过创建多个同名空文件来“满足”错误路径。

## 页面白屏

先打开浏览器开发者工具 Console，查看第一条错误。再看 Network：`index.html`、入口 JS、CSS 的状态码是否为 200。`document.querySelector` 返回 null 时检查 HTML 元素 id。若仅部署后白屏，检查资源 URL 与 `base`。若直接双击 `dist/index.html` 失败，改用 `npm run preview`，因为构建结果应通过 HTTP 服务检查。

## 环境变量是 undefined

确认名称以 `VITE_` 开头；确认文件位于项目根或配置的 envDir；确认读取方式是 `import.meta.env.VITE_NAME`；修改 env 后重启；确认当前 mode 对应哪个文件。若变量是敏感值，不要为了让它可读而加 `VITE_`，应移动到后端。

## 接口代理失败

确认后端服务真实可访问；前端路径是否匹配 proxy 的 key；target 的协议和端口是否正确；是否错误地删除或保留了 `/api`；观察状态码。开发代理在正式部署中不存在，线上问题要查平台或服务器代理。502 多半是目标连接失败，404 多半是路由不匹配，但仍应以真实响应为准。

## 缓存与依赖预构建

Vite 会缓存预构建依赖，官方建议在确有需要时使用 `--force` 重新优化，或清理浏览器缓存/相关缓存目录。不要把清理所有缓存作为每次启动步骤。先证明问题与依赖缓存有关，例如链接依赖变化没有被识别，再采取针对性操作。

## 求助时提供什么

提供 Node 与 npm 版本、Vite 版本、操作系统、执行命令、当前目录结构、完整错误、最小相关配置、预期与实际结果。删除密码、令牌、公司域名和个人信息。不要只说“打不开”，也不要只发一张裁掉上下文的红字截图。

检查点：给任意故障先标记阶段；保留原始错误；只做一个修改；重复原操作；记录结果。连续三次无方向的尝试后停下，回到第一步重新分类。

官方依据：https://cn.vite.dev/guide/troubleshooting 与 https://cn.vite.dev/guide/dep-pre-bundling
