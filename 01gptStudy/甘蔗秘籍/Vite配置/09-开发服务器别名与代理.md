# 第 09 课：开发服务器、路径别名与代理

## 本课目标

会设置固定端口，理解 `strictPort`、`host`、`open`，用绝对路径创建别名，并知道代理只影响开发服务器，不是正式部署方案。

## 开发服务器配置

一个适合学习的示例：

```js
import { defineConfig } from 'vite'

export default defineConfig({
  server: {
    port: 3000,
    strictPort: true,
    open: false,
  },
})
```

`port` 指定尝试使用的端口。默认情况下端口被占用时，Vite 可能尝试下一个端口；`strictPort: true` 会让占用时直接退出，适合必须固定回调地址的项目。`open` 控制启动后是否自动打开浏览器，它不影响页面功能。`host: true` 或命令行 `--host` 会让服务监听包括局域网地址在内的地址，可能扩大可访问范围，只在可信网络并明确需要手机联调时使用。开发服务器仍不是正式生产服务器。

## 路径别名要指向绝对路径

项目变大后，可把 `src` 配成 `@`：

```js
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'

export default defineConfig({
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
})
```

之后可写 `import { add } from '@/math.js'`。文件系统路径别名应解析为绝对路径，避免相对别名受到导入位置影响。别名只是改变解析方式，不会自动创建文件，也不会忽略大小写问题。TypeScript 或某些编辑器还可能需要相应路径提示配置；不要只看 Vite 能运行就认为 IDE 配置完整。

## 代理解决什么问题

前端开发地址可能是 `http://localhost:5173`，后端是 `http://localhost:8080`。浏览器直接跨源请求可能受 CORS 限制。开发时可以让请求先发给 Vite，再由 Vite 转发：

```js
import { defineConfig } from 'vite'

export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
      },
    },
  },
})
```

客户端写 `fetch('/api/users')`，匹配 `/api` 的请求会被开发服务器代理。是否需要 `rewrite` 取决于后端真实路由：后端本来就是 `/api/users` 就不要删除 `/api`；后端只有 `/users` 时才考虑重写。不能凭习惯固定加 rewrite。

代理不会自动修复后端报错，也不会在 `dist` 中生成一个代理服务器。正式部署时，需要由 Nginx、网关、平台规则或后端处理代理与 CORS。若开发代理正常但上线接口失败，检查生产环境 API 地址与部署服务器规则，不要继续修改 Vite 开发代理。

## 排查代理的顺序

先确认后端地址可访问；再确认前端请求路径真的以 `/api` 开头；再看 Vite 终端日志；然后看浏览器 Network 中的状态码。404 多半是路径不匹配，502 常表示代理连接不到目标服务，CORS 报错说明请求可能没有经过预期代理。改完 `vite.config` 要重启开发服务器。

## 检查点

把端口改为 3000 并设置 `strictPort: true`，重启后确认地址。建立 `@` 别名并替换一个相对导入。代理练习必须有真实可访问的后端目标；没有后端时只读示例，不要编造接口。最后执行生产构建，记住 `server` 配置不等于生产部署配置。
