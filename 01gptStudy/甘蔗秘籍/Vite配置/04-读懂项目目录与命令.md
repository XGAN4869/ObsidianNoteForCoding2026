# 第 04 课：读懂项目目录与 npm 命令

## 本课目标

看见项目文件时不慌张，知道哪些是自己写的源码，哪些是依赖，三个默认脚本分别做什么。以下结构以 create-vite 的原生模板为例，框架模板会多出自己的文件。

## 从最外层开始

`package.json` 是项目说明和命令清单。它记录项目名称、模块类型、脚本以及依赖。它不是普通注释文件，JSON 的双引号、逗号和花括号必须正确。`package-lock.json` 是 npm 生成的锁文件，用来让依赖解析更稳定，通常不要手工编辑。`node_modules` 存放安装后的第三方包，体积大、可通过 `npm install` 恢复，通常被 `.gitignore` 排除。`.gitignore` 告诉 Git 哪些文件不应提交。

`index.html` 位于项目根目录，这是 Vite 有意设计的入口，不需要把它移动到 `public`。Vite 会解析其中的 `<script type="module" src="/src/main.js"></script>`，再从 JavaScript 的 `import` 继续建立模块关系。`src` 用于放主要源码。原生模板中的 `src/main.js` 是页面逻辑入口，样式文件和图片也可能放在 `src` 中并被导入。`public` 适合不经过转换、需要保持原文件名并按根路径访问的资源，第 06 课详讲。

## 读懂 scripts

常见的 `package.json` 片段如下：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

执行 `npm run dev`，npm 查找 `dev` 并运行 `vite`；执行 `npm run build`，运行生产构建；执行 `npm run preview`，预览已经构建的结果。脚本左边的名字可以由项目维护者定义，所以接手陌生项目时先看 `package.json`，不要想当然地猜命令。可以执行 `npm run` 列出可用脚本。

额外参数要放在第二个 `--` 后面。例如：

```powershell
npm run dev -- --port 3000
npm run dev -- --host
```

第一条临时指定端口 3000，第二条允许开发服务器监听更多网络地址。`--host` 可能让同一局域网的其他设备访问你的开发服务，因此只应在可信网络和确有需要时使用，不能把它当成正式部署。固定配置会在第 09 课介绍。

## 用“谁生成、能否恢复”分类

自己维护：`src`、`index.html`、`package.json`、Vite 配置、环境变量模板。工具生成但应保留：`package-lock.json`。安装可恢复：`node_modules`。构建可恢复：默认的 `dist`。这个分类能帮助你判断哪些文件可以清理，哪些修改必须认真审查。切勿在不确定目录位置时执行批量删除命令。

## 检查点

打开自己的项目，找到 `package.json`，只读不改。指出 `dev`、`build`、`preview` 三个脚本。再找到 `index.html` 中加载入口 JavaScript 的 `script`。最后运行 `npm run`，确认终端列出的脚本与文件内容一致。若框架模板的文件名不同，不代表错误，以该模板实际生成的结构为准。

## 常见错误

在项目外层运行 `npm run dev`，会提示找不到 `package.json`。手工修改 `node_modules`，重装后改动会消失。把 `dist` 当源码修改，下次构建会覆盖。漏写 JSON 逗号会导致 npm 无法解析。最可靠的做法是先确认终端当前路径，再确认文件名，再执行一个命令。
