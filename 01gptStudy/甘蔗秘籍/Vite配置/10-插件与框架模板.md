# 第 10 课：插件与框架模板

## 本课目标

知道插件为什么存在，能区分“框架模板已经配置的官方插件”和“自己额外安装的插件”，学会在安装前检查包名、文档、兼容版本和必要性。

## 插件是扩展点

Vite 插件可以在解析、加载、转换、HTML 处理、开发服务器和构建等阶段扩展行为。插件不是越多越好。每个插件都会增加依赖、配置和升级成本，部分插件还会影响启动或构建速度。遇到需求时先查 Vite 是否已经内置支持；例如普通 CSS、CSS Modules、静态资源导入、JSON 导入等通常不需要额外插件。

使用插件的一般步骤是：阅读插件针对当前 Vite 主版本的安装说明；把包安装到开发依赖；从正确包名导入工厂函数；在 `plugins` 数组里调用；重启开发服务器；同时验证开发与构建。示意代码：

```js
import { defineConfig } from 'vite'
import examplePlugin from 'vite-plugin-example'

export default defineConfig({
  plugins: [examplePlugin()],
})
```

`vite-plugin-example` 只是说明结构的占位名字，不是真实推荐包，不能直接安装。真正使用时必须以插件官方 README 的包名和 API 为准。不要凭插件名称猜导出方式，也不要把旧版博客的配置直接用于新版。

## Vue 和 React 为什么需要插件

Vite 核心可以处理普通 JavaScript、TypeScript、CSS 等，但 Vue 单文件组件 `.vue` 和 React 的框架级刷新体验需要相应集成。create-vite 的 Vue、React 模板已经安装并配置官方插件，不需要再重复安装。官方 Vite 组织维护 Vue 的 `@vitejs/plugin-vue`、Vue JSX 的 `@vitejs/plugin-vue-jsx`、React 的 `@vitejs/plugin-react`，也提供 React SWC 方案等。选择模板后先使用模板现有组合，不要同时叠加多个做相同转换的插件。

例如 Vue 模板通常会有类似：

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
})
```

这不是在浏览器里“开启 Vue”，而是告诉 Vite 如何处理 Vue 特有文件和开发更新。

## 创建框架项目

学习 Vue 时可以创建独立练习目录：

```powershell
npm create vite@latest my-vue-app -- --template vue
cd my-vue-app
npm install
npm run dev
```

React 对应 `--template react`，TypeScript 模板通常使用 `vue-ts` 或 `react-ts`。不要把已有 vanilla 项目直接改一半当成框架项目；初学时新建独立模板更容易比较结构。框架本身的语法、路由、状态管理不属于 Vite 核心，需查框架官方文档。

## 安装前四问

第一，Vite 是否已经内置？第二，插件文档是否明确支持当前 Vite 版本？第三，包名和维护仓库是否可信？第四，删除这个插件后需求是否真的无法完成？安装命令常见为 `npm install -D 包名`，但运行时库不一定是开发依赖，应遵循该库官方说明。

出现问题时，先看 `package.json` 中 Vite、框架和插件版本，再看配置中是否重复注册。升级 Vite 主版本前阅读迁移指南和插件兼容说明。不要同时升级所有包再猜哪一个造成故障。

## 检查点

在自己的配置中指出 `plugins` 数组。若使用框架模板，确认官方插件已在 `devDependencies` 中并只注册一次。回答：普通 CSS 是否需要插件？通常不需要。占位包名能直接安装吗？不能。插件在开发正常是否足够？不够，还要运行构建验证。

官方依据：https://cn.vite.dev/guide/using-plugins 与 https://cn.vite.dev/guide/features#frameworks
