# 第 01 课：认识 Vite

## 本课目标

学完后，你能用自己的话回答三个问题：Vite 是什么，为什么开发时感觉快，`npm run dev` 与 `npm run build` 有什么不同。本课不要求写复杂配置。

## 先记住一句话

Vite 是前端开发和构建工具。开发时，它启动一个本地开发服务器；准备上线时，它把源码处理成适合部署的静态文件。它不是 Vue，也不是 React，更不是浏览器。Vue、React 是用来组织页面的框架，Vite 负责让项目更容易启动、更新、构建。

“本地开发服务器”可以想成一个只在你电脑上工作的送餐员。浏览器说“我要 `main.js`”，服务器就把对应模块送过去。开发时 Vite 主要利用浏览器原生 ES 模块，只按需要处理被访问的模块，因此不必每次启动都先把整个应用打成一个巨大文件。你保存源码后，Vite 的模块热替换，也叫 HMR，会尽量只更新变化的部分。页面状态有时可以保留，但是否保留也取决于所用框架和具体改动。

生产构建是另一件事。执行 `npm run build` 时，Vite 会分析入口和模块关系，转换、拆分并优化资源，然后通常输出到 `dist` 目录。`dist` 才是通常交给静态服务器的构建结果。开发服务器的地址如 `http://localhost:5173` 只代表本机正在运行的服务，不是公开网站，也不能把这个地址直接发给所有人当成正式上线地址。

## 三个阶段要分清

开发阶段：运行 `npm run dev`，边改代码边在浏览器查看，重点是反馈快。构建阶段：运行 `npm run build`，生成准备部署的文件，重点是优化和正确性。预览阶段：运行 `npm run preview`，在本机查看已经构建出来的 `dist`，重点是发现“开发正常、构建后异常”的问题。预览命令不是生产服务器，不应该长期承担正式流量。

Vite 默认提供了很多能力，例如处理 HTML、JavaScript、TypeScript、CSS 和被导入的图片。它也能通过插件支持 Vue 单文件组件、React Fast Refresh 等框架能力。这里的“支持 TypeScript”首先表示可以把 `.ts` 转成浏览器可执行的 JavaScript，不表示 Vite 会替你完成完整类型检查；第 13 课会专门说明。

## 一个最小心智图

你修改 `src/main.js`，Vite 开发服务器收到浏览器请求，处理相关模块，再把更新送给浏览器。准备上线时，Vite 从 `index.html` 出发找到相关模块，生成 `dist`。因此排错时要先问：问题发生在开发服务器、生产构建，还是部署服务器？这三个阶段混在一起，会让简单问题变难。

## 检查点

请不用背定义，只回答：第一，Vite 是否等于 Vue？答案是否。第二，保存文件后局部快速更新叫什么？答案是 HMR。第三，通常部署源码目录还是 `dist`？答案是构建后的 `dist`。第四，`npm run preview` 是否等于正式生产服务器？答案是否。

## 常见误解

误解一：“装了 Vite 就学会 Vue。”错误，Vite 是工具，框架语法仍要单独学习。误解二：“开发页面能打开就一定能上线。”错误，还要构建并预览。误解三：“越多配置越专业。”错误，Vite 有合理默认值，先用默认值完成目标，只有出现明确需要时才增加配置。
