# 第 07 课：环境变量与模式

## 本课目标

学会用 `.env` 保存非敏感配置，正确读取 `VITE_` 前缀变量，理解所有客户端环境变量最终都可能被用户看到，区分 mode 和 `NODE_ENV`。

## 最重要的安全规则

在前端代码中能通过 `import.meta.env` 读到的值，会进入发送给浏览器的代码。Vite 默认只把以 `VITE_` 开头的自定义变量暴露给客户端，这是防止意外暴露的过滤规则，不是加密。`VITE_API_KEY`、`VITE_DB_PASSWORD` 仍然会暴露，因此密码、私钥、数据库凭据、真正需要保密的 API 密钥不能放在任何 `VITE_*` 变量里。秘密应由后端或安全的服务端函数保存。

## 第一个环境变量

在项目根目录创建 `.env`：

```dotenv
VITE_APP_TITLE=学习 Vite
```

在客户端 JavaScript 中读取：

```js
const title = import.meta.env.VITE_APP_TITLE
document.querySelector('h1').textContent = title
```

修改 `.env` 后必须重启开发服务器，因为 Vite 在启动时加载环境文件。所有读取到的自定义环境变量都是字符串。即使写 `VITE_PAGE_SIZE=20`，得到的也是 `'20'`，使用数字前应明确转换：

```js
const pageSize = Number(import.meta.env.VITE_PAGE_SIZE)
```

布尔值也不能直接用 `Boolean('false')`，因为非空字符串会得到 `true`。可以写 `import.meta.env.VITE_FEATURE_ON === 'true'`。

## 四类常见 env 文件

`.env` 始终加载；`.env.local` 始终加载但只供本地使用；`.env.[mode]` 只在对应模式加载；`.env.[mode].local` 只在对应模式加载且只供本地使用。模式专用文件比通用文件优先级高，Vite 启动时已经存在的进程环境变量优先级最高。包含 `.local` 的文件可能有本地敏感值，应通过 `.gitignore` 排除，团队可以另写不含秘密的 `.env.example` 说明需要哪些变量。

开发服务器默认使用 `development` 模式，构建默认使用 `production` 模式。若执行：

```powershell
npm run build -- --mode staging
```

Vite 会使用 `staging` 模式，并加载 `.env.staging`。模式名帮助选择配置集合，不会自动把应用部署到某个服务器。

## 内置常量

`import.meta.env.MODE` 是当前模式字符串；`BASE_URL` 来自 `base` 配置；`DEV` 和 `PROD` 是相反的布尔值；`SSR` 表示代码是否运行在服务端渲染环境。写条件时不要给布尔常量再加字符串引号：

```js
if (import.meta.env.DEV) {
  console.log('只在开发判断分支中出现')
}
```

`NODE_ENV` 与 mode 是不同概念。`vite build --mode development` 的 mode 是 development，但构建命令默认仍属于生产构建语境。初学项目优先使用 Vite 的 `MODE`、`DEV` 和 `PROD`，不要自己猜二者关系。

## 配置文件中的特殊点

`.env*` 文件不会在 Vite 解析配置之前自动注入 `process.env`。如果某个 env 值必须决定 `vite.config.js` 自身的端口或插件，就使用 Vite 导出的 `loadEnv(mode, directory, prefix)`。如果只是给客户端应用读取，不需要在配置里调用 `loadEnv`。

## 检查点

建立 `.env` 和 `.env.staging`，让同一个标题在开发与 staging 构建时不同。确认修改 env 后必须重启。回答：`VITE_SECRET` 是否安全？不安全。`VITE_COUNT=10` 是数字吗？读取时是字符串。`.env.local` 是否应提交？通常不应。完成后再检查 `.gitignore` 是否包含 `*.local`。
