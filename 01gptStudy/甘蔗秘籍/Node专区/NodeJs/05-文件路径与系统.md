# 05 文件系统、路径和操作系统信息

## 1. `fs/promises` 读写文件

```js
import * as fs from 'node:fs/promises'

async function saveNote() {
  await fs.writeFile('note.txt', '第一条笔记\n', 'utf8')
  const text = await fs.readFile('note.txt', 'utf8')
  console.log(text)
}

saveNote().catch(error => {
  console.error('文件操作失败：', error.message)
  process.exitCode = 1
})
```

写入会覆盖原文件；需要追加时使用 `fs.appendFile`。创建目录可用 `fs.mkdir(dir, { recursive: true })`。

## 2. 永远不要手拼路径

不同系统的分隔符可能不同。使用 `path.join` 或 `path.resolve`：

```js
import path from 'node:path'
const dataPath = path.join(process.cwd(), 'data', 'notes.json')
```

用户提供的文件名必须先校验。`../../secret.txt` 这类输入可能造成路径穿越；不要只用字符串替换来“修复”，应把用户输入限制为允许的 ID/文件名，并确认最终路径仍在指定目录内。

## 3. JSON 文件的可靠读写

```js
const text = await fs.readFile(dataPath, 'utf8')
const notes = JSON.parse(text)
```

`JSON.parse` 可能抛错。保存重要数据时，先写临时文件，再通过可靠的替换流程更新目标文件，避免进程中断留下半个 JSON。多人同时写同一 JSON 文件也会互相覆盖，正式服务应使用数据库。

## 4. 流与大文件

`readFile` 会把整个文件放进内存；大文件应使用流和 `pipeline`：

```js
import { createReadStream, createWriteStream } from 'node:fs'
import { pipeline } from 'node:stream/promises'

await pipeline(
  createReadStream('big.log'),
  createWriteStream('big-copy.log')
)
```

流有背压机制：下游处理不过来时，上游会放慢。记住：流也要在错误和关闭时正确处理。

## 5. `os` 与 `process`

```js
import os from 'node:os'
console.log(os.platform(), os.cpus().length, os.totalmem())
console.log(process.pid, process.env.NODE_ENV)
```

不要把环境变量当成可信用户输入；启动时校验必需配置，缺失就给出清楚错误。

## 动手题与检查

练习创建数据目录、写入 JSON、读取后打印条数；再把内容改成大文件复制。完成后确认：

- [ ] 使用 `node:path`，没有硬编码 `\\`。
- [ ] 捕获了 JSON 和文件权限错误。
- [ ] 大文件没有一次性读进内存。
- [ ] 用户输入不会直接变成任意文件路径。
