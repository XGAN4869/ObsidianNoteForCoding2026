# 17 测试、调试与日志

## 1. 为什么测试

测试不是为了证明程序永远没问题，而是快速确认“这个输入得到这个结果”。先测试最重要、最容易出错的业务规则：空标题、权限、重复提交、失败重试。

## 2. Node 内置测试

Node 20 可使用内置 `node:test`：

```js
import test from 'node:test'
import assert from 'node:assert/strict'

test('标题会去掉首尾空格', () => {
  assert.equal('  学习  '.trim(), '学习')
})
```

运行 `node --test`。把纯函数优先抽出来，测试会比直接启动真实数据库和网络更快、更稳定。

## 3. 测试层次

- 单元测试：一个函数或服务规则。
- 集成测试：服务与数据库/Redis 的连接。
- API 测试：发送 HTTP 请求检查状态码和正文。
- 端到端测试：从真实用户流程验证多个系统。

测试环境使用独立数据库和假数据，绝不连接生产库。时间、随机数、外部 API 都要能替换或模拟。

## 4. Inspector 调试

运行 `node --inspect src/server.js`，在 Chrome DevTools 中设置断点、查看调用栈和变量。遇到异步代码，先确认函数是否被调用、Promise 是否等待、异常是否被捕获，再看业务条件。

## 5. 结构化日志

日志至少包含时间、级别、消息、request id、路径、状态码和耗时。生产环境使用 JSON 便于搜索；错误记录堆栈，但返回给用户的错误要脱敏。不要记录密码、Cookie、Authorization 和不必要的个人信息。

## 6. 指标与追踪

关注请求数、错误率、延迟分位数、数据库慢查询、队列积压和事件循环延迟。单条日志无法解释跨服务请求时，使用 trace id 关联调用。

## 动手题

为记事本服务写 8 个测试：健康检查、列表、创建成功、空标题、查询不存在、删除成功、重复删除、错误 JSON。每修一个 bug，先补一个能复现它的测试。
