# 13 Node.js 安全基础

安全不是某一个插件，而是每一次读取、写入和授权都做正确的判断。

## 1. 输入校验和权限

对每个输入检查类型、长度、格式、范围和业务权限。认证回答“你是谁”，授权回答“你能不能做这件事”。只验证登录而不验证资源归属，会产生越权漏洞。

```js
const title = typeof body.title === 'string' ? body.title.trim() : ''
if (title.length < 1 || title.length > 100) {
  return res.status(400).json({ error: 'INVALID_TITLE' })
}
```

## 2. 密码、Token 和 JWT

密码不能明文保存，应使用经过验证的密码哈希算法（如 Node `crypto.scrypt`，或成熟的 Argon2 库）并为每个密码使用随机 salt。登录 Token 要设置过期时间、撤销策略和传输保护。JWT payload 默认可被读取，不要放密码、密钥或敏感隐私；服务端固定允许的签名算法，并校验 `iss`、`aud`、过期时间等声明。

## 3. SQL、XSS、CSRF 和 CORS

- SQL：始终参数化查询。
- XSS：输出到 HTML 前转义；Markdown/HTML 使用成熟解析器并启用安全过滤。
- CSRF：Cookie 会自动随请求发送时，要使用 SameSite、CSRF Token 等防护。
- CORS：只允许需要的来源、方法和请求头，不要把“允许所有来源”当默认安全设置。

## 4. 文件与 SSRF

上传文件要限制大小、数量、MIME/内容签名，使用随机存储名和隔离目录。下载时检查用户权限和最终路径。服务端根据用户传入 URL 发请求时要防 SSRF：限制协议、域名、解析后的内网地址，并设置超时和响应大小。

## 5. 密钥、日志和依赖

密钥放环境变量或密钥管理系统，轮换时不要写进 Git。日志要有 request id、状态和耗时，但不记录密码、Cookie、Authorization 或完整个人信息。定期执行 `npm audit`，阅读高危依赖的修复建议，不要盲目忽略告警。

## 安全练习

为记事本 API 加“用户只能读写自己的笔记”的判断；测试未登录、登录但不是作者、正常作者三种情况。再检查错误响应是否泄露堆栈。

## 检查清单

- [ ] 每个资源操作都检查归属。
- [ ] 没有拼接 SQL、硬编码密钥或明文密码。
- [ ] 上传、下载、远程 URL 都有边界和超时。
- [ ] 生产错误响应不暴露内部细节。
