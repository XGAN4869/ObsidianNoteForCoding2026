# 18 部署、运维和性能

## 1. 可重复构建

生产环境固定 Node 主版本，提交 lock 文件，执行 `npm ci`。发布流程通常包括：安装依赖、运行测试、构建、数据库迁移、启动新实例、健康检查、逐步切流和失败回滚。

## 2. 环境与进程

生产配置通过环境变量或密钥管理注入。PM2、systemd、容器编排平台等都可以管理进程，但工具不会替你修复业务错误。多进程（cluster/PM2 多实例）之间不共享普通内存，计数和会话应放 Redis/数据库。

## 3. 健康检查和优雅退出

健康检查可分为：

- liveness：进程是否还能响应。
- readiness：是否准备好接收流量（数据库等依赖可用）。

收到 `SIGTERM` 时，停止接收新请求，等待已有请求（设置上限），关闭 HTTP server、数据库池、Redis 和消费者，最后设置退出码。关闭操作也要有超时，不能无限等待。

## 4. 反向代理与静态资源

Nginx、云负载均衡或网关通常负责 TLS、压缩、静态文件、限流和转发。应用要配置可信代理数量，正确处理 `X-Forwarded-*`。静态资源适合 CDN；API 要设置请求超时，外部重试要有上限。

## 5. 性能先测再改

先用日志、指标和 profiling 找瓶颈，再决定优化。常见方向：数据库索引和慢查询、连接池、缓存命中、批量请求、避免同步的 CPU/文件 API。大 CPU 任务可用 worker_threads、独立进程或队列，不能无限占用 libuv 线程池。

## 6. 部署检查清单

- [ ] 测试和迁移在发布前完成。
- [ ] 健康检查可用，失败可回滚。
- [ ] 进程有日志、指标和告警。
- [ ] 密钥不在镜像和代码仓库中。
- [ ] 进程使用非 root 用户，文件权限最小化。
- [ ] 已验证备份恢复，而不只是“有备份”。
