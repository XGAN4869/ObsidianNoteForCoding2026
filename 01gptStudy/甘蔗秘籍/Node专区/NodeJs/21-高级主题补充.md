# 21 高级主题补充：把“知道名词”变成“知道边界”

这一章不要求初学者立刻写生产系统。重点是知道它们解决什么问题、有哪些限制，以及什么时候应该查官方文档。

## 1. SSR、CSR 与静态资源

CSR（客户端渲染）主要在浏览器生成页面；SSR（服务端渲染）由服务器先生成 HTML，再由浏览器接管交互。SSR 可能改善首屏和搜索引擎抓取，但会增加服务器计算、缓存和数据注入的复杂度。静态 CSS、JS、图片通常交给 CDN 或 Nginx，API 服务专注于动态请求。

## 2. 反向代理、超时与重试

反向代理接收客户端请求，再转给 Node。它可以终止 TLS、压缩、限流和做健康检查。应用要设置连接、请求体、上游响应等超时；重试只对明确安全且幂等的操作使用，并限制次数和退避时间。盲目重试 POST 可能重复创建数据。

## 3. 邮件（SMTP）

SMTP 服务通常由邮件供应商提供。使用 TLS/STARTTLS、供应商要求的端口和认证方式；账号、密码从密钥管理系统注入。邮件发送应放入队列，记录供应商返回的 message id，并处理退信。不要把用户输入直接当作任意邮件头，主题和正文应按库的安全接口传入。

## 4. MVC 与服务分层

MVC 常把 Model（数据）、View（展示）、Controller（协调请求）分开。Node API 常进一步使用 Controller → Service → Repository：Controller 处理 HTTP，Service 处理规则，Repository 负责数据库。分层的目的是真正降低耦合，不是机械地为每个函数创建文件。

## 5. JWT、OAuth2 与 OIDC

JWT 是带签名的令牌格式，不等于完整登录方案。服务端应固定算法，检查签名、过期时间、issuer、audience，并考虑撤销和轮换。OAuth2 负责授权，OIDC 在其上提供身份层；不要自己发明登录协议。敏感操作仍应在服务端查询最新权限。

## 6. Serverless

Serverless 函数由平台按请求启动，常见限制是冷启动、执行时长、临时磁盘、并发和费用模型。不要依赖进程内全局变量长期保存状态；连接池和初始化要适配复用与突发并发。把持久数据放数据库/对象存储，把慢任务放队列。

## 7. Node-API 原生扩展

Node-API 是编写跨 Node 版本原生扩展的稳定 C/C++/Rust 接口。适合调用系统能力或高性能算法，但会增加编译、平台兼容、安全审查和发布成本。先用纯 JavaScript 或独立服务验证需求，再决定是否需要原生扩展。

## 8. HTTP/2 与协议升级

HTTP/2 支持多路复用和头部压缩，通常通过 TLS（HTTPS）提供；是否使用还要看客户端、代理、负载均衡和运维平台兼容性。不要为了“更快”强行开启，先测真实延迟和错误率。

## 9. 短链接

短链接服务要生成不可预测的短码、设置过期和撤销能力，并校验目标 URL 的协议（只允许 `https` 等明确方案）。跳转前防止开放重定向滥用，记录创建者、点击次数和异常流量。

## 10. SSO、单设备登录与扫码

企业单点登录优先使用 OIDC/OAuth2。单设备登录可在服务端保存 session version 或设备会话并撤销旧会话。扫码码值应短期有效、一次使用、防重放，二维码中不要放长期密钥或完整个人资料。

## 11. 对象存储（OSS）与预签名 URL

对象存储适合图片、视频和备份。服务端验证用户权限后生成短期预签名 URL，并限定对象 key、HTTP 方法、大小和内容类型。桶默认私有；公开资源也要评估缓存、盗链和个人信息泄露。

## 12. Fastify 与 Schema

Fastify 强调 schema 驱动的路由验证和序列化。schema 能让输入边界更清楚、响应更快，但仍要写业务权限判断。不要同时混用多个框架的生命周期约定；迁移时按官方插件兼容矩阵选择版本。

## 13. Nacos 与动态配置

Nacos 常用于服务注册、发现和配置管理。配置变更必须可审计、分环境、可回滚；敏感配置要使用合适的密钥权限。客户端断连时要有本地安全默认值和告警，不能把任意远程配置直接执行成代码。

## 14. Elasticsearch

`keyword` 适合精确过滤、聚合和排序，`text` 适合全文检索。索引 mapping 应根据查询设计，避免把高基数字段盲目聚合。深分页优先 `search_after`，并使用稳定排序；写入和搜索存在刷新延迟，不能把它当作强一致主数据库。

## 15. cluster、worker_threads 与 PM2

Node 的 cluster/PM2 多实例可以利用多个 CPU，但实例不共享普通内存；会话、计数和锁要放外部存储。worker_threads 适合隔离 CPU 密集 JavaScript；libuv 线程池主要服务部分 I/O 和加密等工作，不能无限提交 CPU 任务。PM2 可管理进程、日志、实例和重启，仍需配合健康检查、优雅退出和外部监控。

## 16. 什么时候停止扩展

当单体服务仍能清楚维护时，不要为了“微服务”“消息队列”“原生扩展”而拆分。每增加一个组件，就增加网络故障、部署、权限、监控和数据一致性成本。先用测试和指标证明瓶颈，再引入工具。
