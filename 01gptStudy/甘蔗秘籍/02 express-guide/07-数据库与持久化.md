# 07 数据库与持久化

## 先理解分层

- route：这个 URL 对应哪个动作。
- controller：读取输入、调用 service、决定响应。
- service：业务规则和事务边界。
- repository：执行 SQL/ORM 查询。

分层的目的不是“文件越多越专业”，而是让数据库细节不污染 HTTP 代码，便于测试和替换。

## SQLite 入门方案

博客练习可以使用 SQLite，文件型数据库无需单独启动服务。生产环境是否使用 SQLite，要根据并发、备份、部署平台评估。

可选库：`better-sqlite3`（同步 API，简单但会占用事件循环）或 `sqlite3`/`在 Node 中支持 Promise 的驱动`。安装前查看 Node 版本和原生模块兼容性；如果编译失败，先看库的官方安装说明。

## 表设计

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE posts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  author_id INTEGER NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  published INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (author_id) REFERENCES users(id)
);
```

## 参数化查询

永远不要把用户输入拼进 SQL：

```js
db.prepare('SELECT * FROM posts WHERE id = ?').get(id);
```

参数化查询能降低 SQL 注入风险。ORM 也要使用它提供的参数绑定功能。

## 分页

```sql
SELECT id, title, created_at
FROM posts
WHERE published = 1
ORDER BY created_at DESC, id DESC
LIMIT ? OFFSET ?;
```

校验 `page`、`pageSize` 的范围，例如 page 至少为 1，pageSize 不超过 100。大数据量时使用基于游标的分页。

## 迁移和备份

表结构变更应使用 migration 文件，而不是手动改线上数据库。生产数据库必须有自动备份、恢复演练和最小权限账号。
