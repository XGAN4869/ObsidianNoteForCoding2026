# 06 项目结构、配置与日志

## 推荐目录

```text
blog-api/
├─ src/
│  ├─ app.js              # 创建 app，不监听端口，方便测试
│  ├─ server.js           # 启动 HTTP 服务
│  ├─ routes/             # 路径和参数
│  ├─ controllers/        # 组织请求/响应
│  ├─ services/           # 业务规则
│  ├─ repositories/       # 数据库访问
│  ├─ middlewares/        # 认证、错误、日志
│  └─ config/             # 环境变量解析
├─ test/
├─ .env.example
├─ .gitignore
└─ package.json
```

小项目可以先把 controller 和 service 写在同一个文件，但随着功能增加要及时拆分。

## app 与 server 分离

`src/app.js`：

```js
const express = require('express');
const app = express();
app.use(express.json());
// 注册路由和错误处理中间件
module.exports = app;
```

`src/server.js`：

```js
require('dotenv').config();
const app = require('./app');
const port = Number(process.env.PORT || 3000);
app.listen(port, () => console.log(`listening on ${port}`));
```

这样测试可以直接 `require('../src/app')`，不必真的占用端口。

## 配置检查

```js
function required(name) {
  const value = process.env[name];
  if (!value) throw new Error(`Missing environment variable: ${name}`);
  return value;
}
module.exports = { jwtSecret: required('JWT_SECRET') };
```

启动时尽早失败，比运行几分钟后才发现密钥为空更容易排查。

## 日志

开发阶段 `console` 足够；生产项目应使用结构化日志库，并记录：时间、请求 ID、方法、路径、状态码、耗时、错误码。禁止记录密码、Token、身份证号等敏感数据。
