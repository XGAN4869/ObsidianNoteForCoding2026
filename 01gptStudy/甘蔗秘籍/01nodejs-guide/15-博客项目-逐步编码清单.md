# 15 博客项目：逐步编码清单

这一章是动手顺序。每完成一个阶段就运行验证命令并提交 Git，不要一次写完所有文件。

## 阶段 A：空项目可启动

```bash
npm init -y
npm install express dotenv
npm install -D typescript tsx @types/node @types/express
```

建立 `src/app.ts`、`src/server.ts`：`app.ts` 导出 Express 实例，`server.ts` 读取端口并监听。先只实现 `GET /health`，用浏览器或 curl 验证返回 `{ "ok": true }`。

## 阶段 B：统一响应和错误

新增 `NotFoundError`、`ValidationError`，最后注册 404 和错误中间件。故意访问不存在路径、发送非法 JSON，确认状态码分别正确且进程不会崩溃。

## 阶段 C：内存 Repository（先不接数据库）

定义 `Post` 类型和 `PostRepository` 接口，先用数组实现 `listPublished`、`findBySlug`、`create`、`update`、`remove`。这样先验证 HTTP 和业务流程，再替换持久化实现。

实现并测试：

```text
GET /api/posts                    -> 200，只有 published
GET /api/posts/:slug              -> 200 或 404
POST /api/posts                   -> 201，校验 title/content/slug
```

## 阶段 D：数据库替换

创建迁移和唯一 slug 约束；把数组 Repository 换成数据库 Repository，service 和 controller 的接口保持不变。运行迁移、插入一条种子文章，然后重复 slug，确认返回 409。

## 阶段 E：登录和授权

接入成熟认证方案或先用测试会话适配器。实现 `requireUser` 和“作者或管理员”检查。用测试用户 A 创建文章，再用用户 B 修改，必须得到 403；不要仅靠前端隐藏按钮。

## 阶段 F：分页、标签和缓存

解析 `page`、`pageSize`、`tag`、`q`，设置最大页大小。为常用过滤字段建索引。公开列表设置可接受的缓存策略；写入后清理列表、标签和详情缓存。

## 阶段 G：质量门禁

```bash
npm test
npm run lint
npm run typecheck
npm run build
```

CI 中按相同顺序执行。测试至少覆盖 401、403、404、409、422 和数据库失败。日志必须包含 requestId，不能包含密码或 Token。

## 阶段 H：上线演练

在与生产相似的环境设置变量，执行迁移和构建；检查健康检查、优雅关闭、HTTPS、备份和回滚。发布一篇文章后验证公开列表、详情、标签和 SEO 信息；删除后确认旧 URL 返回 404。

## 每阶段提交模板

```text
feat(blog): add published post list
test(blog): cover forbidden update
fix(api): map duplicate slug to 409
```

提交说明“做了什么”，PR 描述“为什么、如何验证、有哪些已知限制”。
