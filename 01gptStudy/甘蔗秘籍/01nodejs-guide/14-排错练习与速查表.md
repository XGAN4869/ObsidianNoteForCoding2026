# 14 排错、练习与速查表

## 1. 排错顺序

复现 → 保存完整请求和日志 → 判断浏览器/Node/数据库边界 → 查看状态码与堆栈 → 用最小数据验证假设 → 修复后回归成功和失败路径。

## 2. 高频问题

- `EADDRINUSE`：端口被占用，结束旧进程或改端口。
- `MODULE_NOT_FOUND`：检查当前目录、依赖安装、ESM/CJS 和导入路径大小写。
- 请求一直不返回：检查中间件是否调用 `next`、是否重复发送响应、下游是否缺少超时。
- 内存持续上涨：检查未移除监听器、无界缓存、未关闭连接和大文件一次性读入。
- 线上“数据旧”：检查缓存头、数据库提交是否成功、是否清理对应缓存。

## 3. 六周练习

1. JavaScript/Node API：做 CLI 记账工具。
2. 异步与文件：做 JSON 文件读写的待办服务。
3. HTTP：用原生 `http` 写健康检查和路由。
4. Express：加校验、错误处理中间件和分页。
5. 数据库/认证：完成博客 MVP 的登录和 CRUD。
6. 测试/部署：CI、日志、压测和回滚演练。

## 4. 速查

| 目标 | 首选 |
|---|---|
| 读文件 | `node:fs/promises` |
| 跨平台路径 | `node:path` |
| 网络服务 | `node:http` 或成熟 Web 框架 |
| 并行异步任务 | `Promise.all` |
| 取消请求 | `AbortController` |
| 配置 | 启动时校验 `process.env` |
| 公开 API | 明确方法、状态码、错误结构 |
| 权限 | 服务端检查身份和资源归属 |
| 大文件 | Stream |
| 发布 | 锁文件 + 测试 + 构建 + 迁移 + 监控 |

## 5. 自测问题

1. 为什么 Node 能同时处理很多 I/O，却不适合长时间 CPU 计算？
2. 为什么 `try/catch` 有时捕获不到异步错误？
3. 为什么隐藏“编辑”按钮不能阻止越权？
4. 为什么 slug 需要数据库唯一约束？
5. 为什么 API 需要超时、分页上限和限流？
