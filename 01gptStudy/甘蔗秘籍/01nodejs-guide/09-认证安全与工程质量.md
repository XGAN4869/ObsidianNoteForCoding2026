# 09 认证、安全与工程质量

## 1. 认证和授权

认证回答“你是谁”，授权回答“你能做什么”。登录后使用安全会话（通常是 HttpOnly、Secure Cookie 或成熟认证方案）；每个读取和写入接口都在服务端重新检查身份和资源归属。隐藏按钮不是权限控制。

密码只保存经过成熟算法处理的哈希，不保存明文。不要自行设计加密、Token 刷新和 OAuth 流程；选择维护良好的库并阅读其当前安全文档。

## 2. 常见攻击与防护

- SQL 注入：参数化查询。
- XSS：输出编码，渲染 Markdown/HTML 前清洗。
- CSRF：正确的 Cookie SameSite、CSRF Token 和来源检查。
- 暴力破解：登录限速、失败监控和安全的重试策略。
- 路径穿越：限制根目录，规范化并校验路径。
- SSRF：访问外部 URL 时使用白名单，限制协议、IP 和超时。

## 3. 输入校验

在边界把未知数据转换成明确类型：字符串长度、数字范围、枚举值、日期格式和嵌套结构都要检查。校验失败返回 400/422，并告诉调用方字段问题；不要把内部堆栈返回客户端。

## 4. 依赖与密钥

锁定依赖版本，定期审查漏洞；最小化权限，生产密钥通过平台密钥管理注入。日志中遮盖 Authorization、Cookie、密码、数据库 URL 和个人数据。

## 5. 工程质量

启用 TypeScript strict、ESLint、格式化、提交前检查和 CI。为业务错误定义可判断的错误码；为关键服务添加超时、重试上限和断路策略。
