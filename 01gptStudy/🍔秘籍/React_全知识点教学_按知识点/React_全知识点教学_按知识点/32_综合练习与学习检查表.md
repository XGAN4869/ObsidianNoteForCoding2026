# 32. 综合练习与学习检查表

## 32.1 本章要解决什么问题

学完一套 React 教材后，最重要的不是“我看完了”，而是：

```text
我能不能自己写出来？
我能不能解释为什么这样写？
我能不能改需求？
```

本章用检查表和练习，帮你确认自己是否真正掌握。

---

## 32.2 React 核心知识检查表

请你一项一项检查。能做到，就打勾。

### JSX

- [ ] 我知道 JSX 不是普通 HTML；
- [ ] 我知道 JSX 中用 `{}` 写 JavaScript 表达式；
- [ ] 我知道 `class` 要写成 `className`；
- [ ] 我知道 `for` 要写成 `htmlFor`；
- [ ] 我知道 JSX 必须有一个根元素，或使用 Fragment；
- [ ] 我知道不能在 JSX 里直接写 `if` 语句，但可以提前计算或用三元表达式。

### 组件

- [ ] 我知道组件是返回 JSX 的函数；
- [ ] 我知道组件名必须大写开头；
- [ ] 我知道页面复杂时要拆组件；
- [ ] 我知道默认导出和命名导出的区别；
- [ ] 我知道组件渲染应尽量保持纯净。

### props

- [ ] 我知道 props 是父组件传给子组件的数据；
- [ ] 我知道 props 是只读的，子组件不应该直接修改 props；
- [ ] 我会传字符串、数字、对象、数组和函数；
- [ ] 我会用回调函数实现子组件通知父组件；
- [ ] 我知道 props 变化会让组件重新渲染。

### state

- [ ] 我知道 state 是组件自己的状态；
- [ ] 我会使用 `useState`；
- [ ] 我知道修改 state 要用 set 函数；
- [ ] 我知道对象和数组 state 要用不可变更新；
- [ ] 我知道旧 state 计算新 state 时推荐函数式更新。

## 32.14 遇到 bug 时的固定检查顺序

以后写 React 项目出错，可以按这个顺序查：

1. 控制台有没有红色报错？
2. import 路径有没有写错？
3. 组件名是不是大写？
4. state 有没有真的更新？
5. props 有没有传到子组件？
6. 条件渲染是不是把内容隐藏了？
7. 列表 key 是否稳定？
8. 表单有没有写 `value` 和 `onChange`？
9. effect 依赖数组是否正确？
10. 接口返回的数据结构是不是和你想的一样？

不要一出错就怀疑自己很笨。  
程序员每天都在查 bug。查 bug 是学习的一部分。

## 32.15 后续学习路线

学完本套教材后，建议按这个顺序继续：

```text
React 基础项目
  ↓
React Router 熟练使用
  ↓
表单和请求项目
  ↓
Redux Toolkit 或 Zustand
  ↓
TypeScript + React
  ↓
组件库，如 Ant Design / MUI
  ↓
测试、性能、安全、部署
  ↓
Next.js 等 React 框架
```

不要同时学太多。  
每次只抓一个目标。

## 32.17 最后提醒

学 React 不要只看。

你要反复做这四步：

```text
看懂
手写
运行
修改
```

如果你只是看完，忘得很快。  
如果你手写三遍，很多知识会变成自己的能力。

学完这套教材后，你的目标不是背 API，而是能独立完成一个小项目。

只要你能独立写出第 31 章的任务管理系统，并能自己改需求，你就已经真正入门 React 了。
