# 23. React 18/19 常见能力与并发基础

## 23.1 本章要解决什么问题

React 18 和 React 19 中，有一些能力经常在新项目或新教程中出现。

初学者不需要一下子把它们全部用熟，但需要知道：

- 它们解决什么问题；
- 什么时候应该用；
- 哪些是 React 18 就常见的能力；
- 哪些是 React 19 新增或更常见的能力；
- 不要把高级 API 当成普通写法乱用。

本章会用简单例子解释，不会故意讲得很玄。

---

## 23.2 先检查项目 React 版本

不同项目的 React 版本可能不同。

查看版本：

```bash
npm list react react-dom
```

你可能看到：

```text
react@18.x
react-dom@18.x
```

或者：

```text
react@19.x
react-dom@19.x
```

重要提醒：

```text
如果你的项目是 React 18，就不要直接使用 React 19 才有的 Hook。
```

本章会标注常见版本范围。

---

## 23.3 React 18 的 createRoot

React 18 开始，常见入口写法是：

```jsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

重点：

- `createRoot` 从 `react-dom/client` 导入；
- 它是现代 React Web 项目的常见入口；
- 使用它可以启用 React 18 之后的并发相关能力。

## 23.4 自动批处理 Automatic Batching

React 会把多次 state 更新合并成一次渲染，减少不必要的更新。

示例：

```jsx
import { useState } from 'react';

export default function App() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('小明');

  function handleClick() {
    setCount((c) => c + 1);
    setName('小红');
  }

  return (
    <div>
      <p>count：{count}</p>
      <p>name：{name}</p>
      <button onClick={handleClick}>修改</button>
    </div>
  );
}
```

点击按钮时，React 通常不会因为两个 `setState` 分别渲染两次，而是合并处理。

初学者只需要记住：

```text
多次状态更新，React 会尽量更聪明地合并渲染。
```

不要依赖“立刻更新后的 DOM”去写逻辑。

## 23.5 什么是并发基础

并发不是说 JavaScript 变成多线程。

在 React 里，可以简单理解为：

```text
React 可以把某些更新安排得更灵活，
让紧急的更新先显示，
不紧急的更新稍后处理。
```

比如搜索框：

- 用户输入文字：很紧急，必须马上显示；
- 根据文字过滤一万个列表项：不那么紧急，可以稍微延后。

这时可以用 transition 思想。

---

## 23.6 startTransition

`startTransition` 用来告诉 React：

```text
这里面的状态更新不是特别紧急。
```

示例：

```jsx
import { startTransition, useState } from 'react';

const bigList = Array.from({ length: 10000 }, (_, index) => `商品 ${index}`);

export default function App() {
  const [text, setText] = useState('');
  const [keyword, setKeyword] = useState('');

  const list = bigList.filter((item) => item.includes(keyword));

  function handleChange(e) {
    const value = e.target.value;

    setText(value); // 紧急：输入框文字立刻显示

    startTransition(() => {
      setKeyword(value); // 不紧急：列表过滤可以稍后
    });
  }

  return (
    <div>
      <input value={text} onChange={handleChange} placeholder="搜索商品" />
      <p>结果数量：{list.length}</p>
      <ul>
        {list.slice(0, 20).map((item) => (
          <li key={item}>{item}</li>
        ))}
      </ul>
    </div>
  );
}
```

解释：

- `text` 控制输入框，用户输入要快；
- `keyword` 控制列表过滤，可以慢一点；
- `startTransition` 告诉 React：列表更新可以当作过渡更新。

## 23.7 useTransition

`useTransition` 和 `startTransition` 类似，但它还提供一个 `isPending`，可以告诉你过渡更新是否还在进行。

```jsx
import { useState, useTransition } from 'react';

const bigList = Array.from({ length: 10000 }, (_, index) => `任务 ${index}`);

export default function App() {
  const [inputValue, setInputValue] = useState('');
  const [keyword, setKeyword] = useState('');
  const [isPending, startTransition] = useTransition();

  const list = bigList.filter((item) => item.includes(keyword));

  function handleChange(e) {
    const value = e.target.value;
    setInputValue(value);

    startTransition(() => {
      setKeyword(value);
    });
  }

  return (
    <div>
      <input value={inputValue} onChange={handleChange} />
      {isPending && <p>列表更新中...</p>}

      <ul>
        {list.slice(0, 30).map((item) => (
          <li key={item}>{item}</li>
        ))}
      </ul>
    </div>
  );
}
```

使用场景：

- 大列表过滤；
- 页面切换时某些非紧急更新；
- 用户输入要保持流畅的地方。

不要所有 `setState` 都包 `startTransition`。

## 23.8 useDeferredValue

`useDeferredValue` 可以让某个值“延迟跟上”。

简单理解：

```text
输入框的值马上变化，
列表使用一个稍微延后的值。
```

```jsx
import { useDeferredValue, useState } from 'react';

const bigList = Array.from({ length: 10000 }, (_, index) => `商品 ${index}`);

export default function App() {
  const [text, setText] = useState('');
  const deferredText = useDeferredValue(text);

  const list = bigList.filter((item) => item.includes(deferredText));

  return (
    <div>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="搜索商品"
      />

      {text !== deferredText && <p>结果更新中...</p>}

      <ul>
        {list.slice(0, 30).map((item) => (
          <li key={item}>{item}</li>
        ))}
      </ul>
    </div>
  );
}
```

它适合：

- 输入框联动大列表；
- 某个子组件渲染很慢；
- 希望用户输入不要被慢组件拖住。

## 23.9 React 19 Actions 是什么

React 19 稳定后，Actions 成为官方重点能力之一。

不要被名字吓到。简单说：

```text
Action 通常就是一个会改变数据的函数，
比如提交表单、保存用户、删除任务。
```

React 19 对表单 action、pending 状态、乐观更新等能力提供了更多内置支持。

如果你的项目是 React 18，本节先当作“认识”。

---

## 23.10 useActionState 基础

`useActionState` 用来处理“提交动作后更新状态”的场景。

简单示例：

```jsx
import { useActionState } from 'react';

async function submitName(previousState, formData) {
  const name = formData.get('name');

  if (!name) {
    return { message: '姓名不能为空' };
  }

  await new Promise((resolve) => setTimeout(resolve, 1000));

  return { message: `保存成功：${name}` };
}

export default function App() {
  const [state, formAction, isPending] = useActionState(submitName, {
    message: '',
  });

  return (
    <form action={formAction}>
      <input name="name" placeholder="请输入姓名" />
      <button disabled={isPending}>
        {isPending ? '提交中...' : '提交'}
      </button>
      <p>{state.message}</p>
    </form>
  );
}
```

解释：

- `submitName` 是提交时执行的函数；
- `previousState` 是上一次返回的状态；
- `formData` 是表单数据；
- `state` 是当前动作状态；
- `isPending` 表示是否正在提交。

## 23.11 useFormStatus 简单认识

`useFormStatus` 来自 `react-dom`，通常用于表单里面的子组件。

它能让子组件知道父级表单是否正在提交。

```jsx
import { useActionState } from 'react';
import { useFormStatus } from 'react-dom';

async function saveUser(previousState, formData) {
  await new Promise((resolve) => setTimeout(resolve, 1000));
  return { message: `已保存：${formData.get('name')}` };
}

function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button disabled={pending}>
      {pending ? '保存中...' : '保存'}
    </button>
  );
}

export default function App() {
  const [state, formAction] = useActionState(saveUser, { message: '' });

  return (
    <form action={formAction}>
      <input name="name" placeholder="姓名" />
      <SubmitButton />
      <p>{state.message}</p>
    </form>
  );
}
```

注意：`useFormStatus` 必须在表单内部的子组件中使用，才能读取到对应表单状态。

## 23.12 useOptimistic 乐观更新

乐观更新的意思是：

```text
先假装成功，马上更新界面。
如果后端失败，再回退或提示错误。
```

适合点赞、收藏、发送消息等场景。

示例：

```jsx
import { useOptimistic, useState } from 'react';

async function sendMessageToServer(text) {
  await new Promise((resolve) => setTimeout(resolve, 1000));
  return { id: Date.now(), text };
}

export default function App() {
  const [messages, setMessages] = useState([]);

  const [optimisticMessages, addOptimisticMessage] = useOptimistic(
    messages,
    (currentMessages, newText) => [
      ...currentMessages,
      { id: `temp-${Date.now()}`, text: newText, sending: true },
    ]
  );

  async function formAction(formData) {
    const text = formData.get('message');
    if (!text) return;

    addOptimisticMessage(text);
    const savedMessage = await sendMessageToServer(text);
    setMessages((prev) => [...prev, savedMessage]);
  }

  return (
    <div>
      <form action={formAction}>
        <input name="message" placeholder="输入消息" />
        <button>发送</button>
      </form>

      <ul>
        {optimisticMessages.map((message) => (
          <li key={message.id}>
            {message.text} {message.sending && '发送中...'}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

初学提醒：

- 乐观更新不是所有场景都适合；
- 金额、库存、权限等重要数据不要随便“假装成功”；
- 后端失败时必须有错误处理。

## 23.13 React 19 中 ref 的变化简单认识

在 React 18 及更早项目中，函数组件接收 ref 常用 `forwardRef`。

旧写法常见示例：

```jsx
import { forwardRef } from 'react';

const MyInput = forwardRef(function MyInput(props, ref) {
  return <input ref={ref} {...props} />;
});
```

React 19 中，ref 作为 prop 的使用更简单。不过旧项目里 `forwardRef` 仍然非常常见。

初学建议：

```text
先会 useRef 操作 DOM。
遇到组件转发 ref 时，再按项目 React 版本查官方写法。
```

不要在还不懂 ref 的情况下过早学习复杂封装。

## 23.14 不要滥用高级 API

这些 API 不是为了让代码看起来高级。

什么时候先不用：

- 页面很小；
- 列表很短；
- 表单很简单；
- 没有明显卡顿；
- 团队项目仍是 React 18；
- 你还没有搞清楚普通 state 和 effect。

正确学习顺序：

```text
useState / props / useEffect
  ↓
useMemo / useCallback / memo
  ↓
useTransition / useDeferredValue
  ↓
React 19 表单相关能力
```

## 23.15 常见错误

### 错误 1：项目是 React 18，却使用 React 19 Hook

先检查版本。

```bash
npm list react react-dom
```

### 错误 2：把 transition 当成防抖

`useTransition` 不是 `debounce`。  
如果你要“停止输入 500ms 后再请求”，那仍然需要防抖逻辑。

### 错误 3：所有更新都包 startTransition

只有“不紧急”的更新才适合 transition。

### 错误 4：乐观更新没有失败处理

如果请求失败，必须提示用户或回退数据。

---

## 23.16 小结与练习

本章重点：

- React 18 使用 `createRoot` 作为现代入口；
- 自动批处理会减少不必要渲染；
- `startTransition` 和 `useTransition` 用于非紧急更新；
- `useDeferredValue` 可以让慢更新延后；
- React 19 有 `useActionState`、`useOptimistic`、`useFormStatus` 等表单和动作相关能力；
- 高级 API 要按场景使用，不要乱用。

练习：

1. 用 `npm list react react-dom` 查看你的项目版本。
2. 写一个大列表搜索，用 `useTransition` 显示“更新中”。
3. 写一个输入框，用 `useDeferredValue` 延迟过滤列表。
4. 如果你项目是 React 19，尝试写一个 `useActionState` 表单。
