# 04 - 镜像基础命令

> 本章目标：理解镜像是什么，掌握拉取、查看、删除、打标签、保存、加载镜像等基础操作。

---

## 1. 本章核心命令

```powershell
docker images
docker image ls
docker pull
docker image inspect
docker history
docker tag
docker rmi
docker image rm
docker save
docker load
docker image prune
```

口诀：

```text
pull 拉镜像
images 看镜像
tag 打标签
rmi 删镜像
history 看层历史
inspect 看详细信息
save/load 离线保存和加载
```

---

## 2. 镜像到底是什么

一句话：

```text
镜像是创建容器的只读模板。
```

镜像里面通常包含：

```text
应用程序
运行依赖
文件系统
默认启动命令
环境变量
元数据
```

例如 `nginx` 镜像里面有 nginx 程序和默认配置；`mysql` 镜像里面有 MySQL 程序和启动脚本。

---

## 3. 镜像和容器关系

```text
镜像 image -> docker run -> 容器 container
```

重要区别：

| 操作 | 对象 |
|---|---|
| `docker images` | 镜像 |
| `docker ps` | 容器 |
| `docker rmi` | 删除镜像 |
| `docker rm` | 删除容器 |

删除容器不会自动删除镜像。  
删除镜像前，通常要先删除使用它的容器。

---

## 4. 镜像名字、标签和仓库

一个镜像常见写法：

```text
nginx:alpine
mysql:8.4
redis:7
ubuntu:24.04
```

格式：

```text
镜像名:标签
```

如果不写标签，Docker 默认使用：

```text
latest
```

例如：

```powershell
docker pull nginx
```

基本等价于：

```powershell
docker pull nginx:latest
```

但是工作中不建议长期依赖 `latest`，因为它可能变化，导致今天和明天拉到的内容不同。

推荐明确版本：

```powershell
docker pull nginx:1.27-alpine
docker pull redis:7-alpine
```

## 5. 拉取镜像：docker pull

```powershell
docker pull nginx
```

```powershell
docker pull nginx:alpine
```

拉取后查看：


## 6. 查看本地镜像

```powershell
docker images
```

或：

```powershell
docker image ls
```

常见字段：

| 字段 | 含义 |
|---|---|
| REPOSITORY | 镜像仓库名 |
| TAG | 标签 |
| IMAGE ID | 镜像 ID |
| CREATED | 创建时间 |
| SIZE | 镜像大小 |

---

## 7. 查看镜像详细信息

```powershell
docker image inspect nginx:alpine
```

会看到 JSON 信息，包括：

```text
镜像 ID
创建时间
环境变量
默认命令
入口点
工作目录
架构
操作系统
镜像层信息
```

初学阶段重点看：

```text
Config.Env
Config.Cmd
Config.Entrypoint
Architecture
Os
RootFS.Layers
```

---

## 8. 查看镜像层历史

```powershell
docker history nginx:alpine
```

你会看到每一层大概来自哪个构建步骤。

Docker 镜像是分层的。  
通俗理解：

```text
第一层：基础系统
第二层：安装软件
第三层：复制配置
第四层：设置启动命令
```

分层的好处：

```text
可复用
可缓存
传输更省流量
构建更快
```

---

## 9. 给镜像打标签：docker tag

镜像 tag 不是复制完整镜像。  
它更像给同一个镜像取一个新名字。

示例：

```powershell
docker pull nginx:alpine
docker tag nginx:alpine my-nginx:1.0
docker images
```

你会看到：

```text
nginx:alpine
my-nginx:1.0
```

它们可能指向同一个 IMAGE ID。

---

## 10. 删除镜像

```powershell
docker rmi my-nginx:1.0
```

或：

```powershell
docker image rm my-nginx:1.0
```

如果镜像被容器使用，可能删除失败。  
先查看容器：

```powershell
docker ps -a
```

删除相关容器后，再删除镜像。

---

## 11. dangling 镜像

有时你会看到：

```text
<none>   <none>
```

这类镜像常被称为 dangling image。  
它们可能来自反复构建镜像后的旧层。

清理 dangling 镜像：

```powershell
docker image prune
```

注意：这个命令会删除未被使用的 dangling 镜像。执行前看清提示。

---

## 12. 保存镜像到文件：docker save

适合没有网络或需要离线传输的场景。

```powershell
docker save -o nginx-alpine.tar nginx:alpine
```

得到：

```text
nginx-alpine.tar
```

---

## 13. 从文件加载镜像：docker load

```powershell
docker load -i nginx-alpine.tar
```

加载后查看：

```powershell
docker images
```

---

## 14. image prune 和 system prune 区别

```powershell
docker image prune
```

主要清理未使用镜像。

```powershell
docker system prune
```

会清理更多资源，例如停止的容器、未使用网络、构建缓存等。

初学阶段不要随便执行：

```powershell
docker system prune -a --volumes
```

它可能清掉你还想保留的数据。

## 15. 镜像常见问题

### 15.1 为什么 pull 很慢或失败

可能原因：

```text
网络不稳定
代理配置错误
公司网络限制
镜像仓库不可达
```

排查：

```powershell
docker pull hello-world
docker info
```

看 Docker Desktop 代理设置，必要时找网络管理员。

---

### 15.2 为什么 rmi 删除失败

常见原因：

```text
有容器正在使用这个镜像
有停止的容器仍然引用这个镜像
同一个镜像 ID 有多个 tag
```

处理：

```powershell
docker ps -a
docker rm 容器名
docker rmi 镜像名:标签
```

---

### 15.3 为什么镜像很大

可能原因：

```text
基础镜像太大
安装了很多无用软件
复制了无用文件
构建缓存没有清理
没有使用 .dockerignore
没有使用多阶段构建
```

后面 Dockerfile 章节会详细讲优化。

## 17. 本章总结

必须记住：

```text
1. 镜像是容器的模板。
2. docker pull 拉取镜像。
3. docker images 查看镜像。
4. docker history 看镜像层历史。
5. docker tag 给镜像打标签。
6. docker rmi 删除镜像。
7. docker save/load 用于离线保存和加载镜像。
8. 工作中尽量不要只依赖 latest。
```
