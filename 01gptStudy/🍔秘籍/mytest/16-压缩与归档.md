## 1. 概述

### 1.1 从"处理文本"到"管理文件"

前六章（第 10--15 章）你掌握了 Linux 文本处理的完整工具链——从查看、搜索、正则表达式，到 sed 编辑、awk 分析与计算，再到 sort/uniq/cut/tr/xargs 工具箱。你学会了在文本的微观世界里游刃有余。

现在，你需要面对更大的图景：

- "如何把整个项目目录打包成一个文件，发给同事？"

这些任务的共同点是：**它们处理的是文件本身，而不是文件的内容。** 你需要将多个文件合并为一个（归档，Archive），再将这个文件缩小体积（压缩，Compression），或者对单个文件直接压缩。

这就是第 16 章——压缩与归档——的主题。它标志着 **Phase 2（基础篇）的最后一站**。完成本章后，你将具备独立管理 Linux 文件的所有基础能力。

### 1.2 归档与压缩：两个独立的概念

很多人把"tar 打包"和"gzip 压缩"混为一谈，但它们是两个完全不同的操作：

```
+------------------------------------------------------------------+
|                    归档 vs 压缩                                    |
|                                                                  |
|  归档（Archiving / Packaging）：                                   |
|  +--------------------------------------------------------------+ |
|  |  file1.txt  file2.log  dir1/  dir2/                          | |
|  |      \         |         |      /                            | |
|  |       \        |         |     /                             | |
|  |        +-------+---------+----+                              | |
|  |             archive.tar   （一个文件，大小 ≈ 原文件之和）        | |
|  +--------------------------------------------------------------+ |
|                                                                  |
|  压缩（Compression）：                                            |
|  +--------------------------------------------------------------+ |
|  |  archive.tar  (100MB)                                        | |
|  |       |                                                      | |
|  |       v  压缩算法                                              | |
|  |  archive.tar.gz  (20MB)                                      | |
|  |  archive.tar.xz  (15MB)                                      | |
|  |  archive.tar.zst (18MB)                                      | |
|  +--------------------------------------------------------------+ |
|                                                                  |
|  两种操作可以分别执行，也可以合并为一步（如 tar -czf）             |
+------------------------------------------------------------------+
```

**关键区别：**

| 维度 | 归档 | 压缩 |
|------|------|------|
| 目的 | 将多个文件合并为一个 | 减小单个文件的体积 |
| 原始文件 | 保留（默认） | 默认替换原文件，保留压缩包 |
| 典型工具 | `tar`, `cpio`, `ar` | `gzip`, `bzip2`, `xz`, `zstd` |
| Linux 传统 | tar 只归档，不压缩 | 压缩工具只压缩单个文件 |
| 现代惯例 | tar + 压缩结合使用（如 .tar.gz） | 也可单独压缩任意文件 |
| 类比 | 把所有文件放进一个盒子 | 把盒子抽真空 |

**Unix 哲学体现：** 归档和压缩分离，是"做好一件事"原则的经典应用。tar 只做归档，gzip 只做压缩，两者通过管道组合。这比"一个工具同时做归档和压缩"更灵活——你可以自由选择压缩算法而不必更换归档工具。

### 1.3 压缩/归档工具全景

本章覆盖的工具列表：

| 工具 | 角色 | 压缩算法 | 常见扩展名 | 典型用途 |

## 2. 核心概念

### 2.1 归档：tar 的数据模型

tar（**T**ape **Ar**chiver）的设计初衷是向磁带机写入数据。磁带是顺序访问设备——你只能从头到尾读写，不能随机跳转。这种历史背景塑造了 tar 的工作方式：

```
+------------------------------------------------------------------+
|                    tar 归档文件的内部结构                           |
|                                                                  |
|  +--------------------------------------------------------------+ |
|  | Header 1 | File 1 Data | Header 2 | File 2 Data | ... | End  | |
|  +--------------------------------------------------------------+ |
|                                                                  |
|  每个 File Header 包含：                                          |
|  +--------------------------------------------------------------+ |
|  | 字段           | 说明                                        | |
|  |----------------+---------------------------------------------| |
|  | filename       | 文件路径（含相对路径）                       | |
|  | mode           | 文件权限（如 0644, 0755）                    | |
|  | uid / gid      | 所有者和组 ID                               | |
|  | size           | 文件大小（字节）                             | |
|  | mtime          | 修改时间戳                                   | |
|  | typeflag       | 类型：普通文件/目录/符号链接/硬链接/设备     | |
|  | linkname       | 符号链接的目标路径                           | |
|  | magic          | "ustar" 魔数，标识 tar 格式                  | |
|  +--------------------------------------------------------------+ |
|                                                                  |
|  注意：tar 不压缩！一个 100MB 的文件在 tar 中仍然占 100MB         |
|        （加上 header 和 padding 的开销，通常会略大一点）           |
+------------------------------------------------------------------+
```

**tar 的核心操作——三个基本模式：**

```
+------------------------------------------------------------------+
|                       tar 三种基本模式                             |
|                                                                  |
|  模式     |  选项  |  操作                  |  文件变化            |
|  ---------+--------+------------------------+---------------------|
|  创建     |  c     |  生成 .tar 文件         |  原文件保留           |
|  列出     |  t     |  查看 .tar 内容         |  无变化               |
|  提取     |  x     |  解出原文件              |  原文件被还原          |
|  ---------+--------+------------------------+---------------------|
|                                                                  |
|  记忆口诀：                                                       |
|  c = Create（创建）                                               |
|  t = lisT（列出——T 是 list 的最后一个字母）                        |
|  x = eXtract（提取——X 是 extract 中的标志字母）                    |
+------------------------------------------------------------------+
```

### 2.2 压缩的本质：无损压缩算法简介

压缩算法（Compression Algorithm）的目标是：**用更少的比特（bit）表示相同的信息。** 我们所讨论的全部压缩工具都是**无损压缩（Lossless Compression）**——解压后得到的文件与原始文件逐字节完全相同。

**无损压缩 vs 有损压缩：**

```
+------------------------------------------------------------------+
|                    压缩分类                                        |
|                                                                  |
|  无损压缩（Lossless）               有损压缩（Lossy）              |
|  解压后：原封不动                   解压后：近似还原                |
|  适用于：文本、代码、               适用于：图片、音频、视频        |
|          日志、数据库、                                          |
|          配置文件、档案                                          |
|  工具：gzip, bzip2, xz,            工具：JPEG, MP3, H.264,       |
|        zstd, zip, 7z                     WebP, Opus              |
|                                                                  |
+------------------------------------------------------------------+
```

本章只讨论无损压缩工具。Linux 系统管理中几乎永远不需要有损压缩。

### 2.3 压缩算法深度对比

每一种压缩工具背后是一种独特的压缩算法。了解它们的原理和差异，是选择正确工具的前提：

#### 2.3.1 gzip / DEFLATE 算法

gzip 使用 **DEFLATE** 算法，它是 **LZ77**（Lempel-Ziv 1977）和 **Huffman 编码（Huffman Coding）** 的组合。

```
+------------------------------------------------------------------+
|                    DEFLATE 算法原理（简化）                         |
|                                                                  |
|  Step 1: LZ77 — 重复字符串检测                                      |
|  输入：  "hello world, hello linux, hello ubuntu"                 |
|               ^^^^^^^^^^^^  ^^^^^^^^^^^^                          |
|  输出：  "hello world, <12,5>linux, <19,5>ubuntu"                 |
|          说明：<12,5> 表示"往回 12 个字符，取 5 个字符"             |
|                （即 "hello" 出现了 3 次，后两次用指针替代）          |
|                                                                  |
|  Step 2: Huffman 编码 — 高频字符用短码                              |
|  出现频率：'e'=150次, 'z'=1次                                     |
|  编码后：  'e' -> 01 (2 bits)                                    |
|           'z' -> 11011011 (8 bits)                               |
|                                                                  |
|  组合效果：                                                        |
|  - 文本文件（代码、日志、HTML）：压缩率好（70-90%）                  |
|  - 二进制文件（图片、视频、已压缩数据）：压缩率差（5-20%）           |
+------------------------------------------------------------------+
```

#### 2.3.2 bzip2 / Burrows-Wheeler 算法

bzip2 使用 **Burrows-Wheeler 变换（BWT, Burrows-Wheeler Transform）** 作为预处理，再结合 Move-to-Front 变换和 Huffman 编码。

BWT 的核心思想：将输入字符串的所有循环移位排序，取最后一列——这样相同的字符会聚集在一起：

```
原始: "banana$"
所有循环移位，按字典序排序：
$banana
a$banan
ana$ban
anana$b
banana$      <-- 原始
na$bana
nana$ba

取每一行最后一列 → "annb$aa"  （相同字符聚集了！）

解压时通过逆变换恢复原始字符串（不需要知道原始，BWT 是可逆的）
```

bzip2 的压缩率通常比 gzip 好 10-20%，但速度慢 2-4 倍。压缩时内存占用也更高。

#### 2.3.3 xz / LZMA2 算法

xz 使用 **LZMA2**（Lempel-Ziv-Markov chain Algorithm 2）算法，由 Igor Pavlov 开发（也是 7-Zip 的作者）。

LZMA2 的核心创新：
- **大字典（Dictionary）**：可达数 GB，能够发现相隔很远的重复模式
- **范围编码器（Range Coder）**：比 Huffman 更精确的熵编码
- **多线程支持**：利用多核 CPU（xz 5.4+ 默认启用）

结果：xz 通常比 gzip 小 30-50%，比 bzip2 小 10-20%，但压缩速度慢 5-10 倍于 gzip。

#### 2.3.4 zstd / Zstandard 算法

zstd 由 Facebook（现 Meta）的 Yann Collet 于 2015 年发布，设计目标是"在任何压缩率下都是最快的"。

Zstandard 的核心特征：
- **芬威克树（Finite State Entropy，FSE）**：一种快速的熵编码方式
- **可调节压缩级别**：1（最快）到 19（最高压缩率），还可开启 --ultra 到 22
- **预训练字典（Dictionary）**：对小数据的压缩率极大提升
- **极快解压速度**：解压速度在所有算法中一骑绝尘

#### 2.3.5 算法对比总结表

以下表格是基于典型文本日志文件（100MB JSON 日志）的实测对比（Ubuntu 24.04, AMD Ryzen, NVMe SSD，仅供参考）：

| 指标 | gzip | bzip2 | xz | zstd (默认) | zstd -19 |
|------|------|-------|----|-----------|----------|
| **压缩算法** | DEFLATE | BWT+Huffman | LZMA2 | Zstandard | Zstandard |
| **压缩率** | ~7:1 | ~9:1 | ~11:1 | ~8:1 | ~10:1 |
| **压缩速度** | ★★★☆ (中) | ★★☆☆ (较慢) | ★☆☆☆ (很慢) | ★★★★ (快) | ★★☆☆ (较慢) |
| **解压速度** | ★★★☆ | ★★★☆ | ★★☆☆ | ★★★★★ (极快) | ★★★★ (快) |
| **内存占用（压缩）** | 低（~1MB） | 中（~8MB） | 高（~100MB+） | 低-中（~1-32MB） | 高（~128MB） |
| **内存占用（解压）** | 低 | 中 | 中（~20MB） | 低 | 低 |
| **多线程压缩** | 需要 pigz | 需要 pbzip2 | 内建（-T0） | 内建（-T0） | 内建（-T0） |
| **多线程解压** | 否 | 否 | 内建（-T0） | 内建（-T0） | 内建（-T0） |
| **流式压缩** | 支持 | 支持 | 支持 | 支持 | 支持 |
| **典型扩展名** | `.gz` | `.bz2` | `.xz` | `.zst` | `.zst` |
| **最佳场景** | Web 传输、通用 | 高压缩率归档 | 极致体积、分发 | 实时压缩、备份 | 高压缩归档 |

**选型建议速查：**

| 场景 | 推荐工具 | 理由 |
|------|---------|------|
| 大量日志日常压缩 | `zstd` | 速度快，解压极快，压缩率不差 |
| Web 服务器 gzip 压缩 | `gzip` | 全球浏览器兼容，DEFLATE 通用 |
| 长期冷归档（不常解压） | `xz` | 体积最小，节省存储费用 |
| 分发源代码包（如 Linux 内核） | `xz` | 业界标准（linux-*.tar.xz） |
| 实时流式压缩（管道） | `zstd` 或 `gzip` | zstd 更快，gzip 兼容性更好 |
| 跨平台分享给 Windows/Mac | `zip` | 所有操作系统原生支持 |
| 需要密码加密 + 高压缩 | `7z` | AES-256 + LZMA2 |
| 增量备份 | `tar` + `gzip` | 工具链成熟，兼容性最好 |

### 2.4 压缩率与速度的真实权衡

压缩是一个经典的时空权衡（Space-Time Tradeoff）问题。以下是直观理解：

```
压缩率（体积小） ←————————————————————————————→ 速度快
      ↑                                            ↑
      xz         bzip2      zstd       gzip      lz4
     (最慢)      (慢)       (快)       (中)      (极快)
     ~11:1      ~9:1       ~8:1       ~7:1      ~4:1

+------------------------------------------------------------------+
|            压缩速度 vs 压缩率的权衡曲线（文字表示）                  |
|                                                                  |
|  压缩比                                                           |
|  12:1 |                                  ● xz                    |
|       |                                   \                      |
|  10:1 |                     ● bzip2        \                     |
|       |                       \             \                    |
|   8:1 |             ● zstd -19 \             \                   |
|       │              \          \             \                  |
|   7:1 │         ● zstd -3   ● gzip            \                 |
|       │          \             \               \                |
|   5:1 │     ● zstd -1           \               \               |
|       │    /                     \               \              |
|   4:1 │ ● lz4                     \               \             |
|       │/                           \               \            |
|       +--------+--------+--------+--------+--------+--------+    |
|       极快     快       中       慢       很慢     极慢            |
|                        压缩速度                                    |
|                                                                  |
|  总结：没有万能工具，只有最适合当前场景的选择                        |
+------------------------------------------------------------------+
```

### 2.5 tar + 压缩的工作模型

了解了归档和压缩是独立的概念后，我们来看它们如何结合。tar 本身不内置任何压缩算法，但它通过调用外部压缩程序实现了透明集成：

```
+------------------------------------------------------------------+
|                   tar + 压缩：三种工作模式                          |
|                                                                  |
|  模式 1：两步法（显式分离）                                        |
|  +-------------------+                                           |
|  | tar -cf dir.tar dir/  |  → 第一步：归档（生成 .tar）            |
|  +-----------+-----------+                                       |
|              v                                                   |
|  +----------------------------+                                  |
|  | gzip dir.tar → dir.tar.gz  |  → 第二步：压缩（生成 .tar.gz）    |
|  +----------------------------+                                  |
|                                                                  |
|  模式 2：一步法（tar 内部管道）                                     |
|  +-----------------------------------------------------+        |
|  | tar -czf dir.tar.gz dir/                              |        |
|  |       └── 归档数据 → 管道 → gzip → 写入 .tar.gz       |        |
|  +-----------------------------------------------------+        |
|  tar 自动启动 gzip 进程，归档数据通过管道传给 gzip 压缩              |
|                                                                  |
|  模式 3：纯管道法（手动组合）                                       |
|  +-----------------------------------------------------+        |
|  | tar -c dir/ | gzip > dir.tar.gz                      |        |
|  | tar -c dir/ | xz > dir.tar.xz                        |        |
|  | tar -c dir/ | zstd > dir.tar.zst                     |        |
|  +-----------------------------------------------------+        |
|  灵活度最高，可以连接任意压缩程序                                   |
|                                                                  |
|  tar 的压缩选项映射：                                               |
|                                                                  |
|  tar 选项   |  实际调用     |  输出扩展名       |  说明               |
|  -----------+--------------+-------------------+--------------------|
|  -z         |  gzip         |  .tar.gz / .tgz   |  最常用             |
|  -j         |  bzip2        |  .tar.bz2 / .tbz2 |  高压缩率           |
|  -J         |  xz           |  .tar.xz / .txz   |  最高压缩率         |
|  --zstd     |  zstd         |  .tar.zst          |  速度最快           |
|  -a         |  根据扩展名    |  自动检测          |  根据文件名自动选择  |
|  -----------+--------------+-------------------+--------------------|
|                                                                  |
+------------------------------------------------------------------+
```

**`-a` 选项（自动检测）详解：**

```bash
# -a 根据输出文件扩展名自动选择压缩程序
tar -caf archive.tar.gz  dir/   # 自动用 gzip
tar -caf archive.tar.bz2 dir/   # 自动用 bzip2
tar -caf archive.tar.xz  dir/   # 自动用 xz
tar -caf archive.tar.zst dir/   # 自动用 zstd

# 等效于
tar -czf archive.tar.gz  dir/
tar -cjf archive.tar.bz2 dir/
tar -cJf archive.tar.xz  dir/
tar -c --zstd -f archive.tar.zst dir/
```

## 3. 命令详解

### 3.1 gzip / gunzip / zcat

**gzip**（GNU zip）是 Linux 世界使用最广泛的压缩工具。它使用 DEFLATE 算法，压缩速度快，解压速度也不错，兼容性极好。

#### 3.1.1 gzip 基本用法

```bash
# 创建测试文件
cat > /tmp/gzip-demo.txt << 'EOF'
本章演示 gzip 压缩工具的使用方法。
gzip 是 Linux 上最常用的压缩程序。
它使用 DEFLATE 算法，由 LZ77 和 Huffman 编码组合而成。
本章演示 gzip 压缩工具的使用方法。
gzip 是 Linux 上最常用的压缩程序。
它使用 DEFLATE 算法，由 LZ77 和 Huffman 编码组合而成。
EOF

# 查看原文件大小
ls -lh /tmp/gzip-demo.txt
# 输出示例：-rw-r--r-- 1 user user 263 ... /tmp/gzip-demo.txt

# 压缩（原文件被替换为 .gz 文件）
gzip /tmp/gzip-demo.txt
ls -lh /tmp/gzip-demo.txt.gz
# 输出示例：-rw-r--r-- 1 user user 196 ... /tmp/gzip-demo.txt.gz
# 263 → 196 字节（约 25% 的体积缩减）

# 解压（.gz 文件被替换为原文件）
gunzip /tmp/gzip-demo.txt.gz
```

### 3.5 zip / unzip

**zip** 和 **unzip** 是唯一同时做归档+压缩的常用工具（在本章列表中），也是跨平台兼容性最好的格式。Windows、macOS、Linux 都原生支持 `.zip` 文件。

zip 的独特价值：它是**少数同时支持归档和压缩的格式**，不需要 tar 作为中间层。

#### 3.5.1 zip 基本用法

```bash

zip -r /tmp/demo.zip .

# 查看压缩包内容
unzip -l /tmp/demo.zip
# 输出：
#   Length      Date    Time    Name
# ---------  ---------- -----   ----
#        16  2026-07-30 10:00   file1.txt

# 解压
mkdir -p /tmp/zip-extract
unzip /tmp/demo.zip -d /tmp/zip-extract

# 清理
cd /tmp
rm -rf /tmp/zip-demo /tmp/zip-extract /tmp/demo.zip
```

### 3.6 7z（7-Zip）

**7z** 是 7-Zip 的命令行版本，提供所有工具中最高的压缩率（对大多数数据类型）。它是归档+压缩一体化工具，支持 AES-256 加密、分卷、多线程等高级特性。

#### 3.6.1 7z 安装

```bash

# 或

```

#### 3.6.2 7z 基本用法

```bash

echo "7z test file 1" > file1.txt
echo "7z test file 2 with longer content" > file2.txt
```

### 3.8 tar：归档工具详解

tar 是 Linux 上最基础的归档工具。理解了 tar，就理解了 Linux 软件分发的核心机制。

#### 3.8.1 tar 基本操作：创建、列出、提取

```bash
# 准备测试目录
mkdir -p /tmp/tar-demo/{src,docs,config}
echo "print('hello')" > /tmp/tar-demo/src/main.py
echo "# README" > /tmp/tar-demo/README.md
echo "port=8080" > /tmp/tar-demo/config/app.conf
echo "user=admin" > /tmp/tar-demo/config/db.conf

# === 操作 1：创建归档（c = create）===
tar -cf /tmp/project.tar -C /tmp tar-demo/
#   -c : 创建归档
#   -f : 指定归档文件名
#   -C : 先切换到指定目录，再操作（影响后面的路径参数）

ls -lh /tmp/project.tar
# 输出示例：-rw-r--r-- 1 user user 10K ... project.tar

# === 操作 2：列出归档内容（t = list）===
tar -tf /tmp/project.tar
# 输出：
# tar-demo/
# tar-demo/src/
# tar-demo/src/main.py
# tar-demo/docs/
# tar-demo/config/
# tar-demo/config/app.conf
# tar-demo/config/db.conf
# tar-demo/README.md

# 更详细信息（类似 ls -l）
tar -tvf /tmp/project.tar
# -rw-r--r-- user/user   17 2026-07-30 08:00 tar-demo/src/main.py
# ...

# === 操作 3：提取归档（x = extract）===
mkdir -p /tmp/tar-extract
tar -xf /tmp/project.tar -C /tmp/tar-extract
ls -lR /tmp/tar-extract/tar-demo/

rm -rf /tmp/tar-demo /tmp/tar-extract /tmp/project.tar
```

#### 3.8.2 tar 核心参数表

**基本操作模式（三者必选其一）：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-c` | 创建（create）归档 | 必选（三选一） | — |
| `-x` | 提取（extract）归档 | 必选（三选一） | — |
| `-t` | 列出（list）归档内容 | 必选（三选一） | — |

**压缩选项（可选）：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-z` | 通过 gzip 压缩/解压 | 可选 | 不压缩 |
| `-j` | 通过 bzip2 压缩/解压 | 可选 | 不压缩 |
| `-J` | 通过 xz 压缩/解压 | 可选 | 不压缩 |
| `--zstd` | 通过 zstd 压缩/解压 | 可选 | 不压缩 |
| `-a` | 根据扩展名自动选择压缩程序 | 可选 | 不压缩 |

**通用选项：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-f FILE` | 归档文件名（必须是最后一个选项） | 必选（实际操作时几乎必选） | 默认是磁带设备 |
| `-v` | 显示详细信息（在处理文件时列出文件名） | 可选 | 关闭 |
| `-C DIR` | 切换到指定目录后再操作 | 可选 | 当前目录 |
| `--exclude=PATTERN` | 排除匹配 PATTERN 的文件 | 可选 | 不排除 |
| `--exclude-from=FILE` | 从 FILE 读取排除模式列表 | 可选 | 不排除 |
| `--strip-components=N` | 提取时剥除路径的前 N 个组件 | 可选 | 0 |
| `-p` | 保留文件权限（提取时） | 可选 | 对普通用户：同 umask |
| `--same-owner` | 保留文件所有者 | 可选 | 关闭（root 默认开启） |
| `-k` | 提取时不覆盖已有文件 | 可选 | 关闭（默认覆盖） |
| `--overwrite` | 提取时覆盖已有文件 | 可选 | 开启 |
| `--remove-files` | 归档后删除原文件 | 可选 | 关闭 |
| `-r` | 追加文件到已有归档末尾 | 可选 | 关闭 |
| `--delete` | 从归档中删除文件（仅对未压缩的 tar） | 可选 | 关闭 |
| `-A` | 将一个归档文件的内容追加到另一个的末尾 | 可选 | 关闭 |
| `-W` | 验证归档文件 | 可选 | 关闭 |

#### 3.8.3 tar 的 -C（目录切换）深度解析

`-C` 是 tar 中最容易被误解的参数。它的作用是：**切换到指定目录，然后以该目录为工作目录执行后续操作。**

```bash
# 准备演示目录
mkdir -p /tmp/tar-C-demo/src /tmp/tar-C-demo/docs
echo "source" > /tmp/tar-C-demo/src/code.py
echo "readme" > /tmp/tar-C-demo/docs/readme.md

# --- 不带 -C：路径中包含目标目录名 ---
tar -cf /tmp/with-path.tar -C /tmp tar-C-demo/
# 归档内的路径：tar-C-demo/src/code.py, tar-C-demo/docs/readme.md

tar -tf /tmp/with-path.tar
# tar-C-demo/
# tar-C-demo/src/
# tar-C-demo/src/code.py
# tar-C-demo/docs/
# tar-C-demo/docs/readme.md

# --- 带 -C + 提取：控制输出位置 ---
mkdir -p /tmp/tar-C-extract
tar -xf /tmp/with-path.tar -C /tmp/tar-C-extract
ls /tmp/tar-C-extract/tar-C-demo/
# 结果：/tmp/tar-C-extract/tar-C-demo/src/code.py ...

# --- -C 可以多次使用，每次影响它之后的路径 ---
# 将多个目录的不同部分打包在一起
tar -cf /tmp/multi-C.tar \
  -C /tmp/tar-C-demo src \
  -C /tmp/tar-C-demo docs
tar -tf /tmp/multi-C.tar
# src/
# src/code.py
# docs/
# docs/readme.md
# 注意：路径中不再包含 tar-C-demo 前缀

rm -rf /tmp/tar-C-demo /tmp/tar-C-extract /tmp/with-path.tar /tmp/multi-C.tar
```

#### 3.8.4 tar 的 --exclude：选择性打包

```bash
# 准备测试目录
mkdir -p /tmp/tar-exclude-demo
cd /tmp/tar-exclude-demo
mkdir -p src tests docs
touch src/main.py src/utils.py src/__pycache__/main.cpython-312.pyc
touch tests/test_main.py tests/__pycache__/test_main.cpython-312.pyc
touch docs/README.md
touch .git/config .git/HEAD
mkdir -p node_modules/some-pkg/dist
echo "build artifact" > node_modules/some-pkg/dist/bundle.js
echo "log line" > app.log

# 打包：排除所有 __pycache__ 目录和 .git 目录
tar -czf /tmp/project-clean.tar.gz \
  --exclude='__pycache__' \
  --exclude='.git' \
  --exclude='node_modules' \
  --exclude='*.log' \
  .

# 验证被排除的文件不在归档中
tar -tzf /tmp/project-clean.tar.gz | sort

rm -rf /tmp/tar-exclude-demo /tmp/project-clean.tar.gz
```

**`--exclude` 模式匹配规则：**

```bash
# 从文件读取排除列表（推荐用于复杂排除规则）
cat > /tmp/exclude-list.txt << 'EOF'
# 排除规则文件（# 开头的行是注释）

__pycache__
*.pyc
*.log

*.swp
*~

# 使用 --exclude-from

  --exclude-from=/tmp/exclude-list.txt \
  /path/to/project/

```

#### 3.8.5 tar 的 --strip-components：路径剥离

`--strip-components=N` 在提取时剥除路径前 N 个组件。这是应对"压缩包内多了一层无用目录"的利器：

```bash
# 准备演示：创建一个归档，内部路径较深
mkdir -p /tmp/strip-src/a/b/c
echo "deep file" > /tmp/strip-src/a/b/c/deep.txt
tar -czf /tmp/deep.tar.gz -C /tmp strip-src/

# 查看归档内容
tar -tzf /tmp/deep.tar.gz
# strip-src/
# strip-src/a/
# strip-src/a/b/
# strip-src/a/b/c/
# strip-src/a/b/c/deep.txt

# 不剥除：解压后有全部路径
mkdir -p /tmp/strip-out-0
tar -xzf /tmp/deep.tar.gz -C /tmp/strip-out-0
find /tmp/strip-out-0 -type f
# /tmp/strip-out-0/strip-src/a/b/c/deep.txt

# 剥除 1 层：去掉 strip-src/
mkdir -p /tmp/strip-out-1
tar -xzf /tmp/deep.tar.gz --strip-components=1 -C /tmp/strip-out-1
find /tmp/strip-out-1 -type f
# /tmp/strip-out-1/a/b/c/deep.txt

# 剥除 4 层：只提取文件本身
mkdir -p /tmp/strip-out-4
tar -xzf /tmp/deep.tar.gz --strip-components=4 -C /tmp/strip-out-4
find /tmp/strip-out-4 -type f
# /tmp/strip-out-4/deep.txt

rm -rf /tmp/strip-src /tmp/deep.tar.gz /tmp/strip-out-0 /tmp/strip-out-1 /tmp/strip-out-4
```

`--strip-components` 在实际工作中非常实用：
- 你从 GitHub 下载了 `myproject-v2.0.tar.gz`，解压后是 `myproject-v2.0/` 目录，但你希望直接得到没有版本号的目录
- CI/CD 构建产物包了一层构建环境的路径前缀，你需要去掉

#### 3.8.6 tar -C 的高级用法：管道中的归档

```bash

# -f - 表示将归档输出到标准输出/从标准输入读取

# 跨目录复制（保留权限和结构）：
```

### 3.9 tar + 压缩的组合用法

这是 Linux 日常工作中最常见的场景。tar 通过 `-z`、`-j`、`-J`、`--zstd` 选项与压缩工具无缝集成。

#### 3.9.1 创建压缩归档

```bash
# 准备测试目录
mkdir -p /tmp/tar-combo/src
for i in $(seq 1 100); do
    echo "Line $i: The quick brown fox jumps over the lazy dog." >> /tmp/tar-combo/src/log.txt
done

echo "=== 创建各种压缩格式的 tar 包 ==="

# gzip 格式（最通用）
tar -czf /tmp/archive.tar.gz /tmp/tar-combo/
ls -lh /tmp/archive.tar.gz

# bzip2 格式（更高压缩率）
tar -cjf /tmp/archive.tar.bz2 /tmp/tar-combo/
ls -lh /tmp/archive.tar.bz2

# xz 格式（最高压缩率）
tar -cJf /tmp/archive.tar.xz /tmp/tar-combo/
ls -lh /tmp/archive.tar.xz

# zstd 格式（最快速度）
tar --zstd -cf /tmp/archive.tar.zst /tmp/tar-combo/
ls -lh /tmp/archive.tar.zst

# 纯 tar（不压缩，作对比基准）
tar -cf /tmp/archive.tar /tmp/tar-combo/
ls -lh /tmp/archive.tar

echo ""
echo "=== 体积对比 ==="
for f in /tmp/archive.tar /tmp/archive.tar.gz /tmp/archive.tar.bz2 /tmp/archive.tar.xz /tmp/archive.tar.zst; do
    printf "%-25s %s\n" "$(basename $f)" "$(ls -lh $f | awk '{print $5}')"
done

rm -f /tmp/archive.tar* /tmp/tar-combo
```

#### 3.9.2 解压压缩归档

```bash
# 对于所有 tar.xxx 格式，tar 都能自动识别压缩类型（GNU tar 1.34+）
# 你甚至不需要指定 -z/-j/-J！

# 准备测试归档
mkdir -p /tmp/tar-auto
echo "test content" > /tmp/tar-auto/test.txt
tar -czf /tmp/test.tar.gz -C /tmp tar-auto/

# 自动识别并解压（推荐方式）
mkdir -p /tmp/tar-auto-extract
tar -xf /tmp/test.tar.gz -C /tmp/tar-auto-extract
# tar 自动检测到 gzip 压缩，无需 -z

# 传统方式（也有效）
tar -xzf /tmp/test.tar.gz -C /tmp/tar-auto-extract

ls -lR /tmp/tar-auto-extract/

rm -rf /tmp/tar-auto /tmp/tar-auto-extract /tmp/test.tar.gz
```

> **重要提示：** 现代 GNU tar（Ubuntu 24.04 中的版本为 1.34+）已经能够自动检测压缩格式。`tar -xf archive.tar.gz` 和 `tar -xzf archive.tar.gz` 效果相同。但 `-z`/`-j`/`-J` 选项在创建时仍然是必须的（如果你不使用 `-a`）。

#### 3.9.3 查看压缩归档内容（不解压）

```bash
# 列出压缩 tar 包的内容——不需要解压
tar -tzf archive.tar.gz    # gzip
tar -tjf archive.tar.bz2   # bzip2
tar -tJf archive.tar.xz    # xz
tar -t --zstd -f archive.tar.zst  # zstd

# 或者统一使用（自动检测）：
tar -tf archive.tar.gz     # 适合所有格式
tar -tf archive.tar.xz     # 同上
```

#### 3.9.4 管道法：tar + 任意压缩工具

```bash
# 管道法给予你最大的灵活性
mkdir -p /tmp/pipe-demo
head -c 1M /dev/urandom > /tmp/pipe-demo/random.bin

# tar + gzip（显式）
tar -cf - /tmp/pipe-demo | gzip > /tmp/pipe.tar.gz

# tar + xz（显式）
tar -cf - /tmp/pipe-demo | xz > /tmp/pipe.tar.xz

# tar + zstd（显式，可指定压缩级别）
tar -cf - /tmp/pipe-demo | zstd -5 > /tmp/pipe.tar.zst

# 解压时同样可以用管道
zstd -d < /tmp/pipe.tar.zst | tar -xf - -C /tmp/pipe-out/
mkdir -p /tmp/pipe-out && zstd -dc /tmp/pipe.tar.zst | tar -xf - -C /tmp/pipe-out/

rm -rf /tmp/pipe-demo /tmp/pipe.tar.gz /tmp/pipe.tar.xz /tmp/pipe.tar.zst /tmp/pipe-out
```

### 3.10 zcat / zless / zgrep 族工具：透明浏览压缩文件

这一组工具让你无需显式解压即可查看和搜索压缩文本文件。它们的工作方式是：先通过对应的解压程序将内容输出到标准输出，再通过管道传给 cat/less/grep。

#### 3.10.1 工具族总览

| 工具 | 对应压缩格式 | 功能 | 等效命令 |
|------|------------|------|---------|
| `zcat` | `.gz` | 将压缩文件内容输出到标准输出 | `gunzip -c` |
| `zless` | `.gz` | 在分页器中查看压缩文件 | `gunzip -c \| less` |
| `zmore` | `.gz` | 在分页器中查看（more 风格） | `gunzip -c \| more` |
| `zgrep` | `.gz` | 在压缩文件中搜索文本 | `gunzip -c \| grep` |
| `zdiff` | `.gz` | 比较两个压缩文件的差异 | — |
| `znew` | `.Z` → `.gz` | 将 compress(.Z) 格式转成 gzip(.gz) | — |
| `bzcat` | `.bz2` | bzip2 压缩文件的 zcat | `bunzip2 -c` |
| `bzgrep` | `.bz2` | bzip2 压缩文件的 zgrep | `bunzip2 -c \| grep` |
| `bzless` | `.bz2` | bzip2 压缩文件的 zless | — |
| `xzcat` | `.xz` | xz 压缩文件的 zcat | `xz -dc` |
| `xzgrep` | `.xz` | xz 压缩文件的 zgrep | — |
| `xzless` | `.xz` | xz 压缩文件的 zless | — |
| `zstdcat` | `.zst` | zstd 压缩文件的 zcat | `zstd -dc` |
| `zstdgrep` | `.zst` | zstd 压缩文件的 zgrep | — |

### 练习 16.5：压缩算法对比——实际测试

**题目：**

（1）使用 `access.log`（在 myproject 目录中）作为测试数据，分别用 gzip、bzip2、xz、zstd 压缩，记录压缩后大小。

（2）比较压缩率（压缩后体积 / 原始体积）。

（3）如果追求最小体积，选哪个？如果追求最快速度，选哪个？

**答案：**

（1）：

```bash
cd ~/ch16-practice

# 查看原始大小
orig_size=$(stat -c%s myproject/access.log)
echo "原始文件大小: ${orig_size} 字节 ($(echo "scale=1; $orig_size/1024" | bc) KB)"

# gzip
cp myproject/access.log /tmp/compare-gzip.log
gzip -6 -f /tmp/compare-gzip.log
gz_size=$(stat -c%s /tmp/compare-gzip.log.gz)
echo "gzip:  ${gz_size} 字节 (压缩率 $(echo "scale=1; $gz_size*100/$orig_size" | bc)%)"

# bzip2
cp myproject/access.log /tmp/compare-bz2.log
bzip2 -f /tmp/compare-bz2.log
bz2_size=$(stat -c%s /tmp/compare-bz2.log.bz2)
echo "bzip2: ${bz2_size} 字节 (压缩率 $(echo "scale=1; $bz2_size*100/$orig_size" | bc)%)"

# xz
cp myproject/access.log /tmp/compare-xz.log
xz -6 -f /tmp/compare-xz.log
xz_size=$(stat -c%s /tmp/compare-xz.log.xz)
echo "xz:    ${xz_size} 字节 (压缩率 $(echo "scale=1; $xz_size*100/$orig_size" | bc)%)"

# zstd
cp myproject/access.log /tmp/compare-zst.log
zstd -3 -q -f /tmp/compare-zst.log
zst_size=$(stat -c%s /tmp/compare-zst.log.zst)
echo "zstd:  ${zst_size} 字节 (压缩率 $(echo "scale=1; $zst_size*100/$orig_size" | bc)%)"

rm -f /tmp/compare-*.log.gz /tmp/compare-*.log.bz2 /tmp/compare-*.log.xz /tmp/compare-*.log.zst
```

（2）：

```bash
# 典型输出（模拟）：
# 原始文件大小: 23500 字节
# gzip:  3200 字节 (压缩率 13.6%)      ← 体积减少约 86%
# bzip2: 2400 字节 (压缩率 10.2%)      ← 体积减少约 90%
# xz:    1800 字节 (压缩率 7.7%)       ← 体积减少约 92%
# zstd:  2900 字节 (压缩率 12.3%)      ← 体积减少约 88%
```

（3）：

- **最小体积：xz**。xz 在所有通用工具中提供最高压缩率。适合长期归档、不常访问的数据。
- **最快速度：zstd**。zstd 的压缩和解压速度在同类产品中遥遥领先。适合实时压缩、备份流水线、数据库 WAL 压缩等场景。
- **平衡选择：gzip**。如果兼容性第一（所有系统都有 gzip），gzip 是最稳妥的选择。

### 练习 16.8：综合场景——备份脚本思路

**题目：**

设计一个备份命令（一行），完成以下需求：

（1）将 `myproject` 打包（排除 `__pycache__`、`node_modules`、`.git`、`build`、`*.log`）。

（2）使用 gzip 压缩。

（3）备份文件名包含当前日期（格式：`YYYYMMDD`），如 `myproject-20260730.tar.gz`。

（4）解压这个备份后，文件路径不包含 `myproject/` 前缀。

**答案：**

```bash
cd ~/ch16-practice

# 方案 1：打包时 -C 到 myproject 的父目录，用 . 代表当前目录
tar -czf "myproject-$(date +%Y%m%d).tar.gz" \
  --exclude='__pycache__' \
  --exclude='node_modules' \
  --exclude='.git' \
  --exclude='build' \
  --exclude='*.log' \
  -C myproject .

# 验证：解压后直接看到 src/ docs/ config/ 等目录
mkdir -p /tmp/verify-strip

ls /tmp/verify-strip/

# 清理
rm -rf /tmp/verify-strip
```

**扩展：一键备份脚本**（可以作为 `/usr/local/bin/backup-project.sh` 的模板）：

```bash
#!/bin/bash
# 项目备份脚本模板
PROJECT_DIR="$1"
BACKUP_DIR="${2:-./backups}"
EXCLUDE_FILE="${3:-}"

DATE=$(date +%Y%m%d-%H%M%S)
PROJECT_NAME=$(basename "$PROJECT_DIR")
BACKUP_NAME="${PROJECT_NAME}-${DATE}.tar.gz"

mkdir -p "$BACKUP_DIR"

EXCLUDE_ARGS="--exclude=__pycache__ --exclude=node_modules --exclude=.git --exclude=build --exclude=*.log"

if [ -n "$EXCLUDE_FILE" ] && [ -f "$EXCLUDE_FILE" ]; then
    tar -czf "${BACKUP_DIR}/${BACKUP_NAME}" \
        --exclude-from="$EXCLUDE_FILE" \
        -C "$(dirname "$PROJECT_DIR")" "$PROJECT_NAME"
else
    tar -czf "${BACKUP_DIR}/${BACKUP_NAME}" \
        $EXCLUDE_ARGS \
        -C "$(dirname "$PROJECT_DIR")" "$PROJECT_NAME"
fi

echo "备份完成: ${BACKUP_DIR}/${BACKUP_NAME}"
ls -lh "${BACKUP_DIR}/${BACKUP_NAME}"
```

## 5. 常见错误与排错

### 5.1 tar: Removing leading '/' from member names

**现象：**

```bash
sudo tar -czf /tmp/etc-backup.tar.gz /etc/ssh/sshd_config
# 输出：
# tar: Removing leading '/' from member names
```

**原因：** tar 为了保护你，自动移除绝对路径开头的 `/`。如果不移除，解压时文件会写到 `/etc/ssh/sshd_config`，覆盖系统文件——这是极其危险的。

**解决：**

```bash
# 方案 1：接受这个行为（推荐）。解压时用 -C 控制输出位置
mkdir -p /tmp/restore-etc
tar -xzf /tmp/etc-backup.tar.gz -C /tmp/restore-etc
# 文件在 /tmp/restore-etc/etc/ssh/sshd_config

# 方案 2：使用相对路径打包
cd /
sudo tar -czf /tmp/etc-backup.tar.gz etc/ssh/sshd_config
# 不会出现警告

# 方案 3：强制保留绝对路径（非常危险，不推荐！）
# tar -czf /tmp/etc-backup.tar.gz --absolute-names /etc/ssh/sshd_config
```

### 5.2 忘记带 -f 参数或 -f 位置不正确

**现象：**

```bash
tar -cz project.tar.gz myproject/
# 错误：tar 认为 "project.tar.gz" 是压缩选项的参数，而非文件名
# 可能报错：tar: You must specify one of the '-Acdtrux'...
```

**原因：** `-f` 参数必须是最后一个选项，后面紧跟文件名。短选项可以合并（如 `-czf`），但 `f` 必须带参数。

**解决：**

```bash
# 正确：f 紧挨着文件名
tar -czf project.tar.gz myproject/

# 或分开写（更清晰）
tar -c -z -f project.tar.gz myproject/

# 错误示例汇总：
# tar -cfz project.tar.gz myproject/    ← z 被误解
# tar -zfc project.tar.gz myproject/    ← c 后面不能跟文件名
# tar -cz project.tar.gz myproject/     ← 没有 -f！
```

### 5.3 用文本编辑器打开压缩文件

**现象：**

```bash
vim file.tar.gz
# 显示二进制乱码，修改后文件损坏
```

**原因：** `.tar.gz` 是二进制压缩格式，不能用文本编辑器打开。即使 `.tar` 文件（未压缩），其头部也是二进制格式。

**解决：**

```bash
# 查看内容：使用 tar -tf
tar -tf file.tar.gz

# 查看压缩文本内容：使用 zcat/zless
zcat file.txt.gz
zless file.txt.gz

# 编辑压缩文件中的内容：先解压，编辑，再压缩
gunzip file.txt.gz
vim file.txt
gzip file.txt
```

### 5.4 gzip 压缩后原文件消失

**现象：**

```bash
gzip important-file.txt
# important-file.txt 消失了！只剩下 important-file.txt.gz
```

**原因：** gzip、bzip2、xz、zstd 默认在压缩后**删除原文件**。这是设计行为——压缩工具认为压缩后你不再需要原文件。

**解决：**

```bash
# 方法 1：使用 -k（keep）保留原文件
gzip -k important-file.txt     # 生成 important-file.txt.gz，保留原文件
bzip2 -k important-file.txt    # 同上
xz -k important-file.txt       # 同上
zstd -k important-file.txt     # 同上

# 方法 2：使用 -c 输出到文件
gzip -c important-file.txt > important-file.txt.gz
# 原文件保留

# 方法 3：使用重定向（替代方案）
gzip < important-file.txt > important-file.txt.gz
```

### 5.5 解压 tar.gz 时覆盖已有文件

**现象：**

```bash
# 当前目录有 file.txt（已修改）
tar -xzf backup.tar.gz
# file.txt 被备份中的旧版本覆盖，修改丢失
```

**原因：** tar 默认覆盖已存在的同名文件。

**解决：**

```bash
# 方法 1：使用 -k（不覆盖已有文件）
tar -xzkf backup.tar.gz

# 方法 2：解压到临时目录，手动对比合并
mkdir /tmp/restore
tar -xzf backup.tar.gz -C /tmp/restore
diff -r . /tmp/restore/

# 方法 3：使用 --skip-old-files
tar -xzf backup.tar.gz --skip-old-files
# GNU tar 1.34+ 支持

# 方法 4：先列出内容，逐文件决定
tar -tzf backup.tar.gz | while read f; do
    if [ ! -f "$f" ]; then
        tar -xzf backup.tar.gz "$f"
    else
        echo "跳过已存在的文件: $f"
    fi
done
```

### 5.6 解压 zip 文件中文文件名乱码

**现象：**

```bash
# 从 Windows 传来的 zip 文件，解压后中文文件名变成乱码
unzip from-windows.zip
# 输出：��文文件��.txt
```

**原因：** Windows 创建的 zip 文件使用 GBK/GB2312 编码存储文件名，而 Linux 默认使用 UTF-8。zip 格式规范中没有强制规定文件名编码。

**解决：**

```bash
# 方法 1：使用 -O 指定源编码（unzip 6.0+）
unzip -O GBK from-windows.zip

# 方法 2：使用 7z 解压（7z 对编码处理更好）
7z x from-windows.zip

# 方法 3：使用 unar（The Unarchiver，编码检测更好）
sudo apt install -y unar
unar from-windows.zip

# 方法 4：用 convmv 批量转换已解压的文件名
# 先解压
unzip from-windows.zip
# 再将 GBK 文件名转为 UTF-8（先预览）
convmv -f gbk -t utf-8 -r . --notest
```

### 5.7 tar: Cowardly refusing to create an empty archive

**现象：**

```bash
tar -czf empty.tar.gz /nonexistent/path/
# 输出：
# tar: /nonexistent/path: Cannot stat: No such file or directory
# tar: Exiting with failure status due to previous errors
```

**原因：** tar 要求至少有一个有效文件/目录才能创建归档。如果所有指定的路径都不存在，tar 拒绝创建空归档。

**解决：**

```bash
# 确认路径存在
ls -d /path/to/archive/

# 如果路径可能不存在，使用条件判断
if [ -d /path/to/archive/ ]; then
    tar -czf backup.tar.gz /path/to/archive/
else
    echo "目录不存在，跳过备份"
fi
```

### 5.8 超过命令行参数长度限制

**现象：**

```bash
# 目录中有数十万个文件
tar -czf huge.tar.gz *
# 输出：
# bash: /usr/bin/tar: Argument list too long
```

**原因：** Shell 展开 `*` 通配符时会把所有文件名作为命令行参数，超出系统的 `ARG_MAX` 限制（通常约 2MB）。

**解决：**

```bash
# 方法 1：使用 tar 的目录递归能力（不依赖 Shell 展开）
tar -czf huge.tar.gz .
# tar 自己遍历目录，不经过 Shell 的参数展开

# 方法 2：使用 find + xargs
find . -type f -print0 | tar -czf huge.tar.gz --null -T -
# -T - : 从标准输入读取文件列表
# --null : 与 find -print0 配合处理特殊字符

# 方法 3：使用 --files-from
find . -type f > /tmp/filelist.txt
tar -czf huge.tar.gz --files-from=/tmp/filelist.txt
```

### 5.9 磁盘空间不足导致的压缩/解压失败

**现象：**

```bash
tar -xzf 10GB-backup.tar.gz
# 中途报错：
# tar: Unexpected EOF in archive
# tar: Error is not recoverable: exiting now
```

**原因：** 解压时磁盘空间不足，tar 无法完成写入。解压 10GB 的归档可能需要 10GB+ 的临时空间。

**解决：**

```bash
# 解压前先检查磁盘空间
df -h /target/directory

# 如果磁盘空间紧张，解压到空间更大的位置
df -h /mnt/bigdisk
tar -xzf 10GB-backup.tar.gz -C /mnt/bigdisk/

# tar 可以在管道中处理，无需全部写入磁盘
# 例如：只提取特定文件
tar -xzf 10GB-backup.tar.gz path/to/specific/file.txt

# 或者：计算归档解压后的大小（近似值）
tar -tzvf 10GB-backup.tar.gz | awk '{sum+=$3} END{print sum " bytes"}'
```

## 6. 进阶延伸

### 6.1 增量备份与差异备份

tar 的 `--newer`（或 `--after-date`）选项支持基于时间戳的增量备份：

```bash
# 准备演示环境
mkdir -p ~/ch16-incremental/data
echo "Initial file" > ~/ch16-incremental/data/file1.txt
echo "Initial file 2" > ~/ch16-incremental/data/file2.txt

# 全量备份（首次）
tar -czf ~/ch16-incremental/full-backup.tar.gz -C ~/ch16-incremental data/

# 模拟一天后的修改
sleep 2  # 确保时间戳有差异
echo "Modified content" > ~/ch16-incremental/data/file1.txt
echo "New file" > ~/ch16-incremental/data/file3.txt

# 增量备份：只备份在上次全量备份之后修改/新增的文件
tar -czf ~/ch16-incremental/incremental-backup.tar.gz \
  --newer=~/ch16-incremental/full-backup.tar.gz \
  -C ~/ch16-incremental data/

# 查看增量备份的内容
echo "=== 增量备份包含的文件 ==="
tar -tzf ~/ch16-incremental/incremental-backup.tar.gz
# 只包含 file1.txt（修改过的）和 file3.txt（新增的）

# 恢复：先恢复全量备份，再覆盖增量备份
mkdir -p /tmp/incremental-restore
tar -xzf ~/ch16-incremental/full-backup.tar.gz -C /tmp/incremental-restore
tar -xzf ~/ch16-incremental/incremental-backup.tar.gz -C /tmp/incremental-restore

rm -rf ~/ch16-incremental /tmp/incremental-restore
```

**增量备份 vs 差异备份：**

| 类型 | 英文 | 基准 | 内容 | 恢复步骤 |
|------|------|------|------|---------|
| 全量备份 | Full | 无 | 全部文件 | 1 步 |
| 增量备份 | Incremental | 上次备份（全量或增量） | 上次备份后改变的文件 | 全量 + 每个增量 |
| 差异备份 | Differential | 上次全量备份 | 上次全量后改变的文件 | 全量 + 最新差异 |

### 6.3 分卷压缩

当需要将大文件分割为多个小文件时（如通过邮件发送、刻录到 FAT32 U 盘），使用分卷压缩：

```bash
# 准备大文件
dd if=/dev/urandom of=/tmp/bigfile.bin bs=1M count=100 2>/dev/null
ls -lh /tmp/bigfile.bin

# === 方法 1：split（通用方法）===
# 先压缩，再分割
gzip -k /tmp/bigfile.bin
split -b 10M /tmp/bigfile.bin.gz /tmp/bigfile.part-
# 生成 bigfile.part-aa, bigfile.part-ab, bigfile.part-ac ...

# 合并后解压
cat /tmp/bigfile.part-* > /tmp/bigfile-restored.bin.gz
gunzip /tmp/bigfile-restored.bin.gz
diff /tmp/bigfile.bin /tmp/bigfile-restored.bin && echo "文件一致"

rm -f /tmp/bigfile.part-* /tmp/bigfile-restored.bin.gz /tmp/bigfile.bin.gz

# === 方法 2：使用 tar 的分卷功能 ===
tar -czf - /tmp/bigfile.bin | split -b 10M - /tmp/bigfile-vol.tar.gz.
# 生成 bigfile-vol.tar.gz.aa, bigfile-vol.tar.gz.ab ...

# 恢复
cat /tmp/bigfile-vol.tar.gz.* | tar -xzf - -C /tmp/restored/
ls -lh /tmp/restored/

# === 方法 3：使用 7z 的分卷功能（最优雅）===
7z a -v10m /tmp/bigfile.7z /tmp/bigfile.bin
# 生成 bigfile.7z.001, bigfile.7z.002 ...

# 解压（7z 自动识别分卷）
7z x /tmp/bigfile.7z.001 -o/tmp/restored-7z/

# === 方法 4：zip 分卷 ===
zip -s 10m /tmp/bigfile.zip /tmp/bigfile.bin

rm -f /tmp/bigfile.bin /tmp/bigfile.bin.gz /tmp/bigfile.part-* \
      /tmp/bigfile-vol.tar.gz.* /tmp/bigfile.7z.* /tmp/bigfile.zip \
      /tmp/bigfile-restored.bin
rm -rf /tmp/restored /tmp/restored-7z
```

### 6.5 自解压脚本（Self-Extracting Archive）

你可以创建一个包含压缩数据的 Shell 脚本，在运行时自动解压。这在分发软件时非常方便（类似 `.run` 安装程序）：

```bash
# 创建自解压脚本
cat > /tmp/create-self-extract.sh << 'SCRIPTEOF'
#!/bin/bash
# 创建自解压脚本

# 1. 创建压缩包
mkdir -p /tmp/selfextract-payload
echo "This is file 1" > /tmp/selfextract-payload/README.txt
echo "This is file 2" > /tmp/selfextract-payload/INSTALL.txt
tar -czf /tmp/payload.tar.gz -C /tmp/selfextract-payload .

# 2. 将压缩数据编码为文本
PAYLOAD_BASE64=$(base64 /tmp/payload.tar.gz)

# 3. 生成自解压脚本
cat > /tmp/myapp-installer.sh << EOF
#!/bin/bash
# 自解压安装脚本
# 用法: bash myapp-installer.sh [目标目录]

TARGET_DIR="\${1:-/tmp/myapp}"
echo "正在解压到: \$TARGET_DIR"

mkdir -p "\$TARGET_DIR"

# 提取嵌入的压缩数据
ARCHIVE=\$(mktemp /tmp/selfextract-XXXXXX.tar.gz)
base64 -d << 'PAYLOAD' > "\$ARCHIVE"
$PAYLOAD_BASE64
PAYLOAD

# 解压
tar -xzf "\$ARCHIVE" -C "\$TARGET_DIR"
rm -f "\$ARCHIVE"

echo "解压完成！文件位于: \$TARGET_DIR"
ls -la "\$TARGET_DIR"
EOF

chmod +x /tmp/myapp-installer.sh
echo "自解压脚本已创建: /tmp/myapp-installer.sh"
SCRIPTEOF

bash /tmp/create-self-extract.sh

# 测试自解压脚本
bash /tmp/myapp-installer.sh /tmp/test-extract
# 输出：
# 正在解压到: /tmp/test-extract
```

> **本章小结：**
>
> 1. **归档**（用 tar 把多个文件合并为一个）和**压缩**（用算法缩小体积）是两个独立概念，tar 通过 `-z`/`-j`/`-J`/`--zstd` 将两者结合
> 2. **压缩算法选型**：xz（体积最小，速度慢）→ bzip2（折中）→ gzip（最通用）→ zstd（速度最快，现代场景首选）→ zip（跨平台）
> 3. **tar 的核心**：`c`（创建）、`x`（提取）、`t`（列出）、`f`（文件）——必须包含 `f` 且它是最后一个选项
> 4. **三个强大标志**：`--exclude`（选择性打包）、`--strip-components`（路径剥离）、`-C`（目录切换，可多次使用）
> 5. **透明浏览**：zcat/zgrep/zless 让你无需解压即可查看和搜索压缩文件，大幅提升效率
> 6. **日常备份**：`tar -czf backup-$(date +%Y%m%d).tar.gz --exclude='pattern' /target/dir`
