## 1. 概述

### 1.1 从"管理硬件"到"管理软件"

第 26 章和第 27 章你深入了 Linux 的存储底层——传统分区、LVM 弹性卷、文件系统对比。这些是"让系统跑起来"的基础设施。现在，你需要转向另一个核心维度：**软件本身**。

- "怎么在 Ubuntu 上安装一个软件？不是双击 .exe，那该用什么？"
- "系统提示有 347 个软件包可以更新——我应该全部更新吗？会不会把系统更崩了？"
- "想安装 nginx 1.26，但 apt 默认只有 1.24——怎么拿到新版本？"
- "删了一个软件，它留下的配置文件、日志、缓存怎么清理干净？"
- "某个包升级后服务挂了，怎么锁定版本不让它更新？"
- "有没有像手机应用商店一样的东西，一键安装、自动更新？"
- "下载了一个 .deb 文件——怎么装？"

这些问题的核心是**软件包管理（Package Management）**——现代 Linux 发行版最基础也最高频的系统管理操作。无论你从事运维、开发还是安全，每天都会与包管理器打交道。

### 1.3 本章覆盖的命令与概念

| 类别 | 命令/概念 | 用途 |
|------|----------|------|

## 2. 核心概念

### 2.1 从源码编译到软件包管理：一段简史

在理解 apt 和 dpkg 之前，先回顾 Linux 软件分发的演进过程。这能帮你理解"为什么需要包管理器"。

```
+------------------------------------------------------------------+
|                   Linux 软件分发方式的演进                           |
|                                                                  |
|  阶段 1：源码分发（1990s 初期）                                     |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  $ wget https://example.com/program-1.0.tar.gz               │ |
|  │  $ tar xzf program-1.0.tar.gz                                │ |
|  │  $ cd program-1.0                                            │ |
|  │  $ ./configure                                               │ |
|  │  $ make                    ← 编译可能需要几十分钟               │ |
|  │  $ sudo make install                                          │ |
|  │                                                              │ |
|  │  痛点：编译慢、依赖手动解决、卸载困难（make uninstall 不可靠）    │ |
|  │  "这个程序需要 libfoo >= 2.1，但系统上只有 1.3——去哪下载？"      │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              ▼                                    |
|  阶段 2：预编译二进制 + 简单打包（1990s 中期）                       |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  .deb / .rpm 诞生：预编译的二进制文件 + 元数据 + 安装脚本       │ |
|  │  $ dpkg -i program_1.0_amd64.deb                             │ |
|  │                                                              │ |
|  │  进步：无需编译，安装秒级完成                                   │ |
|  │  新痛点：dpkg 不管依赖——"这个包需要 libfoo，但你没装" → 装不了   │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              ▼                                    |
|  阶段 3：高级包管理器（2000s 至今）                                 |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  APT / YUM / DNF：自动解析依赖、从远程仓库下载、处理冲突         │ |
|  │  $ apt install nginx                                         │ |
|  │  → 自动查找依赖 → 下载所有需要的包 → 按顺序安装 → 完成           │ |
|  │                                                              │ |
|  │  这一层的本质：在 dpkg 之上建立依赖解析和远程下载能力             │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              ▼                                    |
|  阶段 4：容器化 / 沙箱化分发（2010s 至今）                          |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  Snap / Flatpak / AppImage：自带所有依赖，与系统隔离              │ |
|  │  $ snap install vlc                                          │ |
|  │  → 下载一个包含所有依赖的 squashfs 镜像 → 挂载运行               │ |
|  │                                                              │ |
|  │  解决："系统库版本太旧"和"不同应用的依赖冲突"                     │ |
|  └──────────────────────────────────────────────────────────────┘ |
+------------------------------------------------------------------+
```

### 2.2 deb 体系 vs RPM 体系：两大阵营对比

Linux 世界有两大主流包格式阵营。理解它们的差异对跨发行版工作至关重要。

```
+------------------------------------------------------------------+
|                    deb 阵营 vs RPM 阵营                             |
|                                                                  |
|   deb（Debian 系）               RPM（Red Hat 系）                 |
|  ┌─────────────────────┐       ┌─────────────────────┐           |
|  │  软件包格式：.deb    │       │  软件包格式：.rpm    │           |
|  │  底层工具：dpkg      │       │  底层工具：rpm       │           |
|  │  高级工具：apt       │       │  高级工具：yum/dnf   │           |
|  └─────────────────────┘       └─────────────────────┘           |
|          │                              │                        |
|  ┌───────┴──────────┐         ┌────────┴──────────┐              |
|  │ Debian           │         │ RHEL / CentOS     │              |
|  │ Ubuntu / Mint    │         │ Fedora            │              |
|  │ Kali / Parrot    │         │ Rocky / AlmaLinux │              |
|  │ Raspberry Pi OS  │         │ openSUSE (.rpm)   │              |
|  │ Deepin / UOS     │         │ Amazon Linux      │              |
|  └──────────────────┘         └───────────────────┘              |
+------------------------------------------------------------------+
```

**deb 与 RPM 的核心差异：**

| 对比维度 | deb（Debian/Ubuntu） | RPM（RHEL/Fedora） |
|---------|---------------------|-------------------|
| **包格式** | `.deb`（ar 归档，含 data.tar 和 control.tar） | `.rpm`（cpio 归档，含 RPM Header） |
| **底层工具** | `dpkg` | `rpm` |
| **依赖解析** | APT（Advanced Package Tool） | YUM（已过时）/ DNF（Fedora/RHEL 8+）/ Zypper（openSUSE） |
| **仓库元数据** | `Packages.gz` / `InRelease` | `repodata/` 目录（XML 格式） |
| **配置文件管理** | debconf（交互式配置） | 无内置等效，通常手动编辑 |
| **包名约定** | `name_version_arch.deb`（如 `nginx_1.24.0_amd64.deb`） | `name-version-release.arch.rpm`（如 `nginx-1.24.0-1.el9.x86_64.rpm`） |
| **命令风格** | `apt install pkg` | `dnf install pkg` |
| **发行版数量** | ~130 个活跃发行版 | ~60 个活跃发行版 |
| **市场份额（服务器）** | ~30%（含 Ubuntu Server） | ~50%（含 RHEL + CentOS 衍生版） |
| **学习曲线** | 较平缓（apt 命令更简洁） | 稍陡（dnf 选项更丰富但更复杂） |

**关键认识：不管是 deb 还是 RPM，现代包管理器都解决同一组问题——安装、升级、依赖解析、卸载、验证。** 学好一个体系后，切换到另一个体系的迁移成本很低。本章聚焦于 deb 体系（因为 Ubuntu 属于 Debian 家族），但核心概念是通用的。

### 2.3 Debian 软件包生态的三层架构

Ubuntu 的包管理建立在 Debian 的成熟架构上，分为三层：

```
+------------------------------------------------------------------+
|                    Debian 包管理体系三层架构                        |
|                                                                  |
|  第三层：APT（Advanced Package Tool）—— 用户交互层                  |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  apt / apt-get / aptitude / synaptic（GUI）                  │ |
|  │  - 从远程仓库下载包索引                                       │ |
|  │  - 解析依赖关系（Dependency Resolution）                      │ |
|  │  - 自动解决冲突和版本约束                                     │ |
|  │  - 调用 dpkg 执行实际的安装和卸载                             │ |
|  │  - 用户 99% 的时间在这一层操作                                │ |
|  └─────────────────────────────────────┬────────────────────────┘ |
|                                        │ 调用                      |
|  第二层：dpkg —— 底层包操作工具                                    |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  dpkg                                                        │ |
|  │  - 解包 .deb 文件，将文件安装到系统目录                       │ |
|  │  - 执行安装前/后脚本（preinst / postinst）                    │ |
|  │  - 维护已安装包的数据库（/var/lib/dpkg/status）               │ |
|  │  - 不理解"仓库"和"依赖解析"——只做本地的包操作                  │ |
|  └─────────────────────────────────────┬────────────────────────┘ |
|                                        │ 读写                      |
|  第一层：.deb 文件 —— 物理包格式                                   |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  .deb 包文件（ar 归档格式）                                    │ |
|  │  ├── debian-binary    （格式版本：2.0）                        │ |
|  │  ├── control.tar.xz   （包元数据：名称、版本、依赖、维护者）    │ |
|  │  └── data.tar.xz      （实际文件：二进制、配置、文档、man）     │ |
|  └──────────────────────────────────────────────────────────────┘ |
+------------------------------------------------------------------+
```

**理解三层关系的关键：**

- **.deb 文件**是"货物"——静态的、可传输的软件包
- **dpkg** 是"搬运工"——把 .deb 里的文件放到系统中，记录放了什么
- **APT** 是"调度中心"——知道去哪里取货（仓库），需要取什么配件（依赖），按什么顺序组装

当你执行 `apt install nginx` 时，完整的数据流是：

```
apt install nginx
  → 1. 从 /etc/apt/sources.list 找到仓库地址
  → 2. 从缓存中查找 nginx 的信息（如果缓存过期则先 apt update）
  → 3. 解析 nginx 的依赖树（nginx 依赖 nginx-core、libc6、libssl3...）
  → 4. 检查哪些依赖已安装、哪些需要下载
  → 5. 下载所有需要的 .deb 文件到 /var/cache/apt/archives/
  → 6. 按依赖顺序调用 dpkg --unpack 解包
  → 7. 调用 dpkg --configure 执行安装后脚本
  → 8. 完成
```

### 2.4 APT 仓库与软件源

**仓库（Repository）** 是 APT 体系的核心概念。它是一个包含大量 .deb 包及其索引的服务端目录。

```
+------------------------------------------------------------------+
|                    APT 仓库的组成                                   |
|                                                                  |
|  http://archive.ubuntu.com/ubuntu/                                |
|  ├── dists/                                                      |
|  │   └── noble/           ← 发行版代号（Ubuntu 24.04 = noble）     |
|  │       ├── main/        ← 官方支持的自由软件（Canonical 维护）    |
|  │       │   ├── binary-amd64/                                    |
|  │       │   │   ├── Packages.gz    ← 包列表索引（核心文件）       |
|  │       │   │   └── Release        ← 此组件的元数据和校验和       |
|  │       │   └── source/            ← 源码包                      |
|  │       ├── universe/    ← 社区维护的自由软件                     |
|  │       ├── multiverse/  ← 非自由软件（版权或许可限制）            |
|  │       ├── restricted/  ← 官方支持的非自由驱动                   |
|  │       ├── noble-updates/       ← 推荐更新（稳定版修复）         |
|  │       ├── noble-security/      ← 安全更新                      |
|  │       └── noble-backports/     ← 从新版本回溯的功能更新         |
|  └── pool/                 ← 所有 .deb 文件的实际存放位置           |
+------------------------------------------------------------------+
```

**五大组件（Components）**：

| 组件 | 全称 | 含义 | 维护方 | 是否默认启用 |
|------|------|------|--------|------------|
| **main** | Main | 官方支持的自由软件 | Canonical | 是 |
| **universe** | Universe | 社区维护的自由软件 | 社区 | 是 |
| **multiverse** | Multiverse | 非自由软件（许可限制） | 社区 | 否（需手动启用） |
| **restricted** | Restricted | 官方支持的非自由驱动 | Canonical | 是 |
| **backports** | Backports | 从新版本回溯的功能 | 社区 | 否 |

**仓库类型（按用途）**：

| 仓库类型 | 后缀示例 | 说明 | 更新频率 |
|---------|---------|------|---------|
| **发行版仓库** | `noble` | 发行版发布时的原始软件包，版本固定不变 | 几乎不变（仅关键修复） |
| **安全更新** | `noble-security` | 安全漏洞修复 | 发现 CVE 时立即更新 |
| **推荐更新** | `noble-updates` | 非关键的 bug 修复和稳定性改进 | 按需发布 |
| **回溯更新** | `noble-backports` | 从后续版本中挑选的较新软件版本 | 不定期 |
| **合作伙伴** | `noble-partner` | Canonical 合作伙伴提供的专有软件 | 按需 |

### 2.5 软件包的生命周期

一个软件包从进入你的视野到最终被清理，会经历一个完整的生命周期：

```
+------------------------------------------------------------------+
|                   .deb 软件包完整生命周期                          |
|                                                                  |
|  ┌────────┐                                                      |
|  │ 搜索发现 │  apt search keyword                                 |
|  └───┬────┘                                                      |
|      ▼                                                          |
|  ┌────────┐                                                      |
|  │ 查看详情 │  apt show pkgname                                   |
|  └───┬────┘                                                      |
|      ▼                                                          |
|  ┌────────┐                                                      |
|  │ 安装软件 │  apt install pkgname         ← 下载 + 解包 + 配置    |
|  └───┬────┘                                                      |
|      ▼                                                          |
|  ┌────────┐                                                      |
|  │ 正常使用 │  软件处于"已安装"状态（installed）                     |
|  └───┬────┘                                                      |
|      │                                                          |
|      ├────→ ┌──────────┐                                         |
|      │      │ apt update │  定期更新包索引                         |
|      │      │ apt upgrade│  升级到新版本                           |
|      │      └───────────┘                                         |
|      │                                                          |
|      ├────→ ┌──────────┐                                         |
|      │      │ apt-mark  │  锁定版本（hold）→ 跳过升级               |
|      │      │ hold pkg  │                                         |
|      │      └───────────┘                                         |
|      │                                                          |
|      ▼                                                          |
|  ┌────────┐                                                      |
|  │ 卸载软件 │  apt remove pkgname          ← 删除二进制，保留配置   |
|  │ 或彻底  │  apt purge pkgname           ← 删除二进制 + 配置文件  |
|  └───┬────┘                                                      |
|      ▼                                                          |
|  ┌────────┐                                                      |
|  │ 清理残留 │  apt autoremove              ← 移除不再需要的依赖     |
|  │        │  apt autoclean                ← 清理缓存的 .deb 文件  |
|  └────────┘                                                      |
+------------------------------------------------------------------+
```

### 2.6 软件包命名规范

理解 .deb 包的命名规则有助于快速识别包的版本和适用架构：

```
nginx_1.24.0-2ubuntu1_amd64.deb
│     │        │          │
│     │        │          └── 架构（Architecture）：amd64, i386, arm64, all
│     │        └── Debian 修订号（-2ubuntu1 表示 Ubuntu 基于 Debian 的第 2 次修改）
│     └── 上游版本号（Upstream Version）
└── 软件包名称（Package Name）
```

**架构类型：**

| 架构标识 | 含义 |
|---------|------|
| `amd64` | 64 位 x86（Intel/AMD 处理器） |
| `i386` | 32 位 x86 |
| `arm64` | 64 位 ARM（树莓派 4/5、Apple Silicon 等） |
| `armhf` | 32 位 ARM（硬浮点） |
| `all` | 平台无关（纯脚本、文档、数据文件） |
| `source` | 源代码包 |

## 3. 命令详解

### 3.1 apt update —— 更新软件包索引

#### 3.1.1 功能

`apt update` 从 `/etc/apt/sources.list` 和 `/etc/apt/sources.list.d/` 中配置的所有仓库下载最新的软件包索引（Packages 文件），更新本地缓存（`/var/lib/apt/lists/`）。

> **关键理解**：`apt update` **不安装任何软件包、不升级任何东西**。它只是刷新"软件目录"。可以把它理解为"刷新应用商店的软件列表"——你看到了新版本，但还没点"更新"按钮。

#### 3.1.2 参数说明

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-y, --yes` | 自动回答 yes（很少用于 update，因为通常不需要交互） | 可选 | 交互式 |
| `-q, --quiet` | 减少输出信息 | 可选 | 正常输出 |
| `--no-download` | 仅验证索引文件不下载 | 可选 | 下载 |
| `--print-uris` | 仅打印将要下载的 URI，不实际下载 | 可选 | 实际下载 |

#### 3.1.3 基本用法

```bash
# 更新软件包索引
sudo apt update

# 输出示例：
# Hit:1 http://security.ubuntu.com/ubuntu noble-security InRelease
# Hit:2 http://archive.ubuntu.com/ubuntu noble InRelease
# Hit:3 http://archive.ubuntu.com/ubuntu noble-updates InRelease
# Hit:4 http://archive.ubuntu.com/ubuntu noble-backports InRelease
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# 13 packages can be upgraded. Run 'apt list --upgradable' to see them.

# 输出解读：
# Hit   = 命中缓存（服务器上的索引和本地一样，不需要重新下载）
# Get   = 需要下载（服务器的索引比本地新）
# Ign   = 忽略（仓库无法访问或配置了跳过）
# 最后一行 → 有 13 个软件包可以升级
```

```bash
# 更新后查看可升级的包
apt list --upgradable

# 输出示例：
# Listing... Done
# libc6/noble-updates 2.39-0ubuntu8.3 amd64 [upgradable from: 2.39-0ubuntu8.2]
# openssh-client/noble-updates 1:9.6p1-3ubuntu13.5 amd64 [upgradable from: 1:9.6p1-3ubuntu13.3]
# python3-urllib3/noble-updates 2.2.1-1ubuntu0.24.04.1 all [upgradable from: 2.2.1-1]
```

### 3.2 apt upgrade —— 升级已安装的软件包

#### 3.2.1 功能

`apt upgrade` 将系统中所有已安装的软件包升级到仓库中的最新版本。它是**非破坏性**的——不会删除任何已安装的包，也不会安装新的依赖（如果这意味着要删除其他包）。

#### 3.2.2 参数说明

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-y, --yes` | 自动确认升级（跳过 "[Y/n]" 提示） | 可选 | 交互式确认 |
| `-s, --simulate` | 模拟升级，显示操作但不执行 | 可选 | 实际执行 |
| `--dry-run` | 同 --simulate | 可选 | 实际执行 |
| `--only-upgrade` | 仅升级指定包（而非全部） | 可选 | 升级所有 |

#### 3.2.3 基本用法

```bash
# 模拟升级（安全——只显示会发生什么，不实际操作）
apt list --upgradable
apt upgrade --simulate

# 输出示例：
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# Calculating upgrade... Done
# The following packages will be upgraded:
#   libc6 libc-bin locales openssh-client python3-urllib3
# 5 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
# Inst libc6 [2.39-0ubuntu8.2] (2.39-0ubuntu8.3 Ubuntu:24.04/noble-updates [amd64])
# ...

# 实际升级（推荐先做 --simulate）
sudo apt upgrade

# 输出示例：
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# Calculating upgrade... Done
# The following packages will be upgraded:
#   libc6 libc-bin locales
# 3 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
# Need to get 5,234 kB of archives.
# After this operation, 12.3 kB of additional disk space will be used.
# Do you want to continue? [Y/n] y
# Get:1 http://archive.ubuntu.com/ubuntu noble-updates/main amd64 libc6 ...
# ...
# Setting up libc6 (2.39-0ubuntu8.3) ...
# Processing triggers for libc-bin ...
```

```bash
# 只升级特定软件包
sudo apt install --only-upgrade nginx

# 等价写法
sudo apt upgrade nginx
```

#### 3.2.4 upgrade vs full-upgrade 的关键区别

```
+------------------------------------------------------------------+
|             apt upgrade  vs  apt full-upgrade                     |
|                                                                  |
|  apt upgrade（保守升级）：                                        |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  - 只升级已安装的包                                           │ |
|  │  - 不删除任何已安装的包                                       │ |
|  │  - 不安装新的依赖（如果新版本需要新的依赖 → 此包被"保留"）      │ |
|  │  - 安全的日常操作                                             │ |
|  │  → 适合：日常维护、生产服务器自动更新                           │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                                                                  |
|  apt full-upgrade（激进升级，旧称 dist-upgrade）：                  |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  - 升级所有已安装的包                                         │ |
|  │  - 如果需要，会删除冲突的旧包                                  │ |
|  │  - 如果需要，会安装新的依赖                                    │ |
|  │  - 智能处理依赖变更（如 libfoo1 → libfoo2 的替换）             │ |
|  │  → 适合：大版本升级、发行版升级前的包刷新                       │ |
|  └──────────────────────────────────────────────────────────────┘ |
+------------------------------------------------------------------+
```

```bash
# 场景：某个包的升级需要移除旧依赖并安装新依赖
# apt upgrade 会"保留"该包不升级，输出类似：
# The following packages have been kept back:
#   python3-numpy

# 这时需要用 full-upgrade 来处理
sudo apt full-upgrade

# 输出示例（正常情况，没有 kept back 的包时两者输出基本一致）：
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# Calculating upgrade... Done
# 0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
```

> **生产环境建议**：日常使用 `apt upgrade`。只有当看到 "kept back"（被保留）的包时，才手动调查后用 `apt full-upgrade` 解决。

### 3.3 apt install —— 安装软件包

#### 3.3.1 功能

安装一个或多个软件包，自动解析并安装所有依赖。

#### 3.3.2 参数说明

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `PKG...` | 要安装的软件包名称（可同时指定多个） | 必选 | - |
| `-y, --yes` | 自动确认安装 | 可选 | 交互式确认 |
| `-s, --simulate` | 模拟安装 | 可选 | 实际执行 |
| `--no-install-recommends` | 不安装推荐的（Recommends）包，只安装必需的依赖 | 可选 | 安装推荐包 |
| `--install-suggests` | 同时安装建议的（Suggests）包 | 可选 | 不安装建议包 |
| `--reinstall` | 重新安装已安装的包（覆盖被修改的文件） | 可选 | 跳过已安装的 |
| `--only-upgrade` | 仅升级指定包（不新装） | 可选 | 安装或升级 |
| `-f, --fix-broken` | 尝试修复断裂的依赖关系 | 可选 | 不修复 |

#### 3.3.3 基本用法

```bash
# 安装单个软件包
sudo apt install nginx

# 输出示例：
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# The following additional packages will be installed:
#   nginx-common nginx-core
# Suggested packages:
#   fcgiwrap nginx-doc
# The following NEW packages will be installed:
#   nginx nginx-common nginx-core
# 0 upgraded, 3 newly installed, 0 to remove and 0 not upgraded.
# Need to get 542 kB of archives.
# After this operation, 1,892 kB of additional disk space will be used.
# Do you want to continue? [Y/n] y
```

```bash
# 同时安装多个包
sudo apt install -y vim git curl htop

# 安装本地 .deb 文件（APT 会自动解决依赖）
sudo apt install ./package_1.0_amd64.deb
# 注意：必须用 ./ 前缀或绝对路径，否则 apt 会把它当成仓库里的包名
```

```bash
# 不安装推荐包（减小安装体积，适合容器/精简系统）
sudo apt install --no-install-recommends nginx

# 对比：
# 默认安装：nginx + nginx-common + nginx-core
# --no-install-recommends：可能只安装 nginx + nginx-core（跳过文档、示例等）
```

```bash
# 重新安装（覆盖被意外修改或损坏的文件）
sudo apt install --reinstall nginx
```

#### 3.3.4 依赖层级

APT 将依赖分为三个层级：

```
Package: nginx
Depends: nginx-core (>= 1.24.0) | nginx-full (>= 1.24.0),
         libc6 (>= 2.38), libssl3t64 (>= 3.0.0)
Recommends: nginx-doc (= 1.24.0)
Suggests: fcgiwrap
```

| 层级 | 含义 | 默认行为 |
|------|------|---------|
| **Depends** | 强依赖——没有它软件根本跑不起来 | 必须安装 |
| **Recommends** | 推荐——通常需要但不是必须的（如文档、辅助工具） | 默认安装（可用 `--no-install-recommends` 跳过） |
| **Suggests** | 建议——锦上添花的功能增强 | 不安装（可用 `--install-suggests` 启用） |
| **Conflicts** | 冲突——不能与该包同时安装 | 安装时会提示卸载冲突包 |
| **Breaks** | 破坏——会导致该包功能不正常 | 安装时会提示升级或卸载 |
| **Replaces** | 替代——该包替代另一个包的文件 | - |
| **Provides** | 虚拟包——该包提供某个虚拟包的功能 | 用于满足其他包的依赖 |

### 3.4 apt remove、purge 与 autoremove —— 删除与清理

#### 3.4.1 功能对比

```
+------------------------------------------------------------------+
|                    remove / purge / autoremove 的区别              |
|                                                                  |
|  apt remove pkgname：                                            |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  删除二进制文件和库，但保留 /etc 下的配置文件                    │ |
|  │  下次重新安装时，之前的配置会自动生效                           │ |
|  │  适合：暂时卸载，保留配置以便将来恢复                           │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                                                                  |
|  apt purge pkgname：                                             |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  删除二进制 + 配置文件 + 数据目录（全清）                       │ |
|  │  注意：/home 下的用户个人配置不会被删除                        │ |
|  │  适合：彻底卸载，不留下任何痕迹                                │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                                                                  |
|  apt autoremove：                                                 |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  删除"不再需要的"自动安装的依赖包                              │ |
|  │  这些包是因为其他包的依赖而被安装的，现在没有包需要它们了        │ |
|  │  适合：清理系统，回收磁盘空间                                  │ |
|  └──────────────────────────────────────────────────────────────┘ |
+------------------------------------------------------------------+
```

#### 3.4.2 参数说明

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `PKG...` | 要删除的软件包名称 | 必选 | - |
| `-y, --yes` | 自动确认 | 可选 | 交互式 |
| `-s, --simulate` | 模拟删除 | 可选 | 实际执行 |
| `--purge` | 同时删除配置文件（等价于 purge） | 可选 | 仅 remove |
| `--autoremove` | 同时删除不再需要的依赖 | 可选 | 仅删除指定包 |

#### 3.4.3 基本用法

```bash
# 示例：先安装一个包来练习删除
sudo apt install -y hello

# 1. 普通卸载（保留配置文件）
sudo apt remove hello

# 输出示例：
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# The following packages will be REMOVED:
#   hello
# 0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
# After this operation, 287 kB disk space will be freed.
# Do you want to continue? [Y/n] y

# 验证配置文件是否保留
dpkg -l hello
# 输出：
# rc  hello  2.12.1-4  amd64  ...
#     ^^
#     状态 rc = removed but config files remain（已删除但配置文件保留）
```

```bash
# 2. 彻底清除（删除配置文件）
sudo apt purge hello

# 等价于
sudo apt remove --purge hello

# 验证
dpkg -l hello
# 输出：
# dpkg-query: no packages found matching hello  ← 彻底清除了

# purge 也会删除系统级配置：
# /etc/hello/ 下的配置文件将被删除
# 但 /home/user/.hello/ 下的用户配置不会被删除（dpkg 不管理用户家目录）
```

```bash
# 3. 清理不再需要的依赖
# 场景：安装 tree 时自动装了 libtree-perl，卸载 tree 后 libtree-perl 就没用了
sudo apt install -y tree
sudo apt remove tree           # 只删 tree，libtree-perl 还在
sudo apt autoremove            # 自动检测并删除孤立的依赖

# 输出示例：
# Reading package lists... Done
# Building dependency tree... Done
# Reading state information... Done
# The following packages will be REMOVED:
#   libtree-perl
# 0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
# After this operation, 1,024 kB disk space will be freed.
# Do you want to continue? [Y/n] y

# 一条命令完成删除+清理
sudo apt remove --autoremove tree
```

#### 3.4.4 dpkg 状态标识

`dpkg -l` 输出的前两列表示软件包的"期望状态"和"当前状态"：

```
dpkg -l | head -5

输出：
|| 名称             | 版本      | 架构   | 描述
+++-================-===========-========-==============
ii  adduser          3.137ubuntu all      add and remove users and groups
ii  apt              2.7.14     amd64     commandline package manager
rc  hello            2.12.1-4   amd64     example package
```

| 状态码 | 含义 | 说明 |
|--------|------|------|
| `ii` | install ok installed | 已正确安装 |
| `rc` | remove ok config-files | 已卸载但配置文件保留 |
| `iU` | install ok unpacked | 已解包但未配置（安装中断） |
| `iF` | install ok half-configured | 配置一半失败（安装出错） |
| `pn` | purge ok not-installed | 已彻底清除 |

### 3.6 apt edit-sources —— 编辑软件源

#### 3.6.1 功能

`apt edit-sources` 用系统的默认文本编辑器打开 `/etc/apt/sources.list` 文件进行编辑。编辑完成后会自动验证语法。

#### 3.6.2 基本用法

```bash
# 编辑主源配置文件（需要 root 权限）
```


**配置行格式：**

```
deb   [选项]  URI  发行版代号  组件1  组件2  ...
│      │      │       │         └── main, universe, restricted, multiverse
│      │      │       └── noble, noble-updates, noble-security...
│      │      └── http://archive.ubuntu.com/ubuntu/

```

### 3.7 apt-get 与 apt-cache —— 传统 APT 命令

#### 3.7.1 apt vs apt-get vs apt-cache

从 Ubuntu 16.04 开始，`apt` 命令作为用户友好的前端被引入，整合了 `apt-get` 和 `apt-cache` 的常用功能。三者的关系如下：

```
+------------------------------------------------------------------+
|                apt / apt-get / apt-cache 关系图                    |
|                                                                  |
|  ┌──────────────────────────────────────────────────────────┐    |
|  │                         apt                               │    |
|  │  面向最终用户的统一前端（彩色输出、进度条、更友好的提示）      │    |
|  │  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐    │    |
```

#### 3.7.2 apt-get 常用操作

```bash
# apt-get 的等效命令（与 apt 对比）

# 更新索引
sudo apt-get update                # = sudo apt update

# 升级软件包
sudo apt-get upgrade               # = sudo apt upgrade
sudo apt-get dist-upgrade          # = sudo apt full-upgrade

# 安装
sudo apt-get install nginx         # = sudo apt install nginx

# 删除
sudo apt-get remove nginx          # = sudo apt remove nginx

# 修复断裂的依赖（apt 没有等价命令）
sudo apt-get -f install

# 下载 .deb 但不安装
apt-get download nginx             # 下载到当前目录
```

#### 3.7.3 apt-cache 常用操作

```bash
#   wget
#   openssh-client

#   curl

# 输出示例：
# nginx:
```

#### 3.7.4 脚本中的最佳实践

```bash
#!/bin/bash
# 在 Shell 脚本中使用 apt-get（而非 apt），因为 apt-get 的 CLI 接口更稳定

# 更新
sudo apt-get update -qq
# -qq = 超级安静（只输出错误）

    echo "WARNING: System reboot required"

# 安装包
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -qq nginx

# 清理
sudo apt-get autoremove -y -qq
sudo apt-get autoclean -qq
```

### 3.8 dpkg —— 底层软件包操作

dpkg 是 deb 体系的基石。它直接操作 .deb 文件，不处理依赖、不知道仓库的存在。理解 dpkg 对于排错和深度管理至关重要。

#### 3.8.1 dpkg -i：安装 .deb 包

```bash
# 下载一个 .deb 文件
apt-get download hello

# 直接用 dpkg 安装（不自动处理依赖！）
sudo dpkg -i hello_*.deb

# 输出示例：
# Selecting previously unselected package hello.
# (Reading database ... 123456 files and directories currently installed.)
# Preparing to unpack hello_2.12.1-4_amd64.deb ...
# Unpacking hello (2.12.1-4) ...
# Setting up hello (2.12.1-4) ...

# 重要警告：如果 .deb 文件有依赖未满足，dpkg -i 会报错
# 这种情况下，使用 apt install ./package.deb 代替（apt 会自动解决依赖）
```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-i, --install DEB_FILE` | 安装指定的 .deb 文件 | 必选 | - |
| `-R, --recursive DIR` | 递归安装目录下所有 .deb | 可选 | - |
| `--force-*` | 强制安装（多种强制选项，危险） | 可选 | 正常模式 |
| `--dry-run` | 模拟安装 | 可选 | 实际安装 |

#### 3.8.2 dpkg -r 与 -P：卸载软件包

```bash
# 卸载但保留配置文件
sudo dpkg -r hello
# 等价于 apt remove hello

# 彻底清除（含配置文件）
sudo dpkg -P hello
# 等价于 apt purge hello
```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-r, --remove PKG` | 删除包但保留配置文件 | 必选 | - |
| `-P, --purge PKG` | 彻底删除含配置文件 | 必选 | - |

#### 3.8.3 dpkg -l：列出已安装的包

```bash
# 列出所有已安装的包
dpkg -l

# 输出示例（前几行）：
# || 名称             | 版本               | 架构    | 描述
# ++-================-===================-========-===========
# ii  adduser          3.137ubuntu1         all       add and remove users
# ii  apt              2.7.14build1         amd64     commandline package manager
# ii  apt-utils        2.7.14build1         amd64     package management related utility

# 搜索特定包（使用通配符）
dpkg -l 'nginx*'

# 输出示例：
# || 名称           | 版本                     | 架构   | 描述
# ++-===============-========================-========-=========
# ii  nginx          1.24.0-2ubuntu7.1         amd64    small, powerful...
# ii  nginx-common   1.24.0-2ubuntu7.1         all      ...common files
# ii  nginx-core     1.24.0-2ubuntu7.1         amd64    ...standard version

# 搜索包含特定名称的所有包
dpkg -l | grep -i python
```

#### 3.8.4 dpkg -L：列出包安装的文件

```bash
# 查看 nginx 包安装了哪些文件到系统中
dpkg -L nginx

# 输出示例：
# /.
# /usr
# /usr/share
# /usr/share/doc
# /usr/share/doc/nginx
# /usr/share/doc/nginx/copyright
# /usr/share/doc/nginx/changelog.Debian.gz
# ...

# 只显示配置文件
dpkg -L nginx | grep /etc/
# /etc
# /etc/nginx
# /etc/nginx/nginx.conf
# ...

# 排除目录，只显示文件
dpkg -L nginx | xargs file 2>/dev/null | grep -v directory
```

#### 3.8.5 dpkg -S：反向查找——文件属于哪个包

```bash
# 查找 /etc/nginx/nginx.conf 属于哪个包
dpkg -S /etc/nginx/nginx.conf

# 输出：
# nginx-common: /etc/nginx/nginx.conf

# 查找某个命令属于哪个包
dpkg -S $(which ls)
# dpkg-query: no path found matching pattern /usr/bin/ls
# ls 属于 coreutils，但它是通过某种方式安装的

# 如果 dpkg -S 找不到，用 apt-file（详见 3.13 节）
```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-S, --search PATTERN` | 查找包含指定文件的包 | 必选 | - |

#### 3.8.6 其他常用 dpkg 操作

```bash
# 查看包的状态（比 dpkg -l 更详细）
dpkg -s nginx
# 输出：Status, Package, Version, Depends, Conffiles, Description...

# 查看包中尚未安装的配置文件（如果有的话）
dpkg --audit

# 查看所有包的状态数据库
wc -l /var/lib/dpkg/status
# 输出：约 10-20 万行（记录了系统上所有包的信息）

# 重新配置已安装的包（触发 postinst 脚本）
sudo dpkg-reconfigure tzdata
# 这会重新运行 tzdata 的配置脚本，通常用于修改时区等设置

# 比较包中的文件与系统上实际文件的差异
dpkg --verify nginx
# 如果所有文件都没有被修改，则无输出
# 如果有文件被修改，显示类似：
# ??5?????? c /etc/nginx/nginx.conf
# （c = conffile, 5 = md5sum mismatch）
```

### 3.9 snap —— 沙箱化软件包管理

#### 3.9.1 snap 简介

**snap** 是 Canonical 公司开发的通用 Linux 软件包格式。与传统的 deb 包不同，snap 包是**自包含（Self-Contained）** 的——它将应用程序及其所有依赖打包成一个 squashfs 镜像，在沙箱中运行，与系统其他部分隔离。

```
+------------------------------------------------------------------+
|                    snap 与 deb 的架构差异                          |
|                                                                  |
|  deb 包方式：                                      snap 包方式：  |
|  ┌──────────────────────┐               ┌──────────────────────┐  |
|  │  应用 (nginx)        │               │  snap 容器（沙箱）     │  |
|  │    ↓                 │               │  ┌────────────────┐  │  |
|  │  依赖：libssl3       │               │  │ 应用 (vlc)      │  │  |
|  │  依赖：libc6         │               │  │ ↓              │  │  |
|  │  依赖：libpcre3      │               │  │ 自带 libssl3   │  │  |
|  │   ...                │               │  │ 自带 libc6     │  │  |
|  └──────┬───────────────┘               │  │ 自带 libpcre3  │  │  |
|         │                               │  │ 自带 所有依赖   │  │  |
|         ▼                               │  └────────────────┘  │  |
|  ┌──────────────────────┐               └──────────────────────┘  |
|  │  系统共享库           │               │                        │
|  │  /usr/lib/x86_64...  │               │  通过严格限制的接口      │
|  │  libssl3.so          │               │  访问系统资源            │
|  │  libc6.so            │               │  （interfaces）         │
|  └──────────────────────┘                                        |
|                                                                  |
|  优点：与系统库隔离，不冲突         优点：一次打包，到处运行          |
|  缺点：依赖地狱（Dependency Hell）   缺点：包体积大，启动稍慢         |
+------------------------------------------------------------------+
```

#### 3.9.2 snap 核心命令

**snap find —— 搜索 snap 包：**

```bash
# 按名称搜索
snap find vlc

# 输出示例：
# Name  Version        Publisher  Notes  Summary
# vlc   3.0.20         videolan✓  -      The ultimate media player

# 搜索开发工具
snap find "go"

# 列出所有可用的 snap（通常有几千个）
snap find | wc -l
```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `QUERY` | 搜索关键词 | 可选 | 返回全部 |
| `--private` | 同时搜索私有 snap | 可选 | 仅公开 snap |
| `--section SECTION` | 按分类过滤 | 可选 | 不过滤 |

**snap install —— 安装 snap 包：**

```bash
# 安装最新稳定版
sudo snap install vlc

# 输出示例：
# vlc 3.0.20 from VideoLAN✓ installed

# 安装特定通道（Channel）的版本
sudo snap install --channel=beta go
sudo snap install --channel=edge vlc

# 安装经典模式（允许完全系统访问，类似传统 deb 包）
sudo snap install --classic code
# --classic 用于 IDE、编辑器等需要访问整个文件系统的应用

# 模拟安装（不实际安装）
snap install --dry-run vlc
```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `SNAP_NAME` | snap 包名称 | 必选 | - |
| `--channel CHANNEL` | 指定通道（stable/candidate/beta/edge） | 可选 | stable |
| `--classic` | 经典模式（安全限制更少，类似 deb 包） | 可选 | strict 模式 |
| `--devmode` | 开发者模式（完全无安全限制） | 可选 | strict 模式 |
| `--dangerous` | 安装未签名的本地 snap 文件 | 可选 | 需要签名 |

**snap remove —— 卸载 snap 包：**

```bash
# 卸载
sudo snap remove vlc

# 输出示例：
# vlc removed

# 同时删除快照（snapshot）
sudo snap remove --purge vlc

# 批量卸载
sudo snap remove vlc firefox
```

**snap list —— 列出已安装的 snap：**

```bash
# 列出所有已安装的 snap
snap list

# 输出示例：
# Name      Version        Rev    Tracking       Publisher   Notes
# core      16-2.63        16928  latest/stable  canonical✓  core
# core22    20240408       1380   latest/stable  canonical✓  base
# firefox   125.0.2-1      4336   latest/stable  mozilla✓    -
# snapd     2.63           21759  latest/stable  canonical✓  snapd

# 按版本过滤
snap list --all
```

**snap refresh —— 更新 snap 包：**

```bash
# 手动刷新所有 snap
sudo snap refresh

# 输出示例：
# firefox 125.0.3-1 from Mozilla✓ refreshed
# snapd 2.63.1 from Canonical✓ refreshed

# 刷新特定 snap
sudo snap refresh firefox

# 查看即将更新的内容（不实际更新）
snap refresh --list

# snap 默认每天自动刷新 4 次（可通过配置修改）
# 查看下次自动刷新的时间
snap refresh --time
# 输出示例：
# timer: 00:00~24:00/4

# 暂停自动刷新（例如在生产服务器上）
sudo snap refresh --hold=72h firefox
# 暂停 72 小时
```

#### 3.9.3 snap 的其他常用操作

```bash
# 查看 snap 的详细信息
snap info vlc
# 输出：name, summary, publisher, license, channels, last-updated...

# 查看 snap 占用的磁盘空间
snap saved

# 创建快照（备份当前 snap 状态）
sudo snap save

# 回滚到上一个版本
sudo snap revert firefox
# 如果更新后出问题，秒级回滚

# 启用/禁用 snap（不用卸载）
sudo snap disable firefox
sudo snap enable firefox

# 查看 snap 的日志
snap logs firefox

# 查看 snap 的接口/权限
snap connections firefox
# 显示：firefox 可以访问摄像头、声音、网络等

# 管理 snap 权限
sudo snap connect firefox:camera           # 允许访问摄像头
sudo snap disconnect firefox:camera        # 禁止访问摄像头
```

### 3.10 flatpak —— 跨发行版的沙箱化应用

#### 3.10.1 flatpak 简介

**Flatpak** 是另一个通用 Linux 应用分发方案，由 freedesktop.org 社区维护。与 snap 类似，它也使用沙箱隔离技术，但设计理念更加去中心化——不绑定到任何单一厂商。

```
+------------------------------------------------------------------+
|                    snap vs Flatpak 对比                            |
|                                                                  |
|  特性            │  snap                    │  Flatpak            |
|  ───────────────┼──────────────────────────┼─────────────────────|
|  开发者          │  Canonical               │  freedesktop.org    |
|  后端/商店       │  Snap Store（闭源）       │  Flathub（开源）     |
|  包格式          │  .snap (squashfs)        │  .flatpakref / OCI  |
|  系统服务        │  snapd（独占）            │  flatpak（可选）     |
|  默认仓库        │  Canonical 控制           │  社区驱动，可自建    |
|  沙箱技术        │  AppArmor + seccomp      │  Bubblewrap + seccomp|
|  桌面集成        │  需要 GNOME 软件中心       │  与主流桌面深度集成   |
|  Ubuntu 支持     │  预装（桌面版）            │  需手动安装          |
|  运行时          │  core / core22           │  共享运行时          |
|  CLI 工具        │  snap                    │  flatpak            |
+------------------------------------------------------------------+
```

#### 3.10.2 安装与基本使用

```bash
# 1. 安装 Flatpak（Ubuntu 24.04）
sudo apt install -y flatpak

# 2. 安装 GNOME 软件中心的 Flatpak 插件（可选）
sudo apt install -y gnome-software-plugin-flatpak

# 3. 添加 Flathub 仓库（最主要的 Flatpak 应用商店）
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo

# 4. 重启系统或重新登录（让桌面环境识别 Flatpak）
# 或直接重启 GNOME Software
```

```bash
# 搜索应用
flatpak search gimp

# 安装应用
flatpak install flathub org.gimp.GIMP

# 运行应用
flatpak run org.gimp.GIMP

# 列出已安装的 Flatpak
flatpak list

# 更新所有 Flatpak
flatpak update

# 卸载应用
flatpak uninstall org.gimp.GIMP

# 清理不再需要的运行时
flatpak uninstall --unused
```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `REMOTE APP_ID` | 要安装的应用（如 flathub org.gimp.GIMP） | 必选 | - |
| `--user` | 仅对当前用户安装（不要求 sudo） | 可选 | 系统级安装 |
| `--system` | 对所有用户安装（需要 sudo） | 可选 | 默认 |
| `-y, --assumeyes` | 自动确认 | 可选 | 交互式确认 |

### 3.11 add-apt-repository 与 PPA 管理

#### 3.11.1 PPA 的概念

**PPA（Personal Package Archive，个人软件包存档）** 是 Canonical 的 Launchpad 平台提供的一项服务：允许任何开发者构建和分发 Ubuntu 软件包。PPA 让你能在官方仓库之外获取更新的软件版本或不包含在官方仓库中的软件。

```
+------------------------------------------------------------------+
|                    PPA 的工作原理                                   |
|                                                                  |
|  Launchpad（Canonical 的平台）                                     |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  ppa:nginx/stable                                            │ |
|  │  ┌────────────────────────────────────────────────────────┐  │ |
|  │  │  开发者上传源码 → Launchpad 自动编译为 .deb             │  │ |
|  │  │  → 为每个支持的 Ubuntu 版本生成对应包 → 发布到 PPA 仓库  │  │ |
|  │  └────────────────────────────────────────────────────────┘  │ |
|  │  生成的仓库 URL：                                              │ |
|  │  https://ppa.launchpadcontent.net/nginx/stable/ubuntu          │ |
|  │  ├── dists/noble/          ← 自动为 noble 编译               │ |
|  │  ├── dists/jammy/          ← 自动为 jammy 编译               │ |
|  │  └── dists/focal/          ← 自动为 focal 编译               │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              │                                     |
|                              ▼                                     |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  你的 Ubuntu 系统                                              │ |
|  │  /etc/apt/sources.list.d/                                     │ |
|  │  └── nginx-ubuntu-stable-noble.list                            │ |
|  │      deb https://ppa.launchpadcontent.net/nginx/stable/ubuntu  │ |
|  │      noble main                                                │ |
|  └──────────────────────────────────────────────────────────────┘ |
+------------------------------------------------------------------+
```

#### 3.11.2 add-apt-repository 的使用

```bash
# 添加 PPA
sudo add-apt-repository ppa:nginx/stable

# 输出示例：
# Repository: 'deb https://ppa.launchpadcontent.net/nginx/stable/ubuntu noble main'
# Description:
# Latest stable version of nginx.
# More info: https://launchpad.net/~nginx/+archive/ubuntu/stable
# Adding repository.

```

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `PPA` | PPA 标识符（格式：ppa:USER/NAME） | 必选 | - |

### 3.12 apt-mark —— 软件包版本锁定

#### 3.12.1 功能

`apt-mark` 用于标记软件包的状态，最重要的功能是 **hold（锁定版本）** 和 **unhold（取消锁定）**。

当你不想让某个包被 `apt upgrade` 升级时（例如：新版本有 Bug、需要保持特定版本以兼容其他软件、等运维窗口），使用 `apt-mark hold` 将包锁定。

#### 3.12.2 参数说明

| 命令 | 说明 |
|------|------|
| `apt-mark hold PKG` | 锁定软件包版本，禁止升级 |
| `apt-mark unhold PKG` | 取消锁定 |
| `apt-mark showhold` | 显示所有被锁定的包 |
| `apt-mark auto PKG` | 标记为"自动安装"（当依赖不再需要时会被 autoremove 清理） |
| `apt-mark manual PKG` | 标记为"手动安装"（防止被 autoremove 清理） |
| `apt-mark showauto` | 显示所有自动安装的包 |
| `apt-mark showmanual` | 显示所有手动安装的包 |

#### 3.12.3 基本用法

```bash
# 1. 锁定软件包（防止被升级）
sudo apt-mark hold nginx

# 输出：
# nginx set on hold.

# 2. 查看已锁定的包
apt-mark showhold

# 输出：
# nginx

# 3. 尝试升级——被锁定的包会被跳过
sudo apt upgrade --simulate
# 输出包含：
# The following packages have been kept back:
#   nginx

# 4. 取消锁定
sudo apt-mark unhold nginx

# 输出：
# Canceled hold on nginx.

# 5. 确认已取消
apt-mark showhold
# （无输出——没有包被锁定）
```

#### 3.12.4 使用场景

```bash
# 场景 1：Docker CE 升级到新版本后与现有容器不兼容
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
# 等容器都迁移到兼容新版本后再 unlock

# 场景 2：Kubernetes 集群要求所有节点使用相同版本的 kubelet
# 在升级整个集群之前，锁定版本
VERSION=1.29.0-1.1
sudo apt-mark hold kubelet kubeadm kubectl

# 场景 3：内核升级后某些硬件驱动有问题
uname -r
# 输出：6.8.0-31-generic
sudo apt-mark hold linux-image-6.8.0-31-generic
# 防止自动升级到有问题的内核

# 场景 4：批量管理
# 锁定某个源的所有包
apt-mark showhold
# 或查看哪些包被标记为"手动安装"
apt-mark showmanual | head -20
```

#### 3.12.5 apt-mark auto 与 manual——控制 autoremove 行为

```bash
# 查看包是"手动"还是"自动"安装的
apt-mark showmanual | grep nginx
apt-mark showauto | grep nginx

# 将包标记为"手动安装"（防止被 autoremove 自动删除）
# 场景：某个依赖你单独使用了，不想它被清理
sudo apt-mark manual libtree-perl

# 将包标记为"自动安装"
# 场景：错误标记为 manual 的依赖回归 auto，以便将来可以自动清理
sudo apt-mark auto libtree-perl
```

### 3.13 apt-file —— 按文件查找软件包

#### 3.13.1 功能

`apt-file` 是 `dpkg -S` 的升级版：它不仅能查找已安装的包，还能查找**仓库中所有可用的包**。当你在终端中遇到"command not found"时，`apt-file` 可以快速告诉你需要安装哪个包。

#### 3.13.2 安装与初始化

```bash
# 安装 apt-file
sudo apt install -y apt-file

# 首次使用需要建立索引（下载文件列表数据库，约需几分钟）
sudo apt-file update

# 输出示例：
# Downloading complete file http://archive.ubuntu.com/...
# ...
# apt-file: update completed successfully.
```

#### 3.13.3 基本用法

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `search PATTERN` | 搜索包含指定文件模式的包 | 必选 | - |
| `list PKG` | 列出指定包安装的所有文件 | 必选 | - |
| `update` | 更新文件列表数据库 | 必选 | - |
| `-x, --regexp` | 使用正则表达式匹配 | 可选 | 普通字符串 |
| `-i, --ignore-case` | 忽略大小写 | 可选 | 区分大小写 |
| `-l, --package-only` | 只显示包名，不显示文件路径 | 可选 | 完整路径 |
| `-a, --all` | 同时查找已安装和未安装的包 | 可选 | 默认行为 |
| `-F` | 按包名查找（仅用于 list） | 可选 | - |

```bash
# 场景 1："command not found"
# 遇到了一个命令，不知道需要装什么包
$ sdiff
# sdiff: command not found
apt-file search bin/sdiff
# 输出：
# diffutils: /usr/bin/sdiff
# → 需要安装 diffutils

# 场景 2：编译时缺少头文件
# fatal error: openssl/ssl.h: No such file or directory
apt-file search openssl/ssl.h
# 输出：
# libssl-dev: /usr/include/openssl/ssl.h
# → 需要安装 libssl-dev

# 场景 3：查找某个配置文件
apt-file search nginx.conf
# 输出：
# nginx-common: /etc/nginx/nginx.conf
# nginx-common: /usr/share/nginx/nginx.conf

# 场景 4：只输出包名
apt-file search -l bin/sdiff
# 输出：
# diffutils

# 场景 5：使用正则表达式
apt-file search -x '/bin/(sdiff|diff3)$'
```

```bash
# iostat 和 sar 属于同一个包
which iostat && echo "iostat 就绪"

# （5）dig
apt-file search -l bin/dig
# 输出：dnsutils（与 nslookup 同包）
# 已安装 dnsutils 的话直接可用
dig +short google.com
```

## 5. 常见错误与排错

### 5.1 错误：`Could not get lock /var/lib/dpkg/lock-frontend`

这是 Ubuntu 包管理最常遇到的错误。

```bash
# 症状：
sudo apt install something
# 错误：
# E: Could not get lock /var/lib/dpkg/lock-frontend. It is held by process 12345 (apt)
# E: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend),
#    is another process using it?

# 原因：有另一个 apt/dpkg 进程正在运行
# 常见触发场景：
# 1. 另一个终端正在运行 apt install/upgrade
# 2. 系统正在后台执行自动更新（unattended-upgrades）
# 3. GNOME Software / Snap Store 在后台检查更新
# 4. 之前的 apt 进程异常退出，锁文件未释放

# 排查：
# 查找占用锁的进程
sudo lsof /var/lib/dpkg/lock-frontend
# 或
sudo fuser /var/lib/dpkg/lock-frontend

# 查找所有 apt/dpkg 相关进程
ps aux | grep -E 'apt|dpkg' | grep -v grep

# 解决方法（按安全程度排序）：
# 方法 1：等待其他 apt 进程完成（推荐）
# 如果是不重要的后台更新，等它完成即可

# 方法 2：终止卡住的进程
sudo kill 12345       # 先尝试优雅终止
sudo kill -9 12345    # 强制终止（最后手段）

# 方法 3：如果没有进程在运行，删除残留的锁文件
sudo rm /var/lib/dpkg/lock-frontend
sudo rm /var/lib/dpkg/lock
sudo rm /var/cache/apt/archives/lock
sudo dpkg --configure -a    # 修复可能的中断状态

# 方法 4：关闭 GNOME Software 的自动下载
gsettings set org.gnome.software download-updates false
```

### 5.2 错误：`dpkg was interrupted`

```bash
# 症状：
sudo apt install something
# 错误：
# E: dpkg was interrupted, you must manually run
#    'sudo dpkg --configure -a' to correct the problem.

# 原因：之前的 dpkg 操作被中断（断电、Ctrl+C 等）

# 解决方法：
sudo dpkg --configure -a
# 这会重新配置所有"半配置"状态的包

# 如果 dpkg --configure -a 也失败：
sudo apt install -f        # 修复依赖
sudo dpkg --configure -a   # 重试

# 如果是特定包导致的问题：
dpkg --audit               # 查看问题包
sudo dpkg --configure PKG  # 只重新配置问题包
```

### 5.3 错误：`Unable to locate package`

```bash
# 症状：
sudo apt install nonexistent-package
# 错误：
# E: Unable to locate package nonexistent-package

# 常见原因：
# 1. 包名拼写错误
apt search nonexistent    # 用部分名称搜索

# 2. 忘记运行 apt update
sudo apt update           # 先更新索引再试

# 3. 包来自未启用的仓库（如 multiverse）
# 检查 sources.list 中是否包含了所有需要的组件
grep -r '^deb' /etc/apt/sources.list /etc/apt/sources.list.d/

# 4. 包不存在于当前 Ubuntu 版本
# 在 https://packages.ubuntu.com/ 搜索确认

# 5. 包来自 PPA 但 PPA 未添加
# 查看包的错误信息中是否提到了 PPA 来源

# 6. 架构不匹配（如 arm64 的包在 amd64 仓库中找不到）
dpkg --print-architecture    # 查看当前架构
dpkg --print-foreign-architectures  # 查看已启用的外部架构
```

### 5.4 错误：`Held broken packages` / `Unmet dependencies`

```bash
# 症状：
sudo apt install some-package
# 错误：
# The following packages have unmet dependencies:
#  some-package : Depends: libfoo (>= 2.0) but 1.5 is to be installed
# E: Unable to correct problems, you have held broken packages.

# 原因：
# 1. 依赖的包版本太旧（如上面 libfoo >= 2.0 但系统上只有 1.5）
# 2. 添加了不同来源的仓库，版本混乱
# 3. locked (hold) 的包阻碍了依赖解析

# 排查：
# 查看包的依赖要求
apt-cache show some-package | grep Depends

# 查看系统上已安装的依赖版本
apt-cache policy libfoo

# 查看是否有包被 hold
apt-mark showhold

# 解决方法：
# 方法 1：升级被 hold 的依赖
sudo apt-mark unhold libfoo
sudo apt install some-package

# 方法 2：使用 aptitude 的交互式冲突解决（apt 没有此功能）
sudo apt install -y aptitude
sudo aptitude install some-package
# aptitude 会提供多个解决方案让你选择

# 方法 3：检查是否混用了不同发行版的仓库
cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/
# 确保没有异版本仓库（如在 noble 上使用 jammy 的源）
```

### 5.5 错误：`Hash Sum mismatch`

```bash
# 症状：
sudo apt update
# 错误：
# E: Failed to fetch http://archive.ubuntu.com/.../Packages.gz
#    Hash Sum mismatch
# E: Some index files failed to download. They have been ignored, or old ones used instead.

# 原因：
# 1. 本地缓存的索引文件损坏
# 2. 网络中间设备（代理、缓存）返回了过时的数据
# 3. 仓库镜像正在同步中（文件不完整）

# 解决方法：
# 方法 1：清理缓存重新下载
sudo rm -rf /var/lib/apt/lists/*
sudo apt update

# 方法 2：更换镜像源（如果当前镜像有问题）
sudo sed -i 's|http://archive.ubuntu.com|http://mirrors.aliyun.com|g' /etc/apt/sources.list
sudo apt update

# 方法 3：如果使用了代理，尝试临时绕过
sudo http_proxy="" apt update
```

### 5.6 错误：`add-apt-repository: command not found`

```bash
# 症状：
sudo add-apt-repository ppa:some/ppa
# sudo: add-apt-repository: command not found

# 原因：add-apt-repository 由 software-properties-common 包提供
# Ubuntu Server 默认未安装

# 解决方法：
sudo apt install -y software-properties-common
sudo add-apt-repository ppa:some/ppa
```

### 5.7 错误：snap 安装后命令找不到

```bash
# 症状：
sudo snap install htop
htop
# htop: command not found

# 原因：snap 的 bin 目录不在 PATH 中
# snap 的可执行文件位于 /snap/bin/ 或通过 snap run 调用

# 排查：
echo $PATH
# 检查 /snap/bin 是否在 PATH 中

# 解决方法：
# 方法 1：检查 PATH
echo $PATH | tr ':' '\n' | grep snap
# 如果没有 /snap/bin，手动添加：
echo 'export PATH="/snap/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

# 方法 2：使用 snap run（不需要修改 PATH）
snap run htop

# 方法 3：确认 snapd 是否正确初始化
systemctl status snapd
sudo systemctl restart snapd
```

### 5.8 错误：apt-file 搜索无结果

```bash
# 症状：
apt-file search somefile
# (没有输出)

# 原因：
# 1. 首次安装后没有运行 apt-file update
# 2. 索引数据库过时

# 解决方法：
sudo apt-file update
# 等待下载完成（首次可能需要几分钟）
apt-file search somefile
# 如果仍然无结果：
# - 确认文件确实由某个包提供
# - 在 https://packages.ubuntu.com/ 上搜索
```

## 6. 进阶延伸

### 6.1 `aptitude`：交互式包管理

`aptitude` 是 APT 的交互式前端，在解决复杂的依赖冲突时非常有用。

```bash
# 安装
sudo apt install -y aptitude

# 启动交互式界面
sudo aptitude

# 命令行模式
aptitude search nginx
aptitude show nginx

# aptitude 的独特价值：当 apt 报 "Held broken packages" 时
sudo aptitude install problematic-package
# aptitude 会提供多个解决方案让你选择：
# 1) 降级某些包
# 2) 删除冲突的包
# 3) 保持当前状态
# 而不是像 apt 那样直接报错放弃

# 查看某个包为什么被安装
aptitude why nginx-core

# 查看某个包需要哪些新的依赖
aptitude why-not somepackage
```

### 6.2 `deborphan`：查找孤立包

```bash
# deborphan 比 autoremove 更激进，能找出真正不再需要的库
sudo apt install -y deborphan

# 列出孤立的库文件（没有其他包依赖它们）
deborphan

# 列出所有孤立包（不仅限于库）
deborphan --all-packages

# 查找孤立包并删除（谨慎！先检查列表）
deborphan | xargs sudo apt remove -y
# 或更安全的方式——逐个确认
deborphan | while read pkg; do
    apt-cache show "$pkg" 2>/dev/null | head -3
    read -p "Remove $pkg? [y/N] " answer
    [ "$answer" = "y" ] && sudo apt remove -y "$pkg"
done
```

### 6.3 搭建本地 APT 仓库镜像

对于离线环境或多台机器需要统一软件版本时，搭建本地镜像仓库非常有用。

```bash
# 使用 apt-mirror 创建本地镜像
sudo apt install -y apt-mirror

# 配置镜像（编辑 /etc/apt/mirror.list）
# 示例：只镜像 noble 的 main 和 universe 组件
cat | sudo tee /etc/apt/mirror.list << 'EOF'
set base_path    /var/spool/apt-mirror
set mirror_path  $base_path/mirror
set skel_path    $base_path/skel
set var_path     $base_path/var
set cleanscript  $base_path/var/clean.sh
set defaultarch  amd64
deb http://archive.ubuntu.com/ubuntu noble main universe
deb http://archive.ubuntu.com/ubuntu noble-updates main universe
deb http://archive.ubuntu.com/ubuntu noble-security main universe
clean http://archive.ubuntu.com/ubuntu
EOF

# 执行镜像（首次下载可能几十 GB，需要足够空间和时间）
sudo apt-mirror

# 配置 Apache 或 Nginx 将镜像目录暴露为 HTTP 服务
# 然后客户端可以将 sources.list 指向这台本地服务器

# 更轻量的替代方案：apt-cacher-ng（代理缓存）
sudo apt install -y apt-cacher-ng
# 客户端配置：echo 'Acquire::http::Proxy "http://proxy:3142";' > /etc/apt/apt.conf.d/01proxy
```

### 6.4 创建自己的 .deb 包

如果能写脚本，你就能创建自己的 .deb 包。这对于内部分发工具极其有用。

```bash
# 安装打包工具
sudo apt install -y build-essential devscripts debhelper

# 创建一个简单的 "hello-world" deb 包
mkdir -p ~/pkg-lesson28/mydeb/hello-1.0
cd ~/pkg-lesson28/mydeb/hello-1.0

# 1. 创建程序
mkdir -p usr/bin
cat > usr/bin/hello-custom << 'EOF'
#!/bin/bash
echo "Hello from my custom Debian package!"
echo "Date: $(date)"
EOF
chmod +x usr/bin/hello-custom

# 2. 创建 DEBIAN 控制目录
mkdir -p DEBIAN
cat > DEBIAN/control << 'EOF'
Package: hello-custom
Version: 1.0
Section: utils
Priority: optional
Architecture: all
Depends: bash
Maintainer: Your Name <you@example.com>
Description: A custom hello-world package
 This is a demo package created for learning dpkg packaging.
EOF

# 3. 构建 .deb 文件
cd ..
dpkg-deb --build hello-1.0
# 输出：hello-1.0.deb

# 4. 安装测试
sudo dpkg -i hello-1.0.deb
hello-custom
# 输出：Hello from my custom Debian package!

# 5. 检查
dpkg -l hello-custom

# 6. 卸载
sudo dpkg -r hello-custom
```

### 6.5 使用 `unattended-upgrades` 实现自动安全更新

对于需要自动保持安全补丁的服务器，配置无人值守更新。

```bash
# 安装
sudo apt install -y unattended-upgrades

# 配置文件在 /etc/apt/apt.conf.d/50unattended-upgrades
# 关键配置：

# 只启用安全更新（强烈推荐）
# Unattended-Upgrade::Allowed-Origins {
#     "${distro_id}:${distro_codename}-security";
# };

# 同时启用推荐更新（谨慎——可能引入不稳定）
# "${distro_id}:${distro_codename}-updates";

# 自动删除不再需要的依赖
# Unattended-Upgrade::Remove-Unused-Kernel-Packages "true";
# Unattended-Upgrade::Remove-New-Unused-Dependencies "true";

# 自动清理缓存
# Unattended-Upgrade::Automatic-Reboot "false";  ← 生产服务器一般关掉

# 启用
sudo dpkg-reconfigure --priority=low unattended-upgrades
# 选择 "Yes"

# 验证
sudo unattended-upgrades --dry-run --debug

# 查看日志
sudo cat /var/log/unattended-upgrades/unattended-upgrades.log
```

### 6.6 清理系统垃圾

```bash
# 综合清理脚本：回收磁盘空间
echo "=== 包管理清理 ==="

# 1. 清理 apt 下载缓存
sudo apt-get clean
echo "1. apt 缓存已清理"

# 2. 清理过时的包（版本已不在仓库中的）
sudo apt-get autoclean
echo "2. 过时缓存已清理"

# 3. 清理不再需要的依赖
sudo apt-get autoremove --purge -y
echo "3. 孤立依赖已清理"

# 4. 清理旧内核（保留当前运行的内核和最新的一个）
dpkg -l 'linux-*' | grep '^ii' | awk '{print $2}' | \
    grep -v $(uname -r | sed 's/-generic//') | \
    xargs sudo apt-get purge -y 2>/dev/null || echo "无旧内核需要清理"

echo "4. 旧内核已清理"

# 5. 清理 dpkg 的配置文件残留
dpkg -l | grep '^rc' | awk '{print $2}' | \
    xargs sudo dpkg --purge 2>/dev/null || echo "无残留配置"
echo "5. 残留配置已清理"

# 6. 清理 snap 的旧版本（snap 自动保留 3 个旧版本）
sudo snap list --all | awk '/disabled/{print $1, $3}' | \
    while read snapname revision; do
        sudo snap remove "$snapname" --revision="$revision" 2>/dev/null
    done
echo "6. snap 旧版本已清理"

# 7. 汇总清理结果
echo ""
echo "=== 清理完成 ==="
df -h / | tail -1
```

### 6.7 APT 钉选（Apt Pinning）—— 精细版本控制

当你有多个 APT 源提供同一软件包的不同版本时，apt pinning 让你精确指定从哪个源安装。

```bash
# 场景：默认使用 stable 源，但 nginx 想用 backports 源的最新版本

# 创建 pinning 配置
cat | sudo tee /etc/apt/preferences.d/nginx-backports << 'EOF'
Package: nginx nginx-common nginx-core
Pin: release a=noble-backports
Pin-Priority: 600
EOF

# Pin-Priority 含义：
#   1001+：优先安装，即使要降级
#   990-1000：如果目标版本不比已安装的旧，则安装
#   500-989：默认优先级（常规仓库）
#   100-499：仅在其他源更高版本不可用时安装
#   -1 到 99：只有没有其他版本时才安装
#   负数：永不安装

# 查看当前 pinning 配置
apt-cache policy nginx
# 观察 Candidate 列是否指向了 backports 版本

# 移除 pinning
sudo rm /etc/apt/preferences.d/nginx-backports
```

### 6.8 包管理性能优化

### 6.9 从 deb 切换到 snap/flatpak 的决策框架

在实际工作中，你需要根据场景选择最合适的包管理方式：

```
+------------------------------------------------------------------+
|              软件包管理方式选择决策树                                |
|                                                                  |
|  需要该软件吗？                                                    |
|      │                                                           |
|      ├── 系统级工具/服务（nginx, docker, sshd）                   |
|      │   └── apt install（deb）← 推荐                             |
|      │       理由：与系统库共享、启动快、安全更新由 Ubuntu 保障     |
|      │                                                           |
|      ├── 桌面应用（VLC, GIMP, VS Code）                           |
|      │   ├── snap install ← 如果 Ubuntu 桌面版，预装 snapd       |
|      │   └── flatpak install ← 如果需要更新的版本或跨发行版       |
|      │       理由：沙箱隔离、自动更新、不污染系统                   |
|      │                                                           |
|      ├── 编程工具/IDE（Go, VS Code, IntelliJ）                    |
|      │   ├── snap install --classic ← 需要访问系统文件            |
|      │   └── 或用开发者的官方安装方式                              |
|      │       理由：classic 模式有完���文件系统访问权限              |
|      │                                                           |
|      ├── 需要最新版本（官方仓库太旧）                               │
|      │   ├── PPA ← 如果有可信的 PPA                              |

|      └── 商业/闭源软件（Skype, Slack, Steam）                     |

+------------------------------------------------------------------+
```
