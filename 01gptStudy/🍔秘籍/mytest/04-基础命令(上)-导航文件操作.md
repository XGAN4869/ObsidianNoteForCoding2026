## 1. 概述

### 1.1 从"看地图"到"动手操作"

上一章为你绘制了 Linux 文件系统的完整"地图"——你学会了什么是 FHS，认识了 `/bin`、`/etc`、`/var`、`/home`、`/proc` 等核心目录，也学会了使用 `pwd`、`ls`、`tree`、`file` 等命令来浏览和探索这套目录体系。

现在，是时候从"浏览者"变成"操作者"了。本章将教你在终端中真正地操控文件——创建目录、复制文件、移动重命名、删除、以及建立链接。这些命令是你每天在 Linux 中使用频率最高的工具，就像键盘和鼠标之于 Windows 一样基本。

### 1.2 本章命令全景

本章覆盖的命令可以分为四组：

| 分组 | 命令 | 功能 |
|------|------|------|
| **导航（Navigation）** | `pwd`、`cd`、`ls` | 确认位置、切换目录、浏览内容 |
| **创建（Creation）** | `mkdir`、`touch` | 创建目录、创建空文件或更新时间戳 |
| **操作（Manipulation）** | `cp`、`mv`、`rm`、`rmdir` | 复制、移动/重命名、删除文件、删除空目录 |
| **信息（Information）** | `ln`、`stat`、`file`、`basename`、`dirname` | 创建链接、查看元数据、判断类型、解析路径 |

其中，`ln`（创建链接）是本章的重点和难点——我们将深入 inode（索引节点，Index Node）层面，讲清硬链接（Hard Link）和软链接（Soft Link / Symbolic Link）的本质区别。`rm` 是另一个重点——我们将讨论安全删除的实践，包括经典的 `rm -rf /` 灾难。

### 1.3 本章学习目标

完成本章后，你将能够：

- 深刻理解绝对路径和相对路径的区别，熟练使用 `.` 和 `..`
- 使用 `pwd` 和 `cd` 在文件系统中自由导航
- 使用 `ls` 的各种选项高效浏览目录，并结合通配符筛选文件
- 使用 `mkdir` 创建目录（包括嵌套创建），使用 `touch` 创建空文件
- 使用 `cp` 复制文件和目录，理解递归复制和交互式覆盖
- 使用 `mv` 移动和重命名文件/目录，理解其与 `cp` 的本质区别
- 使用 `rm` 和 `rmdir` 删除文件和目录，养成安全删除习惯
- 理解 inode 的概念，并能用 `stat` 查看文件的 inode 元数据
- 创建硬链接和软链接，从 inode 层面解释二者区别，知道何时用哪种
- 使用 `file` 判断文件真实类型，使用 `basename` 和 `dirname` 解析路径

## 2. 核心概念

### 2.1 路径概念深入

在操控文件之前，必须彻底理解路径。上一章第 2.3 节初步介绍了绝对路径和相对路径，这里我们做更深入的理解。

#### 2.1.1 绝对路径（Absolute Path）

绝对路径是从根目录 `/` 开始，逐级向下定位到目标文件/目录的完整路径。它始终以 `/` 开头。

**特征：** 无论你当前"站在"文件系统的哪个位置，同一个绝对路径永远指向同一个目标。

```
/home/zhangsan/Documents/report.txt
│
└── 以 / 开头，从根目录出发
```

**示例：**

```bash
# 无论当前在哪个目录，以下命令访问的都是同一个文件
cat /etc/hostname
ls /usr/bin
cd /var/log
```

#### 2.1.2 相对路径（Relative Path）

相对路径从当前工作目录（Current Working Directory）出发，使用 `.`、`..` 或直接以目录名/文件名开始。

**特征：** 同样的相对路径，在不同位置指向不同的目标。

假设当前目录是 `/home/zhangsan/`：

| 相对路径 | 等价绝对路径 | 说明 |
|----------|-------------|------|
| `Documents/report.txt` | `/home/zhangsan/Documents/report.txt` | 直接向下 |
| `./Documents/report.txt` | `/home/zhangsan/Documents/report.txt` | `.` 代表当前目录，写不写效果一样 |
| `../lisi/notes.txt` | `/home/lisi/notes.txt` | `..` 回到上级，再进入 lisi |
| `../../etc/hostname` | `/etc/hostname` | `..` 两次回到根目录，再进入 etc |

#### 2.1.3 `.` 和 `..`：每个目录里的两个"隐藏入口"

在 Linux 中，**每一个**目录（包括空目录）都天然包含两个特殊条目：

| 符号 | 含义 | 本质 |
|------|------|------|
| `.` | 当前目录本身 | 指向本目录的硬链接 |
| `..` | 上级目录（Parent Directory） | 指向父目录的硬链接 |

验证——即使在一个空目录中，`.` 和 `..` 也存在：

```bash
mkdir /tmp/testdir
ls -la /tmp/testdir
```

预期输出：

```
total 8
drwxrwxr-x 2 zhangsan zhangsan 4096 Jul 29 10:00 .
drwxrwxrwt 3 root     root     4096 Jul 29 10:00 ..
```

注意输出中第一行是 `.`，第二行是 `..`。`ls -a` 才能看到它们，因为以 `.` 开头即是隐藏文件。

**实用场景：**

```bash
# 执行当前目录下的脚本（必须有 ./ 前缀，否则 Shell 会在 PATH 中搜索）
./myscript.sh

# 返回上级目录
cd ..

# 复制文件到当前目录
cp /etc/hostname .

# 当前目录的上级的上级
cd ../..
```

#### 2.1.4 `~` 和 `-`：两个便利的快捷符号

| 符号 | 含义 | 示例 |
|------|------|------|
| `~` | 当前用户的家目录（Home Directory） | `cd ~` 等价于 `cd /home/zhangsan` |
| `~用户名` | 指定用户的家目录 | `ls ~lisi` 列出 lisi 的家目录（如果有权限） |
| `-` | 上一次所在的工作目录 | `cd -` 在两个目录之间来回切换 |

`cd -` 的实际演示：

```bash
cd /etc
cd /var/log
cd -          # 返回 /etc
pwd           # 输出 /etc
cd -          # 又回到 /var/log
```

这就像浏览器中的"后退"按钮，当你需要在两个目录之间来回操作时非常方便。

### 2.2 理解 inode：文件的底层"身份证"

要真正理解 `ln`（硬链接与软链接的区别）、`stat`（文件元数据）以及 `rm`（删除的实质），必须先理解 inode 的概念。

#### 2.2.1 文件系统中，文件名和文件数据是分开的

很多初学者以为"文件名就是文件"。实际上，Linux 文件系统将文件拆分为三个层次：

```
┌──────────────────────────────────────────────────────────┐
│  目录项（Directory Entry）                                 │
│  ┌─────────────┬──────────┐                               │
│  │ 文件名       │ inode 号 │                               │
│  │ "report.txt"│  524311  │                               │
│  └─────────────┴──────────┘                               │
│         │                                                 │
│         ▼                                                 │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  inode（Index Node，索引节点）                        │  │
│  │  inode 号: 524311                                    │  │
│  │  文件类型: 普通文件                                   │  │
│  │  权限: rw-r--r--                                     │  │
│  │  所有者: zhangsan (UID 1000)                         │  │
│  │  所属组: zhangsan (GID 1000)                         │  │
│  │  文件大小: 1024 字节                                  │  │
│  │  时间戳（访问/修改/变更）                              │  │
│  │  数据块指针 → [block 88201] [block 88202] ...        │  │
│  └─────────────────────────────────────────────────────┘  │
│         │                                                 │
│         ▼                                                 │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  数据块（Data Blocks）                                │  │
│  │  文件的实际内容存放在磁盘的数据块中                    │  │
│  └─────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

**关键认知：**
- **文件名**只存在于目录项中，是给人类看的"标签"
- **inode** 是文件的真正"身份证"——它存储了文件的所有元数据（Metadata）以及数据块（Data Block）在磁盘上的位置
- **数据块**是文件内容的实际存放处
- **目录本质上是一个映射表：文件名 -> inode 号**

#### 2.2.2 用 `ls -i` 观察 inode 号

```bash
# 创建测试文件
echo "Hello Linux" > /tmp/test_inode.txt

# 使用 -i 选项查看 inode 号
ls -li /tmp/test_inode.txt
```

预期输出：

```
524311 -rw-rw-r-- 1 zhangsan zhangsan 12 Jul 29 10:00 /tmp/test_inode.txt
```

第一列 `524311` 就是这个文件的 inode 号。这个数字在整个文件系统（分区）内是唯一的。

再看目录自己的 inode：

```bash
ls -lid /tmp
```

第一列即为 `/tmp` 目录的 inode 号。

#### 2.2.3 inode 中不包含文件名

这是最需要记住的一点：**inode 不存储文件名。** 文件名只存储在它所在目录的目录项中。这意味着：

- 你可以有**多个不同的文件名**指向**同一个 inode**——这就是硬链接
- 删除文件的"名字"（`rm filename`）实际上是删除该目录项，inode 和数据块何时真正释放取决于 inode 的链接计数（Link Count）是否归零
- 你可以读取一个文件的内容却不知道该文件"叫什么名字"——只要有进程持有该文件的文件描述符（File Descriptor）即可

### 2.3 硬链接 vs 软链接：inode 层面的本质区别

在上面的 inode 概念基础上，理解两种链接的差异就清晰了。

#### 2.3.1 硬链接（Hard Link）

**定义：** 硬链接是同一个 inode 的**另一个目录项**——它给同一个 inode 起了另一个"名字"。

```
创建硬链接前：
  目录 /tmp/
  ┌──────────────┬──────────┐
  │ original.txt │ inode 100│
  └──────────────┴──────────┘
                        │
                        ▼
                  ┌─────────────┐
                  │ inode 100   │
                  │ 链接计数: 1 │
                  │ 数据块 → ... │
                  └─────────────┘

创建硬链接后（ln original.txt hardlink.txt）：
  目录 /tmp/
  ┌──────────────┬──────────┐
  │ original.txt │ inode 100│
  ├──────────────┼──────────┤
  │ hardlink.txt │ inode 100│   ← 新增条目，指向同一个 inode
  └──────────────┴──────────┘
                        │
                        ▼
                  ┌─────────────┐
                  │ inode 100   │
                  │ 链接计数: 2 │   ← 链接计数从 1 变为 2
                  │ 数据块 → ... │
                  └─────────────┘
```

**核心特征：**

| 特性 | 说明 |
|------|------|
| **同一 inode** | 硬链接和原文件共享相同的 inode 号，通过 `ls -i` 可以验证 |
| **链接计数** | inode 中有一个"链接计数"（Link Count）字段，记录有多少个目录项指向它。用 `ls -l` 输出的第二列即是链接计数 |
| **删除行为** | 删除其中一个名字（`rm original.txt`），链接计数减 1。只要链接计数 > 0，inode 和数据块就不会释放——文件内容仍然可以通过另一个名字访问 |
| **不能跨文件系统** | 硬链接必须和原文件在同一个文件系统（分区）内，因为 inode 号只在同一文件系统内唯一 |
| **不能链接目录** | 普通用户不能为目录创建硬链接（`.` 和 `..` 是文件系统自动维护的例外）。这是为了防止形成目录环，导致文件系统遍历陷入死循环 |

#### 2.3.2 软链接（Soft Link / Symbolic Link）

**定义：** 软链接是一个**独立的新文件**（有自己的 inode 和数据块），其数据块中存储的内容是**目标文件的路径字符串**。它类似于 Windows 中的快捷方式（Shortcut）。

```
创建软链接前：
  目录 /tmp/
  ┌──────────────┬──────────┐
  │ original.txt │ inode 100│
  └──────────────┴──────────┘
                        │
                        ▼
                  ┌─────────────┐
                  │ inode 100   │
                  │ 链接计数: 1 │
                  │ 数据块 → ... │
                  └─────────────┘

创建软链接后（ln -s original.txt symlink.txt）：
  目录 /tmp/
  ┌──────────────┬──────────┐
  │ original.txt │ inode 100│
  ├──────────────┼──────────┤
  │ symlink.txt  │ inode 200│   ← 全新 inode，独立的文件
  └──────────────┴──────────┘
              │               │
              ▼               ▼
        ┌─────────────┐  ┌─────────────────────────┐
        │ inode 100   │  │ inode 200               │
        │ 链接计数: 1 │  │ 类型: 符号链接           │
        │ 数据块 → ... │  │ 数据块存储路径字符串:     │
        └─────────────┘  │ "original.txt"           │
                         └─────────────────────────┘
```

**核心特征：**

| 特性 | 说明 |
|------|------|
| **不同 inode** | 软链接有自己的 inode 和数据块，它不是"别名"，而是一个指向其他文件的"指针文件" |
| **存储的是路径** | 软链接的数据块中存储的是目标文件的路径（一个字符串）。因此它可以指向不存在的文件（成为悬空链接，Dangling Link） |
| **可以跨文件系统** | 因为存储的是路径字符串而非 inode 号，软链接可以跨越不同的文件系统/分区 |
| **可以链接目录** | 软链接可以指向目录，使用起来非常方便 |
| **删除行为** | 如果删除了目标文件（original.txt），软链接仍然存在，但指向了一个不存在的路径——访问它会报"No such file or directory" |

#### 2.3.3 对比总结

| 维度 | 硬链接（Hard Link） | 软链接（Soft Link） |
|------|-------------------|-------------------|
| **本质** | 同一个 inode 的另一个目录项（别名） | 一个独立的"路径指针"文件 |
| **inode 号** | 与原文件相同 | 与原文件不同 |
| **链接计数** | 创建后，inode 的链接计数 +1 | 不影响原文件的链接计数 |
| **跨文件系统** | 不可以 | 可以 |
| **链接目录** | 不可以（用户级） | 可以 |
| **目标删除后** | 数据仍在，通过硬链接仍可访问 | 链接断裂，成为悬空链接 |
| **磁盘占用** | 仅占用一个目录项（极少） | 占用一个 inode + 一个数据块（存储路径） |
| **识别方式** | `ls -l` 第二列 > 1；`ls -i` 显示相同 inode | `ls -l` 显示 `l` 类型，第一列以 `l` 开头，文件名后有 `-> 目标路径` |
| **相对/绝对路径** | 无所谓（直接用 inode 定位） | 路径可以是相对的或绝对的——如果是相对路径，则以软链接自身所在的目录为基准解析 |

#### 2.3.4 选择指南：何时用硬链接，何时用软链接

| 场景 | 推荐 | 理由 |
|------|------|------|
| 目录的快捷访问 | **软链接** | 硬链接不支持目录 |
| 跨分区的链接 | **软链接** | 硬链接不能跨文件系统 |
| 防止误删文件（增加引用） | **硬链接** | 删除"原文件"，硬链接不受影响 |
| 创建版本化备份（节省磁盘空间） | **硬链接** | 多个版本共享未变化的数据块，如 rsync 的 `--link-dest` 选项 |
| 指向动态变化的路径 | **软链接** | 修改软链接的目标路径即可（`ln -sfn`），不影响目标文件 |
| 替代可执行文件的旧版本 | **软链接** | 如 `/usr/bin/python` -> `/usr/bin/python3` |

## 3. 命令详解

以下全部命令的示例，请打开终端逐一运行验证。建议你在家目录下创建一个练习用目录，避免影响系统文件：

```bash
mkdir -p ~/ch04-practice
cd ~/ch04-practice
pwd
```

### 3.1 pwd -- 确认当前工作目录

`pwd`（Print Working Directory）在上一章已介绍。此处我们从文件操作的视角补充两个要点。

**为什么文件操作前要先 `pwd`：**

当你使用相对路径执行 `cp`、`mv`、`rm` 等操作时，最终作用的位置取决于当前工作目录。`pwd` 就像开车前看一眼导航定位——避免在错误的目录里执行了操作。

```bash
# 坏习惯：不知道自己在哪就开始操作
rm -rf some_directory/

# 好习惯：先确认位置
pwd
# 确认无误后再操作
rm -rf some_directory/
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-L` | 输出逻辑路径（Logical），保留符号链接。如果通过符号链接进入当前目录，显示链接路径 | 可选 | 已启用（默认行为） |
| `-P` | 输出物理路径（Physical），解析所有符号链接。显示磁盘上的实际位置 | 可选 | 否 |

演示 `-L` 和 `-P` 的区别（回顾）：

```bash
cd /bin          # /bin 是指向 /usr/bin 的符号链接
pwd -L           # 输出 /bin
pwd -P           # 输出 /usr/bin
cd ~             # 返回家目录
```

### 3.2 cd -- 切换工作目录

`cd`（Change Directory）是导航命令中最常用的一个。它改变当前 Shell 会话的工作目录。

> **注意：** `cd` 是 Shell **内置命令**（Built-in Command），没有独立的可执行文件。可以用 `type cd` 验证。

**语法：**

```
cd [目录路径]
```

如果不带任何参数，`cd` 默认返回当前用户的家目录。

**基础用法：**

```bash
# 切换到绝对路径
cd /etc
pwd                           # 输出: /etc

# 切换到相对路径
cd ..
pwd                           # 输出: / (上一步在 /etc，上级是根)

# 返回家目录（三种等价写法）
cd ~
cd $HOME
cd

# 切换到上一个所在目录（来回切换）
cd /var/log
cd /etc
cd -                          # 回到 /var/log
cd -                          # 又回到 /etc
```

**路径中包含空格时：**

```bash
# 如果用引号包围
cd "my documents"

# 如果用转义字符
cd my\ documents

# Tab 补全会自动转义空格，推荐使用 Tab 补全而非手动输入
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| （无参数） | 切换到当前用户的家目录 | 可选 | -- |
| 目录路径 | 切换到指定目录 | 可选 | 家目录 |
| `-` | 切换到上一次所在的工作目录 | 可选 | 上一次目录 |

### 3.3 ls -- 列出目录内容

`ls`（List）在上一章已详细讲解。本节从文件操作的视角补充一些实用技巧，避免与上一章重复。

#### 3.3.1 使用 `ls` 验证文件操作结果

执行 `mkdir`、`cp`、`mv`、`rm` 等操作后，立即用 `ls` 确认结果，是良好的工作习惯：

```bash
touch newfile.txt
ls -l newfile.txt             # 确认文件已创建
rm newfile.txt
ls newfile.txt                # 确认文件已删除（应报 No such file or directory）
```

#### 3.3.2 用于本章的关键 ls 选项补充

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` | 长格式（Long Format），显示权限、链接计数、所有者、大小、时间 | 可选 | 简略格式 |
| `-a` | 显示所有（All），包括 `.` 开头的隐藏条目 | 可选 | 不显示隐藏条目 |
| `-h` | 人类可读（Human-readable）文件大小 | 可选 | 字节 |
| `-i` | 显示 inode 号（Index Node Number）。配合 `-l` 使用为 `ls -li` | 可选 | 不显示 |
| `-d` | 显示目录本身（Directory），而非目录的内容 | 可选 | 显示内容 |
| `-F` | 追加类型指示符（`/`=目录, `*`=可执行, `@`=符号链接） | 可选 | 否 |
| `-R` | 递归（Recursive）列出所有子目录的内容 | 可选 | 仅当前层 |
| `-t` | 按修改时间（Time）排序 | 可选 | 字母序 |
| `-S` | 按文件大小（Size）排序 | 可选 | 字母序 |
| `-r` | 反转（Reverse）排序结果 | 可选 | 否 |
| `-1` | 每行仅显示一个条目（单列输出） | 可选 | 多列 |

#### 3.3.3 用 `ls` 配合通配符筛选文件

通配符（Glob）允许你按模式（Pattern）而非完整名称来匹配文件：

```bash
# 列出所有 .txt 文件
ls *.txt

# 列出所有以 a 或 b 开头的文件
ls [ab]*

# 列出所有单个字符的文件名
ls ?

# 列出所有不以 .txt 结尾的文件（在 Bash 中使用扩展通配符）
ls !(*.txt)
```

通配符的完整语法将在本章 [6.2 节](#62-通配符glob-pattern全面指南) 中详细展开。

### 3.4 mkdir -- 创建目录

`mkdir`（Make Directory）用于创建新目录。

**语法：**

```
mkdir [参数] <目录路径>
```

**基础用法：**

```bash
# 创建一个目录
mkdir myproject

# 验证
ls -ld myproject
```

预期输出：

```
drwxrwxr-x 2 zhangsan zhangsan 4096 Jul 29 10:00 myproject
```

注意第一列以 `d` 开头，表示这是一个目录。

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-p` | 递归创建父目录（Parents）。如果父目录不存在，则一并创建。不报错 | 可选 | 父目录不存在时报错 |
| `-v` | 显示详细信息（Verbose），每创建一个目录都打印出来 | 可选 | 静默 |
| `-m` | 指定新目录的权限模式（Mode），如 `-m 755` | 可选 | 由 umask 决定（通常是 755 或 775） |

**创建嵌套目录（`-p` 参数）：**

```bash
# 不用 -p：逐层创建（繁琐）
mkdir a
mkdir a/b
mkdir a/b/c

# 用 -p：一步到位
mkdir -p a/b/c

# 验证
ls -R a
```

预期输出：

```
a:
b

a/b:
c

a/b/c:
```

> **实用技巧：** 如果目录已存在，`mkdir -p` 不会报错。这使得它非常适合在脚本中使用——你不必先检查目录是否存在再创建。直接 `mkdir -p /some/path` 即可。

```bash
# 目录已经存在，不加 -p 会报错
mkdir myproject
# mkdir: cannot create directory 'myproject': File exists

# 加了 -p，静默成功
mkdir -p myproject
# （无输出，操作成功）
```

**创建带特定权限的目录（`-m` 参数）：**

```bash
# 创建一个仅自己可读写的目录
mkdir -m 700 private_dir
ls -ld private_dir
```

预期输出：

```
drwx------ 2 zhangsan zhangsan 4096 Jul 29 10:00 private_dir
```

权限 `rwx------` 表示仅所有者（zhangsan）可以读、写、进入该目录，同组和其他用户没有任何权限。

**使用 `-v` 查看创建过程：**

```bash
mkdir -pv a/b/c/d/e
```

预期输出：

```
mkdir: created directory 'a'
mkdir: created directory 'a/b'
mkdir: created directory 'a/b/c'
mkdir: created directory 'a/b/c/d'
mkdir: created directory 'a/b/c/d/e'
```

### 3.5 touch -- 创建空文件与更新时间戳

`touch` 命令有两个主要用途：
1. **创建一个空的普通文件**（如果文件不存在）
2. **更新文件的访问时间和修改时间戳**（如果文件已存在）

**语法：**

```
touch [参数] <文件路径>
```

**基础用法：**

```bash
# 创建一个空文件
touch readme.txt

# 验证
ls -l readme.txt
```

预期输出：

```
-rw-rw-r-- 1 zhangsan zhangsan 0 Jul 29 10:00 readme.txt
```

注意第 5 列的文件大小是 `0`——`touch` 创建的文件确实是空的。

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-a` | 仅修改访问时间（Access Time / atime） | 可选 | 修改所有时间 |
| `-m` | 仅修改修改时间（Modification Time / mtime） | 可选 | 修改所有时间 |
| `-t` | 指定时间戳（格式 `[[CC]YY]MMDDhhmm[.ss]`） | 可选 | 当前时间 |
| `-d` | 指定日期时间字符串，如 `"2024-01-15 14:30:00"` | 可选 | 当前时间 |
| `-c` | 不创建文件（No-create），仅更新时间戳（如果文件存在） | 可选 | 文件不存在则创建 |
| `-r` | 以参考文件（Reference）的时间戳为准，而非当前时间 | 可选 | 当前时间 |

**一次创建多个文件：**

```bash
touch file1.txt file2.txt file3.txt
ls -l file*.txt
```

预期输出：

```
-rw-rw-r-- 1 zhangsan zhangsan 0 Jul 29 10:00 file1.txt
-rw-rw-r-- 1 zhangsan zhangsan 0 Jul 29 10:00 file2.txt
-rw-rw-r-- 1 zhangsan zhangsan 0 Jul 29 10:00 file3.txt
```

**批量创建带编号的文件（使用大括号展开）：**

```bash
touch chapter_{01..05}.txt
ls -1
```

预期输出：

```
chapter_01.txt
chapter_02.txt
chapter_03.txt
chapter_04.txt
chapter_05.txt
```

**更新已有文件的时间戳：**

```bash
# 查看当前时间戳
ls -l readme.txt

# 更新到当前时间
touch readme.txt

# 再次查看——时间戳已更新
ls -l readme.txt
```

**将文件时间戳设置为特定时间：**

```bash
# 设置为 2024 年 1 月 15 日 09:30:00
touch -t 202401150930.00 oldfile.txt
ls -l oldfile.txt
```

预期输出（注意日期部分）：

```
-rw-rw-r-- 1 zhangsan zhangsan 0 Jan 15  2024 oldfile.txt
```

**使用参考文件的时间戳：**

```bash
touch ref.txt
touch -r ref.txt new.txt
# new.txt 的时间戳与 ref.txt 完全一致
ls -l ref.txt new.txt
```

### 3.6 cp -- 复制文件与目录

`cp`（Copy）用于复制文件或目录。

**语法：**

```
cp [参数] <源路径> <目标路径>
```

**核心行为对照表（必记）：**

| 操作 | 命令形式 | 结果 |
|------|----------|------|
| 复制文件到文件 | `cp a.txt b.txt` | 将 a.txt 的内容复制到 b.txt。如果 b.txt 已存在则覆盖；不存在则创建 |
| 复制文件到目录 | `cp a.txt /tmp/` | 将 a.txt 复制到 /tmp/ 目录下，文件名保持不变 |
| 复制目录 | `cp -r dir1/ dir2/` | 将 dir1 及其所有内容递归复制到 dir2。如果 dir2 不存在则创建；如果存在则 dir1 成为 dir2 的子目录 |
| 复制多个文件到目录 | `cp a.txt b.txt /tmp/` | 将 a.txt 和 b.txt 都复制到 /tmp/ 下 |

**基础用法：**

```bash
# 准备一个测试文件
echo "Hello, cp command!" > source.txt

# 复制文件（创建新副本）
cp source.txt dest.txt
cat dest.txt          # 输出: Hello, cp command!

# 复制到指定目录
mkdir -p backup
cp source.txt backup/
ls backup/            # 输出: source.txt
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-r` / `-R` | 递归（Recursive）复制目录及其全部内容。复制目录时必须使用 | 可选 | 不递归 |
| `-i` | 交互式（Interactive），覆盖已有文件前询问确认 | 可选 | 静默覆盖 |
| `-v` | 显示详细信息（Verbose），每复制一个文件都打印出来 | 可选 | 静默 |
| `-p` | 保留（Preserve）文件属性——权限、时间戳、所有者等 | 可选 | 使用当前用户的默认属性 |
| `-a` | 归档模式（Archive），等价于 `-dR --preserve=all`，递归复制并保留所有属性、符号链接等 | 可选 | 否 |
| `-u` | 仅当源文件比目标文件新（Update）或目标文件不存在时才复制 | 可选 | 总是复制 |
| `-n` | 不覆盖（No-clobber）已存在的文件 | 可选 | 默认覆盖 |
| `-f` | 强制（Force），如果目标文件无法打开则删除后重试 | 可选 | 否 |
| `-b` | 覆盖前创建备份（Backup），备份文件名后附加 `~` | 可选 | 直接覆盖 |

**递归复制目录：**

```bash
# 创建测试目录结构
mkdir -p project/src project/docs
echo "main code" > project/src/main.c
echo "readme" > project/docs/readme.md

# 递归复制整个目录
cp -r project project_backup

# 验证
tree project_backup
```

预期输出：

```
project_backup
├── docs
│   └── readme.md
└── src
    └── main.c

2 directories, 2 files
```

**交互式复制（防止意外覆盖）：**

```bash
echo "original" > important.txt
echo "new content" > temp.txt

# 使用 -i：如果目标已存在，会询问
cp -i temp.txt important.txt
```

系统会提示：

```
cp: overwrite 'important.txt'?
```

输入 `y` 确认覆盖，`n` 取消。

**保留文件属性复制：**

```bash
cp -p source.txt preserved.txt
ls -l source.txt preserved.txt
# 两个文件拥有相同的时间戳和权限
```

**归档复制（最完整的保留）：**

```bash
# -a 等价于递归 + 保留所有属性
cp -a project/ project_archive/
```

**详细模式（查看复制了什么）：**

```bash
cp -rv project/ project_verbose/
```

预期输出：

```
'project/' -> 'project_verbose'
'project/docs' -> 'project_verbose/docs'
'project/docs/readme.md' -> 'project_verbose/docs/readme.md'
'project/src' -> 'project_verbose/src'
'project/src/main.c' -> 'project_verbose/src/main.c'
```

### 3.7 mv -- 移动与重命名

`mv`（Move）用于移动文件/目录（更改位置）和重命名（更改名称）。在 Linux 文件系统中，移动和重命名实际上是**同一个操作**——都是在目录中更改目录项（文件名到 inode 号的映射），不涉及实际数据的复制（前提是同一文件系统内）。

**语法：**

```
mv [参数] <源路径> <目标路径>
```

**核心行为对照表：**

| 操作 | 命令形式 | 结果 |
|------|----------|------|
| 重命名文件 | `mv old.txt new.txt` | old.txt 改名为 new.txt。inode 不变 |
| 移动文件到目录 | `mv a.txt /tmp/` | a.txt 被移动到 /tmp/ 下 |
| 移动并重命名 | `mv a.txt /tmp/b.txt` | a.txt 被移动到 /tmp/ 并改名为 b.txt |
| 移动目录 | `mv dir1/ dir2/` | 若 dir2 不存在，dir1 重命名为 dir2；若 dir2 存在，dir1 移入 dir2 成为其子目录 |

**基础用法：**

```bash
# 准备测试文件
echo "sample content" > original.txt

# 重命名
mv original.txt renamed.txt
ls -l original.txt          # 报错: No such file or directory
ls -l renamed.txt           # 文件存在

# 移动到子目录
mkdir -p subdir
mv renamed.txt subdir/
ls subdir/                  # 输出: renamed.txt

# 验证 inode 不变（同一文件系统内移动）
touch test_mv.txt
ls -i test_mv.txt           # 记下 inode 号，例如 524400
mv test_mv.txt subdir/
ls -i subdir/test_mv.txt    # inode 号不变，仍为 524400
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-i` | 交互式（Interactive），覆盖已有文件前询问确认 | 可选 | 静默覆盖 |
| `-v` | 显示详细信息（Verbose），每移动一个文件都打印出来 | 可选 | 静默 |
| `-n` | 不覆盖（No-clobber）已存在的文件 | 可选 | 默认覆盖 |
| `-u` | 仅当源文件比目标文件新（Update）或目标不存在时才移动 | 可选 | 总是移动 |
| `-b` | 覆盖前创建备份（Backup），备份文件名后附加 `~` | 可选 | 直接覆盖 |
| `-f` | 强制（Force），不提示确认 | 可选 | 否 |

**mv 与 cp 的本质区别：**

```bash
# cp：复制数据，创建新 inode
cp largefile.bin copy.bin    # 读取 + 写入，耗时取决于文件大小
ls -i largefile.bin copy.bin # inode 号不同

# mv：仅修改目录项，inode 不变（同一文件系统）
mv largefile.bin moved.bin   # 瞬间完成，与文件大小无关
ls -i moved.bin              # inode 号与原来相同
```

> **重要：** 在**同一文件系统**内，`mv` 是 O(1) 操作（不随文件大小增长），因为它只修改目录项中的文件名记录，不触碰数据块。但**跨文件系统**时（如从 `/home` 移动到 `/mnt/external_disk`），`mv` 会自动退化为"cp + rm"——先复制全部数据再删除源文件。

**跨文件系统移动的演示：**

```bash
# 创建一个小文件
dd if=/dev/urandom of=test_big.dat bs=1M count=50

# 在同一文件系统内移动——瞬间完成
time mv test_big.dat ~/Downloads/
# real 耗时接近 0 秒

# 跨文件系统移动（假设 /mnt/usb 是另一个分区）——耗时长
# time mv ~/Downloads/test_big.dat /mnt/usb/
# real 耗时可能数秒
```

### 3.8 rm -- 删除文件

`rm`（Remove）用于删除文件。这是命令行中最"危险"的命令之一——一旦删除，文件不会进入回收站（Trash/Recycle Bin），而是被直接移除。

**语法：**

```
rm [参数] <文件路径...>
```

**基础用法：**

```bash
# 创建一个测试文件然后删除
echo "temporary" > temp.txt
ls temp.txt                 # 确认存在
rm temp.txt
ls temp.txt                 # 报错: No such file or directory
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-r` / `-R` | 递归（Recursive）删除，用于删除目录及其全部内容 | 可选 | 仅删除普通文件 |
| `-i` | 交互式（Interactive），删除每个文件前询问确认（输入 `y` 确认，`n` 跳过） | 可选 | 静默删除 |
| `-f` | 强制（Force），忽略不存在的文件，不提示确认，跳过权限检查 | 可选 | 否 |
| `-v` | 显示详细信息（Verbose），每删除一个文件都打印出来 | 可选 | 静默 |
| `-d` | 删除空目录（等同于 `rmdir`） | 可选 | 不删除目录 |
| `--preserve-root` | 保护根目录 `/` 不被误删（Ubuntu 24.04 默认启用） | 可选 | 已启用 |

#### 3.8.1 安全删除习惯

**黄金法则：永远在按回车之前再读一遍命令。**

具体可操作的习惯：

```bash
# 1. 删除前先用 ls 确认要删的是哪些文件
ls *.tmp
rm *.tmp                      # 确认 ls 列出的正是你要删的

# 2. 使用 -i 交互模式
rm -i important_config.conf   # 系统会问"rm: remove regular file 'important_config.conf'?"

# 3. 使用 -v 查看删了哪些
rm -v *.log                   # 每行输出 deleted 'xxx.log'

# 4. 对于重要的删除操作，先用 echo 模拟
echo rm -rf /some/directory   # 调试脚本时，先用 echo 看看命令长什么样
# 确认无误后去掉 echo 再执行

# 5. 优先使用 trash-cli 替代 rm（详见 6.1 节）
```

#### 3.8.2 删除目录：`rm -r`

```bash
mkdir -p test_dir/sub
touch test_dir/sub/file.txt
rm -r test_dir                 # 递归删除目录及其所有内容
ls test_dir                    # 报错: No such file or directory
```

#### 3.8.3 `rm -rf`：最危险的组合

`rm -rf` 组合使用 `-r`（递归）和 `-f`（强制，不询问），是威力最大的命令组合之一。

```bash
# 这可以是一种正常用法——快速清理一个完整的目录
rm -rf /tmp/build_cache/

# 这也可能是一场灾难——如果路径变量为空
rm -rf /$EMPTY_VAR/something
# 等价于: rm -rf //something → rm -rf /something（危险！）
```

**经典的 `rm -rf /` 灾难：**

这并不是神话或传说。许多系统管理员都有过（或目睹过）类似的经历。当你以 root 身份运行以下命令时：

```bash
# 意图：删除当前目录下的所有内容
rm -rf ./*

# 如果你不小心在 . 和 / 之间多了一个空格：
rm -rf . /*
# 等价于两条命令：
# rm -rf .     ← 删除当前目录（还好）
# rm -rf /*    ← 删除根目录下的所有内容（灾难！）
```

根目录 `/` 下的文件一旦开始被递归删除，系统将在数秒内变得不可用——`/bin`、`/etc`、`/lib` 中的关键文件逐个消失，正在运行的命令纷纷报错，系统彻底崩溃，唯一的恢复方式是从备份中重建或重装系统。

在 Ubuntu 24.04 中，GNU coreutils 版本的 `rm` 默认启用了 `--preserve-root` 保护：

```bash
# 尝试 rm -rf / 会被拒绝
sudo rm -rf /
# rm: it is dangerous to operate recursively on '/'
# rm: use --no-preserve-root to override this failsafe
```

但这个保护仅适用于字面上的 `/`。以下变体仍然危险：

```bash
rm -rf /*            # 通配符展开后不受保护
rm -rf /home/oops /  # 多参数中的 / 同样危险
```

**底线：** 不要以 root 身份运行你不完全理解的 `rm` 命令。在使用 `rm -rf` 之前，停下来，再读一遍命令，确认路径完全正确。

### 3.9 rmdir -- 删除空目录

`rmdir`（Remove Directory）专门用于删除**空目录**。如果目录中包含任何文件或子目录，`rmdir` 会拒绝删除并报错。

**语法：**

```
rmdir [参数] <目录路径>
```

**基础用法：**

```bash
mkdir empty_dir
rmdir empty_dir
ls empty_dir                 # 报错: No such file or directory
```

删除非空目录时会被拒绝：

```bash
mkdir nonempty_dir
touch nonempty_dir/file.txt
rmdir nonempty_dir
# rmdir: failed to remove 'nonempty_dir': Directory not empty
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-p` | 递归删除嵌套空目录（Parents）。删除目标后，如果其父目录也变成空目录，则继续向上删除 | 可选 | 仅删除目标 |
| `-v` | 显示详细信息（Verbose） | 可选 | 静默 |
| `--ignore-fail-on-non-empty` | 如果目录非空，不报错（静默跳过） | 可选 | 报错 |

**使用 `-p` 清理空目录链：**

```bash
mkdir -p a/b/c/d
rmdir -pv a/b/c/d
```

预期输出：

```
rmdir: removing directory, 'a/b/c/d'
rmdir: removing directory, 'a/b/c'
rmdir: removing directory, 'a/b'
rmdir: removing directory, 'a'
```

**`rmdir` vs `rm -r`：**

| | `rmdir` | `rm -r` |
|------|---------|---------|
| 仅删除空目录 | 是 | 否（删除所有内容） |
| 安全性 | 高——绝不会误删有内容的目录 | 低——操作不可逆 |
| 适用场景 | 清理已知为空的目录结构 | 确实要删除含文件的目录时 |
| 推荐 | 首选，更安全 | 确认后再用 |

```bash
# 安全做法：先用 rmdir 尝试，失败了再考虑 rm -r
rmdir mydir 2>/dev/null || echo "目录非空，需要手动检查内容"
```

### 3.10 stat -- 查看文件的元数据

`stat` 命令显示文件的详细元数据（Metadata）——包括 inode 号、链接计数、三种时间戳、文件大小和权限等。它是理解 Linux 文件系统的"透视镜"。

**语法：**

```
stat [参数] <文件路径>
```

**基础用法：**

```bash
echo "Hello stat" > stat_demo.txt
stat stat_demo.txt
```

预期输出：

```
  File: stat_demo.txt
  Size: 11              Blocks: 8          IO Block: 4096   regular file
Device: 8,3     Inode: 524311      Links: 1
Access: (0664/-rw-rw-r--)  Uid: ( 1000/zhangsan)   Gid: ( 1000/zhangsan)
Access: 2024-07-29 10:00:00.000000000 +0800
Modify: 2024-07-29 10:00:00.000000000 +0800
Change: 2024-07-29 10:00:00.000000000 +0800
 Birth: 2024-07-29 10:00:00.000000000 +0800
```

**输出字段解读：**

| 字段 | 值（示例） | 含义 |
|------|-----------|------|
| `File` | `stat_demo.txt` | 文件名 |
| `Size` | `11` | 文件大小（字节） |
| `Blocks` | `8` | 文件占用的磁盘块数（每个块 512 字节） |
| `IO Block` | `4096` | 文件系统的 I/O 块大小 |
| `Device` | `8,3` | 设备号（主设备号, 次设备号） |
| `Inode` | `524311` | inode 号 |
| `Links` | `1` | 硬链接计数 |
| `Access` | `(0664/-rw-rw-r--)` | 文件权限（八进制 + 符号表示） |
| `Uid` / `Gid` | `(1000/zhangsan)` | 所有者用户 ID 和组 ID |
| `Access` 时间 | ... | 访问时间（Access Time / atime）——文件数据最后一次被读取的时间 |
| `Modify` 时间 | ... | 修改时间（Modification Time / mtime）——文件内容最后一次被修改的时间 |
| `Change` 时间 | ... | 变更时间（Change Time / ctime）——文件元数据（权限、所有者等）最后一次被更改的时间 |
| `Birth` 时间 | ... | 创建时间（Birth Time）——文件被创建的时间。并非所有文件系统都支持 |

**三种时间戳的区别：**

| 时间戳 | 含义 | 触发变更的操作 |
|--------|------|---------------|
| **atime**（Access Time） | 文件数据被读取的时间 | `cat file`、`grep` 读取文件内容 |
| **mtime**（Modification Time） | 文件内容被修改的时间 | `echo "x" >> file`、编辑器保存 |
| **ctime**（Change Time） | 文件元数据被变更的时间 | `chmod`、`chown`、`mv`（同一文件系统内）、`ln` |
| **Birth**（Creation Time） | 文件创建的时间 | 文件首次创建时设置，之后不再改变 |

**验证 atime 和 mtime：**

```bash
# 查看初始时间
stat stat_demo.txt

# 读取文件内容——更新 atime
cat stat_demo.txt
stat stat_demo.txt           # Access 时间已更新

# 修改文件内容——更新 mtime 和 ctime
echo "new line" >> stat_demo.txt
stat stat_demo.txt           # Modify 和 Change 时间已更新
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-c` / `--format=FORMAT` | 自定义输出格式（使用格式说明符） | 可选 | 完整输出 |
| `-f` | 显示文件系统状态而非文件状态 | 可选 | 文件状态 |
| `-L` | 跟随符号链接（Dereference），显示目标文件的信息 | 可选 | 显示符号链接自身信息 |
| `-t` | 简洁模式（Terse），一行输出，无标签 | 可选 | 完整格式 |

**自定义输出格式：**

```bash
# 仅显示文件名和大小
stat -c "File: %n, Size: %s bytes" stat_demo.txt

# 仅显示 inode 号和链接计数
stat -c "Inode: %i, Links: %h" stat_demo.txt

# 显示三种时间戳
stat -c "Access: %x | Modify: %y | Change: %z" stat_demo.txt
```

常用格式说明符：

| 格式符 | 含义 |
|--------|------|
| `%n` | 文件名 |
| `%s` | 文件大小（字节） |
| `%i` | inode 号 |
| `%h` | 硬链接计数 |
| `%a` | 八进制权限 |
| `%A` | 符号权限（如 `-rw-rw-r--`） |
| `%U` | 所有者用户名 |
| `%G` | 所属组名 |
| `%x` / `%y` / `%z` | atime / mtime / ctime |

### 3.11 file -- 判断文件类型

`file` 命令在上一章已有介绍。此处从文件操作的视角补充两个实用参数和典型使用场景。

### 3.12 ln -- 创建硬链接与软链接

`ln`（Link）用于在文件之间创建链接。这是本章最深度的内容——我们将从命令层面到 inode 层面全面讲解。

**语法：**

```
ln [参数] <目标> [链接名]
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-s` | 创建软链接（Symbolic Link / Soft Link） | 可选 | 创建硬链接 |
| `-f` | 强制（Force），如果链接名已存在则覆盖 | 可选 | 不覆盖 |
| `-n` | 如果链接名已存在且是一个指向目录的软链接，不进入该目录 | 可选 | 否 |
| `-v` | 显示详细信息（Verbose） | 可选 | 静默 |
| `-b` | 覆盖前创建备份 | 可选 | 直接覆盖 |

**注意：** `ln` **默认创建硬链接**。要创建软链接，**必须**加 `-s`。新手常犯的错误就是忘记 `-s`，创建了意料之外的硬链接。

#### 3.12.1 硬链接实战

**创建硬链接并验证 inode 相同：**

```bash
# 创建原始文件
echo "This is the original file." > original.txt

# 创建硬链接
ln original.txt hardlink.txt

# 验证：查看 inode 号——两者完全相同
ls -li original.txt hardlink.txt
```

预期输出（注意第一列 inode 号相同，第三列链接计数为 2）：

```
524350 -rw-rw-r-- 2 zhangsan zhangsan 27 Jul 29 10:00 hardlink.txt
524350 -rw-rw-r-- 2 zhangsan zhangsan 27 Jul 29 10:00 original.txt
```

**验证：修改任意一个，另一个同步变化（因为是同一个 inode）：**

```bash
echo "追加一行" >> original.txt
cat hardlink.txt
```

输出：

```
This is the original file.
追加一行
```

**验证：删除"原文件"后，硬链接仍然有效：**

```bash
rm original.txt
cat hardlink.txt             # 内容仍然完整！

# 查看 inode 信息——链接计数从 2 降为 1
ls -li hardlink.txt
```

预期输出（链接计数变为 1）：

```
524350 -rw-rw-r-- 1 zhangsan zhangsan 41 Jul 29 11:00 hardlink.txt
```

**验证：不能跨文件系统创建硬链接：**

```bash
# 如果 /tmp 是独立分区（tmpfs），以下命令将失败
ln hardlink.txt /tmp/hardlink_copy.txt
# ln: failed to create hard link '/tmp/hardlink_copy.txt' => 'hardlink.txt': Invalid cross-device link
```

**验证：不能为目录创建硬链接：**

```bash
mkdir mydir
ln mydir mydir_link
# ln: mydir: hard link not allowed for directory
```

> 唯一的例外是 `.` 和 `..`，它们由文件系统在创建目录时自动维护。

#### 3.12.2 软链接实战

**创建软链接：**

```bash
# 创建原始文件
echo "Target content" > target.txt

# 创建软链接
ln -s target.txt symlink.txt

# 验证——文件类型显示为 l，文件名后有 -> target.txt
ls -l symlink.txt
```

预期输出：

```
lrwxrwxrwx 1 zhangsan zhangsan 10 Jul 29 10:00 symlink.txt -> target.txt
```

注意：
- 第一列以 `l` 开头，表示这是一个符号链接
- 文件名后面有 `-> target.txt`，显示它指向的目标
- 权限字段显示为 `rwxrwxrwx`（全权限），但实际访问权限依然由目标文件（target.txt）的权限决定
- 链接计数为 1（软链接不影响目标文件的链接计数）

**验证 inode 不同：**

```bash
ls -li target.txt symlink.txt
```

预期输出（注意 inode 号**不同**）：

```
524360 -rw-rw-r-- 1 zhangsan zhangsan 15 Jul 29 10:00 symlink.txt
524355 -rw-rw-r-- 1 zhangsan zhangsan 15 Jul 29 10:00 target.txt
```

**通过软链接读取和修改内容：**

```bash
cat symlink.txt              # 输出: Target content
echo "追加" >> symlink.txt
cat target.txt               # 输出中也包含"追加"——修改透过软链接作用于目标文件
```

**删除目标文件后软链接断裂：**

```bash
rm target.txt
cat symlink.txt
# cat: symlink.txt: No such file or directory

# 软链接本身还在
ls -l symlink.txt
# 输出: lrwxrwxrwx 1 zhangsan zhangsan 10 Jul 29 10:00 symlink.txt -> target.txt
# 但颜色可能变为红色（表示断开的链接）
```

**指向目录的软链接：**

```bash
mkdir -p /tmp/test_link_dir
ln -s /tmp/test_link_dir dir_link
ls -l dir_link               # 输出: dir_link -> /tmp/test_link_dir
cd dir_link                  # 可以像进入普通目录一样进入软链接
pwd -L                       # 输出包含 dir_link 的逻辑路径
pwd -P                       # 输出 /tmp/test_link_dir（物理路径）
```

**使用相对路径创建软链接（重要陷阱）：**

```bash
# 假设当前在 ~/ch04-practice/
mkdir -p sub/dir
echo "deep file" > sub/dir/deep.txt

# 在 sub/ 下创建指向 dir/deep.txt 的软链接
cd sub
ln -s dir/deep.txt link_to_deep     # 使用相对路径
cat link_to_deep                     # 正常工作，输出 "deep file"

# 但是，如果移动这个软链接，相对路径就可能失效
cd ..
mv sub/link_to_deep .
cat link_to_deep
# cat: link_to_deep: No such file or directory
# 因为 link_to_deep 中存储的路径 "dir/deep.txt" 在当前目录下不存在
```

> **教训：** 如果软链接可能需要被移动，创建时目标应使用绝对路径：`ln -s /home/zhangsan/ch04-practice/sub/dir/deep.txt link_to_deep`

#### 3.12.3 用 stat 区分硬链接和软链接

```bash
# 创建对比样本
echo "data" > compare.txt
ln compare.txt hard_compare.txt          # 硬链接
ln -s compare.txt soft_compare.txt       # 软链接

# 对比 stat 输出
echo "=== 硬链接 ==="
stat hard_compare.txt | grep -E "Inode|Links|Size"
echo "=== 软链接 ==="
stat soft_compare.txt | grep -E "Inode|Links|Size"
```

关键区别：
- 硬链接的 Inode 号和原文件相同，Links 为 2
- 软链接的 Inode 号与原文件不同，Links 为 1，Size 为路径字符串的长度

### 3.13 basename 与 dirname -- 路径解析

`basename` 和 `dirname` 是两个文本处理命令，用于从路径字符串中提取文件名和目录名。它们不访问文件系统——只是对字符串做路径解析。

**语法：**

```
basename <路径> [后缀]
dirname <路径>
```

**基础用法：**

```bash
# basename：提取路径的最后一部分（文件名或最末级目录名）
basename /home/zhangsan/Documents/report.txt
# 输出: report.txt

basename /home/zhangsan/Documents/
# 输出: Documents

# dirname：提取除最后一部分之外的路径（目录部分）
dirname /home/zhangsan/Documents/report.txt
# 输出: /home/zhangsan/Documents

dirname /home/zhangsan/
# 输出: /home
```

**basename 去除后缀：**

```bash
# 指定要去除的后缀
basename /path/to/script.sh .sh
# 输出: script

basename /path/to/archive.tar.gz .gz
# 输出: archive.tar（仅去除 .gz）

basename /path/to/archive.tar.gz .tar.gz
# 输出: archive（去除整个 .tar.gz）
```

**实用场景——在脚本中使用：**

```bash
FILEPATH="/var/log/syslog"

# 获取文件名
FILENAME=$(basename "$FILEPATH")
echo "文件: $FILENAME"        # 输出: 文件: syslog

# 获取所在目录
DIRPATH=$(dirname "$FILEPATH")
echo "目录: $DIRPATH"         # 输出: 目录: /var/log
```

**参数：**

| 命令 | 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|------|----------|--------|
| `basename` | `-a` | 支持多个参数（All），每个参数独立处理 | 可选 | 仅处理第一个 |
| `basename` | `-s` | 指定要去除的后缀（Suffix） | 可选 | 不去除 |
| `basename` | `-z` | 以空字符（Null / `\0`）而非换行符分隔输出 | 可选 | 换行符 |
| `dirname` | `-z` | 以空字符而非换行符分隔输出 | 可选 | 换行符 |

**处理多个路径：**

```bash
basename -a /etc/hostname /var/log/syslog /home/zhangsan
# 输出:
# hostname
# syslog
# zhangsan

basename -a -s .txt chapter01.txt chapter02.txt
# 输出:
# chapter01
# chapter02
```

## 5. 常见错误与排错

### 5.1 "No such file or directory"（文件或目录不存在）

**现象：**

```bash
cd /tmp/nonexistent
```

```
bash: cd: /tmp/nonexistent: No such file or directory
```

**常见原因与排查：**

| 原因 | 排查方法 | 解决 |
|------|----------|------|
| 拼写错误 | 用 `ls` 列出父目录，对比拼写；善用 Tab 补全 | 修正拼写 |
| 大小写错误 | Linux 区分大小写。`Documents` != `documents` | 核对实际大小写 |
| 相对路径理解错误 | 执行 `pwd` 确认当前目录，再推算路径 | 用绝对路径或修正相对路径 |
| 路径中包含空格未引号 | `ls "path with spaces"` 或 `ls path\ with\ spaces` | 始终给含空格的路径加引号 |
| 软链接指向的目标已删除 | `ls -l symlink` 查看目标路径，检查目标是否存在 | 重建目标或删除断裂的软链接 |

### 5.2 "Permission denied"（权限不足）

**现象：**

```bash
rm /etc/passwd
```

```
rm: remove write-protected regular file '/etc/passwd'?
```

或：

```bash
mkdir /new_system_dir
```

```
mkdir: cannot create directory '/new_system_dir': Permission denied
```

**原因与解决：**

| 场景 | 解决方法 |
|------|----------|
| 需要 root 权限的操作 | 使用 `sudo` 前缀：`sudo mkdir /new_system_dir` |
| 文件设置了不可变属性 | 使用 `lsattr` 查看，`chattr -i` 解除（需要 root） |
| 目录权限不足（无 w 权限） | 使用 `ls -ld dir/` 查看权限，需要所有者或 root 修改 |
| 文件系统以只读方式挂载 | 使用 `mount` 查看挂载选项，若包含 `ro` 则需 `sudo mount -o remount,rw /` |

### 5.3 "Directory not empty"（目录非空）

**现象：**

```bash
rmdir my_directory
```

```
rmdir: failed to remove 'my_directory': Directory not empty
```

**原因：** `rmdir` 只能删除空目录。目录中可能包含普通文件、隐藏文件或子目录。

**排查与解决：**

```bash
# 先看看目录里有什么（包括隐藏文件）
ls -la my_directory

# 如果确认要全部删除，使用 rm -r
rm -r my_directory

# 更安全的做法：先列出再删除
ls -la my_directory
# 确认内容无误后
rm -rf my_directory
```

> **注意：** `rm -rf dir` 不会询问确认。假如你 `rm -rf /etc`（用 root 权限），系统就会"没了"。使用前务必确认路径正确。

### 5.4 cp 覆盖文件时未提示

**现象：**

你执行了 `cp source.txt target.txt`，发现 `target.txt` 原来的内容被静默覆盖了，没有收到任何警告。

**原因：** 默认情况下，`cp` 直接覆盖目标文件而不询问。

**解决：** 养成使用 `-i`（交互式）或 `-n`（不覆盖）的习惯：

```bash
# 交互式——覆盖前询问
cp -i source.txt target.txt

# 不覆盖——目标已存在则跳过
cp -n source.txt target.txt

# 为 cp 设置别名（一劳永逸）
alias cp='cp -i'
```

Ubuntu 24.04 默认为 root 用户设置了 `alias cp='cp -i'`，但普通用户可能没有。你可以手动添加：

```bash
# 将别名加入 ~/.bashrc 以永久生效
echo "alias cp='cp -i'" >> ~/.bashrc
echo "alias mv='mv -i'" >> ~/.bashrc
echo "alias rm='rm -i'" >> ~/.bashrc
source ~/.bashrc
```

### 5.5 mv 后文件"消失"

**现象：**

执行 `mv file.txt /etc` 后，`file.txt` 在当前目录不见了，但你期望的是把它"放进去"。

**原因：** 这通常不是命令的错误——`mv` 的行为正是如此（移走）。但以下情况可能让你困惑：

- 目标是一个**已有目录**：文件被移入该目录，原位置的文件消失（这是预期行为）
- 目标路径拼写错误：比如 `mv file.txt /etcc`（多了一个 c），文件被重命名为根目录下的 `etcc`，而非移入 `/etc/` 中

**排查与预防：**

```bash
# 移动前先确认信息
ls -ld /etc             # 确认目标是一个目录

# 如果要移动文件到目录，在目标路径后加 / 进一步明确意图
mv file.txt /etc/       # 如果 /etc/ 不是目录，mv 会报错而不是重命名
```

### 5.6 rm 误删后的数据恢复可能性

**场景：** 不小心执行了 `rm important_file.txt`，文件没有进入回收站。

**恢复原理：**

在传统机械硬盘（HDD）上，`rm` 删除文件后，inode 和数据块被标记为"可用"，但数据本身并未被立即覆写。在数据被新文件覆盖之前，有可能通过数据恢复工具（如 `extundelete`、`testdisk`、`photorec`）恢复。

在 SSD 上，由于 TRIM 命令的存在，数据会在删除后被快速擦除，恢复可能性极低。

**立刻采取的行动：**

```bash
# 1. 立即停止写入任何数据到该文件所在的分区！
#    不要再创建新文件、安装软件、下载内容——写入可能覆盖被删除的数据块

# 2. 如果分区可以卸载（非系统分区），立即卸载
sudo umount /dev/sdXY

# 3. 使用恢复工具
# （以下仅示意，实际使用需要先安装对应工具）
# sudo extundelete /dev/sdXY --restore-all
```

> **最重要的结论：** 恢复从未被保证。最可靠的"恢复"是**备份**。如果你有重要数据，请养成分阶段备份的习惯——即使最简单的 `cp -a /important/data /backup/location` 也远好过追悔莫及。

### 5.7 软链接"断裂"（Dangling Link）

**现象：**

```bash
ls -l mylink
# lrwxrwxrwx 1 zhangsan zhangsan 15 Jul 29 10:00 mylink -> /nonexistent/path
# 在某些终端中，断开的软链接会以红色闪烁或红色背景显示
```

**排查与修复：**

```bash
# 检查目标是否存在
test -e mylink && echo "有效" || echo "断裂"

# 找到并列出所有断裂的软链接
find /path/to/check -xtype l

# 修复：删除断裂链接或重建目标
rm mylink                    # 删除断裂链接
ln -sf /real/path mylink     # 重建指向正确目标的软链接
```

### 5.8 在循环或脚本中使用相对路径

**现象：** 你写了一个脚本，使用相对路径进行操作，但脚本的执行结果取决于你从哪个目录运行它，有时成功有时失败。

**原因：** 相对路径是基于**当前工作目录**解析的，而不是基于脚本文件所在的位置。

**解决：**

```bash
# 脚本开头，切换到脚本所在的目录
cd "$(dirname "$0")"

# 或者使用绝对路径
DATA_DIR="/home/zhangsan/data"
cp "$DATA_DIR/source.txt" "$DATA_DIR/backup/"
```

### 6.1 trash-cli：安全的删除替代方案

如前文所述，`rm` 删除的文件不经过回收站，直接不可见。`trash-cli` 是一个命令行工具套件，提供类似桌面回收站（Trash）的功能——删除的文件先进入回收站，需要时可以恢复，确认不需要时可以永久清空。

**安装：**

```bash
sudo apt install trash-cli -y
```

**核心命令：**

| 命令 | 功能 | 对应 rm 的什么 |
|------|------|---------------|
| `trash-put` | 将文件/目录移入回收站 | 替代 `rm` |
| `trash-list` | 列出回收站中的所有条目 | 无对应 |
| `trash-restore` | 交互式恢复回收站中的文件 | 无对应（`rm` 后无法恢复） |
| `trash-empty` | 清空回收站（永久删除） | 无对应 |
| `trash-rm` | 从回收站中删除特定文件 | 无对应 |

**使用示例：**

```bash
# 将文件放入回收站
echo "important data" > crucial.txt
trash-put crucial.txt
ls crucial.txt               # 报错: No such file or directory（已在回收站中）

# 查看回收站内容
trash-list
# 输出类似: 2024-07-29 10:00:00 /home/zhangsan/ch04-practice/crucial.txt

# 恢复文件
trash-restore                # 交互式选择要恢复的条目

# 永久清空回收站
trash-empty
```

**创建别名用 trash-put 替代 rm：**

```bash
# 将以下内容加入 ~/.bashrc
alias rm='echo "请使用 trash-put 代替 rm，或使用 \\rm 绕过别名"'
alias tp='trash-put'         # 简短的别名

# 当你确实需要绕过回收站时
\rm somefile.txt             # 前置反斜杠绕过别名
```

> **注意：** 在服务器脚本中不要使用 `trash-put` 作为 `rm` 的替代——日志文件、构建缓存等应该直接删除，否则回收站会很快被填满。`trash-cli` 适合交互式使用，特别是对重要个人文件的删除操作。

### 6.2 通配符（Glob Pattern）全面指南

通配符是命令行中的模式匹配（Pattern Matching）语法，Shell 在命令执行前将模式**展开**为匹配的文件名列表。这不是正则表达式（Regex），语法有区别。

#### 6.2.1 基本通配符

| 通配符 | 含义 | 示例 | 匹配结果 |
|--------|------|------|----------|
| `*` | 匹配任意长度（含零个）的任意字符 | `*.txt` | `a.txt`、`readme.txt`、`123.txt` |
| `?` | 匹配**恰好一个**任意字符 | `file?.txt` | `file1.txt`、`fileA.txt`，不匹配 `file10.txt` |
| `[abc]` | 匹配方括号中列出的任意一个字符 | `file[123].txt` | `file1.txt`、`file2.txt`、`file3.txt` |
| `[a-z]` | 匹配指定范围内的任意一个字符 | `file[a-z].txt` | `filea.txt`、`filez.txt` |
| `[!abc]` | 匹配**不在**方括号中的任意一个字符 | `file[!0-9].txt` | `fileA.txt`，不匹配 `file1.txt` |

#### 6.2.2 展开时机

通配符由 Shell 在命令执行**之前**展开，传递到命令的是已展开的文件列表：

```bash
# 假设当前目录有 a.txt, b.txt, c.txt
echo *.txt
# Shell 将 *.txt 展开为 a.txt b.txt c.txt 后传给 echo
# 输出: a.txt b.txt c.txt

# 如果没有匹配的文件，默认原样保留（Bash 默认行为）
echo *.xyz
# 输出: *.xyz
```

#### 6.2.3 扩展通配符（Extended Globbing）

Bash 支持扩展通配符，但需要先启用：

```bash
shopt -s extglob
```

| 模式 | 含义 | 示例 |
|------|------|------|
| `?(pattern)` | 匹配 0 次或 1 次 | `file?(s).txt` 匹配 `file.txt` 和 `files.txt` |
| `*(pattern)` | 匹配 0 次或多次 | `file*(s).txt` 匹配 `file.txt`、`filess.txt` 等 |
| `+(pattern)` | 匹配 1 次或多次 | `file+(a).txt` 匹配 `filea.txt`、`fileaa.txt` |
| `@(p1\|p2)` | 匹配给定模式之一 | `@(*.txt\|*.md)` 匹配任何 .txt 或 .md 文件 |
| `!(pattern)` | 匹配**不**符合模式的内容 | `!(*.txt)` 匹配所有非 .txt 文件 |

#### 6.2.4 通配符与文件操作结合

```bash
# 删除所有 .log 文件
rm -v *.log

# 复制所有 .c 和 .h 文件到目标目录
cp *.[ch] target_dir/

# 列出所有不以 .txt 结尾的文件
ls -d !(*.txt)

# 移动所有以数字编号开头的文件
mv [0-9]* archive/
```

### 6.3 深入 inode 与文件系统

#### 6.3.1 查看文件系统的 inode 使用情况

`df -i` 显示每个文件系统的 inode 总量和使用量：

```bash
df -i
```

预期输出（示例）：

```
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
tmpfs           251888    692  251196    1% /run
/dev/sda3      1875968 379501 1496467   21% /
```

如果 inode 用尽（IFree = 0 且 IUse% = 100%），即使磁盘还有剩余空间，也无法创建新文件——每个文件都需要一个 inode。这种情况常见于邮件服务器（大量小文件）或 Docker 容器中。

#### 6.3.2 目录的链接计数

还记得 `ls -l` 输出的第二列吗？对于目录，这个数字有特殊的含义：

```bash
mkdir test_dir
ls -ld test_dir               # Links: 2
```

为什么新建的空目录链接计数是 2？

- **1 个来自目录项的自身**：`test_dir`（位于其父目录的目录项中）
- **1 个来自 `test_dir/.`**：`.` 是指向本目录的一个硬链接

再创建子目录：

```bash
mkdir test_dir/sub
ls -ld test_dir               # Links: 3
```

为什么变成 3 了？

- **新增 1 个来自 `test_dir/sub/..`**：每个新子目录的 `..` 都指向父目录，使父目录的链接计数 +1

这意味着：**目录的链接计数 = 2 + 直接子目录的数量**。

#### 6.3.3 同一个文件系统内 mv 是原子操作

在同一个文件系统（分区）内，`mv` 操作是原子的（Atomic）——它只修改目录项中的文件名记录，不涉及数据块的复制。这意味着：

```bash
# 即使移动超大文件，也瞬间完成
mv huge_file.dat /same_partition/other_dir/

# mv 不会产生中间状态——要么旧名字还在，要么新名字生效
# 不会出现"文件暂时不存在"或"文件内容不完整"的情况
```

这也是为什么许多程序在保存文件时使用"写临时文件 + 移动"的策略：

```bash
# 常见的原子保存模式
echo "new content" > file.tmp
mv file.tmp file.txt          # 原子替换
# 不会出现 file.txt 的内容被"写到一半"的状态
```

文件系统内部，`mv` 的原子性来自系统调用 `rename()`，它仅在目录项层面操作，不触碰 inode 或数据块。
