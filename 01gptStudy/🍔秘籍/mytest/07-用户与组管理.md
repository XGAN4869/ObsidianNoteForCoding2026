## 1. 概述

### 1.1 从"单枪匹马"到"团队协作"

迄今为止，你所做的一切操作——创建文件、删除目录、查看日志——都是在"你自己"的账户下完成的。你的家目录、你的文件权限、你的 Shell 配置，全部围绕"你"这一个用户运转。Linux 像一台单用户操作系统那样为你服务。

但这只是错觉。

Linux 从诞生之初就是一个**多用户（Multi-user）**操作系统。即使你现在只有一个人在使用这台机器，系统内部早已"住"着几十个"用户"——Web 服务以 `www-data` 的身份运行，数据库以 `mysql` 的身份运行，日志系统以 `syslog` 的身份运行……这些不是你创建的"人"，而是系统在安装过程中自动创建的**服务账户（Service Account）**。

当你把一台 Linux 服务器交给多个管理员、多个开发者、甚至多个应用同时使用时，"谁可以做什么"这个问题就变得至关重要。本章正是回答这个问题的起点——你将学会如何创建用户和组、如何管理密码和账户过期策略、以及如何赋予和限制管理权限。

### 1.2 本章命令全景

本章覆盖的 17 个命令可以分为五组：

| 分组 | 命令 | 功能 |
|------|------|------|
| **身份查看（Identity）** | `whoami`、`id`、`who`、`w`、`users`、`last` | 查看当前用户身份、用户组归属、登录用户、登录历史 |
| **用户管理（User Admin）** | `useradd`、`usermod`、`userdel` | 创建、修改、删除用户账户 |
| **组管理（Group Admin）** | `groupadd`、`groupmod`、`groupdel` | 创建、修改、删除用户组 |
| **密码与过期（Password）** | `passwd`、`chage` | 设置/修改密码、管理密码过期策略 |
| **权限切换（Privilege）** | `su`、`sudo`、`visudo` | 切换用户身份、以其他用户身份执行命令、安全编辑 sudo 配置 |

其中，`sudo` 和 `visudo` 是本章的绝对重点。`sudo` 是 Ubuntu 安全模型的核心——它让你在不暴露 root 密码的前提下，按需获取管理权限。`visudo` 是编辑 sudo 配置的唯一安全方式——它能防止配置错误导致的灾难性后果（例如把自己完全锁定在 sudo 之外）。

### 1.3 为什么这些命令默认不让你用

敏锐的你可能会发现：这一章的许多命令（`useradd`、`passwd`、`visudo` 等）在运行时会提示 `Permission denied`（权限不足）。这不是 bug，这是设计。在练习本章的命令之前，你需要先理解一个概念：

**你当前登录的普通用户没有"管理其他用户"的权限。** 这是 Linux 安全模型的基础——只有 root（超级用户）以及被授权的 sudo 用户才能执行用户管理操作。

因此，本章的练习需要你使用 `sudo` 前缀。例如：

```bash
# 错误：普通用户直接执行
useradd testuser                          # Permission denied

# 正确：使用 sudo 提升权限
sudo useradd -m testuser                  # 成功创建用户
```

如果你还不熟悉 `sudo` 的含义，不用担心——本章 §3.16 将对它做详细讲解。在那之前，你只需记住：**当看到 `sudo` 前缀时，把它视为"以管理员身份执行"即可。**

### 1.4 本章学习目标

完成本章后，你将能够：

- 理解 UID（用户标识号，User ID）和 GID（组标识号，Group ID）的概念及其在文件系统中的底层作用
- 读懂 `/etc/passwd`、`/etc/shadow`、`/etc/group` 三个文件的每一个字段
- 使用 `whoami`、`id`、`who`、`w`、`users`、`last` 查看当前用户身份和系统登录状态
- 使用 `useradd` 创建用户账户，理解 `-m`、`-s`、`-G` 等关键参数
- 使用 `usermod` 修改已有用户的属性（家目录、Shell、附加组等）
- 使用 `userdel` 安全地删除用户（含 `-r` 清理家目录）
- 使用 `groupadd`、`groupmod`、`groupdel` 管理用户组
- 使用 `passwd` 设置和修改密码、锁定和解锁账户
- 使用 `chage` 配置密码过期策略（强制用户定期修改密码）
- 使用 `su` 切换到其他用户身份
- 深刻理解 `sudo` 的工作原理，能安全地使用 `visudo` 编辑 sudoers 配置
- 配置 NOPASSWD 免除密码输入，配置命令白名单限制 sudo 权限范围
- 理解用户管理背后的安全原则——最小权限原则（Principle of Least Privilege）

## 2. 核心概念

### 2.1 多用户系统的本质：谁是谁，谁可以做什么

在深入命令之前，必须先建立三个底层概念。没有这三个概念，你只是在"背诵命令"；理解了它们，你才能真正"驾驭命令"。

```
┌──────────────────────────────────────────────────────────────────┐
│                        Linux 多用户安全模型                       │
│                                                                  │
│   你是谁                   你能做什么              发生在哪里     │
│   ─────────                ─────────              ────────       │
│   UID (用户标识号)    →    文件权限              →  /etc/passwd   │
│   GID (组标识号)     →    目录权限              →  /etc/shadow   │
│   Groups (附加组)    →    sudo 授权             →  /etc/group    │
│                                                                  │
│   认证（Authentication）   授权（Authorization）   审计（Audit）   │
│   验证你就是你             决定你能做什么           记录你做了什么   │
└──────────────────────────────────────────────────────────────────┘
```

#### 2.1.1 UID（用户标识号，User ID）

**计算机不认识人名，只认识数字。** 当你创建一个叫 `zhangsan` 的用户时，Linux 内核并不关心这个名字——它只关心分配给 `zhangsan` 的 UID（一个无符号整数）。

| UID 范围 | 用途 | 说明 |
|----------|------|------|
| **0** | root（超级用户） | 拥有系统全部权限，只有一个 |
| **1 - 999** | 系统用户（System Users） | 由系统或软件包自动创建，用于运行后台服务。旧版 Linux 使用 1-499，Ubuntu 24.04 使用 1-999 |
| **1000 - 60000** | 普通用户（Regular Users） | 你创建的人类用户。Ubuntu 24.04 中第一个普通用户通常从 UID 1000 开始 |
| **65534** | `nobody` 用户 | 一个权限极低的特殊用户，常用于运行"谁都不应该以特权身份运行"的服务 |

**查看你的 UID：**

```bash
# 方法一：使用 id 命令
id -u

# 方法二：查看 /etc/passwd
grep "^$(whoami):" /etc/passwd
```

预期输出（示例）：

```
1000
zhangsan:x:1000:1000:Zhang San,,,:/home/zhangsan:/bin/bash
```

> **关键认知：** 当你执行 `ls -l` 查看文件属性时，看到的 `zhangsan` 不是存储在文件 inode 中的——inode 中只存储了 UID 数字（如 `1000`）。`ls` 在显示时通过查询 `/etc/passwd` 将 UID 翻译成人类可读的用户名。如果 `/etc/passwd` 中删除了 `zhangsan` 的条目，文件仍然属于 UID 1000，但 `ls` 将只能显示数字 `1000`。

#### 2.1.2 GID（组标识号，Group ID）与用户组

组的本质是一个**权限共享机制**——你可以把多个用户放进同一个组，然后对组统一授权，而不需要对每个用户单独设置。

| GID 范围 | 用途 |
|----------|------|
| **0** | root 组 |
| **1 - 999** | 系统组（System Groups） |
| **1000 - 60000** | 普通用户组 |

每个用户同时拥有两种组身份：

| 类型 | 说明 | 存储位置 |
|------|------|----------|
| **主组（Primary Group）** | 用户创建文件时，文件默认所属的组。每个用户**必须**有一个主组，且只能有一个 | `/etc/passwd` 第 4 个字段 |
| **附加组（Supplementary Groups）** | 用户额外加入的其他组。一个用户可以有 0 到多个附加组 | `/etc/group` 第 4 个字段 |

**查看你的组归属：**

```bash
# 查看当前用户的所有组（主组 + 附加组）
id
groups
```

预期输出（示例）：

```
uid=1000(zhangsan) gid=1000(zhangsan) groups=1000(zhangsan),4(adm),27(sudo),100(users)
```

**解读：** `zhangsan` 的主组是 GID 1000（`zhangsan` 组），同时还是 `adm`（可读日志）、`sudo`（可执行管理命令）、`users` 组的成员。

#### 2.1.3 Ubuntu 的"默认同组"策略

你可能注意到你的主组名和用户名是一样的（都是 `zhangsan`）。这不是巧合——Ubuntu 遵循**用户私有组（UPG, User Private Group）**策略：

- 每创建一个用户，系统自动创建一个**同名的私有组**作为该用户的主组
- 这避免了早期 Unix 中"用户默认属于 `users` 组导致文件权限不安全"的问题
- UPG 的默认 umask 为 0002（新建文件默认 `rw-rw-r--`），使同组成员可以协作编辑

```bash
# 验证你的用户和组是否采用 UPG 策略
id -un                                  # 你的用户名
id -gn                                  # 你的主组名
# 两者应该相同
```

### 2.2 /etc/passwd 文件：用户账户的信息登记簿

`/etc/passwd` 是 Linux 系统中最古老、最核心的配置文件之一。尽管名字是"passwd"（密码文件），但现代 Linux 中**密码已经不在这个文件里了**——密码被分离到了 `/etc/shadow` 中。

**但 `/etc/passwd` 仍然是"每个用户的第一入口"。** 当你登录时，系统做的第一件事就是在这个文件中查找你的用户名是否存在。

#### 2.2.1 文件格式：冒号分隔的七个字段

```bash
# 查看 /etc/passwd 文件内容
cat /etc/passwd
```

你会看到类似这样的每一行：

```
zhangsan:x:1000:1000:Zhang San,,,:/home/zhangsan:/bin/bash
```

格式为：

```
用户名:密码占位符:UID:GID:GECOS:家目录:登录Shell
```

**逐字段详解：**

| 字段序号 | 字段名 | 含义 | 示例值 | 说明 |
|----------|--------|------|--------|------|
| **1** | 用户名（Username） | 用户登录时使用的名称 | `zhangsan` | 区分大小写，建议只使用小写字母、数字、下划线和连字符 |
| **2** | 密码占位符（Password Placeholder） | 曾经存放加密密码，现在固定为 `x` | `x` | 真正的密码哈希存储在 `/etc/shadow` 第 2 个字段中。如果此字段为空（`::`），该账户无需密码即可登录——极度危险！ |
| **3** | UID | 用户的数字标识号 | `1000` | 0 = root，1-999 = 系统用户，1000+ = 普通用户 |
| **4** | GID | 用户主组的数字标识号 | `1000` | 对应 `/etc/group` 中的某个组 |
| **5** | GECOS（用户描述信息，General Electric Comprehensive Operating System 的缩写） | 用户的注释信息（全名、电话、办公室等） | `Zhang San,,,` | 兼容性字段，可以留空。格式：全名,办公室,工作电话,家庭电话 |
| **6** | 家目录（Home Directory） | 用户登录后的起始目录 | `/home/zhangsan` | 必须是绝对路径。如果目录不存在，用户登录时可能会收到警告或被拒绝登录 |
| **7** | 登录 Shell（Login Shell） | 用户登录后启动的 Shell 程序 | `/bin/bash` | 如果想禁用某用户的交互式登录，可以设置为 `/usr/sbin/nologin` 或 `/bin/false` |

#### 2.2.2 实际分析：逐行解读 /etc/passwd

```bash
# 查看你自己的 passwd 条目
grep "^$(whoami):" /etc/passwd

# 查看 root 的 passwd 条目
grep "^root:" /etc/passwd

# 查看所有普通用户（UID >= 1000）
awk -F: '$3 >= 1000 && $3 < 65534' /etc/passwd

# 查看所有系统用户（UID 1-999）
awk -F: '$3 >= 1 && $3 < 1000' /etc/passwd

# 统计用户总数
wc -l /etc/passwd
```

**典型条目解读：**

```
root:x:0:0:root:/root:/bin/bash
```

| 字段 | 值 | 解读 |
|------|-----|------|
| 用户名 | `root` | 超级用户 |
| 密码 | `x` | 密码在 /etc/shadow 中 |
| UID | `0` | UID 为 0 即拥有超级权限 |
| GID | `0` | 主组是 root 组 |
| GECOS | `root` | 描述文本 |
| 家目录 | `/root` | 注意：不是 `/home/root`，而是 `/root` |
| Shell | `/bin/bash` | 使用 bash |

```
nobody:x:65534:65534:nobody:/nonexistent:/usr/sbin/nologin
```

| 字段 | 值 | 解读 |
|------|-----|------|
| 用户名 | `nobody` | 一个"谁都不是"的特殊用户 |
| UID | `65534` | 这是 Linux 中最大、权限最低的 UID |
| 家目录 | `/nonexistent` | 这个目录不存在——nobody 不应该有家目录 |
| Shell | `/usr/sbin/nologin` | 禁止登录 |

```
sshd:x:110:65534::/run/sshd:/usr/sbin/nologin
```

| 字段 | 值 | 解读 |
|------|-----|------|
| 用户名 | `sshd` | SSH 守护进程的服务账户 |
| GECOS | （空） | 空描述字段（连续两个冒号之间为空） |
| Shell | `/usr/sbin/nologin` | 服务账户不应该能登录 |

#### 2.2.3 系统用户的识别特征

系统用户（服务账户）通常有四个共同特征：

1. **UID 在 1-999 之间**
2. **Shell 被设置为 `/usr/sbin/nologin` 或 `/bin/false`**——禁止交互式登录
3. **家目录通常是 `/nonexistent`、`/var/run/xxx` 或不存在的路径**
4. **密码占位符为 `x`，但 `/etc/shadow` 中密码字段为 `*` 或 `!`**——表示密码被锁定，无法通过密码认证登录

```bash
# 查看一个服务账户的完整信息
sudo grep "^sshd:" /etc/passwd
sudo grep "^sshd:" /etc/shadow
```

### 2.3 /etc/shadow 文件：密码的保险库

`/etc/shadow` 存储了实际的密码哈希（Password Hash）和密码过期策略。这个文件的权限极其严格：

```bash
# 查看 /etc/shadow 的权限
ls -l /etc/shadow
```

预期输出：

```
-rw-r----- 1 root shadow 1537 Jul 29 10:00 /etc/shadow
```

**关键：** `etc/shadow` 的所有者是 `root`，所有组是 `shadow`，只有 root 可以读写，shadow 组的成员（如 `passwd` 命令）可以读取。**普通用户完全无法访问此文件。**

```bash
# 普通用户尝试读取 shadow 会失败
cat /etc/shadow                          # Permission denied

# 需要 sudo 权限
sudo cat /etc/shadow | head -n 5
```

#### 2.3.1 文件格式：冒号分隔的九个字段

```
zhangsan:$y$j9T$ABCDEF...:19888:0:99999:7:::
```

格式为：

```
用户名:加密密码:上次修改日期:最小天数:最大天数:警告天数:不活动天数:过期日期:保留字段
```

**逐字段详解：**

| 字段序号 | 字段名 | 含义 | 示例值 |
|----------|--------|------|--------|
| **1** | 用户名（Username） | 与 `/etc/passwd` 中的用户名对应 | `zhangsan` |
| **2** | 加密密码（Encrypted Password） | 密码的哈希值 | `$y$j9T$...` |
| **3** | 上次修改日期（Last Password Change） | 从 1970-01-01 算起的天数 | `19888`（对应 2024-06-15 左右） |
| **4** | 最小修改间隔（Minimum Days） | 两次改密码之间最少间隔天数 | `0`（随时可改） |
| **5** | 最大有效天数（Maximum Days） | 密码的最大有效期 | `99999`（约 274 年，几乎不过期） |
| **6** | 过期警告天数（Warning Days） | 密码过期前多少天开始提醒用户 | `7` |
| **7** | 不活动锁定天数（Inactivity Days） | 密码过期后多少天未修改则锁定账户 | （空=不锁定） |
| **8** | 账户过期日期（Account Expiration） | 从 1970-01-01 算起的天数，此日期后账户被禁用 | （空=永不过期） |
| **9** | 保留字段（Reserved） | 保留给未来使用 | （当前为空） |

#### 2.3.2 密码字段的格式解读

```bash
# 查看某个用户的密码哈希
sudo grep "^$(whoami):" /etc/shadow | cut -d: -f2
```

密码字段的格式为 `$算法ID$盐值$哈希值`：

| 算法 ID | 哈希算法 | 说明 |
|---------|----------|------|
| `$1$` | MD5 | 已废弃，不安全 |
| `$2a$` 或 `$2b$` | Blowfish | 较老的 bcrypt |
| `$5$` | SHA-256 | 较老的 SHA-2 |
| `$6$` | SHA-512 | 传统 Linux 默认算法 |
| `$y$` | yescrypt | **Ubuntu 24.04 默认使用的现代密码哈希算法** |

> **yescrypt** 是 Ubuntu 20.04 及之后版本的默认密码哈希算法。它针对暴力破解做了内存和计算优化，比 SHA-512 更安全。你不需要记住这个名字——只需要知道 `$y$` 开头的哈希是现代的、安全的即可。

#### 2.3.3 特殊密码字段值

| 密码字段值 | 含义 |
|-----------|------|
| `!` 或 `!!` 前缀 | 密码被锁定（Locked）。用户无法通过密码登录，但可以通过 SSH 密钥等方式 |
| `*` | 密码被永久禁用。通常用于服务账户——这些账户本就不应该用于登录 |
| 空字段 | 无密码！任何人都可以不输入密码就登录此账户。**这是一项严重的安全隐患** |

```bash
# 检查是否存在空密码或无密码的账户（安全检查）
sudo awk -F: '($2 == "" || $2 == "!") { print $1 " 没有密码或密码被锁定" }' /etc/shadow

# 查看服务账户的密码字段
sudo grep -E "^(sshd|www-data|mysql):" /etc/shadow | cut -d: -f1,2
```

预期输出（示例）：

```
sshd:!
www-data:!
mysql:!
```

这些服务账户的密码字段为 `!` 或 `*`，说明它们被锁定——这是正确且安全的配置。

### 2.4 /etc/group 文件：组的登记簿

`/etc/group` 定义了系统中的所有用户组及其成员。

```bash
# 查看 /etc/group 文件
cat /etc/group | head -n 20
```

#### 2.4.1 文件格式：冒号分隔的四个字段

```
sudo:x:27:zhangsan,lisi
```

格式为：

```
组名:组密码占位符:GID:组成员列表
```

**逐字段详解：**

| 字段序号 | 字段名 | 含义 | 示例值 |
|----------|--------|------|--------|
| **1** | 组名（Group Name） | 用户组的名称 | `sudo` |
| **2** | 组密码占位符（Group Password） | 现代 Linux 中固定为 `x`。组密码功能几乎不再使用 | `x` |
| **3** | GID | 组的数字标识号 | `27` |
| **4** | 组成员列表（Member List） | 以逗号分隔的用户名列表，这些用户将此组作为**附加组** | `zhangsan,lisi` |

**注意：** 组成员的**主组用户不会出现在此列表中**。例如，`zhangsan` 的主组是 GID 1000（`zhangsan` 组），那么在 `/etc/group` 的 `zhangsan:x:1000:` 条目中，成员列表可能是空的——因为 `zhangsan` 通过主组机制自动归属，不需要显式列出。

```bash
# 查看 sudo 组的成员
grep "^sudo:" /etc/group

# 查看你的主组和附加组成员
grep "^$(whoami):" /etc/group       # 你的主组
grep ":$(whoami)" /etc/group        # 你在哪些组的附加成员列表中
```

#### 2.4.2 /etc/gshadow 文件

`/etc/gshadow` 是 `/etc/group` 的"影子文件"，存储组的加密密码和组管理员信息。但在现代 Linux 中，组密码功能几乎无人使用（它存在严重的共享密码安全隐患），因此这里不做深入讨论。

### 2.5 用户管理的基本流程

将一个完整的用户生命周期串联起来，你会发现用户管理其实只有四类操作：

```
创建用户                 管理用户                 管理密码                 删除用户
────────               ────────                ────────                ────────
useradd                usermod                  passwd                  userdel
  │                      │                       │                        │
  ├─ -u UID              ├─ -l 改用户名           ├─ 修改密码               ├─ 仅删除账户
  ├─ -g 主组             ├─ -d 改家目录           ├─ -l 锁定密码            └─ -r 连同家目录
  ├─ -G 附加组           ├─ -m 迁移家目录         ├─ -u 解锁密码
  ├─ -d 家目录           ├─ -s 改Shell            ├─ -e 强制过期
  ├─ -s Shell            ├─ -aG 追加附加组        └─ -S 查看密码状态
  ├─ -m 创建家目录       ├─ -L 锁定账户
  ├─ -c 注释信息         └─ -U 解锁账户          chage
  └─ -e 过期日期                                  ├─ -l 列出策略
                                                  ├─ -M 最大天数
                                                  ├─ -W 警告天数
                                                  └─ -E 过期日期
```

### 2.6 权限提升：su 与 sudo 的本质区别

在练习本章命令之前，你还需要理解两个关键命令的定位差异：

| 维度 | `su` | `sudo` |
|------|------|--------|
| **全称** | Substitute User（或 Switch User） | SuperUser Do |
| **工作机制** | 切换到目标用户身份，开启一个新的 Shell 会话 | 以目标用户（默认 root）的身份**执行一条命令**，执行完毕后回到当前用户 |
| **需要谁的密码** | 需要**目标用户**的密码 | 需要**当前用户**的密码（而非 root 的密码） |
| **审计能力** | 无——无法追踪谁用 root 做了什么 | 有——每一条 sudo 命令都会记录日志 |
| **权限粒度** | 全有或全无——切换后拥有目标用户的全部权限 | 精细控制——可限制到特定命令、特定参数 |
| **Ubuntu 默认行为** | root 密码被锁定，`su` 不可直接使用 | 安装时创建的第一个用户自动加入 sudo 组 |

**Ubuntu 的设计哲学：** 默认情况下，root 账户的密码是锁定的——你**无法**通过 `su -` 直接切换到 root（因为没有 root 密码可用）。所有需要特权的操作都必须通过 `sudo` 完成。这不是 bug，这是 Ubuntu 安全模型的核心设计：**永远不需要知道 root 密码，永远不需要以 root 身份登录，每次特权操作都显式地加上 `sudo` 前缀。**

## 3. 命令详解

以下全部命令的示例，请打开终端逐一运行验证。

### 3.1 whoami -- 我是谁

`whoami` 是本章最简单的命令——它只做一件事：**打印当前有效用户（Effective User）的用户名**。

**语法：**

```
whoami [参数]
```

**基础用法：**

```bash
whoami
```

预期输出（示例）：

```
zhangsan
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `--help` | 显示帮助信息 | 可选 | -- |
| `--version` | 显示版本信息 | 可选 | -- |

#### 3.1.1 whoami 的"有效用户"含义

`whoami` 显示的是**有效用户**（Effective User），而非登录用户（Login User）。这个区别在使用 `su` 或 `sudo` 后尤为明显：

```bash
# 当前用户 zhangsan
whoami                                   # 输出: zhangsan

# 使用 sudo 以 root 身份执行 whoami
sudo whoami                              # 输出: root

# 切换到 lisi 后
sudo su - lisi
whoami                                   # 输出: lisi
```

#### 3.1.2 whoami、id -un、$USER 的区别

```bash
# 三种方式查看当前用户
whoami                                   # 最简单直接
id -un                                   # 来自 id 命令
echo "$USER"                             # 来自环境变量（可能被修改，不要用于安全决策）
```

**在脚本中应该用哪个？** 如果需要根据当前用户做安全决策，使用 `id -un`——它是三者中最不容易被欺骗的。`$USER` 环境变量可以被任意修改。`whoami` 命令本质上是调用 `id -un` 的别名。

```bash
# 验证 $USER 可以被篡改
USER="root" whoami                       # whoami 不受影响，仍返回真实用户名
echo "$USER"                             # 当前 Shell 中的 $USER 不变
```

### 3.2 id -- 查看用户身份和组归属

`id` 是本章最常用的身份查看命令。它显示用户的 UID、GID 以及所属的所有组。

**语法：**

```
id [参数] [用户名]
```

**基础用法：**

```bash
# 查看当前用户的所有身份信息
id

# 查看指定用户的身份信息
id root
```

`id` 的预期输出：

```
uid=1000(zhangsan) gid=1000(zhangsan) groups=1000(zhangsan),4(adm),27(sudo),100(users)
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-u` | 仅显示 UID（数字） | 可选 | 显示全部 |
| `-g` | 仅显示主组 GID（数字） | 可选 | 显示全部 |
| `-G` | 仅显示所有组的 GID（数字），空格分隔 | 可选 | 显示全部 |
| `-n` | 配合 `-u`/`-g`/`-G` 使用，将数字替换为名称（Name） | 可选 | 显示数字 |
| `-r` | 显示真实 ID（Real ID），而非有效 ID（Effective ID）。仅在使用 `sudo` 等权限提升后有区别 | 可选 | 显示有效 ID |

#### 3.2.1 `-n` 参数的组合使用

```bash
# 只显示当前用户名
id -un

# 只显示当前用户的主组名
id -gn

# 显示所有组的名称（不含 GID 数字）
id -Gn
```

预期输出（示例）：

```
zhangsan
zhangsan
zhangsan adm sudo users
```

#### 3.2.2 按用户名查询

```bash
# 查看 root 的 UID 和组
id root

# 查看一个服务账户
id www-data
```

预期输出（示例）：

```
uid=0(root) gid=0(root) groups=0(root)
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

#### 3.2.3 `-r` 参数：真实 ID vs 有效 ID

```bash
# 正常情况：真实 ID = 有效 ID
id -u                    # 1000（有效 UID）
id -r -u                 # 1000（真实 UID）

# 使用 sudo 后：有效 UID 变成 0（root），真实 UID 不变
sudo id -u               # 0（有效 UID）
sudo id -r -u            # 1000（真实 UID——仍然是你）
```

这个区别在调试权限问题时很有用——`sudo` 改变了有效 ID，但原始用户的真实 ID 仍可追溯。

### 3.3 who -- 谁在线

`who` 显示当前登录到系统的**所有用户**的信息（用户名、终端、登录时间、来源 IP）。

**语法：**

```
who [参数]
```

**基础用法：**

```bash
who
```

预期输出（示例）：

```
zhangsan  tty1         2024-07-29 09:15
zhangsan  pts/0        2024-07-29 10:23 (192.168.1.100)
lisi      pts/1        2024-07-29 11:05 (10.0.0.5)
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-a` | 显示所有信息（等效于 `-b -d --login -p -r -t -T -u`） | 可选 | 基本信息 |
| `-b` | 显示系统最后一次启动时间 | 可选 | 不显示 |
| `-d` | 显示已死亡的进程（Dead Processes） | 可选 | 不显示 |
| `-H` | 显示列标题（Header） | 可选 | 不显示 |
| `-l` | 显示登录进程信息（Login） | 可选 | 不显示 |
| `-q` | 仅显示登录用户数量和用户名（Quick） | 可选 | 完整信息 |
| `-r` | 显示当前运行级别（Runlevel） | 可选 | 不显示 |
| `-s` | 仅显示用户名、终端、时间（Short，此为默认行为） | 可选 | 短格式 |
| `-u` | 显示登录用户的空闲时间 | 可选 | 不显示 |

#### 3.3.1 常用组合

```bash
# 显示带列标题的完整信息
who -H

# 快速查看有多少用户在线
who -q

# 查看系统上次启动时间
who -b

# 查看当前运行级别
who -r
```

#### 3.3.2 输出字段解读

```
zhangsan  pts/0        2024-07-29 10:23 (192.168.1.100)
│         │            │                  │
│         │            │                  └── 来源 IP 地址（远程连接时显示）
│         │            └── 登录时间
│         └── 终端名称（pts/0 表示第一个伪终端，即第一个 SSH 或终端窗口）
└── 用户名
```

| 终端类型 | 含义 |
|----------|------|
| `tty1`-`tty6` | 本地虚拟控制台（按 Ctrl+Alt+F1 到 F6 切换） |
| `pts/0`、`pts/1`…… | 伪终端（Pseudo Terminal Slave），每打开一个 SSH 连接或终端模拟器窗口即创建一个 |
| `:0` | 图形界面（X11/Wayland）的显示服务端 |

```bash
# 查看当前使用的是哪个终端
tty
```

### 3.4 w -- 谁在线，在做什么

`w` 是 `who` 的增强版。除了显示谁在线，它还会显示**每个用户当前正在运行什么命令**以及系统的**负载平均值（Load Average）**。

**语法：**

```
w [参数] [用户名]
```

**基础用法：**

```bash
w
```

预期输出（示例）：

```
 12:30:05 up 3 days,  2:15,  3 users,  load average: 0.08, 0.12, 0.09
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU  WHAT
zhangsan tty1     -                09:15    3:05m  0.20s  0.02s  -bash
zhangsan pts/0    192.168.1.100   10:23    2.00s  0.50s  0.03s  w
lisi     pts/1    10.0.0.5        11:05   12:30   1.20s  0.15s  vim report.txt
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-h` | 不显示标题行（Header） | 可选 | 显示标题 |
| `-s` | 短格式（Short），省略 FROM、JCPU、PCPU 列 | 可选 | 长格式 |
| `-f` | 显示/关闭 FROM 列 | 可选 | 显示 |
| `-o` | 使用旧式输出格式（Old-style） | 可选 | 新格式 |

#### 3.4.1 输出首行解读

```
 12:30:05 up 3 days,  2:15,  3 users,  load average: 0.08, 0.12, 0.09
 │        │            │     │          └── 系统负载平均值（1分钟、5分钟、15分钟）
 │        │            │     └── 当前登录用户数
 │        │            └── 系统已运行时间
 │        └── 当前系统时间
```

**负载平均值（Load Average）**是衡量系统繁忙程度的关键指标。三个数字分别代表过去 1 分钟、5 分钟、15 分钟内**处于可运行状态或不可中断睡眠状态**的进程平均数。作为简单参考：如果此值持续超过 CPU 核心数，说明系统可能出现性能瓶颈。

```bash
# 查看 CPU 核心数
nproc
```

#### 3.4.2 输出各列解读

| 列名 | 含义 |
|------|------|
| `USER` | 用户名 |
| `TTY` | 终端名称 |
| `FROM` | 来源 IP 或主机名（`-` 表示本地登录） |
| `LOGIN@` | 登录时间 |
| `IDLE` | 空闲时间（用户多久没有键盘输入） |
| `JCPU` | 该终端上所有进程累计使用的 CPU 时间（Job CPU） |
| `PCPU` | 当前进程（WHAT 列中的进程）使用的 CPU 时间（Process CPU） |
| `WHAT` | 当前正在运行的命令 |

```bash
# 查看特定用户的活动
w zhangsan

# 短格式输出
w -s
```

**语法：**

users

### 3.6 last -- 登录历史记录

`last` 显示所有用户的系统登录历史，包括已注销的登录记录和系统重启记录。数据来源是 `/var/log/wtmp` 文件。

**语法：**

```
last [参数] [用户名...] [终端...]
```

**基础用法：**

```bash
# 查看所有用户的登录历史（输出可能很长，建议用 less）
last | head -n 20

# 查看特定用户的登录历史
last zhangsan

# 查看系统重启记录
last reboot
```

预期输出（示例）：

```
zhangsan pts/0        192.168.1.100    Tue Jul 29 10:23   still logged in
zhangsan tty1                         Tue Jul 29 09:15   still logged in
lisi     pts/1        10.0.0.5         Mon Jul 28 14:30 - 18:45  (04:15)
reboot   system boot  6.8.0-40-generic Mon Jul 28 08:00   still running
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-n 数字` | 限制显示的记录条数 | 可选 | 显示全部 |
| `-R` | 不显示主机名（Hostname）列 | 可选 | 显示 |
| `-a` | 在最后一列显示主机名 | 可选 | 在其他位置显示 |
| `-d` | 将 IP 地址转换为主机名（DNS 反向解析，较慢） | 可选 | 不转换 |
| `-F` | 显示完整的登录/注销时间和日期 | 可选 | 简短格式 |
| `-i` | 显示 IP 地址而非主机名 | 可选 | 显示主机名 |
| `-s` | 显示指定时间之后的记录 | 可选 | 不限时间 |
| `-t` | 显示指定时间之前的记录 | 可选 | 不限时间 |
| `-w` | 显示完整的用户名和域名 | 可选 | 简化格式 |
| `-x` | 显示系统关机条目和运行级别变化（关机/重启记录） | 可选 | 仅用户登录 |

```bash
# 显示最近 10 条登录记录
last -n 10

# 显示包含系统关机和重启的记录
last -x | head -n 20

# 显示完整时间格式
last -F | head -n 10
```

#### 3.6.1 last 的数据来源

`last` 从 `/var/log/wtmp` 读取数据。但这个文件是二进制的，不能用 `cat` 直接查看：

```bash
# 错误：二进制文件，显示乱码
cat /var/log/wtmp

# 正确：使用 last 读取
last

# 也可以使用 utmpdump 查看原始记录
utmpdump /var/log/wtmp | head -n 20
```

#### 3.6.2 失败的登录尝试：lastb

与 `last` 对应的是 `lastb`，它记录**失败的登录尝试**（数据来源：`/var/log/btmp`）。这是安全检查的重要命令：

```bash
# 查看失败的登录尝试（需要 sudo）
sudo lastb | head -n 20

# 查看最近 5 次失败登录
sudo lastb -n 5
```

如果 `lastb` 输出中有大量来自外部的失败尝试，说明你的服务器可能正在遭受暴力破解攻击。

### 3.7 useradd -- 创建用户

`useradd` 是创建用户账户的底层命令。Ubuntu 24.04 也提供了 `adduser`（一个交互式的 Perl 脚本），但 `useradd` 是标准化的原生命令，更适合脚本和自动化。

**语法：**

```
useradd [参数] <用户名>
```

**基础用法：**

```bash
# 创建一个最简单的用户（仅添加到 /etc/passwd，不创建家目录）
sudo useradd testuser1

# 验证创建结果
grep "^testuser1:" /etc/passwd
id testuser1

# 推荐：创建用户并同时创建家目录、复制骨架文件
sudo useradd -m testuser2

# 验证家目录已创建
ls -la /home/testuser2
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-m` | 创建用户的家目录（Make home directory） | 可选 | Ubuntu 中通常默认不创建 |
| `-M` | 明确不创建家目录 | 可选 | -- |
| `-d 路径` | 指定家目录路径（Directory），默认 `/home/用户名` | 可选 | `/home/用户名` |
| `-u UID` | 指定 UID（User ID）数字 | 可选 | 自动分配（通常从 1000 开始递增） |
| `-g 组名或GID` | 指定主组（Group） | 可选 | 系统自动创建一个与用户名同名的组 |
| `-G 组1,组2,...` | 指定附加组（Supplementary Groups）列表 | 可选 | 无附加组 |
| `-s Shell路径` | 指定登录 Shell | 可选 | `/bin/bash`（由 `/etc/default/useradd` 决定） |
| `-c 注释` | 添加 GECOS 注释信息（Comment） | 可选 | 空 |
| `-e 日期` | 账户过期日期（Expire），格式 `YYYY-MM-DD` | 可选 | 永不过期 |
| `-f 天数` | 密码过期后多少天禁用账户（Force disable），-1 = 不禁用 | 可选 | -1 |
| `-k 目录` | 指定骨架目录（Skeleton）路径，默认 `/etc/skel` | 可选 | `/etc/skel` |
| `-r` | 创建系统账户（System Account），UID 自动分配在系统范围内 | 可选 | 创建普通用户 |
| `-p 密码` | 指定加密后的密码（生产环境不推荐，密码会出现在命令历史中） | 可选 | 创建时无密码 |

#### 3.7.1 创建用户的完整示例

```bash
# 创建一个功能齐全的普通用户
sudo useradd -m \
  -u 2000 \
  -g users \
  -G sudo,adm \
  -s /bin/bash \
  -c "Wang Xiaoming,Dev Team" \
  wangxm

# 验证
id wangxm
ls -la /home/wangxm
grep "^wangxm:" /etc/passwd
```

#### 3.7.2 关于 `-m`：为什么要显式指定

许多教程中 `useradd` 默认就会创建家目录，但**在 Ubuntu 24.04 中，`useradd` 默认不创建家目录**。这是因为 Ubuntu 的行为由 `/etc/default/useradd` 文件控制：

```bash
# 查看 useradd 的默认配置
cat /etc/default/useradd
```

如果输出中没有 `CREATE_HOME=yes`，则 `-m` 参数是必需的：

```bash
# 始终显式使用 -m，不让默认行为决定
sudo useradd -m newuser          # 明确表达意图：创建家目录
sudo useradd -M newuser          # 明确表达意图：不创建家目录
```

#### 3.7.3 骨架目录（/etc/skel）

当你使用 `-m` 创建家目录时，`useradd` 会将 `/etc/skel/` 目录下的所有文件复制到新用户的家目录中。这称为**骨架目录（Skeleton Directory）**。

```bash
# 查看骨架目录中有什么
ls -la /etc/skel/
```

预期输出（示例）：

```
total 20
drwxr-xr-x  2 root root 4096 Sep 25  2023 .
drwxr-xr-x 75 root root 4096 Jul 29 10:00 ..
-rw-r--r--  1 root root  220 Mar 31  2024 .bash_logout
-rw-r--r--  1 root root 3771 Mar 31  2024 .bashrc
-rw-r--r--  1 root root  807 Mar 31  2024 .profile
```

这些文件是每个新用户 Shell 配置的基础。如果公司要求所有新用户默认包含某个配置文件（例如统一的 `.vimrc` 或 `.gitconfig`），可以将其放入 `/etc/skel/`。

```bash
# 测试：在骨架目录添加一个文件
sudo touch /etc/skel/.welcome_message

# 创建新用户并检查
sudo useradd -m testuser3
ls -la /home/testuser3/.welcome_message     # 应该存在
```

#### 3.7.4 为新用户设置密码

`useradd` 创建的用户默认**没有密码**（密码字段为 `!`，即被锁定）：

```bash
# 查看新用户的 shadow 条目
sudo grep "^testuser1:" /etc/shadow
# 密码字段为 "!": testuser1:!:...
```

必须使用 `passwd` 命令设置密码后才能登录：

```bash
# 为新用户设置初始密码
sudo passwd testuser1
# 提示输入新密码（两次确认）
```

#### 3.7.5 创建系统用户

```bash
# 创建一个用于运行应用服务的系统用户
sudo useradd -r -s /usr/sbin/nologin -d /opt/myapp myapp

# 验证
grep "^myapp:" /etc/passwd
# myapp:x:996:996::/opt/myapp:/usr/sbin/nologin
```

系统用户的特点：
- `-r` 参数将 UID 分配在 1-999 范围内
- Shell 设置为 `/usr/sbin/nologin` 或 `/bin/false`
- 通常不创建家目录

### 3.8 usermod -- 修改用户属性

`usermod`（User Modify）用于修改已有用户的账户属性。它的参数与 `useradd` 高度对应。

**语法：**

```
usermod [参数] <用户名>
```

**基础用法：**

```bash
# 假设已存在 testuser2
# 修改 testuser2 的注释信息
sudo usermod -c "Test User Number Two" testuser2

# 验证
grep "^testuser2:" /etc/passwd
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l 新用户名` | 修改用户名（Login name） | 可选 | 不修改 |
| `-u UID` | 修改 UID | 可选 | 不修改 |
| `-g 组名/GID` | 修改主组 | 可选 | 不修改 |
| `-G 组1,组2,...` | **重新设置**附加组列表（覆盖原有附加组） | 可选 | 不修改 |
| `-aG 组1,组2,...` | **追加**到附加组列表（-a = Append，必须配合 -G 使用） | 可选 | 不修改 |
| `-d 路径` | 修改家目录路径 | 可选 | 不修改 |
| `-m` | 配合 `-d` 使用，将旧家目录的内容迁移（Move）到新家目录 | 可选 | 不迁移 |
| `-s Shell` | 修改登录 Shell | 可选 | 不修改 |
| `-c 注释` | 修改 GECOS 注释信息 | 可选 | 不修改 |
| `-e 日期` | 修改账户过期日期 | 可选 | 不修改 |
| `-f 天数` | 修改密码过期后禁用天数 | 可选 | 不修改 |
| `-L` | 锁定用户（Lock），在密码前加 `!`，禁止密码登录 | 可选 | 不锁定 |
| `-U` | 解锁用户（Unlock），移除密码前的 `!` | 可选 | 不解锁 |

#### 3.8.1 `-G` vs `-aG`：这是最常踩的坑

```bash
# 创建测试用户
sudo useradd -m testuser4

# 将 testuser4 加入 sudo 组
sudo usermod -aG sudo testuser4

# 之后，又需要将 testuser4 加入 adm 组
# 错误做法——这会覆盖原有的附加组，移除 sudo！
sudo usermod -G adm testuser4      # ❌ testuser4 不再属于 sudo 组了！

# 正确做法——追加到附加组
sudo usermod -aG adm testuser4     # ✅ testuser4 同时属于 sudo 和 adm

# 最佳实践：始终使用 -aG，除非你确定要覆盖
```

**记忆技巧：** `-a` = Append（追加），`-G` = Groups（附加组列表）。`-aG` = "追加到附加组列表"。

**为什么有人"把 sudo 搞丢了"：**

```bash
# 这是一个经典错误场景
sudo usermod -aG docker zhangsan                  # 第一次：追加 docker
# 后来……
sudo usermod -G kvm zhangsan                      # 第二次：覆盖！丢失了 sudo 和 docker
# 结果：zhangsan 再也无法 sudo，且不是 docker 组成员
```

如果你真的犯了这种错误，需要用自己的密码以 root 身份修复：

```bash
# 恢复方法：使用 su 切换到 root（需要 root 密码，但 Ubuntu 默认未设置）
# 或重启进入恢复模式（Recovery Mode）
# 最实际的方法：如果有另一个 sudo 用户，用它来修复
sudo usermod -aG sudo zhangsan
```

#### 3.8.2 修改用户名

```bash
# 修改用户名（不会自动修改家目录名称）
sudo usermod -l newname123 testuser4

# 手动修改家目录名称
sudo mv /home/testuser4 /home/newname123
sudo usermod -d /home/newname123 newname123
```

**注意：** 修改用户名不会自动修改家目录路径或邮件缓冲区。如果用户正在登录中，修改用户名可能导致进程出现问题。

#### 3.8.3 锁定和解锁用户

```bash
# 锁定用户（在 /etc/shadow 密码字段前加 !）
sudo usermod -L testuser2

# 查看效果
sudo grep "^testuser2:" /etc/shadow
# testuser2:!$y$j9T$...:...     ← 密码前多了 "!"

# 解锁用户
sudo usermod -U testuser2
```

**锁定后用户的登录行为：**
- 无法通过密码登录（SSH 密码认证或本地终端）
- 如果配置了 SSH 密钥认证，**仍然可以通过密钥登录**

```bash
# 如果要完全阻止登录，将 Shell 改为 nologin
sudo usermod -s /usr/sbin/nologin testuser2
```

### 3.9 userdel -- 删除用户

`userdel`（User Delete）用于从系统中删除用户账户。

**语法：**

```
userdel [参数] <用户名>
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-r` | 同时删除用户的家目录和邮件池（Remove home directory and mail spool） | 可选 | 仅删除账户，保留家目录 |
| `-f` | 强制删除（Force），即使用户仍在登录中。谨慎使用 | 可选 | 温和删除 |
| `-Z` | 删除用户的 SELinux 用户映射 | 可选（SELinux 环境） | 不删除 |

```bash
# 仅删除用户账户，保留家目录和数据
sudo userdel testuser1

# 连同家目录一起删除
sudo userdel -r testuser2

# 验证：testuser2 已从 /etc/passwd 中消失
grep "testuser2" /etc/passwd || echo "用户已删除"
```

#### 3.9.1 删除前的安全检查

```bash
# 1. 确认用户当前未登录
who | grep username

# 2. 确认用户没有运行中的进程
sudo ps -u username

# 3. 查找文件系统中属于该用户的文件
sudo find / -user username 2>/dev/null

# 4. 确认无误后再删除
sudo userdel -r username
```

#### 3.9.2 误删恢复

`userdel` 本身没有"撤销"命令。如果误删了一个用户，可以重新创建它（但 UID 可能不同，从而导致旧文件所有权不匹配）：

```bash
# 如果文件还在（未使用 -r），重新创建用户
sudo useradd -u 旧UID -m 用户名
# 旧文件的所有者将自动匹配新的同一 UID
```

### 3.10 groupadd -- 创建用户组

**语法：**

```
groupadd [参数] <组名>
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-g GID` | 指定 GID（Group ID）数字 | 可选 | 自动分配 |
| `-r` | 创建系统组（System Group），GID 分配在系统范围内 | 可选 | 创建普通组 |
| `-f` | 如果组已存在，则静默退出（不报错）。配合 `-g` 使用时，如果 GID 已被占用，则使用不同的 GID | 可选 | 组存在时报错 |

```bash
# 创建一个普通用户组
sudo groupadd developers

# 创建一个指定 GID 的用户组
sudo groupadd -g 3000 designers

# 创建一个系统组
sudo groupadd -r appgroup

# 验证
grep -E "^(developers|designers|appgroup):" /etc/group
```

### 3.11 groupmod -- 修改用户组属性

**语法：**

```
groupmod [参数] <组名>
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-g GID` | 修改 GID | 可选 | 不修改 |
| `-n 新组名` | 修改组名（New name） | 可选 | 不修改 |

```bash
# 修改组名
sudo groupmod -n devteam developers

# 修改 GID
sudo groupmod -g 4000 designers

# 验证
grep -E "^(devteam|designers):" /etc/group
```

**注意：** 修改组的 GID 后，属于该旧 GID 的文件不会自动更新。你需要手动修复文件所有权：

```bash
# 查找属于旧 GID 的文件
sudo find / -gid 3000 2>/dev/null

# 修改文件所属组
sudo find / -gid 3000 -exec chgrp designers {} \; 2>/dev/null
```

### 3.12 groupdel -- 删除用户组

**语法：**

```
groupdel <组名>
```

```bash
# 删除用户组
sudo groupdel designers

# 验证
grep "^designers:" /etc/group || echo "组已删除"
```

**限制：** 不能删除任何用户的主组（因为至少有一个用户将此组设为主组）。必须先修改用户的 GID 或先删除用户：

```bash
# 试试删除某个用户的主组
sudo groupdel testuser4                      # 如果 testuser4 的主组是它自己
# groupdel: cannot remove the primary group of user 'testuser4'

# 先修改用户的主组
sudo usermod -g users testuser4
# 再删除组
sudo groupdel testuser4
```

### 3.13 passwd -- 密码管理

`passwd` 是最常用的密码管理命令：设置密码、修改密码、锁定/解锁密码、查看密码状态。

**语法：**

```
passwd [参数] [用户名]
```

**基础用法：**

```bash
# 修改当前用户的密码
passwd
# 提示：Current password: → 输入旧密码
# 提示：New password: → 输入新密码
# 提示：Retype new password: → 再次输入新密码

# 管理员为指定用户设置密码
sudo passwd testuser3
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` | 锁定用户的密码（Lock），在 `/etc/shadow` 密码前加 `!` | 可选 | 不锁定 |
| `-u` | 解锁用户的密码（Unlock） | 可选 | 不解锁 |
| `-d` | 删除密码（Delete），使账户变为无密码状态。**极度危险！** | 可选 | 不删除 |
| `-e` | 强制密码立即过期（Expire），用户下次登录时**必须**修改密码 | 可选 | 不强制 |
| `-S` | 显示密码状态信息（Status） | 可选 | 不显示 |
| `-n 天数` | 设置密码最小修改间隔（Minimum days） | 可选 | 0 |
| `-x 天数` | 设置密码最大有效天数（Maximum days） | 可选 | 99999 |
| `-w 天数` | 设置密码过期前的警告天数（Warning） | 可选 | 7 |
| `-i 天数` | 设置密码过期后的不活动锁定天数（Inactive） | 可选 | -1（不锁定） |

#### 3.13.1 查看密码状态（`-S`）

```bash
# 查看自己的密码状态
passwd -S

# 查看指定用户的密码状态（需要 sudo）
sudo passwd -S testuser3
```

预期输出（示例）：

```
testuser3 P 07/29/2024 0 99999 7 -1
```

输出格式：`用户名 状态 最后修改日期 最小天数 最大天数 警告天数 不活动天数`

| 状态标记 | 含义 |
|----------|------|
| `P` | 有密码，正常可用（Password set） |
| `L` | 密码被锁定（Locked） |
| `NP` | 无密码（No Password） |
| `PS` | 有密码，且为系统账户 |

```bash
# 查看所有用户的密码状态
sudo passwd -S -a
```

#### 3.13.2 强制用户下次登录改密码

```bash
# 为新用户设置初始密码后，强制他们首次登录时修改
sudo passwd -e testuser3
```

下次 `testuser3` 登录时会看到：

```
You are required to change your password immediately (administrator enforced).
Changing password for testuser3.
Current password:
New password:
Retype new password:
```

#### 3.13.3 密码复杂度要求

Ubuntu 24.04 默认使用 `pam_pwquality` 模块来强制密码复杂度。如果你设置过于简单的密码（如 `123456` 或 `password`），系统会拒绝：

```bash
sudo passwd testuser3
# 如果输入弱密码：
# BAD PASSWORD: The password fails the dictionary check - it is too simplistic/systematic
```

但在 root 用户（通过 `sudo`）下，你可以强制设置简单密码——系统会警告但不阻止。

### 3.14 chage -- 密码过期策略管理

`chage`（Change Age）专门用于管理密码的过期和老化策略。它比 `passwd` 的 `-x`/`-w` 等参数提供了更丰富的过期控制。

**语法：**

```
chage [参数] <用户名>
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` | 列出用户的密码过期策略（List） | 可选 | 不列出 |
| `-d 日期或天数` | 设置密码的最后修改日期（Last change Date）。设为 0 会强制用户下次登录时修改密码 | 可选 | 不修改 |
| `-m 天数` | 设置密码的最小修改间隔天数（Minimum） | 可选 | 0 |
| `-M 天数` | 设置密码的最大有效天数（Maximum） | 可选 | 99999 |
| `-W 天数` | 设置密码过期前的警告天数（Warning） | 可选 | 7 |
| `-I 天数` | 设置密码过期后的不活动锁定天数（Inactive） | 可选 | -1（不锁定） |
| `-E 日期或天数` | 设置账户过期日期（Expire）。格式：YYYY-MM-DD，或从 1970-01-01 算起的天数。设为 -1 则取消过期 | 可选 | 永不过期 |

#### 3.14.1 查看密码过期策略

```bash
# 查看自己账户的策略
chage -l $(whoami)

# 查看指定用户的策略
sudo chage -l testuser3
```

预期输出（示例）：

```
Last password change                                    : Jul 29, 2024
Password expires                                        : never
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 99999
Number of days of warning before password expires       : 7
```

#### 3.14.2 配置密码过期策略

```bash
# 为 testuser3 配置：密码每 90 天过期，过期前 14 天开始警告
sudo chage -M 90 -W 14 testuser3

# 验证
sudo chage -l testuser3

# 强制用户下次登录时修改密码（两种等效方式）
sudo chage -d 0 testuser3
# 或
sudo passwd -e testuser3

# 设置账户过期日期（2025-01-01 后该账户被禁用）
sudo chage -E 2025-01-01 testuser3

# 取消账户过期限制
sudo chage -E -1 testuser3
```

#### 3.14.3 chage 的实际应用场景

| 场景 | 命令 |
|------|------|
| 新员工入职：首次登录必须改密码 | `sudo chage -d 0 newemployee` |
| 安全审计要求：密码 60 天一换 | `sudo chage -M 60 -W 10 username` |
| 实习生离职：账户在最后一天自动失效 | `sudo chage -E 2024-09-30 intern` |
| 临时账户：密码过期后 7 天锁定 | `sudo chage -M 30 -I 7 tempuser` |

### 3.15 su -- 切换用户

`su`（Substitute User / Switch User）用于切换到另一个用户身份。

**语法：**

```
su [参数] [用户名]
```

**基础用法：**

```bash
# 创建测试用户以便验证
sudo useradd -m -s /bin/bash testuser5
sudo passwd testuser5            # 设置密码

# 切换到 testuser5
su testuser5
# 提示输入 testuser5 的密码
# 切换后验证
whoami                  # testuser5
pwd                     # /home/zhangsan（注意：环境未改变！）
exit                    # 退出，回到原用户
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-` 或 `-l` 或 `--login` | 模拟完整的登录过程（Login Shell），加载目标用户的环境变量、切换到目标用户的家目录 | 可选 | 不加载环境、不切换目录 |
| `-c 命令` | 以目标用户身份执行单条命令（Command），执行后返回 | 可选 | 进入交互式 Shell |
| `-m` 或 `-p` | 保留当前环境变量（Preserve environment） | 可选 | 不保留 |
| `-s Shell` | 使用指定的 Shell 而非目标用户的默认 Shell | 可选 | 目标用户的登录 Shell |

#### 3.15.1 `su` vs `su -`：最关键的区分

这是 Linux 中最容易混淆的概念之一：

```bash
# su testuser5 — 非登录模式（仅切换用户身份，不切换环境）
su testuser5
whoami          # testuser5（身份变了）
pwd             # /home/zhangsan（目录没变！）
echo $HOME      # /home/zhangsan（HOME 环境变量没变！）

exit

# su - testuser5 — 登录模式（完全模拟 testuser5 登录）
su - testuser5
whoami          # testuser5
pwd             # /home/testuser5（目录变了！）
echo $HOME      # /home/testuser5（环境变量变了！）
```

**`su -` 实际上做的事：**
1. 切换到目标用户的有效 UID 和 GID
2. 切换到目标用户的家目录（`cd ~目标用户`）
3. 设置 `HOME`、`USER`、`LOGNAME`、`PATH` 等环境变量为目标用户的值
4. 启动目标用户的登录 Shell（`/etc/passwd` 第 7 个字段）

**何时用哪个：**

| 场景 | 用 `su` 还是 `su -` |
|------|---------------------|
| 保留当前目录和环境，临时以其他身份执行操作 | `su user` |
| 完全模拟该用户的登录环境，调试该用户的 Shell 配置问题 | `su - user` |
| 需要确保使用目标用户的完整 PATH 环境 | `su - user` |

#### 3.15.2 切换到 root

```bash
# 切换到 root（登录模式）
su -

# 或者
su - root

# 非登录模式切换
su root
```

**Ubuntu 中的特殊情况：** 默认情况下，Ubuntu 24.04 的 root 密码是锁定的，因此 `su -` 会提示输入 root 密码但无法通过。你要么先用 `sudo passwd root` 设置 root 密码（不推荐），要么使用 `sudo su -` 绕过密码输入：

```bash
# 使用 sudo 来 su（这是 Ubuntu 中切换到 root 的常用方式）
sudo su -
# 无需输入 root 密码，因为 sudo 已经验证了你的身份
```

#### 3.15.3 `-c` 参数：以其他用户身份执行单条命令

```bash
# 以 testuser5 身份执行一条命令
su - testuser5 -c "whoami && pwd"

# 与 sudo 对比
sudo -u testuser5 whoami
```

### 3.16 sudo -- 以其他用户身份安全执行命令

`sudo`（SuperUser Do）是 Ubuntu 安全模型的核心支柱。它允许授权的用户以 root（或其他用户）的身份执行命令，同时记录每一条操作。

**为什么需要 sudo？** 在实际运维中，你很少需要"完全变成 root"——你只需要偶尔提升权限来完成某些特定操作（安装软件、修改配置文件、重启服务等）。`sudo` 让你以**最小权限**的方式完成这些操作，每次都需要显式地加上 `sudo` 前缀，避免"忘记自己以 root 身份在操作"的危险。

**语法：**

```
sudo [参数] <命令>
```

**基础用法：**

```bash
# 以 root 身份执行命令
sudo whoami                              # 输出: root

# 以指定用户身份执行命令
sudo -u testuser5 whoami                 # 输出: testuser5

# 以 root 身份运行交互式 Shell
sudo -i                                  # 启动 root 的登录 Shell
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-u 用户名` | 以指定用户的身份执行命令（User） | 可选 | root |
| `-i` | 以目标用户的登录 Shell 方式运行（Interactive login） | 可选 | 不模拟登录 |
| `-s` | 以目标用户的 Shell 方式运行（Shell），不模拟登录 | 可选 | 不启动 Shell |
| `-l` | 列出当前用户被允许（和被禁止）的 sudo 命令（List） | 可选 | 不列出 |
| `-v` | 刷新 sudo 的时间戳（Verify），延长密码缓存 15 分钟 | 可选 | -- |
| `-k` | 使当前用户的 sudo 时间戳立即失效（Kill），下次 sudo 必须重新输入密码 | 可选 | -- |
| `-K` | 彻底删除用户的所有 sudo 时间戳（类似 `-k` 但更彻底） | 可选 | -- |
| `-b` | 在后台运行命令（Background） | 可选 | 前台运行 |
| `-E` | 保留当前用户的环境变量（Environment） | 可选 | 使用精简的安全环境 |

#### 3.16.1 sudo 的密码缓存机制

执行 `sudo` 时，默认需要输入**当前用户的密码**（不是 root 的密码）。但你不需要每条命令都输一次密码——`sudo` 会缓存验证结果：

- **默认缓存时间：15 分钟**（可配置）
- 在这个窗口内，同个终端的后续 `sudo` 命令无需重新输入密码
- 关闭终端或使用 `sudo -k` 会立刻清除缓存

```bash
sudo whoami                # 第一次：需要输入密码
sudo whoami                # 15 分钟内：无需密码
sudo -k                    # 清除缓存
sudo whoami                # 又需要输入密码了
```

#### 3.16.2 查看 sudo 权限（`-l`）

```bash
# 查看当前用户被授予了哪些 sudo 权限
sudo -l
```

预期输出（示例）：

```
Matching Defaults entries for zhangsan on ubuntu-server:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin, use_pty

User zhangsan may run the following commands on ubuntu-server:
    (ALL : ALL) ALL
```

**解读：** 最后一行的 `(ALL : ALL) ALL` 意味着：
- 用户 `zhangsan` 可以以**任何用户**的身份（第一个 `ALL`）
- 以**任何组**的身份（第二个 `ALL`）
- 执行**任何命令**（第三个 `ALL`）

这是最开放的 sudo 权限——Ubuntu 中所有 sudo 组用户在默认情况下都拥有这种权限。

#### 3.16.3 sudo -i vs sudo -s vs sudo su -

| 命令 | 行为 | 环境变量 | 当前目录 |
|------|------|----------|----------|
| `sudo command` | 以 root 身份执行一条命令 | 使用 sudo 安全环境（精简的 PATH） | 保持当前目录 |
| `sudo -i` | 启动 root 的**登录 Shell**（Source `.profile` 等） | 完全模拟 root 登录后的环境 | 切换到 `/root` |
| `sudo -s` | 启动 root 的 Shell（不模拟登录） | 保持 `$HOME` 为当前用户的家目录 | 保持当前目录 |
| `sudo su -` | 通过 sudo 调用 su 切换到 root 登录 Shell | 相当于 `sudo -i` | 切换到 `/root` |

```bash
# 验证四种方式的区别
sudo whoami                           # 输出: root，只执行这一条命令

sudo -i
whoami                                 # root
pwd                                    # /root
echo $HOME                             # /root
exit

sudo -s
whoami                                 # root
pwd                                    # /home/zhangsan（当前目录不变）
echo $HOME                             # /home/zhangsan（HOME 不变！）
exit
```

#### 3.16.4 sudo 记录日志

每一条 `sudo` 命令都会被记录到系统日志中。你可以通过以下方式查看：

```bash
# 查看今天的 sudo 日志
sudo grep sudo /var/log/auth.log | tail -n 20

# 或者使用 journalctl
sudo journalctl -t sudo | tail -n 20
```

这就是 `sudo` 的**审计能力（Auditability）**——可以追溯谁在什么时候以什么身份执行了什么命令。`su` 切换到 root 后执行的命令则没有这种追溯能力。

#### 3.16.5 什么情况下使用 sudo，什么情况下使用 su

| 场景 | 推荐命令 | 原因 |
|------|----------|------|
| 执行单条管理命令（安装软件、重启服务） | `sudo command` | 最小权限，有审计记录 |
| 需要执行多条管理命令 | `sudo -i` 或 `sudo -s` | 避免每条命令都加 sudo |
| 切换到其他用户调试环境问题 | `su - username` | 需要该用户的完整环境 |
| 永久以其他用户身份操作（运维场景） | `sudo -u user command` | 不暴露目标用户密码 |
| 切换到 root 执行大量操作 | `sudo -i` | Ubuntu 推荐的 root 访问方式 |

### 3.17 visudo -- 安全编辑 sudoers 配置

`visudo` 是编辑 sudo 配置文件（`/etc/sudoers`）的**唯一安全方式**。

**为什么不能用普通编辑器直接编辑 /etc/sudoers？**

1. **语法验证：** `/etc/sudoers` 有严格的语法要求。一个语法错误可能导致所有用户都无法使用 `sudo`——包括你自己。`visudo` 在保存前会检查语法，如果发现错误会拒绝保存并提示你重来。
2. **并发锁定：** `visudo` 使用文件锁防止两个人同时编辑导致配置被覆盖。
3. **原子写入：** 修改要么完整写入，要么完全不变——不会出现写一半的损坏状态。

**语法：**

```
visudo [参数]
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-c` | 仅检查（Check）现有 sudoers 文件的语法是否正确 | 可选 | 打开编辑器 |
| `-f 文件` | 指定要编辑的 sudoers 文件路径 | 可选 | `/etc/sudoers` |
| `-q` | 安静模式（Quiet），不显示语法错误之外的提示 | 可选 | 正常模式 |
| `-s` | 严格模式（Strict），对废弃的语法也报错 | 可选 | 宽松模式 |

```bash
# 检查 sudoers 语法（不进入编辑器）
sudo visudo -c

# 编辑主 sudoers 文件
sudo visudo

# 编辑某个用户的专用 sudoers 文件
sudo visudo -f /etc/sudoers.d/zhangsan
```

#### 3.17.1 sudoers 文件的结构

```bash
# 查看 sudoers 文件（只读查看，不要用普通编辑器打开）
sudo cat /etc/sudoers
```

典型的 `/etc/sudoers` 包含以下几个部分：

```
# 1. Defaults：设置 sudo 的默认行为
Defaults        env_reset
Defaults        mail_badpass
Defaults        secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin"
Defaults        use_pty

# 2. 权限规则：谁可以在哪里以谁的身份做什么
root    ALL=(ALL:ALL) ALL
%sudo   ALL=(ALL:ALL) ALL

# 3. 通过 @includedir 包含子目录中的配置文件
@includedir /etc/sudoers.d
```

**sudoers 规则语法详解：**

```
谁        在哪里 = (以谁的身份) 可以做什么
WHO       WHERE = (AS_WHOM)    WHAT
```

每条规则的每个部分：

| 部分 | 说明 | 示例 |
|------|------|------|
| **WHO** | 授权对象。用户名表示单个用户，`%组名` 表示组的所有成员 | `zhangsan`、`%sudo`、`%admin` |
| **WHERE** | 适用主机。几乎总是 `ALL`（表示所有计算机）。多主机环境下可指定特定主机名 | `ALL`、`server1` |
| **AS_WHOM** | 以谁的身份执行。`ALL` = 任意用户，`ALL:ALL` = 任意用户和任意组 | `(ALL)`、`(root)`、`(ALL:ALL)` |
| **WHAT** | 允许执行的命令。`ALL` = 所有命令，也可以列出具体命令的完整路径 | `ALL`、`/usr/bin/systemctl restart apache2` |

#### 3.17.2 Ubuntu 默认的 sudo 配置

Ubuntu 24.04 默认将 sudo 权限授予 `sudo` 组的所有成员：

```
%sudo   ALL=(ALL:ALL) ALL
```

这意味着：**任何属于 `sudo` 组的用户都可以执行任何 `sudo` 命令。** 安装时创建的第一个用户会被自动加入 `sudo` 组。

```bash
# 验证你是否在 sudo 组中
groups | grep -w sudo
```

#### 3.17.3 配置案例一：为用户授予完整 sudo 权限

通过 `visudo` 添加：

```
# 为单个用户授予完整 sudo 权限
zhangsan  ALL=(ALL:ALL) ALL
```

但更推荐的做法是将用户加入 `sudo` 组（这样更清晰、更易管理）：

```bash
sudo usermod -aG sudo zhangsan
```

#### 3.17.4 配置案例二：NOPASSWD（免密码执行 sudo）

无需输入密码即可执行 `sudo` 命令。这在自动化脚本中非常有用，但**牺牲了安全性**——任何能够接触到你的终端的人都可以执行 sudo 命令。

```
# 为特定用户设置所有命令的 NOPASSWD
zhangsan  ALL=(ALL:ALL) NOPASSWD: ALL

# 为 sudo 组的所有成员设置 NOPASSWD
%sudo  ALL=(ALL:ALL) NOPASSWD: ALL

# 更安全的做法：只对特定命令免密码
zhangsan  ALL=(ALL:ALL) NOPASSWD: /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx
```

**使用 `visudo` 添加 NOPASSWD 的完整步骤：**

```bash
# 1. 打开 /etc/sudoers.d/ 中的专用文件（比修改主文件更好）
sudo visudo -f /etc/sudoers.d/zhangsan-nopasswd

# 2. 在编辑器中添加：
#    zhangsan  ALL=(ALL:ALL) NOPASSWD: ALL

# 3. 保存并退出。visudo 会自动检查语法。

# 4. 验证配置是否生效
sudo -l
```

#### 3.17.5 配置案例三：命令白名单（Command Whitelisting）

限制用户只能通过 sudo 执行特定的命令——这是**最小权限原则（Principle of Least Privilege）**的具体实践：

```
# jr_admin 只能重启 nginx 和查看其状态，不能做其他任何 sudo 操作
jr_admin  ALL=(ALL:ALL) /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx

# deployer 只能以 www-data 身份运行部署脚本
deployer  ALL=(www-data:www-data) /opt/deploy/deploy.sh

# backup_op 只能运行备份命令，且不需要密码
backup_op  ALL=(ALL:ALL) NOPASSWD: /usr/local/bin/backup.sh
```

**命令白名单的安全注意事项：**

1. **务必使用命令的完整绝对路径**——不要写 `systemctl`，要写 `/usr/bin/systemctl`
2. **考虑命令的"逃生"能力**——某些看似无害的命令（如 `vim`、`less`、`awk`）可以被滥用来执行任意代码、读取任意文件或逃逸到 Shell。以下是一些常见的高风险命令：

```bash
# 这些命令允许攻击者逃逸到 Shell 或以 root 身份执行任意操作
# 永远不要将它们列入 sudo 白名单！

# vim/vi：:!bash 可以在 vim 中启动 Shell
# less：!bash 可以在 less 中启动 Shell
# awk：awk 'BEGIN {system("/bin/bash")}' 可以启动 Shell
# find：find . -exec /bin/bash \; 可以执行任意命令
# nano：Ctrl+R Ctrl+X 可以执行外部命令
# tar：tar cf /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/bash
```

3. **参数限制的局限性：** sudoers 支持用通配符限制命令参数，但这容易产生漏洞。如果参数限制不够严谨，攻击者可能通过参数注入绕过。对于需要严格权限控制的场景，考虑编写专用的、不接受外部输入的包装脚本。

#### 3.17.6 使用 /etc/sudoers.d/ 目录

**最佳实践：不要直接修改 `/etc/sudoers`，而是将自定义规则放入 `/etc/sudoers.d/` 目录。**

```bash
# 创建一个新文件存放自定义规则（文件名建议使用用户名）
sudo visudo -f /etc/sudoers.d/zhangsan

# 在其中添加规则：
zhangsan  ALL=(ALL:ALL) NOPASSWD: /usr/bin/systemctl restart nginx

# 配置完成后验证
sudo visudo -c
sudo -l -U zhangsan
```

`/etc/sudoers.d/` 的优点：
- 规则按文件隔离——出问题更容易定位
- 软件包可以在这里安全地添加自己的 sudo 规则
- 不会在升级时修改主 `/etc/sudoers` 文件
- 可以按用户名命名文件，一目了然

```bash
# 查看 sudoers.d 目录中已有的配置
ls -la /etc/sudoers.d/
```

#### 3.17.7 sudoers 语法检查（救命工具）

如果你通过非 `visudo` 方式修改了 `/etc/sudoers`（强烈不推荐），或者只是想在修改后做一次确定性检查：

```bash
# 语法检查
sudo visudo -c

# 如果输出 "parsed OK"，说明语法正确
# 如果输出有错误，会显示具体行号和错误信息
```

**如果 sudoers 语法错误导致 sudo 不可用：**

```
# 情况：你修改了 /etc/sudoers，保存后发现 sudo 无法使用
# 症状：任何 sudo 命令都报错 "parse error in /etc/sudoers"

# 救援方案：使用 pkexec 以 root 身份修复
pkexec visudo

# 如果 pkexec 也不可用，需要重启进入恢复模式：
# 1. 重启系统
# 2. 在 GRUB 菜单中选择 "Advanced options for Ubuntu"
# 3. 选择 "(recovery mode)"
# 4. 选择 "root - Drop to root shell prompt"
# 5. 以读写模式重新挂载根分区：mount -o remount,rw /
# 6. 修复 /etc/sudoers：visudo
# 7. 重启：reboot
```

## 5. 常见错误与排错

### 5.1 "useradd: Permission denied"——忘记 sudo

**现象：**

```bash
useradd newuser
```

```
useradd: Permission denied.
useradd: cannot lock /etc/passwd; try again later.
```

**原因：** `useradd` 需要修改 `/etc/passwd`、`/etc/shadow`、`/etc/group` 等系统文件，只有 root 或 sudo 用户才能执行。

**解决：**

```bash
sudo useradd -m newuser
```

**记忆技巧：** 所有用户管理命令（`useradd`、`usermod`、`userdel`、`groupadd`、`groupmod`、`groupdel`、`passwd`（修改他人密码时）、`visudo`、`chage`（修改他人策略时））都需要 `sudo`。`whoami`、`id`、`who`、`w`、`users`、`last` 不需要。

### 5.2 "useradd: user 'xxx' already exists"——用户已存在

**现象：**

```bash
sudo useradd testuser
```

```
useradd: user 'testuser' already exists
```

**排查：**

```bash
# 检查用户是否真的存在
grep "^testuser:" /etc/passwd
id testuser
```

**处理：**
- 如果这是一个旧测试账户，可以删除：`sudo userdel -r testuser`
- 如果要保留，换个新用户名：`sudo useradd -m testuser2`

### 5.3 "usermod: user xxx is currently used by process NNN"——用户正在使用中

**现象：**

```bash
sudo usermod -l newname oldname
```

```
usermod: user oldname is currently used by process 12345
```

**原因：** 目标用户当前有正在运行的进程。`usermod` 修改用户名或 UID 时，如果该用户有活跃进程，可能导致系统状态不一致。

**解决：**

```bash
# 查看该用户的所有进程
ps -u oldname

# 方法一：等待用户退出所有进程
# 或让用户自行退出

# 方法二：终止用户的进程（谨慎）
sudo pkill -u oldname

# 方法三：如果安全可控，先锁定用户再修改
sudo usermod -L oldname
sudo pkill -u oldname
sudo usermod -l newname oldname
sudo usermod -U newname
```

### 5.4 "groupdel: cannot remove the primary group of user 'xxx'"——不能删除用户的主组

**现象：**

```bash
sudo groupdel zhangsan
```

```
groupdel: cannot remove the primary group of user 'zhangsan'
```

**原因：** 至少有一个用户将此组设为主组（`/etc/passwd` 第 4 个字段指向此 GID）。

**解决：**

```bash
# 查找哪些用户以此组为主组
awk -F: -v gid=$(grep "^zhangsan:" /etc/group | cut -d: -f3) '$4 == gid { print $1 }' /etc/passwd

# 对于每个用户，修改其主组
sudo usermod -g users zhangsan

# 再删除组
sudo groupdel zhangsan
```

### 5.5 "passwd: Authentication token manipulation error"——密码修改失败

**现象：**

```bash
sudo passwd testuser
```

```
passwd: Authentication token manipulation error
```

**常见原因与解决：**

| 原因 | 解决 |
|------|------|
| `/etc/shadow` 文件系统为只读（如因磁盘错误被重新挂载为 ro） | `mount -o remount,rw /` 重新挂载为读写 |
| 磁盘空间已满（无法写入 shadow 文件） | `df -h /` 检查磁盘空间，清理无用文件 |
| PAM（可插拔认证模块，Pluggable Authentication Module）配置错误 | 检查 `/etc/pam.d/common-password` 是否被误修改；如有备份则恢复 |
| `/etc/shadow` 权限不正确 | `ls -l /etc/shadow`——应为 `-rw-r----- 1 root shadow` |

### 5.6 sudo 后仍然 "Permission denied"——sudo 未生效

**可能原因：**

```bash
# 原因 1：用户不在 sudo 组中
groups | grep sudo

# 原因 2：/etc/sudoers 配置错误或权限太严格
sudo -l

# 原因 3：使用了重定向但 sudo 只对命令生效
sudo echo "test" > /etc/protected_file    # 权限拒绝！
# 解释：sudo 只提升了 echo 的权限，> 重定向仍以当前用户身份执行

# 正确做法：使用 tee 或将整个 Shell 提升
echo "test" | sudo tee /etc/protected_file > /dev/null
# 或
sudo bash -c 'echo "test" > /etc/protected_file'
```

### 5.7 "visudo: /etc/sudoers busy"——sudoers 文件被占用

**现象：**

```bash
sudo visudo
```

```
visudo: /etc/sudoers busy, try again later.
```

**解决：**

```bash
# 查看是否另一个 visudo 会话正在进行
ps aux | grep visudo

# 如果没有，可能是之前异常退出留下的锁文件。清理它：
sudo rm -f /etc/sudoers.tmp
```

### 5.8 "sudo: no tty present and no askpass program specified"——脚本中 sudo 的常见错误

**现象：** 在 cron 任务或非交互式脚本中使用 `sudo` 时出现此错误。

**原因：** `sudo` 需要终端（TTY）来提示输入密码，但 cron 等后台任务没有 TTY。

**解决：**

```bash
# 方案一：在 sudoers 中为特定命令配置 NOPASSWD（推荐）
# 使用 visudo -f /etc/sudoers.d/scriptname 创建：
#   scriptuser  ALL=(ALL:ALL) NOPASSWD: /path/to/command

# 方案二：在 sudoers 中关闭该用户的 requiretty
# Defaults:scriptuser !requiretty

# 方案三：使用 sudo -n（非交互模式，不提示密码，直接失败如果未授权）
sudo -n command        # 如果没有NOPASSWD权限，立即失败而非卡住等待
```

## 6. 进阶延伸

### 6.1 用户管理的安全原则

#### 6.1.1 最小权限原则（Principle of Least Privilege）

每个用户只应拥有完成其工作所需的**最小权限**。这体现在本章的多个方面：

| 原则 | 具体实践 |
|------|----------|
| 不直接使用 root 登录 | 使用 `sudo` 替代 `su -` |
| 命令白名单而非全部授权 | `/etc/sudoers.d/` 中限制可执行命令 |
| 服务账户使用 nologin Shell | `useradd -r -s /usr/sbin/nologin` |
| 密码过期策略 | `chage -M 90 -W 14` 确保密码定期轮换 |
| 账户生命周期管理 | 离职用户设置 `chage -E YYYY-MM-DD` |

#### 6.1.2 sudo 审计

```bash
# 查看今天的所有 sudo 操作记录
sudo grep sudo /var/log/auth.log | grep "$(date +%Y-%m-%d)"

# 查看使用 sudo 最频繁的 10 个用户
sudo grep "sudo.*COMMAND" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head -10

# 实时监控 sudo 操作（另开一个终端窗口）
sudo tail -f /var/log/auth.log | grep --line-buffered "sudo"
```

### 6.2 /etc/nologin 文件：一键禁止所有非 root 登录

当需要进行系统维护时，可以在 `/etc/` 下创建一个名为 `nologin` 的文件，它的存在会导致**除了 root 以外的所有用户**无法登录：

```bash
# 创建 nologin 文件，禁止普通用户登录
sudo sh -c 'echo "系统维护中，预计 14:00 恢复。如有疑问请联系管理员。" > /etc/nologin'

# 文件内容会作为拒绝登录时显示给用户的提示信息
```

此时任何普通用户尝试登录都会看到：

```
系统维护中，预计 14:00 恢复。如有疑问请联系管理员。
```

然后连接被关闭。

```bash
# 维护完成后删除该文件，恢复登录
sudo rm /etc/nologin
```

### 6.3 /etc/login.defs：新用户创建的默认值

`/etc/login.defs` 定义了 `useradd` 创建用户时的默认参数：

```bash
cat /etc/login.defs | grep -v "^#" | grep -v "^$"
```

关键配置项：

| 配置项 | 含义 | Ubuntu 24.04 默认值 |
|--------|------|---------------------|
| `UID_MIN` | 普通用户的最低 UID | 1000 |
| `UID_MAX` | 普通用户的最高 UID | 60000 |
| `SYS_UID_MIN` | 系统用户的最低 UID | 100 |
| `SYS_UID_MAX` | 系统用户的最高 UID | 999 |
| `GID_MIN / GID_MAX` | 普通组的 GID 范围 | 1000 / 60000 |
| `CREATE_HOME` | 是否默认创建家目录 | no（注意：这就是为什么 `-m` 必须显式指定！） |
| `UMASK` | 新建家目录的权限掩码 | 022（对应 `755`，即 `rwxr-xr-x`） |
| `PASS_MAX_DAYS` | 默认密码最大有效天数 | 99999 |
| `PASS_MIN_DAYS` | 默认密码最小修改间隔 | 0 |
| `PASS_WARN_AGE` | 默认密码过期警告天数 | 7 |

### 6.4 /etc/default/useradd：useradd 的默认行为配置

```bash
cat /etc/default/useradd
```

预期输出：

```

```

| 配置项 | 含义 |
|--------|------|
| `GROUP=100` | 默认 GID（仅在未启用 UPG 时使用。Ubuntu 默认启用了 USERGROUPS_ENAB，所以实际不依赖此值） |
| `HOME=/home` | 默认家目录的父目录 |

| `SHELL=/bin/bash` | 默认登录 Shell |
| `SKEL=/etc/skel` | 骨架目录路径 |
| `CREATE_MAIL_SPOOL=no` | 是否创建邮件缓冲区 |

### 6.5 PAM：Linux 认证系统的底层魔方

你可能注意到，本章中没有一个命令是"孤立工作的"。`passwd` 修改密码时会检查密码复杂度，`su` 切换用户时需要认证，`sudo` 运行时需要验证身份——这些都不是各命令自己实现的，而是通过一个叫做 **PAM**（Pluggable Authentication Modules，可插拔认证模块）的统一框架完成的。

PAM 是 Linux 认证系统的"总调度员"——它将"你是谁"的验证问题从各个应用中抽离出来，形成一套可插拔的模块体系。这使得系统管理员可以在不改动应用代码的情况下，灵活调整认证策略（例如强制使用双因素认证、限定登录时间段、检查用户是否在特定组中）。

```bash
# 查看与 passwd 命令相关的 PAM 配置
cat /etc/pam.d/common-password | grep -v "^#" | grep -v "^$"

# 查看与 su 命令相关的 PAM 配置
cat /etc/pam.d/su | grep -v "^#" | grep -v "^$"

# 查看与 sudo 命令相关的 PAM 配置
cat /etc/pam.d/sudo | grep -v "^#" | grep -v "^$"
```

常见的 PAM 模块：

| 模块 | 功能 |
|------|------|
| `pam_unix.so` | 传统的 `/etc/passwd` + `/etc/shadow` 密码认证 |
| `pam_pwquality.so` | 密码复杂度检查（最小长度、字符类别等） |
| `pam_tally2.so` | 登录失败次数限制（防止暴力破解） |
| `pam_faillock.so` | 登录失败锁定（现代替代 `pam_tally2`） |
| `pam_access.so` | 基于 `/etc/security/access.conf` 的访问控制 |
| `pam_time.so` | 基于时间的登录限制 |
| `pam_google_authenticator.so` | Google Authenticator 双因素认证 |

```bash
# 查看当前系统上可用的所有 PAM 模块
ls /lib/x86_64-linux-gnu/security/
```

PAM 的"/etc/pam.d/ 配置文件结构：

```
type    control    module-path    arguments
类型    控制标志    模块路径       参数
```

| 类型 | 含义 |
|------|------|
| `auth` | 认证——验证"你是谁"（密码、指纹、密钥） |
| `account` | 账户——检查账户状态（是否过期、是否允许此时登录） |
| `password` | 密码——更新密码时的处理 |
| `session` | 会话——登录后和退出前的环境设置和清理 |

> PAM 是 Linux 安全体系中最强大也最复杂的组件之一。本章不做深入展开，但了解它的存在和基本工作原理，对你理解"为什么 passwd 会检查密码复杂度""为什么 sudo 能记住密码 15 分钟"等问题至关重要。这些都不是命令自身实现的，而是 PAM 在背后统一调度。

### 6.6 理解用户命名空间（User Namespace）

如果你未来接触到 Docker 等容器技术，会听到"用户命名空间（User Namespace）"这个概念。它是 Linux 内核的一项特性，允许在一个隔离的命名空间中映射 UID：

- 容器内部看起来是 UID 0（root），拥有完整的 root 权限
- 但在宿主机上，这个"root"实际映射为 UID 100000（或其他非特权 UID）
- 也就是说：容器里的 root 不等于宿主机的 root

```bash
# 查看当前系统的用户命名空间相关的内核配置
cat /proc/sys/kernel/unprivileged_userns_clone
```

这个特性是容器安全隔离的基石——它保证了即使容器内的进程被攻破，攻击者也只是一个"假的 root"，对宿主机无能为力。
