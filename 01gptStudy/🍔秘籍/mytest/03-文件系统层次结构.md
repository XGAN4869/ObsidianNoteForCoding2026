## 1. 概述

### 1.1 从 Windows 到 Linux：文件系统的"世界观"差异

如果你是从 Windows 转过来的用户，打开 Ubuntu 的终端输入 `ls /` 之后，你可能会感到困惑——没有 C 盘，没有 D 盘，只有一个孤零零的 `/`（根目录，Root Directory），下面是一堆名字陌生的目录。在 Windows 中，每个磁盘分区都是一个独立的"王国"（C:、D:、E:）；而在 Linux 中，只存在**一个**根目录 `/`，所有磁盘、分区、USB 设备、甚至内存中的数据，都作为子目录"挂载"（Mount）到这个统一的目录树下。

本章将带你深入理解这套被称为 **FHS（Filesystem Hierarchy Standard，文件系统层次结构标准）** 的目录体系。理解它，你就理解了 Linux 系统的"骨架"。

### 1.2 什么是 FHS

FHS 是由 Linux 基金会维护的一份标准文档，它定义了 Linux 发行版中各个目录的名称、位置和用途。几乎所有主流发行版（Ubuntu、Debian、Fedora、RHEL、Arch Linux）都遵循 FHS，这确保了：
- 用户在不同发行版之间切换时不会感到陌生
- 软件开发者可以预知自己软件的文件应该放到哪里
- 系统管理员可以快速定位配置文件、日志和可执行文件

### 1.3 本章学习目标

完成本章后，你将能够：

- 理解 Linux 的单根目录树结构及其与 Windows 多盘符结构的本质区别
- 说出 `/bin`、`/etc`、`/var`、`/home`、`/proc` 等核心目录的用途
- 使用 `pwd` 查看当前所在目录
- 使用 `ls` 浏览目录内容，并使用常用选项调整输出格式
- 使用 `tree` 以树状图展示目录层次
- 使用 `which` 和 `whereis` 查找可执行文件的位置
- 使用 `file` 判断文件的类型

## 2. 核心概念

### 2.1 一切皆文件（Everything is a File）

Linux 最核心的设计哲学之一就是"一切皆文件"。这不仅仅是口号——在 Linux 中：
- 普通文本和图片当然以文件形式存在
- 硬件设备被抽象为文件（存放在 `/dev` 目录中）
- 内核的运行状态被暴露为文件（存放在 `/proc` 和 `/sys` 中）
- 甚至一个网络连接也可以是一个文件

这意味着，很多操作都可以用同一套文件操作命令（如 `cat`、`echo`、`ls`）来完成。例如，读取鼠标的输入数据可以像读一个普通文件一样使用 `cat /dev/input/mice`，查看 CPU 信息可以用 `cat /proc/cpuinfo`。

### 2.2 根目录（Root Directory）—— `/`

`/` 是整个 Linux 文件系统的起点，所有文件和目录都位于根目录之下。它类似于 Windows 中的"此电脑"（This PC），但 Windows 中的 C:、D: 等盘符与根目录是**平级**的，而 Linux 中的所有内容都是**同一个根目录的子节点**。

用 `ls` 看看根目录下有什么：

```bash
ls /
```

预期输出（Ubuntu 24.04 LTS，略有出入属正常）：

```
bin   dev  home  lib    lib64   media  mnt  opt   proc  root  run  sbin  srv  sys  tmp  usr  var
boot  etc  lib32  libx32  lost+found
```

> **注意：** 在 Ubuntu 24.04 LTS 中，`/bin` 实际上是 `/usr/bin` 的符号链接（Symbolic Link）。这是 Ubuntu 推行 **usrmerge**（`/usr` 合并）方案的体现，目的是简化目录结构。类似地，`/sbin` 指向 `/usr/sbin`，`/lib` 指向 `/usr/lib`。后文在介绍这些目录时会具体说明。

我们将在第 2.4 节逐一介绍每个目录的用途。

### 2.3 绝对路径与相对路径

在浏览文件系统之前，必须先理解两种路径表示方式：

| 类型 | 定义 | 示例 | 特征 |
|------|------|------|------|
| **绝对路径（Absolute Path）** | 从根目录 `/` 开始的完整路径 | `/home/zhangsan/Documents/report.txt` | 始终以 `/` 开头，无论当前在哪个目录，结果都一样 |
| **相对路径（Relative Path）** | 从当前工作目录开始的路径 | `Documents/report.txt` | 不以 `/` 开头，其结果取决于你当前在哪个目录 |

**特殊目录符号：**

| 符号 | 含义 |
|------|------|
| `.` | 当前目录（Current Directory） |
| `..` | 上级目录（Parent Directory） |
| `~` | 当前用户的家目录（Home Directory），如 `/home/zhangsan` |
| `-` | 上一次所在目录（仅 `cd -` 使用，详见后文） |

**示例：** 假设当前在 `/home/zhangsan/`，以下各组路径指向同一个位置：

| 绝对路径 | 等价相对路径 |
|----------|-------------|
| `/home/zhangsan/Documents` | `Documents` 或 `./Documents` |
| `/home/zhangsan` | `~` |
| `/home` | `..` |

### 2.4 根目录下各目录逐一详解

#### `/bin` —— 基本用户命令（Essential User Binaries）

**用途：** 存放系统启动和单用户模式（Single-User Mode）下必需的基本用户命令。这些命令对所有用户可用。

**Ubuntu 24.04 现状：** 在 Ubuntu 24.04 中，`/bin` 是一个指向 `/usr/bin` 的符号链接。

验证：

```bash
ls -l /bin
```

预期输出：

```
lrwxrwxrwx 1 root root 7 Aug  1  2024 /bin -> usr/bin
```

这意味着，你输入 `ls`、`cp`、`cat` 等命令时，实际执行的是 `/usr/bin/ls`、`/usr/bin/cp`、`/usr/bin/cat`。

哪些命令存放在这里：

| 命令 | 用途 |
|------|------|
| `ls` | 列出目录内容 |
| `cp` | 复制文件 |
| `mv` | 移动 / 重命名文件 |
| `rm` | 删除文件 |
| `cat` | 连接并显示文件内容 |
| `echo` | 输出文本 |
| `bash` | Bash Shell 本身 |

查找示例：

```bash
ls /usr/bin/ls
```

输出：

```
/usr/bin/ls
```

```bash
ls /usr/bin | head -n 20
```

输出（示例，显示前 20 个命令）：

```
[
aa-enabled
aa-exec
aa-features-abi
applygnupgdefaults
apropos
apt
apt-add-repository
apt-cache
apt-cdrom
apt-config
aptdcon
apt-get
apt-key
apt-mark
apturl
apturl-gtk
arch
awk
awk-3unit-test-runner
b2sum
```

#### `/sbin` —— 系统管理命令（System Binaries）

**用途：** 存放系统管理（System Administration）相关的命令，通常只有 root 用户（或在 sudo 下）才需要使用。这些命令用于系统启动、修复和恢复。

**Ubuntu 24.04 现状：** 与 `/bin` 类似，`/sbin` 也是指向 `/usr/sbin` 的符号链接。

```bash
ls -l /sbin
```

预期输出：

```
lrwxrwxrwx 1 root root 8 Aug  1  2024 /sbin -> usr/sbin
```

典型命令：

| 命令 | 用途 |
|------|------|
| `fdisk` | 磁盘分区管理 |
| `ifconfig` | 网络接口配置（已逐渐被 `ip` 替代） |
| `iptables` | 配置防火墙规则 |
| `mkfs` | 创建文件系统（格式化） |
| `mount` | 挂载文件系统 |
| `shutdown` | 关机或重启 |

查看：

```bash
ls /usr/sbin | head -n 20
```

#### `/usr` —— 用户系统资源（User System Resources）

**用途：** `/usr` 是 Linux 中最大的目录之一，包含绝大多数用户程序、库文件、文档和共享数据。它的名字来自最早的 Unix 含义"Unix System Resources"，而非"user"。

**关键子目录：**

| 子目录 | 用途 | 典型内容 |
|--------|------|----------|
| `/usr/bin` | 用户可执行程序 | `python3`、`gcc`、`git`、`vim`、`firefox` |
| `/usr/sbin` | 系统管理可执行程序 | `sshd`、`httpd`、`cron` |
| `/usr/lib` | 程序库文件（Libraries，即 `.so` 文件） | `libc.so`、`libssl.so` |
| `/usr/share` | 与架构无关的共享数据 | 文档、图标、字体、man 手册页 |
| `/usr/local` | 本地自行编译安装的软件 | 用户手动从源码编译（`make install`）的程序安装到此 |
| `/usr/include` | C/C++ 头文件（Header Files，即 `.h` 文件） | `stdio.h`、`stdlib.h` |
| `/usr/src` | 源代码（Source Code） | 内核源码（如果安装的话） |

浏览示例：

```bash
ls /usr/bin | wc -l
```

输出（示例）：

```
2865
```

在 Ubuntu 24.04 中，`/usr/bin` 里有两千多个可执行文件。

```bash
ls /usr/share
```

预期输出（示例）：

```
acpi-support     applications    bash-completion  color   desktop-directories  dict
adduser          apport          ca-certificates  common-licenses    doc
alsa             apt             cinnamon         dbus-1              drirc.d
```

查看 man 手册页的存放位置（它们都是纯文本文件）：

```bash
ls /usr/share/man/man1 | head -n 10
```

#### `/etc` —— 系统配置文件（Et Cetera / Editable Text Configuration）

**用途：** `/etc` 是整个系统的"配置中心"。几乎所有软件的系统级配置文件都位于此目录中。它最初的名字意为"et cetera"（等等、杂项），后来被重新解释为"Editable Text Configuration"（可编辑的文本配置）。

**你是普通用户也经常光顾此处**——修改网络配置、设置软件源、管理用户账户，都离不开 `/etc`。

**关键配置文件：**

| 文件 / 子目录 | 用途 |
|---------------|------|
| `/etc/passwd` | 用户账户信息（不含密码） |
| `/etc/shadow` | 用户加密密码（仅 root 可读） |
| `/etc/group` | 用户组信息 |
| `/etc/hostname` | 本机主机名 |
| `/etc/hosts` | 主机名到 IP 地址的静态映射 |
| `/etc/fstab` | 文件系统挂载表（开机时自动挂载哪些分区） |
| `/etc/apt/sources.list` | APT 软件源列表 |
| `/etc/ssh/sshd_config` | SSH 服务器配置 |
| `/etc/network/` | 网络配置 |
| `/etc/systemd/` | systemd 服务配置 |
| `/etc/default/` | 各类服务的默认参数 |

浏览示例：


#### `/var` —— 可变数据（Variable Data）

**用途：** `/var` 存放系统运行过程中会不断变化的数据——日志文件（Logs）、缓存（Cache）、队列（Spool）、数据库文件等。这些数据在系统正常运行时会持续增长，因此 `/var` 通常需要较大的磁盘空间。

**关键子目录：**

| 子目录 | 用途 | 备注 |
|--------|------|------|
| `/var/log` | 系统和应用程序日志 | **最常用的目录**。`syslog`、`auth.log`、`kern.log`、`apt/history.log` 等 |
| `/var/cache` | 应用程序缓存数据 | APT 下载的软件包缓存（`/var/cache/apt/archives/`） |
| `/var/spool` | 等待处理的任务队列 | 打印队列、邮件队列、cron 任务等 |
| `/var/lib` | 应用程序的持久状态数据 | 数据库文件（如 MySQL 的默认数据目录）、包管理器的状态数据库 |
| `/var/tmp` | 持久化的临时文件 | 与 `/tmp` 不同，`/var/tmp` 中的文件在重启后**不会**被自动清理 |
| `/var/run` | → 已迁移至 `/run` | 现代系统中此目录是指向 `/run` 的符号链接 |

浏览示例：

```bash
ls /var/log
```

预期输出（示例）：

```
alternatives.log  boot.log      dmesg        kern.log      syslog
apt               boot.log.1    dpkg.log     lastlog       ubuntu-advantage-timer.log
auth.log          bootstrap.log gdm3         openvpn       unattended-upgrades
auth.log.1        btmp          gpu-manager.log  private    vmware-vmsvc-root.log
```

查看最近的系统日志（最后 20 行）：

```bash
tail -n 20 /var/log/syslog
```

**典型场景：**当你遇到系统异常、SSH 登录失败或软件崩溃时，`/var/log/` 是你排查问题的第一站。

#### `/tmp` —— 临时文件（Temporary Files）

**用途：** 存放所有用户和程序生成的临时文件。所有用户都有读写权限，但通常仅允许修改自己的文件（由 `sticky bit` 保护）。

**重要特性：** 在 Ubuntu 24.04 中，`/tmp` 通常挂载为 tmpfs（内存文件系统），这意味着：
- 文件存储在内存中，读写速度极快
- 系统重启后 `/tmp` 中的文件**全部清空**
- 不适合存放需要持久化的大文件

验证 `/tmp` 的挂载类型：

```bash
df -h /tmp
```

预期输出（示例）：

```
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           1.9G  2.0M  1.9G   1% /tmp
```

注意第一列的 `tmpfs`，确认它是内存文件系统。

**典型使用场景：**
- 作为程序运行时的临时数据交换区
- 编译软件时存放中间文件
- 解压临时文件分析后丢弃

不要将重要文档保存到 `/tmp`，也不要在 `/tmp` 中存储需要长期保留的数据。

---

#### `/home` —— 用户家目录（User Home Directories）

**用途：** 每个普通用户都有一个以自己用户名命名的子目录，用于存放个人文件、配置和数据。类似于 Windows 中的 `C:\Users\你的用户名`。

**结构：**

```
/home/
├── zhangsan/        # 张三的个人目录
│   ├── Desktop/     # 桌面文件
│   ├── Documents/   # 文档
│   ├── Downloads/   # 下载
│   ├── Music/       # 音乐
│   ├── Pictures/    # 图片
│   ├── Videos/      # 视频
│   ├── .bashrc      # Bash 个人配置（隐藏文件）
│   ├── .profile     # Shell 登录配置（隐藏文件）
│   └── .config/     # 用户级应用配置（隐藏目录）
├── lisi/            # 李四的个人目录
└── wangwu/          # 王五的个人目录
```

> **隐藏文件（Hidden Files）：** 以 `.` 开头的文件和目录在 Linux 中代表"隐藏"。这与 Windows 的文件属性中的"隐藏"不同——Linux 中只要文件名以 `.` 开头就是隐藏的。使用 `ls -a` 才能看到它们。

查看你的家目录：

```bash
ls -la ~
```

查看家目录下的隐藏配置文件：

```bash
ls -ld ~/.* | head -n 20
```

**比喻理解：** `/home` 好比一栋公寓楼，每个用户是楼里的一个房间。你可以在自己的房间里随便摆放物品（创建、删除文件），但未经允许不能进入别人的房间（其他用户的家目录）。

---

#### `/root` —— root 用户的家目录

**用途：** 这是超级用户 root 的专属家目录。与普通用户的家目录（位于 `/home/` 下）不同，root 的家目录直接位于根目录下，路径为 `/root`。

**为什么要独立：** root 的特殊性体现在两个方面：
1. **安全隔离：** 有时 `/home` 可能挂载在一个独立的磁盘分区上，如果该分区故障无法挂载，root 仍需要有一个可用的家目录来登录和修复系统。把 `/root` 放在根分区上确保了这一点。
2. **权限保护：** `/root` 默认仅 root 用户可访问，普通用户无法查看其内容。

验证：

```bash
sudo ls /root
```

你需要 `sudo` 才能浏览 `/root` 的内容。普通用户执行 `ls /root` 会收到"权限不足"（Permission denied）的提示。

---

#### `/opt` —— 可选第三方软件（Optional Add-on Software）

**用途：** 存放那些不遵循 FHS 标准目录布局的第三方应用软件。简单说：不把文件散落在 `/usr/bin`、`/usr/lib`、`/etc` 等各处，而是把所有相关文件打包在一个目录下。

**典型内容：**

| 软件 | 安装路径 |
|------|----------|
| Google Chrome | `/opt/google/chrome/` |
| Visual Studio Code | （通常通过 snap 安装，`/snap/` 下） |
| 商业软件（如 MATLAB、VMware Tools） | `/opt/<vendor>/` |

浏览：

```bash
ls /opt
```

在刚安装好的 Ubuntu 24.04 中，`/opt` 通常是空的。

**使用原则：** 通过 APT 安装的软件遵循 FHS，散落在 `/usr/bin`、`/usr/lib`、`/etc` 等处；仅当软件有自己的完整目录结构需求时才放到 `/opt`。

#### `/proc` —— 进程与内核信息（Process Information Pseudo-Filesystem）

**用途：** `/proc` 是一个**虚拟文件系统**（Virtual / Pseudo-Filesystem）——它不占用磁盘空间，完全存在于内存中。它由内核动态生成，暴露了进程信息、内核参数和系统硬件信息。

**重要警告：** `/proc` 下的内容不是"真正"的磁盘文件——它们是内核实时生成的接口。不要用文本编辑器去"修改"这些文件（除非你确切知道自己在做什么），否则可能导致系统不稳定。

**关键文件：**

| 文件 / 子目录 | 内容 | 示例用途 |
|---------------|------|----------|
| `/proc/cpuinfo` | CPU 详细信息 | 查看 CPU 型号和核心数 |
| `/proc/meminfo` | 内存使用信息 | 查看总内存和可用内存 |
| `/proc/version` | 内核版本信息 | 快速查看内核版本 |
| `/proc/uptime` | 系统运行时间 | 查看系统开机了多久 |
| `/proc/loadavg` | 系统负载均值 | 查看系统的繁忙程度 |
| `/proc/[PID]/` | 每个进程的专属目录 | 查看某个进程的详细信息 |
| `/proc/mounts` | 当前挂载的文件系统 | 查看所有已挂载的分区 |
| `/proc/partitions` | 磁盘分区信息 | 查看磁盘分区布局 |

实践示例：

查看 CPU 信息（型号名称）：

```bash
grep "model name" /proc/cpuinfo
```

查看总内存和可用内存：

```bash
grep -E "^(MemTotal|MemAvailable):" /proc/meminfo
```

查看系统已运行时间（秒为单位）：

```bash
cat /proc/uptime
```

第一个数字是运行秒数，第二个数字是空闲秒数。

查看内核版本：

```bash
cat /proc/version
```

---

#### `/sys` —— 内核与设备信息（Sysfs）

**用途：** 与 `/proc` 类似，`/sys` 也是内存中的虚拟文件系统。它由 sysfs 子系统提供，专门用于暴露内核对象（Kernel Objects）——包括设备驱动、总线、模块和电源管理等——的信息和控制接口。

**与 `/proc` 的关系：** `/proc` 是一个"大杂烩"，什么都有；`/sys` 则更结构化，专注于设备和驱动的统一视图。部分原本在 `/proc` 中的信息已迁移到 `/sys`。

**关键子目录：**

| 子目录 | 内容 |
|--------|------|
| `/sys/block/` | 块设备（硬盘、SSD）信息 |
| `/sys/class/` | 按设备类别组织的设备信息（如 `net` 为网络设备、`backlight` 为屏幕背光） |
| `/sys/devices/` | 所有设备的层次化视图 |
| `/sys/kernel/` | 内核可调参数 |

实践示例：

查看系统中块设备的名称：

```bash
ls /sys/block
```

预期输出（示例）：

```
loop0  loop1  loop2  loop3  loop4  loop5  loop6  loop7  sda  sr0
```

其中 `sda` 是虚拟硬盘（SCSI Disk A），`sr0` 是虚拟光驱，`loop` 是回环设备（Loop Device，用于挂载 ISO 等）。

---

#### `/dev` —— 设备文件（Device Files）

**用途：** `/dev` 存放设备文件（Device Files），每个文件代表一个硬件设备或伪设备。这是"一切皆文件"哲学最直观的体现。

**关键设备文件：**

| 设备文件 | 对应的硬件 / 功能 | 类型 |
|----------|-------------------|------|
| `/dev/sda` | 第一块 SCSI/SATA 硬盘 | 块设备（Block Device） |
| `/dev/sda1` | 第一块硬盘的第一个分区 | 块设备 |
| `/dev/sr0` | 第一个光驱 | 块设备 |
| `/dev/tty` | 当前终端 | 字符设备（Character Device） |
| `/dev/null` | "黑洞"——丢弃所有写入的数据 | 字符设备 |
| `/dev/zero` | "零生成器"——不断输出零字节 | 字符设备 |
| `/dev/random` | 高质量随机数生成器（可能阻塞） | 字符设备 |
| `/dev/urandom` | 非阻塞随机数生成器 | 字符设备 |
| `/dev/stdin` | 标准输入 | 符号链接 |
| `/dev/stdout` | 标准输出 | 符号链接 |
| `/dev/stderr` | 标准错误 | 符号链接 |

浏览块设备：

```bash
ls -l /dev/sd*
```

浏览 `/dev` 前 20 个条目：

```bash
ls /dev | head -n 20
```

**经典用法示例：**

```bash
# 把输出丢进黑洞（丢弃）
echo "这条信息不会出现在任何地方" > /dev/null

# 生成 1 MB 的空数据文件
dd if=/dev/zero of=empty.bin bs=1M count=1

# 生成 16 字节随机数
dd if=/dev/urandom of=random.bin bs=16 count=1
```

---

#### `/run` —— 运行时可变数据（Runtime Data）

**用途：** `/run` 是一个 tmpfs 文件系统（存储在内存中），存放系统启动以来的运行时数据。这些数据在系统运行时需要，但重启后可以丢弃。

**关键内容：**

| 路径 | 内容 |
|------|------|
| `/run/user/[UID]/` | 每个已登录用户的运行时数据 |
| `/run/lock/` | 锁文件（Lock Files），防止多个进程同时操作同一资源 |
| `/run/systemd/` | systemd 运行时数据 |
| `/run/utmp` | 当前登录用户信息 |

验证 `/run` 是 tmpfs：

```bash
df -h /run
```

查看你的用户运行时目录：

```bash
ls -la /run/user/$(id -u)
```

预期输出（示例）：

```
total 0
drwx------ 5 zhangsan zhangsan 100 Jul 29 10:00 .
drwxr-xr-x 3 root     root      60 Jul 29 10:00 ..
srw-rw-rw- 1 zhangsan zhangsan   0 Jul 29 10:00 bus
drwx------ 2 zhangsan zhangsan  60 Jul 29 10:00 dconf
drwx------ 3 zhangsan zhangsan  60 Jul 29 10:00 gnupg
drwx------ 2 zhangsan zhangsan  40 Jul 29 10:00 pulse
```

---

#### `/mnt` —— 临时挂载点（Temporary Mount Point）

**用途：** 系统管理员手动临时挂载文件系统的地方。比如你想临时挂载一个 ISO 文件、插入一块备用硬盘，可以挂载到 `/mnt` 下。

**典型使用场景：**

```bash
# 创建一个临时挂载目录
sudo mkdir -p /mnt/mydisk

# 挂载一个分区
sudo mount /dev/sdb1 /mnt/mydisk

# 使用完毕后卸载
sudo umount /mnt/mydisk
```

在 Ubuntu 24.04 中，`/mnt` 通常为空。你可以在 `/mnt` 下随意创建子目录用于临时挂载。

---

#### `/media` —— 可移动介质挂载点（Removable Media Mount Point）

**用途：** 系统自动挂载可移动介质（USB 驱动器、CD/DVD、外接硬盘等）的地方。当你插入一个 U 盘，Ubuntu 会自动将它挂载到 `/media/你的用户名/U盘名称/`。

**与 `/mnt` 的区别：**

| 特性 | `/mnt` | `/media` |
|------|--------|----------|
| 谁在管理 | 系统管理员手动操作 | 系统（通过 udisks2 等）自动管理 |
| 用途 | 临时手动挂载 | 可移动介质的自动挂载 |
| 挂载位置 | `/mnt/子目录` | `/media/用户名/卷标` |

插入 U 盘后查看：

```bash
ls /media/$(whoami)
```

如果你插入了一个卷标为"KINGSTON"的 U 盘，预期会看到 `KINGSTON` 这个目录。

---

#### `/boot` —— 引导文件（Boot Files）

**用途：** 存放系统启动（Boot）所必需的文件，包括 Linux 内核镜像（vmlinuz）、初始 RAM 磁盘镜像（initrd.img）和引导加载器（GRUB，GRand Unified Bootloader）的配置文件。

**关键文件：**

| 文件 / 目录 | 用途 |
|-------------|------|
| `vmlinuz-*` | 压缩的 Linux 内核镜像 |
| `initrd.img-*` | 初始 RAM 磁盘（Initial RAM Disk），包含启动必需的驱动和工具 |
| `System.map-*` | 内核符号表（Kernel Symbol Table），调试用 |
| `config-*` | 当前内核的编译配置参数 |
| `grub/` | GRUB 引导加载器的配置文件 |

浏览：

```bash
ls -lh /boot
```

预期输出（示例）：

```
total 260M
-rw-r--r-- 1 root root 277K Apr  8  2024 config-6.8.0-31-generic
drwx------ 3 root root 4.0K Jan  1  1970 efi
drwxr-xr-x 5 root root 4.0K Jul 29 10:00 grub
lrwxrwxrwx 1 root root   28 Jun 17 10:30 initrd.img -> initrd.img-6.8.0-31-generic
-rw-r--r-- 1 root root  67M Jul 29 10:00 initrd.img-6.8.0-31-generic
lrwxrwxrwx 1 root root   28 Jun 17 10:30 initrd.img.old -> initrd.img-6.8.0-31-generic
-rw------- 1 root root 8.1M Apr  8  2024 System.map-6.8.0-31-generic
lrwxrwxrwx 1 root root   25 Jun 17 10:30 vmlinuz -> vmlinuz-6.8.0-31-generic
-rw------- 1 root root  14M Apr  8  2024 vmlinuz-6.8.0-31-generic
```

> **警告：** `/boot` 是系统的"心脏"。不要随意删除或修改其中的文件。如果 `/boot` 被破坏，系统将无法启动。普通用户的日常操作完全不需要接触 `/boot`。

---

#### `/lib` —— 共享库文件（Shared Libraries）

**用途：** 存放系统启动和基本命令所必需的共享库（Shared Library，即动态链接库，在 Linux 上是 `.so` 文件，类似于 Windows 的 `.dll` 文件）。这些库文件被 `/bin` 和 `/sbin` 中的命令所依赖。

**Ubuntu 24.04 现状：** 与 `/bin` 类似，在 usrmerge 方案下，`/lib` 也是指向 `/usr/lib` 的符号链接。

验证：

```bash
ls -l /lib
```

预期输出：

```
lrwxrwxrwx 1 root root 7 Aug  1  2024 /lib -> usr/lib
```

查看 `/usr/lib` 中部分库文件：

```bash
ls /usr/lib/x86_64-linux-gnu/ | head -n 20
```

**为什么需要库文件：** 假设有 100 个程序都需要操作网络，如果每个程序都实现一遍网络协议栈，既浪费磁盘空间又浪费内存。库文件将这些通用功能提取出来，程序在运行时动态加载即可。这就是"共享"的含义。

---

### 2.5 与 Windows 目录结构对比

理解 Linux 文件系统的一个好方法是将它与熟悉的 Windows 对比。以下是常见的对应关系：

| Windows | Linux (Ubuntu) | 说明 |
|---------|----------------|------|
| `C:\`、`D:\`、`E:\` | `/` | Windows 的每个盘符是独立的根；Linux 只有一个根 `/`，所有分区都挂载在它下面 |
| `C:\Windows\` | `/` + `/boot` | Windows 系统文件和内核在一起；Linux 中内核在 `/boot`，系统工具分散在 `/bin`、`/sbin`、`/usr` |
| `C:\Windows\System32\` | `/usr/bin/`、`/usr/lib/` | 存放系统程序、DLL 库 |
| `C:\Program Files\` | `/usr/bin/`、`/opt/` | 安装第三方应用程序的位置 |
| `C:\Users\` | `/home/` | 用户个人文件和配置 |
| `C:\Users\Administrator\` | `/root/` | 管理员的家目录（Windows 中没有严格的"超级用户"概念） |
| 注册表（Registry） | `/etc/` | Windows 用注册表集中管理配置；Linux 用分散于 `/etc/` 的纯文本文件 |
| `C:\Windows\Temp\` | `/tmp/` | 临时文件 |
| `C:\Windows\Logs\` | `/var/log/` | 系统日志 |
| 设备管理器 | `/dev/`、`/sys/` | Windows 用设备管理器管理硬件；Linux 将硬件抽象为文件 |
| 任务管理器 | `/proc/` | 查看进程和系统资源 |
| 盘符分配（D:、E:） | 挂载点（如 `/mnt`、`/media`） | Linux 没有"盘符"概念，新磁盘以目录形式出现在文件树中 |

**路径分隔符：**
- Windows 使用反斜杠 `\`：`C:\Users\张三\Documents`
- Linux 使用正斜杠 `/`：`/home/zhangsan/Documents`

**大小写敏感性（Case Sensitivity）：**
- Windows 不区分大小写：`Readme.txt` 和 `readme.txt` 是同一个文件
- Linux 严格区分大小写：`Readme.txt`、`readme.txt`、`README.TXT` 可以是三个完全不同的文件

实战验证大小写：

```bash
echo "大写" > Test.txt
echo "小写" > test.txt
ls -l Test.txt test.txt
```

你会看到两个独立文件。

**文件扩展名（File Extension）：**
- Windows 强依赖扩展名：`.exe` 是可执行程序，`.txt` 是文本文件，`.docx` 是 Word 文档
- Linux 不依赖扩展名：可执行性由文件的**权限位（Permission Bits）**决定，文件类型由**内容（Magic Bytes）**决定，而非扩展名。扩展名在 Linux 中仅为"人类提示"，系统看的是文件的内容和权限

验证：

```bash
echo "echo 我被执行了" > myscript
chmod +x myscript
./myscript
```

输出：

```
我被执行了
```

这个文件没有 `.sh` 或 `.exe` 后缀，但因为有了执行权限（`+x`），它依然可以运行。

## 3. 命令详解

本章介绍 6 个用于探索和导航文件系统的命令。请打开终端，逐一运行这些示例。

### 3.1 pwd —— 显示当前工作目录

`pwd`（Print Working Directory，打印工作目录）告诉你当前"身处"文件系统中的哪个位置。这是最基础但非常重要的命令——执行任何涉及路径的操作前，先确认自己在哪里，就像开车前先看地图一样。

```bash
pwd
```

预期输出：

```
/home/zhangsan
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-L` | 输出逻辑路径（Logical Path），保留符号链接。如果当前目录是通过符号链接进入的，显示链接路径而非实际路径 | 可选 | 已启用 |
| `-P` | 输出物理路径（Physical Path），解析所有符号链接。显示实际的物理目录位置 | 可选 | 否 |

**`-L` 与 `-P` 的区别演示：**

```bash
# 先看看 /bin 实际是什么
ls -l /bin

# 进入 /bin（这是一个符号链接，指向 /usr/bin）
cd /bin

# 逻辑路径（默认行为）
pwd -L

# 物理路径
pwd -P
```

`-L` 输出 `/bin`，`-P` 输出 `/usr/bin`。

返回家目录：

```bash
cd ~
pwd
```

---

### 3.2 ls —— 列出目录内容

`ls`（List）是使用频率最高的命令之一。它列出目录中的文件和子目录。

#### 基础用法

列出当前目录的内容：

```bash
ls
```

列出指定目录的内容：

```bash
ls /etc
```

列出多个目录的内容：

```bash
ls /etc /var
```

#### 常用选项

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` | 长格式（Long Format）显示，展示权限、所有者、大小、修改时间等详细信息 | 可选 | 简略格式 |
| `-a` | 显示所有文件（All），包括以 `.` 开头的隐藏文件 | 可选 | 不显示隐藏文件 |
| `-h` | 人类可读（Human-readable）的文件大小（如 1K、234M、2G） | 可选 | 以字节显示 |
| `-t` | 按修改时间（Time）排序，最新的在前 | 可选 | 按字母排序 |
| `-r` | 反转（Reverse）排序结果 | 可选 | 不反转 |
| `-S` | 按文件大小（Size）排序，最大的在前 | 可选 | 按字母排序 |
| `-R` | 递归（Recursive）列出子目录的内容 | 可选 | 仅当前目录 |
| `-d` | 显示目录本身而非其内容（Directory） | 可选 | 显示内容 |
| `--color=auto` | 根据文件类型自动着色 | 可选 | Ubuntu 默认启用 |
| `-F` | 在条目后追加类型指示符（`/`=目录, `*`=可执行, `@`=符号链接） | 可选 | 否 |

#### 示例：各种 ls 用法

**长格式显示，人类可读大小：**

```bash
ls -lh /boot
```

**显示隐藏文件：**

```bash
ls -a ~
```

你会看到 `.bashrc`、`.profile`、`.config` 等以 `.` 开头的文件和目录。

**按修改时间排序（最近修改的在最前）：**

```bash
ls -lt /var/log
```

**按文件大小排序（最大的在最前）：**

```bash
ls -lSh /usr/bin | head -n 20
```

**递归列出某个目录的完整内容（注意：可能很长）：**

```bash
ls -R /etc/cron.d
```

**仅列出目录本身，不展开内容：**

```bash
ls -ld /etc
```

输出：

```
drwxr-xr-x 139 root root 12288 Jul 29 10:00 /etc
```

第一列显示了它的权限和类型（`d` 开头表示是目录）。

#### 解读 `ls -l` 的输出

```bash
ls -l /etc/hostname
```

输出（示例）：

```
-rw-r--r-- 1 root root 7 Jul 29 10:00 /etc/hostname
```

逐列解读：

| 列 | 示例值 | 含义 |
|----|--------|------|
| 第 1 列 | `-rw-r--r--` | 文件类型与权限（详见后续章节）。`-` 表示普通文件，`d` 表示目录，`l` 表示符号链接 |
| 第 2 列 | `1` | 硬链接（Hard Link）计数 |
| 第 3 列 | `root` | 文件所有者（Owner） |
| 第 4 列 | `root` | 所属用户组（Group） |
| 第 5 列 | `7` | 文件大小（字节），配合 `-h` 可显示为人类可读格式 |
| 第 6 列 | `Jul 29 10:00` | 最后修改时间 |
| 第 7 列 | `/etc/hostname` | 文件名 |

**权限字段的 10 位含义：**

```
-  rw-  r--  r--
│  └───┘  └───┘  └───┘
│   所有者   用户组  其他用户
│
文件类型
```

文件类型代码：
- `-`：普通文件（Regular File）
- `d`：目录（Directory）
- `l`：符号链接（Symbolic Link）
- `b`：块设备（Block Device）
- `c`：字符设备（Character Device）

权限位的细节将在后续权限管理章节中深入讲解。

> **注意：** `ls` 实际上是一个"别名"（alias）。Ubuntu 默认为 `ls` 设置了 `--color=auto` 选项，让你看到不同颜色的输出。你可以通过 `alias ls` 查看确认。

```bash
alias ls
```

预期输出：

```
alias ls='ls --color=auto'
```

### 3.3 tree —— 以树状图显示目录结构

`tree` 命令以树状图（Tree Diagram）的形式递归地展示目录结构，比 `ls -R` 的输出直观得多。在大型项目中，`tree` 是快速了解目录布局的利器。

**安装：**

```bash
sudo apt install tree -y
```

**基础用法：**

```bash
tree /etc/cron.d
```

预期输出：

```
/etc/cron.d
├── anacron
└── e2scrub_all

0 directories, 2 files
```

针对家目录显示树状结构：

```bash
tree ~/Documents
```

如果 `~/Documents` 为空，则仅显示头尾信息。

**常用参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-L n` | 限制显示深度为 n 层（Level） | 可选 | 无限 |
| `-d` | 仅显示目录（Directory），不显示文件 | 可选 | 显示全部 |
| `-a` | 显示隐藏文件（All） | 可选 | 不显示隐藏文件 |
| `-h` | 以人类可读格式显示文件大小 | 可选 | 默认 |
| `-s` | 显示每个文件的大小 | 可选 | 不显示 |

**示例：**

显示 `/etc` 下两层深度的结构（仅目录）：

```bash
tree -d -L 2 /etc
```

显示 `/usr/share` 下一层深度：

```bash
tree -L 1 /usr/share
```

### 3.4 which —— 查找可执行文件的路径

`which` 告诉你当你输入一个命令名时，Shell 实际执行的是哪个文件。它在 `PATH` 环境变量列出的目录中搜索。

```bash
which ls
```

预期输出：

```
/usr/bin/ls
```

```bash
which bash
```

预期输出：

```
/usr/bin/bash
```

```bash
which python3
```

预期输出：

```
/usr/bin/python3
```

查找多个命令：

```bash
which ls cat rm echo pwd
```

输出：

```
/usr/bin/ls
/usr/bin/cat
/usr/bin/rm
/usr/bin/echo
/usr/bin/pwd
```

如果一个命令不存在，`which` 不会输出任何内容：

```bash
which nonexistent_command
```

（无输出）

**与 PATH 的关系：** `which` 只在 `$PATH` 环境变量指定的目录中查找。查看你的 PATH：

```bash
echo $PATH
```

输出（示例）：

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
```

PATH 中的目录用冒号 `:`（Windows 中为分号 `;`）分隔，Shell 按**从左到右**的顺序搜索命令。

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-a` | 显示所有匹配项（而非仅第一个）。当同名命令存在于多个 PATH 目录中时有用 | 可选 | 仅显示第一个 |

---

### 3.5 whereis —— 查找命令的二进制、源码和手册页

`whereis` 比 `which` 搜索的范围更广——它不仅搜索可执行文件，还搜索相关的源代码（Source Code）和 man 手册页（Manual Page）。

```bash
whereis ls
```

预期输出：

```
ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
```

输出解读：
- `/usr/bin/ls`：可执行文件本身
- `/usr/share/man/man1/ls.1.gz`：man 手册页所在的文件（`.gz` 表示 gzip 压缩过）

查找多个命令：

```bash
whereis bash python3
```

输出：

```
bash: /usr/bin/bash /etc/bash.bashrc /usr/share/man/man1/bash.1.gz
python3: /usr/bin/python3 /usr/bin/python3.12 /usr/lib/python3 /etc/python3 /etc/python3.12 /usr/share/man/man1/python3.1.gz
```

> **注意：** `whereis` 使用的是固定的内部数据库路径（硬编码的搜索路径），而不依赖 `$PATH` 环境变量。因此，在某些情况下它可以找到不在 PATH 中的文件。

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-b` | 仅搜索二进制（Binary）可执行文件 | 可选 | 搜索全部 |
| `-m` | 仅搜索 man 手册页（Manual） | 可选 | 搜索全部 |
| `-s` | 仅搜索源代码（Source） | 可选 | 搜索全部 |

示例：只找 ls 的 man 手册页：

```bash
whereis -m ls
```

### 3.6 file —— 判断文件类型

`file` 命令不依赖文件的扩展名，而是**读取文件的实际内容**来判断其类型——这被称为魔法数字（Magic Number）检测。在 Linux 中，这是识别文件类型的最可靠方法。

```bash
file /etc/hostname
```

预期输出：

```
/etc/hostname: ASCII text
```

```bash
file /bin/ls
```

预期输出：

```
/bin/ls: symbolic link to usr/bin/ls
```

```bash
file /usr/bin/ls
```

预期输出：

```
/usr/bin/ls: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=..., for GNU/Linux 3.2.0, stripped
```

输出解读：
- `ELF`：可执行文件的格式（Executable and Linkable Format）
- `64-bit`：64 位程序
- `dynamically linked`：动态链接（依赖共享库 .so 文件）
- `x86-64`：目标架构为 x86-64（AMD64）

**检测各种文件类型：**

```bash
# 压缩文件
file /usr/share/man/man1/ls.1.gz

# 目录自身
file /etc

# 设备文件
file /dev/null

# 符号链接
file /bin
```

**参数：**

| 参数 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-b` | 简洁模式（Brief），不输出文件名 | 可选 | 输出文件名+类型 |
| `-i` | 输出 MIME 类型字符串（MIME Type） | 可选 | 输出人类可读描述 |
| `-z` | 尝试读取压缩文件内部的内容来判断类型 | 可选 | 否 |

### 练习 4.7：探索 `/proc` 和 `/sys` 虚拟文件系统

**题目：** 使用 `cat` 或 `grep` 命令从 `/proc` 和 `/sys` 中获取以下信息：

（1）你的 CPU 有几个核心（物理核心和逻辑核心）？
（2）系统总内存是多少？
（3）系统已经运行了多长时间（换算成小时）？
（4）系统中有哪几个块设备（Block Devices）？


输出逻辑核心总数。

```bash
grep MemTotal /proc/meminfo
```

输出：`MemTotal:        xxxxxxx kB`

（3）查看系统运行时间：

```bash
cat /proc/uptime
```

输出两个数字，第一个是运行秒数。计算小时：

```bash
awk '{print $1/3600 " 小时"}' /proc/uptime
```

（4）查看块设备：

```bash
ls /sys/block
```

## 5. 常见错误与排错

### 5.1 "No such file or directory"（文件或目录不存在）

**现象：**

```bash
ls /etcc
```

```
ls: cannot access '/etcc': No such file or directory
```

**原因与解决：**

| 原因 | 解决方法 |
|------|----------|
| 路径拼写错误 | 检查拼写。使用 Tab 补全可以避免拼错目录名 |
| 大小写错误 | Linux 区分大小写。`/ETC` 不等于 `/etc`。检查路径中的大小写是否与实际一致 |
| 文件已被移动或删除 | 使用 `ls` 检查上级目录中是否仍有该文件 |
| 路径中包含空格但未加引号 | 如果文件名或目录名包含空格，用双引号包围，如 `ls "my documents"` 或使用转义 `ls my\ documents` |

---

### 5.2 "Permission denied"（权限不足）

**现象：**

```bash
ls /root
```

```
ls: cannot open directory '/root': Permission denied
```

**原因：** 当前用户没有访问该目录的权限。Linux 的文件权限系统严格限制了不同用户对文件和目录的操作。

**解决方法：**
- 如果是 root 专属目录，使用 `sudo` 前缀提升权限：`sudo ls /root`
- 如果是其他用户的家目录，需要对方授予你访问权限
- 不要随意用 `sudo` 列出所有目录——只在你清楚自己在做什么时使用

---

### 5.3 在 `/proc` 或 `/sys` 中尝试用文本编辑器"修改"文件

**现象：** 用 `nano /proc/somefile` 打开了一个 `/proc` 下的文件，修改后试图保存，结果报错"只读文件系统"或导致系统异常。

**原因：** `/proc` 和 `/sys` 是虚拟文件系统，内容由内核实时生成。大部分文件是只读的，少数可写文件也需要以特定方式写入（通常是向其中 `echo` 特定值）。

**解决方法：**
- 读取信息请使用 `cat`、`grep` 等只读命令
- 修改内核参数请使用 `sysctl` 命令，或确认该文件确实支持写入后再用 `echo` 写入
- 永远不要用文本编辑器（如 nano、vim）去编辑 `/proc` 或 `/sys` 下的文件

---

### 5.4 误把 `/` 当作家目录

**现象：** 执行 `ls` 后发现列出的是根目录的内容，或者创建的文件找不到。

**原因：** 你可能在执行 `cd /` 后忘记返回家目录，当前工作目录停留在了根目录。

**解决方法：**

```bash
# 随时返回家目录
cd ~

# 或者
cd

# 养成在执行重要操作前先 pwd 的习惯
pwd
```

---

### 5.5 tree 命令报"command not found"

**现象：**

```bash
tree
```

```
tree: command not found
```

**原因：** `tree` 不是 Ubuntu 预装的命令，需要手动安装。

**解决方法：**

```bash
sudo apt install tree -y
```

---

### 5.6 which 找不到已安装的命令

**现象：**

```bash
which myprogram
```

（无输出，但你知道这个程序已安装）

**原因：**
1. 该程序的可执行文件不在 `$PATH` 中的任何目录里
2. 该程序是 Shell 内置命令（Built-in Command），如 `cd`、`alias`、`echo`（在 Bash 中 `echo` 既是内置命令也是外部命令）

**解决方法：**

对于情况 1，使用 `whereis` 搜索更广的范围：

```bash
whereis myprogram
```

对于情况 2，查看命令类型：

```bash
type cd
```

输出：`cd is a shell builtin`。Shell 内置命令没有独立的可执行文件，使用 `which` 找到的是外部版本（如果有的话）。

```bash
type echo
```

输出：`echo is a shell builtin`，但 `which echo` 仍能找到 `/usr/bin/echo`，因为 echo 同时有内置版本和外部版本的实现。

## 6. 进阶延伸

### 6.1 usrmerge：为什么 `/bin` 变成了符号链接

在较早的 Linux 系统中，`/bin`、`/sbin`、`/lib` 是独立的物理目录。随着系统复杂度的增加，这种分离带来了很多问题：
- 软件包维护者需要决定每个文件应该放在 `/bin`、`/sbin` 还是 `/usr/bin`，容易出错
- 在最小化系统（如嵌入式系统或容器）中，同时维护两套目录结构浪费空间

**usrmerge** 方案将所有内容统一到 `/usr` 下：
- `/bin` -> `/usr/bin`（符号链接）
- `/sbin` -> `/usr/sbin`（符号链接）
- `/lib` -> `/usr/lib`（符号链接）

这从 Ubuntu 20.04 LTS 开始成为默认配置。对于普通用户，这完全透明——你输入的命令依然有效，只是底层的物理存储位置统一了。

验证系统已启用 usrmerge：

```bash
ls -l / | grep -E "bin|sbin|lib"
```

预期会看到多个以 `->` 结尾的符号链接条目。

### 6.2 文件系统的挂载与卸载

"挂载"（Mount）是 Linux 文件系统最核心的概念之一。它使得不同分区、不同设备上的文件系统能够无缝地插入到统一的目录树中。

**查看当前系统中所有挂载的文件系统：**

```bash
mount | head -n 10
```

或使用更友好的输出：

```bash
df -h
```

输出示例：

```
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           197M  2.3M  194M   2% /run
/dev/sda3        28G   13G   14G  49% /
tmpfs           984M     0  984M   0% /dev/shm
tmpfs           5.0M  8.0K  5.0M   1% /run/lock
/dev/sda2       512M  6.1M  506M   2% /boot/efi
tmpfs           197M   84K  197M   1% /run/user/1000
```

可以看到：
- `/dev/sda3` 挂载到了根目录 `/`
- `/dev/sda2`（EFI 分区）挂载到了 `/boot/efi`
- `tmpfs` 类型的条目是内存文件系统

**手动挂载示例（挂载 ISO 文件）：**

```bash
# 创建挂载点
sudo mkdir -p /mnt/iso

# 挂载 ISO（假设 iso 文件在 /tmp 下）
sudo mount -o loop /tmp/sample.iso /mnt/iso

# 浏览 ISO 内容
ls /mnt/iso

# 卸载
sudo umount /mnt/iso
```

### 6.3 深入理解 PATH 环境变量

`$PATH` 决定了当你输入一个命令名时系统去哪里找它。理解 PATH 对于排查"明明安装了软件却提示 command not found"的问题至关重要。

查看当前 PATH：

```bash
echo $PATH
```

PATH 的设计原则：
1. **按优先级搜索：** 在 PATH 中越靠前的目录优先级越高。如果有两个不同版本的同名命令在 `/usr/local/bin` 和 `/usr/bin` 中，Shell 会使用 `/usr/local/bin` 中的版本（因为它在 PATH 中排在前面）。
2. **安全性：** PATH 中不应包含 `.`（当前目录），否则攻击者可以在 `/tmp` 下放置名为 `ls` 的恶意脚本，当你进入 `/tmp` 后运行 `ls` 时执行恶意代码。
3. **用户自定义：** 你可以将自己的自定义脚本所在目录添加到 PATH：

```bash
# 在 ~/bin 中创建自定义脚本目录
mkdir -p ~/bin

# 临时将 ~/bin 加入 PATH（当前会话有效）
export PATH="$HOME/bin:$PATH"

# 永久生效：在 ~/.bashrc 末尾添加同一行
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### 6.4 符号链接与硬链接

Linux 中有两种链接（Link）：
- **符号链接（Symbolic Link / Symlink / 软链接）：** 类似于 Windows 中的"快捷方式"。它是一个独立文件，指向目标文件/目录的路径。如果目标被删除，符号链接就"断了"（成为悬空链接，Dangling Link）。
- **硬链接（Hard Link）：** 多个文件名指向同一个 inode（磁盘上的实际数据块）。删除"原始文件"不会影响硬链接——因为数据仍在磁盘上，只要还有一个硬链接指向它。

**创建符号链接：**

```bash
ln -s /usr/bin/ls ~/桌面/myls
file ~/桌面/myls
ls -l ~/桌面/myls
```

**创建硬链接：**

```bash
echo "Hello Link" > original.txt
ln original.txt hardlink.txt
ls -li original.txt hardlink.txt
```

注意 `-i` 输出中的 inode 编号（第一列）——两个文件具有相同的 inode 编号，说明它们指向同一个磁盘数据块。

删除原始文件后，硬链接依然能读取内容：

```bash
rm original.txt
cat hardlink.txt          # 仍然输出 "Hello Link"
```

**关键区别：**
- 符号链接可以跨文件系统（一个在 `/home`，另一个在 `/var`），硬链接不能
- 符号链接可以指向目录，硬链接不能（精确说是有限制）
- 删除目标后，符号链接断裂，硬链接不受影响

### 6.5 使用 du 和 df 查看磁盘使用情况

在浏览文件系统时，了解磁盘空间使用情况非常重要。

**df**（Disk Free）——查看文件系统级别的磁盘空间：

```bash
df -h
```

| 参数 | 说明 |
|------|------|
| `-h` | 人类可读格式 |
| `-T` | 显示文件系统类型（ext4、tmpfs 等） |
| `-i` | 显示 inode 使用情况（而非空间） |

示例：

```bash
df -hT /
```

**du**（Disk Usage）——查看目录或文件占用的磁盘空间：

```bash
# 查看家目录总占用
du -sh ~

# 查看某目录下各子目录/文件的大小，排序
du -sh /var/log/* | sort -hr | head -n 10

# 仅查看一层深度的汇总
du -h --max-depth=1 /usr
```

| 参数 | 说明 |
|------|------|
| `-s` | 仅显示总计（Summary） |
| `-h` | 人类可读格式 |
| `--max-depth=N` | 仅显示 N 层深度 |
| `-c` | 在最后追加总计行 |

### 6.6 深入 `/proc` 进行系统诊断

`/proc` 不仅仅能查看信息，部分文件还支持写入来调整内核行为。以下是一些高级用法：

**查看进程列表：**

```bash
ls /proc | grep -E '^[0-9]+$' | head -n 10
```

这列出了当前运行中进程的 PID（Process ID，进程标识符）。

**查看特定进程的详细信息（以 PID=1 的 systemd 为例）：**

```bash
sudo ls /proc/1/
```

```
arch_status  attr        autogroup  auxv  cgroup  clear_refs  cmdline  comm  coredump_filter  ...
```

关键文件：
- `/proc/[PID]/cmdline`：启动该进程的完整命令
- `/proc/[PID]/cwd`：进程当前的工作目录（符号链接）
- `/proc/[PID]/environ`：进程的环境变量
- `/proc/[PID]/fd/`：进程打开的文件描述符

**修改内核参数（需谨慎）：**

```bash
# 查看内核是否允许 IP 转发（IPv4 路由）
cat /proc/sys/net/ipv4/ip_forward

# 临时启用 IP 转发（重启后失效）
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
```

> **警告：** 直接修改 `/proc/sys/` 下的参数仅临时生效，重启后会恢复。如需永久修改，应使用 `/etc/sysctl.conf` 或 `/etc/sysctl.d/` 中的配置文件，配合 `sysctl` 命令。
