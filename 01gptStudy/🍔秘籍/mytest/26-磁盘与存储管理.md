## 1. 概述

### 1.1 从"脚本工程师"到"系统管理员"

第 23-25 章（Bash 脚本三部曲）你掌握了 Shell 编程的全套武器——变量、条件、循环、函数、trap、getopts、调试。这三章让你有能力编写复杂的自动化脚本，但脚本操作的对象此前主要是"文件"和"文本"。

现在，你需要将视野提升到"硬件"层面：

- "服务器上有几块硬盘？容量多大？"
- "新加的硬盘怎么分区？MBR 还是 GPT？"
- "分区完了怎么格式化？ext4 还是 XFS？"
- "格式化之后怎么挂载到目录树？`/etc/fstab` 里的六个字段各是什么意思？"
- "怎么备份整个磁盘或分区？`dd` 的 `of=` 写错了会发生什么？"
- "系统意外断电后分区挂不上了——`fsck` 怎么修复？"
- "根分区快满了，能在线扩容吗？"

这些问题的核心是**磁盘与存储管理**——系统管理的基石。所有数据最终都存储在磁盘上，进程会死、内存会清空，但磁盘上的数据不能丢。如果你管理的服务器磁盘满了或者文件系统损坏了，用户的业务就会中断。

### 1.3 数据在 Linux 中的旅程：从键盘到磁盘

在你学会"管理磁盘"之前，先理解一条数据从诞生到持久化的完整路径，这能帮你建立全局视角：

```
+------------------------------------------------------------------------+
|                   一条数据在 Linux 中的完整旅程                           |
|                                                                        |
|  1. 键盘输入                                                   用户态   |
|  ┌──────────────┐   2. Shell / 程序处理                                |
|  │ $ echo "hello" │────►  echo 程序通过 write() 系统调用写入 stdout    │
|  └──────────────┘                                                      |
|                                                    ─────── 系统调用 ────|
|                                                                        |
|  3. VFS（虚拟文件系统层）                                    内核态     |
|  ┌──────────────────────────────────────────────────────────────┐     |
|  │  Virtual File System（VFS）：统一的文件操作接口                │     |
|  │  - 上承系统调用（open/read/write/close）                       │     |
|  │  - 下接具体文件系统（ext4/XFS/Btrfs/NFS...）                  │     |
|  └──────────────────────────────────────────────────────────────┘     |
|                              │                                          |
|  4. 具体文件系统（ext4 / XFS）                                         |
|  ┌──────────────────────────────────────────────────────────────┐     |
|  │  将"写文件"转化为"写数据块"和"写 inode"                         │     |
|  │  - 日志（Journal）：先写日志再写数据，保证崩溃后一致性            │     |
|  │  - inode：文件元数据（大小、权限、时间戳、数据块指针）            │     |
|  │  - 数据块（Data Block）：文件的实际内容                          │     |
|  └──────────────────────────────────────────────────────────────┘     |
|                              │                                          |
|  5. 块层（Block Layer）                                                |
|  ┌──────────────────────────────────────────────────────────────┐     |
|  │  调度 I/O 请求、合并相邻请求、缓存读写                          │     |
|  └──────────────────────────────────────────────────────────────┘     |
|                              │                                          |
|  6. 设备驱动（Device Driver）                                          |
|  ┌──────────────────────────────────────────────────────────────┐     |
|  │  SCSI / NVMe / SATA / virtio 驱动                             │     |
|  └──────────────────────────────────────────────────────────────┘     |
|                              │                                          |
|  7. 物理存储                                        ─────── 硬件 ──────|
|  ┌──────────┐  ┌──────────┐  ┌──────────┐                           |
|  │   HDD    │  │   SSD    │  │ NVMe SSD │                           |
|  │  /dev/sda│  │  /dev/sdb│  │/dev/nvme │                           |
|  └──────────┘  └──────────┘  └──────────┘                           |
+------------------------------------------------------------------------+
```

本章重点讲解第 4 层到第 7 层：从分区到文件系统到挂载——即如何将裸盘变成可用的存储。

## 2. 核心概念

### 2.1 从物理磁盘到可用存储——四层抽象

Linux 将物理磁盘（Hard Disk）抽象为四个层次，每一层解决一个问题：

```
+------------------------------------------------------------------+
|                     Linux 存储的四层抽象                            |
|                                                                  |
|  第 4 层：文件系统层（Filesystem Layer）                           |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  /data/report.txt  ← 用户看到的文件路径                        │ |
|  │  问题：如何组织文件和目录？                                     │ |
|  │  答案：在分区上创建文件系统（ext4/XFS/Btrfs），提供文件/目录抽象  │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              ▲                                    |
|  第 3 层：挂载层（Mount Layer）                                    |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  /data  ← 挂载点（Mount Point）                                │ |
|  │  问题：分区如何接入系统目录树？                                  │ |
|  │  答案：通过 mount 将分区关联到某个目录                           │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              ▲                                    |
|  第 2 层：分区层（Partition Layer）                                |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  /dev/sda1, /dev/sda2, /dev/nvme0n1p1, /dev/nvme0n1p2      │ |
|  │  问题：一块 1TB 磁盘太大了，如何分割？                           │ |
|  │  答案：用 MBR 或 GPT 分区表将磁盘划分为多个独立区域              │ |
|  └──────────────────────────────────────────────────────────────┘ |
|                              ▲                                    |
|  第 1 层：物理设备层（Physical Device Layer）                      |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │  /dev/sda, /dev/sdb, /dev/nvme0n1, /dev/vda                 │ |
|  │  问题：内核如何识别物理磁盘？                                   │ |
|  │  答案：块设备驱动程序注册设备文件到 /dev                         │ |
|  └──────────────────────────────────────────────────────────────┘ |
+------------------------------------------------------------------+
```

**操作顺序不可颠倒**：物理磁盘（/dev/sda）→ 分区（/dev/sda1）→ 格式化/创建文件系统（mkfs.ext4）→ 挂载（mount）→ 可用。

### 2.2 磁盘设备命名规则

Linux 内核通过设备文件（Device File）向用户态暴露存储设备。不同类型的磁盘驱动器和接口有不同的命名模式。理解这些命名规则是正确识别磁盘的第一步。

#### 2.2.1 传统 SCSI/SATA 磁盘：`/dev/sdX`

这是最常见的命名模式，适用于 SCSI、SATA、SAS、USB 存储设备和大多数虚拟机虚拟磁盘：

```
/dev/sda   — 第一块磁盘（device 'a'）
/dev/sdb   — 第二块磁盘（device 'b'）
/dev/sdc   — 第三块磁盘（device 'c'）
...
/dev/sdz   — 第 26 块磁盘
/dev/sdaa  — 第 27 块磁盘（z 之后用双字母）
```

**字母分配规则**：字母按内核探测到的顺序分配，**不是按物理插槽位置**。这意味着在不同启动中，同一块磁盘可能获得不同的字母。

**分区编号规则**：
- MBR 分区表中，主分区（Primary Partition）从 1 到 4，逻辑分区（Logical Partition）从 5 开始
- GPT 分区表中，所有分区从 1 开始连续编号

```
/dev/sda   — 整块磁盘
/dev/sda1  — 第一个分区
/dev/sda2  — 第二个分区
/dev/sda5  — 第一个逻辑分区（MBR only）
```

#### 2.2.2 NVMe 磁盘：`/dev/nvmeXnY`

NVMe（Non-Volatile Memory Express）是高性能 SSD 使用的协议，通过 PCIe 总线直连 CPU：

```
/dev/nvme0n1    — 第一个 NVMe 控制器，第 1 个命名空间
/dev/nvme0n2    — 第一个 NVMe 控制器，第 2 个命名空间
/dev/nvme1n1    — 第二个 NVMe 控制器，第 1 个命名空间
```

命名格式：`nvme<控制器号>n<命名空间号>`

**分区编号规则**：NVMe 分区在设备名后加 `p<N>`：

```
/dev/nvme0n1     — 整块 NVMe 磁盘
/dev/nvme0n1p1   — 第一个分区
/dev/nvme0n1p2   — 第二个分区
```

之所以加 `p`，是因为 `nvme0n1` 本身已经以数字结尾，不加分隔符会导致歧义（`nvme0n11` 究竟是第 1 号命名空间的第 1 个分区，还是第 11 号命名空间？）。

#### 2.2.3 虚拟化环境磁盘：`/dev/vdX` 和 `/dev/xvdX`

在虚拟机中，磁盘设备由虚拟化平台提供的前端驱动暴露：

```
/dev/vda    — KVM/QEMU virtio 虚拟磁盘（第一块）
/dev/vdb    — KVM/QEMU virtio 虚拟磁盘（第二块）
/dev/xvda   — Xen 虚拟磁盘（第一块）
```

virtio 是 KVM/QEMU 虚拟化平台的高效半虚拟化（Paravirtualization）磁盘驱动协议，也是云服务器（AWS、GCP、阿里云等）最常见的磁盘命名方式。

#### 2.2.4 其他设备命名

```
/dev/loop0      — 回环设备（Loop Device），用于挂载 .iso 或磁盘镜像文件
/dev/md0        — 软件 RAID 设备（Multiple Device）
/dev/dm-0       — Device Mapper 设备（LVM、LUKS 加密等）
/dev/sr0        — SCSI CD-ROM 设备（vm）
/dev/mmcblk0    — SD 卡 / eMMC 存储（常见于 ARM 单板机如树莓派）
```

#### 2.2.5 查看系统中的所有块设备

```bash
# 查看所有块设备（Block Device）
lsblk

# 更详细的信息，含文件系统类型和 UUID
lsblk -f

# 查看块设备的设备文件
ls -l /dev/sd* /dev/nvme* /dev/vd* 2>/dev/null
```

### 2.3 分区表：MBR vs GPT

分区表（Partition Table）是在磁盘起始位置存储的数据结构，用来记录"磁盘上有几个分区、每个分区从哪里开始、到哪里结束"。Linux 中主要有两种分区表格式。

#### 2.3.1 MBR：传统分区表

**MBR（Master Boot Record，主引导记录）** 是自 1983 年 IBM PC/XT 以来一直使用的分区表格式。它位于磁盘的最开始 512 字节中：

```
+------------------------------------------------------------------+
|                    MBR 结构（磁盘前 512 字节）                       |
|                                                                  |
|  ┌─────────────────────────┬─────────────────────────────────┐   |
|  │  引导代码（446 字节）     │  分区表（64 字节 = 4条目×16字节） │   │
|  │  Bootloader Code        │  Partition Table               │   |
|  └─────────────────────────┴─────────────────────────┬───────┘   |
|                                                      │           |
|                                    ┌─────────────────┘           |
|                                    │ 引导签名（2 字节）             |
|                                    │ Boot Signature (0x55AA)     |
|                                    └─────────────────────────────┘
```

**MBR 的限制：**

| 限制项 | 具体数值 | 影响 |
|--------|---------|------|
| 分区数量 | 最多 4 个主分区 | 如果需要更多分区，必须将其中一个主分区设为"扩展分区（Extended Partition）"，在其中创建"逻辑分区（Logical Partition）" |
| 磁盘容量 | 最大 2 TiB（2^32 × 512 字节） | 如果磁盘大于 2 TiB，超出部分无法被 MBR 寻址 |
| 冗余性 | 无备份 | 分区表损坏后难以恢复 |
| 分区标识 | 1 字节分区类型码 | 标识能力有限（0x83=Linux, 0x82=Swap, 0x8E=Linux LVM, ...） |

**MBR 分区类型：**
- **主分区（Primary Partition）**：最多 4 个，可直接使用
- **扩展分区（Extended Partition）**：占用一个主分区槽位，是一个容器，内部可创建多个逻辑分区
- **逻辑分区（Logical Partition）**：存在于扩展分区内部，编号从 5 开始

#### 2.3.2 GPT：现代分区表

**GPT（GUID Partition Table，全局唯一标识符分区表）** 是 UEFI 规范的一部分，解决了 MBR 的所有历史限制：

```
+------------------------------------------------------------------+
|                    GPT 磁盘布局                                    |
|                                                                  |
|  ┌─────────────────┐                                              |
|  │  Protective MBR  │  LBA 0（保护性 MBR，防止旧工具误认磁盘为空）  │
|  ├─────────────────┤                                              |
|  │  GPT Header      │  LBA 1（分区表头，含分区条目数量和大小）       │
|  ├─────────────────┤                                              |
|  │  分区条目 1-4    │  LBA 2-5（示例：每个条目 128 字节）            │
|  ├─────────────────┤                                              |
|  │  分区条目 5-128  │  LBA 6-33（可容纳 128 个分区）                │
|  ├─────────────────┤                                              |
|  │                  │                                              |
|  │   实际分区数据    │  LBA 34 ~ 磁盘末尾 - 34                      |
|  │                  │                                              |
|  ├─────────────────┤                                              |
|  │  GPT Header 备份 │  磁盘末尾 LBA - 1（备份分区表头）              │
|  ├─────────────────┤                                              |
|  │  分区条目 备份    │  末尾的 32 个 LBA（备份分区表条目）            │
|  └─────────────────┘                                              |
+------------------------------------------------------------------+
```

**GPT 相对于 MBR 的优势：**

| 特性 | MBR | GPT |
|------|-----|-----|
| 分区数量 | 4 个主分区 | 通常 128 个（Windows 限制，Linux 可更多） |
| 最大磁盘容量 | 2 TiB | 9.4 ZB（9.4 × 10²¹ 字节） |
| 冗余备份 | 无 | 磁盘头部和尾部各有一份 |
| 分区标识 | 1 字节类型码 | 128 位 GUID（全球唯一） |
| 校验机制 | 无 | CRC32 校验和 |
| 分区命名 | 不支持 | 支持 36 个 Unicode 字符的分区名称（Label） |
| 启动方式 | BIOS Legacy | UEFI |

#### 2.3.3 如何选择 MBR 还是 GPT

```
判断流程图：

磁盘大于 2 TiB？
  ├── 是 → 必须用 GPT
  └── 否 → 系统是 UEFI 启动？
              ├── 是 → 推荐用 GPT
              └── 否 → 传统 BIOS 启动
                         ├── 磁盘 ≤ 2 TiB → MBR 和 GPT 都可以
                         │   - 需要 >4 个分区 → 用 GPT
                         │   - 习惯传统方式 → 用 MBR
                         └── 特殊需求 → 根据需要选择
```

**经验法则：**
- **新安装的系统，优先选 GPT**：除非有明确的兼容性需求
- **大于 2 TiB 的磁盘，必须用 GPT**
- **UEFI 启动的系统，强烈推荐 GPT**（虽然 UEFI 规范也允许 MBR）
- **旧硬件（2012 年前）或特定嵌入式系统**：可能需要 MBR

#### 2.3.4 查看当前分区表类型

```bash
# 方法 1：使用 parted 查看（推荐，最直观）
sudo parted -l
# 输出中 "Partition Table: gpt" 或 "Partition Table: msdos"

# 方法 2：使用 fdisk 查看
sudo fdisk -l
# 输出中 "Disklabel type: gpt" 或 "Disklabel type: dos"

# 方法 3：检查 /sys（不需要 root）
cat /sys/block/sda/queue/physical_block_size
```

### 2.4 文件系统：数据的组织者

分区只是划分了区域，文件系统（Filesystem）才是真正管理数据的方式。它决定了文件如何存储、目录如何组织、权限如何记录。

#### 2.4.1 Linux 常用文件系统

| 文件系统 | 类型 | 特点 | 典型应用场景 |
|----------|------|------|-------------|
| **ext4** | 日志文件系统 | 稳定、成熟、性能均衡；最大 1 EiB 卷、16 TiB 文件 | 通用 Linux 系统，Ubuntu 默认 |
| **XFS** | 64 位日志文件系统 | 高并发性能好、支持大文件；但不能缩减（只能扩容） | 数据库、大文件存储、RHEL/CentOS 默认 |
| **Btrfs** | 写时复制（COW）文件系统 | 快照、子卷、压缩、数据校验；功能丰富但仍在成熟中 | 需要快照和回滚功能的场景 |
| **NTFS** | Windows 文件系统 | Linux 通过 ntfs-3g 读写 | 双系统数据共享盘 |
| **FAT32/exFAT** | 跨平台轻量文件系统 | 兼容性好但功能弱（无权限、无日志） | U 盘、移动硬盘、EFI 系统分区 |
| **swap** | 交换分区/文件 | 虚拟内存的后备存储 | 当物理内存不足时将不活跃页面换出 |

#### 2.4.2 ext4 文件系统内部结构

ext4 是 Ubuntu 默认的文件系统。理解其内部结构有助于后续理解 `fsck`、`tune2fs`、`resize2fs` 的操作原理：

```
+------------------------------------------------------------------+
|                    ext4 文件系统布局                                |
|                                                                  |
|  ┌──────────────┬──────────────┬──────────────┬──────────────┐   |
|  │  引导块       │  块组 0      │  块组 1      │  块组 2 ...   │   |
|  │  (1024 字节)  │              │              │              │   |
|  └──────────────┴──────────────┴──────────────┴──────────────┘   |
|                                                                  |
|  每个块组（Block Group）的内部结构：                               |
|  ┌────────────┬──────────┬──────────┬───────────┬───────────┐   |
|  │ 超级块备份  │ 块组描述符│ 块位图    │ inode 位图 │ inode 表  │   |
|  │ Superblock │ GDT      │ Block    │ Inode     │ Inode     │   |
|  │            │          │ Bitmap   │ Bitmap    │ Table     │   |
|  ├────────────┴──────────┴──────────┴───────────┴───────────┤   |
|  │                    数据块（Data Blocks）                   │   |
|  └───────────────────────────────────────────────────────────┘   |
+------------------------------------------------------------------+
```

**关键概念：**

- **超级块（Superblock）**：文件系统的"元数据头"，记录文件系统大小、块大小、空闲空间、挂载次数、最后挂载时间等。超级块有多个备份散布在各块组中。

- **inode（索引节点）**：每个文件对应一个 inode，存储文件的元数据（大小、权限、所有者、时间戳、数据块指针），**但不存储文件名**。文件名存储在目录的数据块中。

- **数据块（Data Block）**：存储文件的实际内容。ext4 默认块大小为 4096 字节。

- **日志（Journal）**：在写入数据之前先写入日志，如果系统崩溃，可以通过重放（Replay）日志来恢复一致性。这就是"日志文件系统（Journaling Filesystem）"的含义。

#### 2.4.3 挂载——将文件系统接入目录树

**挂载（Mount）** 是 Linux 存储系统中最重要的概念之一。在 Linux 中，所有存储都统一在单一的目录树（Directory Tree）下，以根目录 `/` 为起点。挂载操作将某个分区上的文件系统关联到这个目录树中的某个目录（挂载点，Mount Point）。

```
                        系统目录树
              ┌─────────────┬──────┴──────┬─────────────┐
              │             │             │             │
             bin           etc           home          mnt
              │             │             │             │
              │        ┌────┴────┐   ┌────┴────┐   ┌────┴────┐
              │        │         │   │         │   │         │
              │     fstab      passwd alice   bob    data   backup
              │                                         │       │
              │                                   /dev/sdb1    /dev/sdc1
              │                                   挂载点：     挂载点：
              │                                   /mnt/data   /mnt/backup
             /bin   — 根文件系统上的目录（来自 /dev/sda2）
             /etc   — 根文件系统上的目录（来自 /dev/sda2）
             /home  — 可能是单独的分区（如 /dev/sda3），挂载到 /home
             /mnt/data  — 数据盘（/dev/sdb1）挂载到这里
             /mnt/backup — 备份盘（/dev/sdc1）挂载到这里
```

**挂载的核心规则：**

1. **根目录 `/` 必须最先挂载**（由内核在启动时完成）
2. **挂载点必须是一个已存在的目录**（挂载后，该目录原先的内容会被"遮蔽"）
3. **一个分区可以挂载到任意目录**（没有任何限制）
4. **一个设备不能同时挂载到多个目录**（但可以通过 bind mount 实现特殊需求）
5. **多个设备不能挂载到同一个挂载点**（后挂载的会覆盖前者）

### 2.5 /etc/fstab——文件系统表

`/etc/fstab`（File System Table，文件系统表）定义了系统启动时应该自动挂载的文件系统。它是系统管理的核心配置文件之一，格式严格且容易出错。

#### 2.5.1 fstab 的六个字段

fstab 的每一行定义了一个挂载规则，由 6 个用空白（空格或 Tab）分隔的字段组成：

```
第 1 字段           第 2 字段       第 3 字段     第 4 字段           第 5 字段   第 6 字段
┌─────────────────┬──────────────┬─────────────┬─────────────────┬──────────┬─────────┐
│ 要挂载的设备      │  挂载点       │  文件系统类型  │  挂载选项        │ dump 备份 │ fsck 检查│
│ (device/device) │ (mount point)│ (type)      │ (options)       │ (dump)   │ (pass)  │
└─────────────────┴──────────────┴─────────────┴─────────────────┴──────────┴─────────┘
```

**字段详解：**

| 字段 | 名称 | 说明 | 示例 |
|------|------|------|------|
| 第 1 字段 | 设备标识 | 要挂载的设备。可用设备路径（`/dev/sda1`）、UUID（`UUID=xxx`）、LABEL（`LABEL=mydata`）或 `PARTUUID`（GPT only） | `UUID=a1b2c3d4-...` |
| 第 2 字段 | 挂载点 | 挂载目标目录。对于 swap，填入 `none` 或 `swap` | `/home` |
| 第 3 字段 | 文件系统类型 | ext4, xfs, ntfs-3g, vfat, swap, nfs, ... | `ext4` |
| 第 4 字段 | 挂载选项 | 逗号分隔的选项列表。`defaults` 是快捷方式 | `defaults,noatime` |
| 第 5 字段 | dump 备份 | `0`=不备份，`1`=需要备份（dump 命令使用，现代系统较少使用） | `0` |
| 第 6 字段 | fsck 检查顺序 | `0`=不检查，`1`=最先检查（仅根文件系统），`2`=其次检查 | `2` |

#### 2.5.2 第 4 字段常用挂载选项

| 选项 | 说明 |
|------|------|
| `defaults` | 等同于 `rw,suid,dev,exec,auto,nouser,async` |
| `rw` / `ro` | 读写（Read-Write）/只读（Read-Only）挂载 |
| `exec` / `noexec` | 允许/禁止执行该文件系统上的二进制文件 |
| `auto` / `noauto` | 开机时 `mount -a` 自动挂载 / 不自动挂载 |
| `user` / `nouser` | 允许/禁止普通用户挂载此设备 |
| `sync` / `async` | 同步（Synchronous）/异步（Asynchronous）I/O |
| `noatime` | 不更新文件访问时间（Access Time），提高性能 |
| `relatime` | 仅在访问时间早于修改时间时才更新（推荐默认） |
| `nofail` | 设备不存在时也不报错，继续启动（适用于可移动设备） |

#### 2.5.3 fstab 示例

```bash
# /etc/fstab 示例
# <设备标识>                   <挂载点>  <类型>  <选项>                   <dump> <pass>
UUID=abc123-def456-...        /         ext4    defaults,relatime        0      1
UUID=ghi789-jkl012-...        /boot     ext4    defaults                 0      2
UUID=mno345-pqr678-...        /home     ext4    defaults,noatime         0      2
UUID=stu901-vwx234-...        none      swap    sw                       0      0
# 一个 nfs 网络文件系统的例子
192.168.1.100:/exports/data   /nfs/data nfs     defaults,_netdev         0      0
# 一个可移动 USB 盘的例子
LABEL=USB_BACKUP              /mnt/usb   ext4    defaults,noauto,nofail  0      0
```

> **重要提示**：第 6 字段（pass）中，根文件系统 `/` 必须设为 `1`，其他需要检查的文件系统设为 `2`，swap 和网络文件系统设为 `0`。

## 3. 命令详解

### 3.1 lsblk —— 列出块设备

`lsblk`（List Block Devices）以树状结构显示系统中所有的块设备（磁盘、分区、逻辑卷等）及其挂载关系。

#### 3.1.1 基本用法

```bash
# 基本输出（树状）
lsblk
# 输出示例：
# NAME   MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
# sda      8:0    0   100G  0 disk
# ├─sda1   8:1    0   512M  0 part /boot/efi
# ├─sda2   8:2    0    50G  0 part /
# └─sda3   8:3    0  49.5G  0 part /home
# sdb      8:16   0   200G  0 disk
# └─sdb1   8:17   0   200G  0 part /mnt/data
# sr0     11:0    1  1024M  0 rom

# 显示文件系统信息
lsblk -f
# 输出示例（增加 FSTYPE, UUID, LABEL 等列）：
# NAME   FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
# sda
# ├─sda1 vfat   FAT32       ABCD-1234                              505.8M     1% /boot/efi
# ├─sda2 ext4   1.0         12345678-...                             42.5G     6% /
# └─sda3 ext4   1.0         87654321-...                             38.2G    14% /home
# sdb
# └─sdb1 ext4   1.0   DATA  11112222-...                            150G     14% /mnt/data
```

#### 3.1.2 lsblk 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-a` / `--all` | 显示所有设备（包括空设备） | 可选 | 隐藏空设备 |
| `-f` / `--fs` | 显示文件系统信息（类型、UUID、LABEL 等） | 可选 | 只显示设备基本信息 |
| `-m` / `--perms` | 显示设备权限和所有者 | 可选 | 不显示 |
| `-o` / `--output` | 指定输出的列（自定义） | 可选 | `NAME,MAJ:MIN,RM,SIZE,RO,TYPE,MOUNTPOINTS` |
| `-J` / `--json` | JSON 格式输出 | 可选 | 表格输出 |
| `-p` / `--paths` | 显示完整设备路径 | 可选 | 只显示设备名 |
| `-n` / `--noheadings` | 不显示表头 | 可选 | 显示表头 |
| `-d` / `--nodeps` | 不显示从属设备（如分区），只显示磁盘 | 可选 | 显示树状结构 |
| `-S` / `--scsi` | 仅显示 SCSI 设备信息 | 可选 | 显示所有设备 |
| `-b` / `--bytes` | 以字节为单位显示大小 | 可选 | 人类可读格式 |
| `-l` / `--list` | 列表模式（非树状） | 可选 | 树状模式 |
| `-r` / `--raw` | 原始格式（无对齐） | 可选 | 对齐格式 |

#### 3.1.3 常用示例

```bash
# 查看所有块设备（含空设备，如未分区的磁盘）
lsblk -a

# 查看完整的设备路径和 UUID
lsblk -fp

# 自定义输出列：设备名、大小、类型、挂载点
lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS

# 只显示磁盘级别的设备（不显示分区）
lsblk -d

# 查看指定设备
lsblk /dev/sda

# 查看 SCSI 设备详细信息
lsblk -S

# JSON 格式（用于脚本解析）
lsblk -J
```

### 3.2 blkid —— 块设备属性查询

`blkid`（Block ID）用于查看块设备的 UUID、文件系统类型、LABEL 等属性。它是一个只读操作，非常安全。

#### 3.2.1 基本用法

```bash
# 列出所有设备的属性
blkid
# 输出示例：
# /dev/sda1: UUID="ABCD-1234" BLOCK_SIZE="512" TYPE="vfat" PARTUUID="abcdef01-01"
# /dev/sda2: UUID="12345678-abcd-..." BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="abcdef01-02"
# ...

# 查询指定设备
sudo blkid /dev/sda2

# 按 UUID 查找设备
sudo blkid -U "12345678-abcd-..."

# 只看指定属性
sudo blkid -s UUID /dev/sda2
# 输出：
# /dev/sda2: UUID="12345678-abcd-..."
```

#### 3.2.2 blkid 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-s <tag>` | 只显示指定的标签（如 UUID, TYPE, LABEL） | 可选 | 显示所有属性 |
| `-o <format>` | 输出格式：`full`（默认）、`value`（纯值）、`device`（仅设备名）、`export`（可导入 Shell）、`udev`（udev 风格） | 可选 | `full` |
| `-p` | 探测模式（Probe），直接读取设备而不用缓存 | 可选 | 使用缓存 |
| `-U <uuid>` | 按 UUID 查找设备 | 可选 | — |
| `-L <label>` | 按 LABEL 查找设备 | 可选 | — |
| `-g` | 刷新缓存 | 可选 | — |
| `-k` | 重置缓存 | 可选 | — |

#### 3.2.3 常用示例

```bash
# 输出为可直接导入 Shell 的格式
sudo blkid -o export /dev/sda2
# 输出：
# DEVNAME=/dev/sda2
# UUID=12345678-abcd-...
# TYPE=ext4

# 只取 UUID 的值
sudo blkid -s UUID -o value /dev/sda2
# 输出：12345678-abcd-...

# 在脚本中使用 blkid
DISK_UUID=$(sudo blkid -s UUID -o value /dev/sda2)
echo "文件系统 UUID 是：$DISK_UUID"
```

### 3.3 fdisk —— MBR 磁盘分区工具

`fdisk` 是传统的 MBR 分区工具，也能够识别 GPT 磁盘（但操作 GPT 推荐使用 `gdisk` 或 `parted`）。它是一款交互式命令行工具。

#### 3.3.1 查看分区信息

```bash
# 列出所有磁盘的分区信息（只读，安全）
sudo fdisk -l

# 查看指定磁盘的分区表
sudo fdisk -l /dev/sda
```

#### 3.3.2 fdisk 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` | 列出分区表后退出（不进入交互模式） | 可选 | 进入交互模式 |
| `-u` | 显示单位（`=cylinders` 或 `=sectors`） | 可选 | sectors |
| `-c` | 关闭/开启 DOS 兼容模式 | 可选 | `-c=dos` |
| `-w` / `-W` | 写入/擦除签名 | 可选 | — |

#### 3.3.3 fdisk 交互模式常用命令

进入交互模式：`sudo fdisk /dev/sdX`

| 命令 | 说明 |
|------|------|
| `m` | 显示帮助菜单 |
| `p` | 打印（Print）当前分区表 |
| `n` | 新建（New）分区 |
| `d` | 删除（Delete）分区 |
| `t` | 更改分区类型 |
| `w` | 写入（Write）分区表并退出（**不可撤销！**） |
| `q` | 退出（Quit）不保存任何修改 |
| `g` | 创建新的 GPT 分区表 |
| `o` | 创建新的 MBR（DOS）分区表 |
| `a` | 切换可启动（Active/Bootable）标志 |
| `v` | 验证分区表 |

#### 3.3.4 使用 fdisk 创建 MBR 分区的完整流程

```bash
# 警告：以下操作为演示，请在实际磁盘上谨慎执行！
# 建议在虚拟机中使用一个空磁盘（如 /dev/sdb）来练习

# 1. 查看当前磁盘状态
sudo fdisk -l /dev/sdb

# 2. 进入 fdisk 交互模式
sudo fdisk /dev/sdb

# 3. 在交互模式中执行以下命令序列：
#    o          创建新的 MBR 分区表（清空原有分区）
#    n          新建分区
#      p        主分区（Primary）
#      1        分区号 1
#      2048     起始扇区（按 Enter 使用默认）
#      +10G     分区大小（10 GiB）
#    n          新建第二个分区
#      p
#      2
#      <Enter>  起始扇区（默认紧接上一个分区）
#      +20G
#    p          打印分区表确认
#    w          写入并退出
```

```bash
# 非交互式创建分区（脚本友好）
# 将命令通过管道传给 fdisk
echo -e "o\nn\np\n1\n\n+10G\nn\np\n2\n\n+20G\nw" | sudo fdisk /dev/sdb
# echo -e 各命令含义：
#   o = 创建 MBR 分区表
#   n = 新建分区1：p（主分区）、编号1、默认起始、+10G
#   n = 新建分区2：p（主分区）、编号2、默认起始、+20G
#   w = 写入并退出
```

### 3.4 gdisk —— GPT 磁盘分区工具

`gdisk`（GPT fdisk）是专门用于 GPT 分区表的工具。它的交互界面设计与 `fdisk` 非常相似，有意识的学习迁移成本很低。

#### 3.4.1 查看 GPT 分区信息

```bash
# 列出所有 GPT 磁盘
sudo gdisk -l /dev/sda
```

#### 3.4.2 gdisk 交互模式常用命令

进入交互模式：`sudo gdisk /dev/sdX`

| 命令 | 说明 |
|------|------|
| `?` 或 `?` | 显示帮助 |
| `p` | 打印当前分区表 |
| `n` | 新建分区 |
| `d` | 删除分区 |
| `t` | 更改分区类型（使用 GPT 类型 GUID） |
| `w` | 写入分区表并退出（**不可撤销！**） |
| `q` | 退出不保存 |
| `o` | 创建新的 GPT 分区表 |
| `c` | 修改分区名称（Label） |
| `i` | 显示分区的详细信息 |
| `r` | 进入恢复和转换子菜单 |
| `x` | 高级功能（专家模式） |

#### 3.4.3 gdisk 创建 GPT 分区的完整流程

```bash
# 1. 进入 gdisk 交互模式
sudo gdisk /dev/sdb

# 2. 在交互模式中执行：
#    o          创建新的 GPT 分区表
#    n          新建分区
#      1        分区号 1
#      <Enter>  起始扇区（默认 2048）
#      +1G      分区大小：1 GiB（EFI 系统分区通常 100M-1G）
#      EF00     分区类型：EFI System Partition
#    n          新建第二个分区
#      2
#      <Enter>
#      +50G
#      8300     分区类型：Linux filesystem（默认）
#    n          新建第三个分区
#      3
#      <Enter>
#      +4G
#      8200     分区类型：Linux swap
#    p          打印确认
#    w          写入并退出
#    (确认 Y)
```

> **GPT 常用类型代码速查：**
> - `8300` — Linux filesystem（ext4/XFS/Btrfs...）
> - `8200` — Linux swap
> - `EF00` — EFI System Partition（ESP）
> - `8E00` — Linux LVM

### 3.5 parted —— 通用分区工具

`parted`（Partition Editor）是一个同时支持 MBR 和 GPT 的分区工具。它的最大优势是**支持非交互式的脚本化操作**，这在自动化部署场景中非常关键。

#### 3.5.1 查看分区

```bash
# 列出所有磁盘的分区信息
sudo parted -l

# 查看指定磁盘
sudo parted /dev/sda print
```

#### 3.5.2 parted 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` / `--list` | 列出所有设备的分区表 | 可选 | 交互模式 |
| `-s` / `--script` | 脚本模式（不提示确认） | 可选 | 交互模式 |
| `-a` / `--align` | 指定对齐方式：`none`/`cylinder`/`minimal`/`optimal` | 可选 | `optimal` |
| `-m` / `--machine` | 机器可解析的输出格式 | 可选 | 人类可读格式 |

#### 3.5.3 parted 交互模式常用命令

| 命令 | 说明 |
|------|------|
| `help` | 显示帮助 |
| `print` | 显示当前分区表 |
| `mklabel <类型>` | 创建分区表：`msdos`（MBR）或 `gpt` |
| `mkpart <名称> <起始> <结束>` | 创建分区 |
| `rm <编号>` | 删除分区 |
| `resizepart <编号> <结束>` | 调整分区大小 |
| `quit` | 退出 |

#### 3.5.4 使用 parted 脚本化创建分区

```bash
# 创建 GPT 分区表并创建两个分区（非交互式，自动化友好）
sudo parted -s /dev/sdb mklabel gpt
sudo parted -s /dev/sdb mkpart primary ext4 0% 50%
sudo parted -s /dev/sdb mkpart primary ext4 50% 100%

# 查看结果
sudo parted /dev/sdb print
```

#### 3.5.5 fdisk vs gdisk vs parted 选型

| 场景 | 推荐工具 |
|------|---------|
| MBR 磁盘，手动分区 | `fdisk` |
| GPT 磁盘，手动分区 | `gdisk` |
| 脚本自动化 | `parted -s` |
| 混合环境（MBR + GPT） | `parted` |
| 需要调整分区大小 | `parted` |

### 3.6 mkfs —— 创建文件系统（格式化）

分区只是划定了区域，必须在其上创建文件系统（格式化）才能存储文件。`mkfs`（Make File System）是一个前端工具，它调用具体的文件系统创建程序。

#### 3.6.1 基本用法

```bash
# 查看可用的文件系统类型
ls /sbin/mkfs.*
# 输出示例：
# /sbin/mkfs.btrfs  /sbin/mkfs.ext2  /sbin/mkfs.ext4
# /sbin/mkfs.cramfs /sbin/mkfs.ext3  /sbin/mkfs.xfs
# ...

# 创建 ext4 文件系统（默认选项）
sudo mkfs.ext4 /dev/sdb1

# 等价形式
sudo mkfs -t ext4 /dev/sdb1

# 创建 ext4 时指定 LABEL
sudo mkfs.ext4 -L "MY_DATA" /dev/sdb1

# 创建 XFS 文件系统
sudo mkfs.xfs /dev/sdb2
# 或
sudo mkfs -t xfs /dev/sdb2
```

#### 3.6.2 mkfs 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-t <type>` | 文件系统类型（ext4, xfs, btrfs 等） | 必选 | — |
| `-V` | 详细（Verbose）输出 | 可选 | 简洁输出 |
| `-c` | 格式化前检查坏块（Bad Blocks） | 可选 | 不检查 |
| `-l <file>` | 从文件读取坏块列表 | 可选 | — |

**mkfs.ext4 特定选项：**

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-L <label>` | 设置文件系统卷标（LABEL） | 可选 | 无 |
| `-b <size>` | 块大小（Block Size）：1024/2048/4096 字节 | 可选 | 4096 |
| `-m <pct>` | 为 root 预留的空间百分比 | 可选 | 5% |
| `-E <opt>` | 扩展选项（如 `lazy_itable_init=1` 加速格式化） | 可选 | — |
| `-i <ratio>` | 每多少字节分配一个 inode | 可选 | 16384 |
| `-I <size>` | inode 大小（128/256/512 字节） | 可选 | 256 |
| `-N <num>` | 预分配 inode 数量 | 可选 | 自动计算 |
| `-q` | 安静（Quiet）模式 | 可选 | 正常输出 |

#### 3.6.3 常用示例

```bash
# 创建 ext4 文件系统，带 LABEL，1% reserved blocks
sudo mkfs.ext4 -L "DB_STORAGE" -m 1 /dev/sdb1

# 创建 ext4 文件系统，使用懒初始化加速（适用于大容量格式化）
sudo mkfs.ext4 -E lazy_itable_init=1 /dev/sdb1

# 创建 swap 分区
sudo mkswap /dev/sdb3
```

> **警告：`mkfs` 是破坏性操作，会清空目标分区上的所有数据。执行前务必使用 `lsblk` 和 `blkid` 双重确认目标设备。**

### 3.7 mount —— 挂载文件系统

`mount` 将文件系统关联到目录树中的挂载点。这是让裸盘数据可用的最后一步。

#### 3.7.1 基本用法

```bash
# 查看当前所有挂载
mount
# 或（更简洁的树状视图）
findmnt

# 挂载分区到目录
sudo mount /dev/sdb1 /mnt/data

# 挂载时指定文件系统类型
sudo mount -t ext4 /dev/sdb1 /mnt/data

# 挂载只读
sudo mount -o ro /dev/sdb1 /mnt/data

# 重新挂载（更改挂载选项，不需要卸载）
sudo mount -o remount,rw /mnt/data
```

#### 3.7.2 mount 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-t <type>` | 文件系统类型 | 可选 | 自动检测 |
| `-o <options>` | 挂载选项（逗号分隔） | 可选 | `defaults` |
| `-a` | 挂载 `/etc/fstab` 中所有 `auto` 条目 | 可选 | — |
| `-r` / `--read-only` | 只读挂载 | 可选 | 读写 |
| `-L <label>` | 按 LABEL 挂载 | 可选 | — |
| `-U <uuid>` | 按 UUID 挂载 | 可选 | — |
| `-B` / `--bind` | 绑定挂载（Bind Mount） | 可选 | — |
| `--move` | 移动挂载点到新位置 | 可选 | — |

#### 3.7.3 挂载选项（`-o`）详表

| 选项 | 说明 |
|------|------|
| `rw` / `ro` | 读写（Read-Write）/ 只读（Read-Only） |
| `sync` / `async` | 同步写入（Synchronous）/ 异步写入（Asynchronous，默认） |
| `noatime` | 不更新文件访问时间，减少磁盘写入 |
| `relatime` | 仅在 mtime/ctime 晚于 atime 时更新 atime（折中方案） |
| `noexec` | 禁止执行该设备上的二进制文件 |
| `nosuid` | 忽略 SUID/SGID 位（安全加固） |
| `nodev` | 不解析设备文件（安全加固） |
| `nofail` | 设备不存在时不报错（用于可移除设备） |
| `user` | 允许普通用户挂载 |
| `exec` / `suid` / `dev` | 分别对应 `noexec`/`nosuid`/`nodev` 的反向 |

#### 3.7.4 常用示例

```bash
# 按 UUID 挂载（推荐！比 /dev/sdX 更稳定）
sudo mount -U "12345678-abcd-..." /mnt/data

# 按 LABEL 挂载
sudo mount -L "MY_DATA" /mnt/data

# 挂载 ISO 镜像文件（回环设备）
sudo mount -o loop ubuntu-24.04.iso /mnt/iso

# 绑定挂载：将已有挂载点的一部分映射到另一位置
sudo mount --bind /data/projects /home/alice/projects

# 挂载后重新挂载为只读
sudo mount -o remount,ro /

# 挂载 NTFS 分区（需安装 ntfs-3g）
sudo mount -t ntfs-3g /dev/sdc1 /mnt/windows
```

### 3.8 umount —— 卸载文件系统

`umount`（注意拼写：没有 'n'）将文件系统从目录树中分离。

#### 3.8.1 基本用法

```bash
# 按挂载点卸载
sudo umount /mnt/data

# 按设备路径卸载
sudo umount /dev/sdb1

# 强制卸载（设备忙时）
sudo umount -f /mnt/data

# 懒惰卸载（先标记，等不忙时再真正卸载）
sudo umount -l /mnt/data
```

#### 3.8.2 umount 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-f` / `--force` | 强制卸载（适用于无响应的 NFS） | 可选 | 正常卸载 |
| `-l` / `--lazy` | 懒惰卸载（Lazy Unmount），先分离再等不忙时清理 | 可选 | 正常卸载 |
| `-r` / `--read-only` | 卸载失败时尝试只读重新挂载 | 可选 | — |
| `-a` / `--all` | 卸载所有 `/etc/mtab` 中的文件系统 | 可选 | — |
| `-t <type>` | 只卸载指定类型的文件系统 | 可选 | — |

#### 3.8.3 卸载失败的常见原因及处理

```bash
# 原因 1：有进程正在使用该挂载点下的文件
# 错误信息：umount: /mnt/data: target is busy.

# 查找占用者
sudo lsof /mnt/data
# 或使用 fuser
sudo fuser -v /mnt/data

# 终止占用进程后重试
sudo fuser -km /mnt/data  # k=kill, m=mount point

# 原因 2：当前工作目录在该挂载点内
cd /  # 先离开再卸载

# 如果确认安全但就是卸载不掉：
sudo umount -l /mnt/data  # 懒惰卸载
```

### 3.9 /etc/fstab —— 管理开机自动挂载

前面在核心概念部分已经详细解释了 fstab 的六个字段。这里重点演示实际操作。

#### 3.9.1 添加新条目到 fstab

```bash
# 第 1 步：获取设备的 UUID（推荐使用 UUID 而非设备路径）
sudo blkid /dev/sdb1

# 第 2 步：创建挂载点
sudo mkdir -p /mnt/data

# 第 3 步：备份原有 fstab
sudo cp /etc/fstab /etc/fstab.bak.$(date +%Y%m%d)

# 第 4 步：编辑 fstab
sudo nano /etc/fstab
# 添加如下行（用上一步获取的 UUID 替换）：
# UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx  /mnt/data  ext4  defaults,noatime  0  2

# 第 5 步：测试 fstab 是否正确（不重启验证）
sudo mount -a
# 如果没有错误输出，说明配置正确

# 第 6 步：验证挂载
df -h /mnt/data
```

#### 3.9.2 fstab 常见错误及排查

```bash
# 错误 1：fstab 有语法错误导致系统无法启动
#   症状：重启后进入 emergency mode
#   解决：在 emergency mode 中编辑 /etc/fstab 注释掉错误行，然后重启

# 错误 2：UUID 写错了
#   症状：mount -a 报错 "can't find UUID=..."
#   解决：sudo blkid 重新确认 UUID

# 错误 3：挂载点目录不存在
#   症状：mount -a 报错 "mount point does not exist"
#   解决：sudo mkdir -p <挂载点>

# 错误 4：文件系统类型写错
#   症状：mount -a 报错 "wrong fs type"
#   解决：sudo blkid 确认文件系统类型

# 预防：修改 fstab 后一定要先执行 mount -a 测试
sudo mount -a && echo "fstab 检查通过"
```

### 3.10 findmnt —— 查询挂载信息

`findmnt` 是一个强大的挂载信息查询工具，比传统的 `mount` 命令输出更结构化、更易于过滤和脚本处理。

#### 3.10.1 基本用法

```bash
# 树状显示所有挂载
findmnt

# 显示指定挂载点
findmnt /home

# 显示指定设备的挂载情况
findmnt /dev/sda1

# 按文件系统类型过滤
findmnt -t ext4
```

#### 3.10.2 findmnt 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-t <type>` | 按文件系统类型过滤 | 可选 | 所有类型 |
| `-S <source>` | 按源设备过滤 | 可选 | — |
| `-T <target>` | 按挂载目标过滤 | 可选 | — |
| `-D` / `--df` | 模仿 `df` 命令的输出 | 可选 | — |
| `-l` / `--list` | 列表模式（非树状） | 可选 | 树状 |
| `-n` / `--noheadings` | 不显示列标题 | 可选 | 显示标题 |
| `-o <columns>` | 自定义输出列 | 可选 | `TARGET,SOURCE,FSTYPE,OPTIONS` |
| `-r` / `--raw` | 原始格式输出 | 可选 | 对齐格式 |
| `-J` / `--json` | JSON 格式输出 | 可选 | — |
| `-P` / `--pairs` | key="value" 格式输出 | 可选 | — |
| `-R` / `--submounts` | 显示子挂载 | 可选 | — |
| `--real` | 只显示真正的文件系统（跳过虚拟的） | 可选 | 全部 |

#### 3.10.3 常用示例

```bash
# 查看挂载详细信息
findmnt -o TARGET,SOURCE,FSTYPE,SIZE,USED,AVAIL,USE%

# 只看 ext4 文件系统
findmnt -t ext4

# 查看 / 所在的设备
findmnt -n -o SOURCE /
# 输出：/dev/sda2

# 脚本中判断某个目录是否是挂载点
if findmnt /mnt/data > /dev/null 2>&1; then
    echo "/mnt/data 已挂载"
else
    echo "/mnt/data 未挂载"
fi

# 只列出真正的物理文件系统（排除 tmpfs、proc 等虚拟文件系统）
findmnt --real

# JSON 输出用于程序解析
findmnt -J --real
```

### 3.11 dd —— 低级别数据复制

`dd`（Data Duplicator / Disk Dump）是 Unix/Linux 中最底层的文件复制工具。它直接按块（Block）读写数据，不关心文件系统结构。这使得它可以用于磁盘克隆、备份、数据销毁和创建启动盘等场景。

#### 3.11.1 基本语法

```
dd if=<输入文件> of=<输出文件> [bs=<块大小>] [count=<块数量>] [其他选项...]
```

| 参数 | 说明 |
|------|------|
| `if=` | 输入文件（Input File）。不指定时默认从 stdin 读取 |
| `of=` | 输出文件（Output File）。不指定时默认写入 stdout |
| `bs=` | 块大小（Block Size）。每次读/写的字节数 |
| `count=` | 复制的块数量（以 bs 为单位） |
| `skip=` | 从输入文件开头跳过的块数 |
| `seek=` | 从输出文件开头跳过的块数 |
| `conv=` | 转换选项（逗号分隔多个） |
| `status=` | 进度显示级别：`none`/`noxfer`/`progress` |

#### 3.11.2 `conv=` 常用转换选项

| 选项 | 说明 |
|------|------|
| `sync` | 将每个输入块用 NUL 填充到 bs 大小 |
| `noerror` | 遇到读取错误时继续执行 |
| `notrunc` | 不截断输出文件 |
| `fsync` | 完成后同步刷新数据到磁盘 |
| `fdatasync` | 完成后只刷新数据（不同步元数据） |

#### 3.11.3 BS 单位的写法

```
bs=512         # 512 字节
bs=1K          # 1024 字节（1 KiB）
bs=1M          # 1024 KiB
bs=4M          # 4096 KiB
bs=1G          # 1024 MiB
bs=64K         # 64 KiB
```

> **性能提示**：`bs` 越大，系统调用次数越少，吞吐量（Throughput）越高。但太大的 `bs` 会占用更多内存。实际使用中 `bs=1M` 或 `bs=4M` 是常见的平衡点。

#### 3.11.4 dd 常用示例

```bash
# 1. 创建测试文件（生成 100MB 的空文件）
dd if=/dev/zero of=/tmp/testfile bs=1M count=100

# 2. 备份 MBR（磁盘前 512 字节，含分区表）
sudo dd if=/dev/sda of=/tmp/sda-mbr.bak bs=512 count=1

# 3. 备份 GPT 表头 + 分区表（LBA 0-33，共 34 个扇区 × 512 = 17408 字节）
sudo dd if=/dev/sda of=/tmp/sda-gpt-header.bak bs=512 count=34

# 4. 克隆整个磁盘（disk to disk clone）
# 危险操作！确保 of 目标磁盘上的数据已经无用
sudo dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# 5. 将磁盘备份到镜像文件
sudo dd if=/dev/sda of=/mnt/backup/sda-full.img bs=4M status=progress

# 6. 从镜像文件恢复到磁盘
sudo dd if=/mnt/backup/sda-full.img of=/dev/sda bs=4M status=progress

# 7. 安全擦除磁盘（覆写随机数据）
sudo dd if=/dev/urandom of=/dev/sdb bs=4M status=progress

# 8. 安全擦除磁盘（覆写零——更快但有数据恢复风险）
sudo dd if=/dev/zero of=/dev/sdb bs=4M status=progress

# 9. 创建 USB 启动盘（从 ISO 文件）
sudo dd if=ubuntu-24.04-desktop-amd64.iso of=/dev/sdc bs=4M status=progress conv=fsync
```

#### 3.11.5 dd 的安全警告

```
┌───────────────────────────────────────────────────────────────────┐
│                    ⚠ dd 安全警告                                  │
│                                                                  │
│  dd 的别名叫 "Disk Destroyer"（磁盘毁灭者）                         │
│                                                                  │
│  以下三条军规必须刻在脑子里：                                       │
│                                                                  │
│  1. 执行 dd 前必须用 lsblk 确认 of= 指向正确的设备                   │
│     lsblk            # 先看设备树                                   │
│     sudo dd ... of=/dev/sdb  # 再三确认是 sdb 不是 sda             │
│                                                                  │
│  2. 不要混淆 if= 和 of=                                            │
│     if= 是输入（源）  → 读出数据                                    │
│     of= 是输出（目标） → 写入数据（会覆盖！）                          │
│     口诀：input file (if) 在前，output file (of) 在后                │
│                                                                  │
│  3. 关键操作前先备份分区表                                          │
│     sudo dd if=/dev/sda of=sda-mbr.bak bs=512 count=1             │
│     这样即使误操作，也可以恢复分区表                                  │
└───────────────────────────────────────────────────────────────────┘
```

### 3.12 fsck —— 文件系统检查与修复

`fsck`（File System Consistency Check）用于检查文件系统的一致性并在发现错误时尝试修复。它本身是一个前端工具，根据文件系统类型调用对应的检查程序（`fsck.ext4`、`fsck.xfs` 等）。

#### 3.12.1 基本用法

```bash
# 检查文件系统（只读，不修复）
sudo fsck -N /dev/sdb1
# -N：显示将要执行的命令，不实际执行

# 检查并自动修复
sudo fsck -a /dev/sdb1

# 检查并交互式修复（每个问题都会问 y/n）
sudo fsck -r /dev/sdb1

# 强制检查（即使文件系统标记为 clean）
sudo fsck -f /dev/sdb1
```

#### 3.12.2 fsck 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-a` / `--auto` | 自动修复，不询问 | 可选 | 交互式 |
| `-r` / `--repair` | 交互式修复，每个问题询问 | 可选 | — |
| `-y` / `--yes` | 对所有问题自动回答 yes | 可选 | — |
| `-n` / `--no` | 对所有问题自动回答 no（只检查不修复） | 可选 | — |
| `-f` / `--force` | 强制检查（即使文件系统显示为 clean） | 可选 | — |
| `-N` | 只显示将要做什么，不实际执行 | 可选 | — |
| `-t <type>` | 指定文件系统类型 | 可选 | 自动检测 |
| `-A` | 检查 `/etc/fstab` 中所有文件系统 | 可选 | — |
| `-R` | 跳过分区（与 `-A` 配合使用） | 可选 | — |
| `-C` | 显示进度条（仅支持 ext 系列） | 可选 | — |
| `-p` | 自动修复（Preen Mode，安全模式下只修无害问题） | 可选 | — |

#### 3.12.3 fsck 检查哪些问题

fsck 主要检查以下一致性（Consistency）问题：

1. **inode 位图一致性**：inode 位图标记为"已使用"的 inode 是否真的存在对应文件
2. **块位图一致性**：块位图标记为"已使用"的块是否真的被某个 inode 引用
3. **inode 链接计数**：每个文件的硬链接计数（Link Count）是否与实际目录项数一致
4. **目录结构完整性**：`.` 和 `..` 条目是否存在且指向正确的 inode
5. **超级块一致性**：超级块中记录的空闲 inode 数和空闲块数是否与实际相符
6. **日志一致性**：日志是否可以被正确重放

#### 3.12.4 安全执行 fsck 的步骤

```bash
# 第 1 步：确保文件系统处于卸载状态（强烈建议！）
sudo umount /dev/sdb1

# 极端情况：根文件系统需要检查
# 方法 1：使用恢复模式（Recovery Mode）启动
# 方法 2：在系统运行时设置下次重启自动检查
sudo tune2fs -c 1 /dev/sda2  # 设置挂载1次后强制检查

# 第 2 步：先做只读检查
sudo fsck -n /dev/sdb1

# 第 3 步：如果有错误，备份超级块
sudo dumpe2fs /dev/sdb1 | grep -i superblock
# 输出会列出备用超级块的位置

# 第 4 步：执行自动修复
sudo fsck -a /dev/sdb1
# 或交互式修复
sudo fsck -r /dev/sdb1

# 第 5 步：重新挂载
sudo mount /dev/sdb1 /mnt/data
```

#### 3.12.5 fsck 的退出码

```bash
sudo fsck /dev/sdb1
echo $?
```

| 退出码 | 含义 |
|--------|------|
| `0` | 没有错误 |
| `1` | 文件系统错误已修复 |
| `2` | 需要重启系统 |
| `4` | 文件系统错误未修复 |
| `8` | 操作错误 |
| `16` | 使用或语法错误 |
| `32` | fsck 被用户取消 |
| `128` | 共享库错误 |

> 退出码 `> 0` 且 `< 4` 时（如 0/1/2）文件系统是可用的，其他退出码表示严重问题。

### 3.13 e2fsck —— ext2/ext3/ext4 专用检查工具

`e2fsck` 是 ext 系列文件系统的专用检查和修复工具，功能比通用的 `fsck` 更丰富。

#### 3.13.1 基本用法

```bash
# 检查文件系统

# 自动修复

# 对所有问题回答 yes

# 强制检查
```

#### 3.13.2 e2fsck 常用选项

#### 3.13.3 使用备用超级块修复

### 3.14 tune2fs —— 调整 ext 文件系统参数

`tune2fs` 用于查看和修改 ext2/ext3/ext4 文件系统的可调参数。这些操作通常不需要卸载文件系统。

#### 3.14.1 查看文件系统信息

```bash
# 查看文件系统详细信息（超级块内容）
sudo tune2fs -l /dev/sda2
# 输出包括：
#   Filesystem UUID, created, last mounted, ...
#   Filesystem features（has_journal, ext_attr, dir_index, ...）
#   Reserved block count, Reserved block %
#   Maximum mount count（达到后强制 fsck）
#   Check interval（两次 fsck 之间的最长时间）

# 只查看特定信息
sudo tune2fs -l /dev/sda2 | grep -E "Mount count|Maximum mount count|Check interval"
```

#### 3.14.2 tune2fs 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-l` | 列出（List）文件系统信息（只读） | 可选 | — |
| `-L <label>` | 设置文件系统卷标 | 可选 | 已有标签 |
| `-U <uuid>` | 设置/清除/随机生成 UUID | 可选 | 已有 UUID |
| `-c <n>` | 最大挂载次数（达到后强制 fsck）。`0` 或 `-1` 禁用 | 可选 | 取决于创建时设置 |
| `-i <interval>` | 两次检查之间的最大时间间隔。`0` 禁用 | 可选 | — |
| `-m <pct>` | 预留空间百分比（Reserved Blocks %） | 可选 | 5% |
| `-r <blocks>` | 预留空间（以块为单位） | 可选 | — |
| `-e <behavior>` | 出错时的行为：`continue`（继续）/ `remount-ro`（只读重新挂载）/ `panic`（内核 panic） | 可选 | `continue` |
| `-o <feature>` | 开启文件系统特性 | 可选 | — |
| `-O <feature>` | 清除文件系统特性（前面加 `^`） | 可选 | — |
| `-g <group>` | 设置可以享受预留空间特权的组 | 可选 | 0 |
| `-j` | 添加 ext3 日志（将 ext2 升级为 ext3） | 可选 | — |

#### 3.14.3 常用示例

```bash
# 查看文件系统信息
sudo tune2fs -l /dev/sda2

# 设置卷标
sudo tune2fs -L "ROOT_FS" /dev/sda2

# 生成新的随机 UUID
sudo tune2fs -U random /dev/sda2

# 设置挂载 30 次后强制检查
sudo tune2fs -c 30 /dev/sda2

# 设置每 180 天强制检查一次
sudo tune2fs -i 180d /dev/sda2
# i 的格式：数字 + d(天)/w(周)/m(月)

# 减少预留空间（对大数据盘，5% 可能浪费很多空间）
sudo tune2fs -m 1 /dev/sdb1   # 改为 1%

# 禁用强制检查（生产环境中不推荐）
sudo tune2fs -c 0 -i 0 /dev/sdb1

# 查看文件系统的特性列表
sudo tune2fs -l /dev/sda2 | grep features
```

### 3.15 resize2fs —— 调整 ext 文件系统大小

`resize2fs` 用于调整 ext2/ext3/ext4 文件系统的大小。它只能用于 ext 系列文件系统（XFS 使用 `xfs_growfs`）。

**重要规则：**
- **扩容（Grow）**：可以在线执行（文件系统已挂载时）
- **缩减（Shrink）**：必须卸载后执行（而且风险较高）
- **扩容前必须先用 `parted` 或 `gdisk` 扩大分区**
- **缩减前必须先用 `resize2fs` 缩小文件系统，再用 `parted` 缩小分区**

#### 3.15.1 扩容流程

```bash
# 完整扩容流程（假设 /dev/sdb1 是 50G 的 ext4 分区，要扩展为 100G）

# 第 1 步：查看当前状态
df -h /mnt/data
lsblk /dev/sdb

# 第 2 步：先扩大分区（必须先做！）
# 使用 parted：
sudo parted /dev/sdb print free       # 查看当前布局
sudo parted /dev/sdb resizepart 1 100% # 将分区 1 扩展到磁盘末尾
# 或使用 gdisk：删除并重建分区（保留起始位置不变）

# 第 3 步：通知内核重新读取分区表
sudo partprobe /dev/sdb
# 或
sudo blockdev --rereadpt /dev/sdb

# 第 4 步：扩展文件系统（在线操作，不用卸载）
sudo resize2fs /dev/sdb1

# 第 5 步：验证
df -h /mnt/data
```

#### 3.15.2 缩减流程（高风险，谨慎操作）

```bash
# 缩减流程（必须先卸载，且需要数据备份！）

# 第 1 步：备份数据
sudo rsync -av /mnt/data/ /backup/data/

# 第 2 步：卸载
sudo umount /mnt/data

# 第 3 步：先检查文件系统
sudo e2fsck -f /dev/sdb1

# 第 4 步：缩小文件系统到 30G
sudo resize2fs /dev/sdb1 30G

# 第 5 步：再缩小分区
sudo parted /dev/sdb resizepart 1 30G

# 第 6 步：重新挂载
sudo mount /dev/sdb1 /mnt/data
df -h /mnt/data
```

#### 3.15.3 resize2fs 常用选项

| 选项 | 说明 | 必选/可选 | 默认值 |
|------|------|----------|--------|
| `-p` | 显示进度条 | 可选 | 不显示 |
| `-f` | 强制执行（跳过一些安全检查） | 可选 | — |
| `-M` | 缩减到最小可能大小 | 可选 | 不缩减 |
| `-d <flags>` | 调试标志 | 可选 | — |

### 练习 26.2：使用 fdisk 创建 MBR 分区

**题目：**

在你的测试磁盘上创建 MBR 分区表，并创建两个主分区：
- 分区 1：2 GiB，类型为 Linux（0x83）
- 分区 2：使用剩余所有空间，类型为 Linux（0x83）

使用非交互方式完成（管道传命令）。

**答案：**

```bash

# 确认磁盘上没有重要数据！

# 非交互式创建 MBR 分区表 + 两个分区

# 命令解释（从左到右按顺序执行）：
#   o  = 创建新的空 MBR（DOS）分区表

#     1  = 分区编号为 1
#     <Enter> = 起始扇区使用默认值（2048）
#     +2G = 分区大小 2 GiB
#   n  = 新建第二个分区
#     p  = 主分区
#     2  = 分区编号为 2
#     <Enter> = 起始扇区使用默认值
#     <Enter> = 结束扇区使用默认值（剩余全部空间）
#   w  = 写入分区表并退出

# 让内核重新读取分区表
sudo partprobe /dev/sdb

# 验证结果
sudo fdisk -l /dev/sdb
# 预期输出应包含 /dev/sdb1 和 /dev/sdb2
```

### 练习 26.5：编写 /etc/fstab 条目实现开机自动挂载

**题目：**

- 使用 UUID 标识设备（不要用 `/dev/sdb1`）
- 挂载到 `/mnt/practice`
- ext4 文件系统
- 使用 `defaults,noatime` 选项
- dump = 0, pass = 2
- 使用 `mount -a` 验证

**答案：**

```bash
# 第 1 步：获取 UUID
UUID=$(sudo blkid -s UUID -o value /dev/sdb1)

sudo cp /etc/fstab /etc/fstab.bak

# 第 3 步：添加条目（用 echo 追加，注意 >> 是追加不是覆盖！）
echo "UUID=$UUID  /mnt/practice  ext4  defaults,noatime  0  2" | sudo tee -a /etc/fstab

# 第 4 步：验证 fstab 语法（mount -a 检查所有 auto 条目）
sudo mount -a
# 如果没有报错，说明 fstab 配置正确

# 第 5 步：确认已挂载
findmnt /mnt/practice

# 第 6 步：测试自动挂载能力
sudo umount /mnt/practice    # 先卸载
sudo mount -a                # 重新挂载 fstab 中所有条目
findmnt /mnt/practice        # 应该再次出现
```

**fstab 六个字段回顾：**

```
第 1 字段              第 2 字段      第 3 字段  第 4 字段            第 5 字段  第 6 字段
UUID=xxx...           /mnt/practice  ext4       defaults,noatime    0          2
↑ 设备唯一标识          ↑ 挂载点       ↑ 文件系统  ↑ 挂载选项          ↑ dump     ↑ fsck 顺序
```

## 5. 常见错误与排错

### 5.1 误操作：dd of= 写错目标设备

这是 Linux 系统管理中最致命的错误之一。`of=` 指向了错误的设备，导致系统盘或其他重要数据被覆盖。

```bash
# 致命错误：
# sudo dd if=ubuntu.iso of=/dev/sda   ← 本想写到 U 盘 /dev/sdc，结果写到了系统盘！
# sudo dd if=/dev/zero of=/dev/sdb    ← 本想清空 sdc，结果清空了数据盘 sdb

# 预防措施 1：操作前用 lsblk 确认设备树
lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS,MODEL
# 仔细核对磁盘大小和型号

# 预防措施 2：写入前先检查目标设备是否已挂载
mount | grep /dev/sdX
# 如果目标设备是系统盘，它必然挂载到了 / 或 /boot 等
# 这个方法可以帮你发现误指向

# 预防措施 3：使用 lsblk 和 blkid 双重确认
lsblk /dev/sdX
sudo blkid /dev/sdX

# 预防措施 4：在命令中加上 status=progress 以观察是否写入了错误的设备
# （如果发现速度异常或写入量不对，立即 Ctrl+C 中断）

# 如果不幸写错了：
# 1. 立即停止（Ctrl+C）
# 2. 不要重启（数据可能还在内存中）
# 3. 如果只是覆盖了分区表（前 512 字节），可以用备份恢复
# 4. 如果覆盖了数据区，需要使用专业的数据恢复工具
# 5. 最好的恢复方法永远是：事先备份
```

### 5.2 错误：fstab 配置错误导致系统无法启动

```bash
# 常见错误 1：UUID 写错
# fstab 中：UUID=wrong-uuid-value  /data  ext4 defaults 0 2
# 结果：系统启动时等待设备超时，进入 emergency mode

# 常见错误 2：挂载点路径不存在
# fstab 中：UUID=...  /mnt/typo_data  ext4 defaults 0 2
# 结果：挂载失败，但有 nofail 选项时不会阻塞启动

# 常见错误 3：文件系统类型写错
# fstab 中：UUID=...  /data  ext3  defaults 0 2  (实际是 ext4)
# 结果：可能无法挂载或挂载为只读

# 预防铁律：修改 fstab 后立即执行 mount -a 验证
sudo mount -a && echo "SUCCESS: fstab 检查通过" || echo "ERROR: 请检查 fstab!"

# 如果不幸系统启动不了：
# 1. 在 GRUB 启动菜单中选择 "Advanced options → Recovery mode"
# 2. 进入 root shell
# 3. mount -o remount,rw /     # 重新挂载根分区为读写
# 4. nano /etc/fstab           # 编辑并注释掉错误行
# 5. reboot
```

### 5.3 错误：卸载时提示 "target is busy"

```bash
# 错误信息：
# umount: /mnt/data: target is busy.

# 排查步骤 1：查看谁在使用
sudo lsof /mnt/data
# 输出示例：
# COMMAND   PID  USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
# bash     1234  alice  cwd    DIR  8,17    4096    2 /mnt/data
# vim      5678  alice   3u    REG  8,17    1024   12 /mnt/data/report.txt

# 排查步骤 2：使用 fuser
sudo fuser -v /mnt/data
# 输出显示哪些进程正在使用该挂载点

# 排查步骤 3：检查当前 Shell 的 cwd
pwd
# 如果当前工作目录正好在 /mnt/data 下，也会导致 busy

# 解决方法：
cd /                                   # 离开挂载点
sudo fuser -km /mnt/data              # 终止所有使用该挂载点的进程
sudo umount /mnt/data                 # 再次尝试卸载

# 终极方案：懒惰卸载
sudo umount -l /mnt/data              # 先分离文件系统，等进程退出后再清理
```

### 5.4 错误：mkfs 格式化了错误的设备

```bash
# 致命错误：
# sudo mkfs.ext4 /dev/sda1            ← 本想格式化 /dev/sdb1，格式化了系统分区！

# 预防：
# 1. 格式化前用 lsblk 和 blkid 双重确认
lsblk -f
sudo blkid

# 2. 格式化前查看设备已有的文件系统信息
sudo blkid /dev/sdX1
# 如果显示 TYPE="ext4" UUID="..."，说明已有文件系统
# 问自己："我真的要覆盖它吗？"

# 3. 查看设备是否已挂载
findmnt /dev/sdX1
# 如果已挂载（尤其是挂载到 /、/boot、/home），绝对不能格式化！

# 4. 对于重要操作，先做一个无害的只读检查
sudo fsck -N /dev/sdX1  # 只显示将要做什么，不实际执行
```

### 5.5 错误：parted 操作后分区未生效

```bash
# 症状：用 parted 创建/修改分区后，lsblk 看不到新分区

# 原因：内核没有重新读取分区表

# 解决方法 1：通知内核
sudo partprobe /dev/sdX

# 解决方法 2：使用 blockdev
sudo blockdev --rereadpt /dev/sdX

# 解决方法 3：重新扫描 SCSI 总线
echo 1 | sudo tee /sys/class/block/sdX/device/rescan

# 解决方法 4：重启（最可靠，但影响最大）
sudo reboot
```

### 5.6 错误：fsck 检查已挂载的文件系统

```bash
# 错误：
# sudo fsck /dev/sda2       ← /dev/sda2 是根分区 /，处于挂载状态

# 正确做法：
# 1. 对于非系统分区：先卸载再检查
sudo umount /dev/sdb1
sudo fsck /dev/sdb1

# 2. 对于根分区：使用 recovery mode 或设置下次启动检查
sudo touch /forcefsck       # 在根目录创建 forcefsck 文件
sudo reboot                 # 重启后系统会自动执行 fsck

# 注意：对已挂载的文件系统运行 fsck 可能造成严重的数据损坏！
```

### 5.7 错误：resize2fs 在分区扩大之前执行

```bash
# 错误操作顺序：
# sudo resize2fs /dev/sdb1    ← 文件系统扩容了，但分区还没扩大
# sudo parted /dev/sdb resizepart 1 100%
# 结果：文件系统的块范围超出了分区的实际范围，可能导致数据损坏

# 正确操作顺序（扩容）：
# 1. 先扩大分区：sudo parted /dev/sdb resizepart 1 100%
# 2. 再扩大文件系统：sudo resize2fs /dev/sdb1

# 记忆口诀：扩容先分区后文件系统，缩减先文件系统后分区
# 扩容：分区 → 文件系统（外→内）
# 缩减：文件系统 → 分区（内→外）
```

## 6. 进阶延伸

### 6.1 LVM——逻辑卷管理器

本章讲解的是"传统分区"方式（磁盘 → 分区 → 文件系统 → 挂载）。这种方式的限制很明显：

- 分区大小固定，难以动态调整
- 跨多块磁盘创建一个大文件系统很麻烦
- 增加磁盘意味着增加挂载点

**LVM（Logical Volume Manager，逻辑卷管理器）** 解决了这些问题：

```
传统分区方式：                     LVM 方式：
┌────────────────┐              ┌─────────────────────────────────┐
│  /dev/sda      │              │  物理卷 PV（Physical Volume）    │
│  └─/dev/sda1   │              │  /dev/sda1  /dev/sdb1           │
│      ext4      │              │       │          │               │
│      50G       │              │       └────┬─────┘               │
│       │        │              │            ▼                     │
│       ▼        │              │  卷组 VG（Volume Group）          │
│    /data       │              │  vg_data（合并所有 PV 的空间）     │
│                │              │       │                          │
│  固定 50G      │              │       ├── 逻辑卷 LV1: lv_home 200G│
│  无法扩容      │              │       ├── 逻辑卷 LV2: lv_data 500G │
│  换磁盘=       │              │       └── 逻辑卷 LV3: lv_logs 100G │
│  换挂载点      │              │            ▼                       │
└────────────────┘              │       mkfs.ext4 + mount           │
                                │                                    │
                                特点：                               │
                                │  - 可以随时在线扩容 LV              │
                                │  - 可以将多块物理磁盘合并到一个 VG   │
                                │  - 可以添加新磁盘到 VG 并分配给 LV   │
                                │  - 支持快照（Snapshot）             │
                                └─────────────────────────────────┘
```

**LVM 基本命令速查：**

```bash
# 查看 LVM 组件
sudo pvs    # 查看物理卷
sudo vgs    # 查看卷组
sudo lvs    # 查看逻辑卷

# 创建 LVM 的简单流程
sudo pvcreate /dev/sdb1           # 创建物理卷
sudo vgcreate vg_data /dev/sdb1   # 创建卷组
sudo lvcreate -L 10G -n lv_app vg_data  # 创建逻辑卷
sudo mkfs.ext4 /dev/vg_data/lv_app      # 格式化
sudo mount /dev/vg_data/lv_app /mnt/app # 挂载

# 在线扩容
sudo lvextend -L +5G /dev/vg_data/lv_app   # 扩大 LV
sudo resize2fs /dev/vg_data/lv_app          # 扩大文件系统
```

### 6.2 RAID —— 磁盘冗余阵列

**RAID（Redundant Array of Independent Disks，独立磁盘冗余阵列）** 通过组合多块物理磁盘来提高性能或/和提供数据冗余。

| RAID 级别 | 最少磁盘数 | 特点 | 可用容量（n 块磁盘，每块大小 S） |
|-----------|-----------|------|--------------------------------|
| RAID 0 | 2 | 条带化（Striping），数据分块存储到多盘；性能好但无冗余，坏一块全丢 | n × S |
| RAID 1 | 2 | 镜像（Mirroring），数据完整复制到每块盘；有冗余但容量利用率低 | (n / 2) × S（通常 2 盘） |
| RAID 5 | 3 | 条带化 + 分布式奇偶校验；允许坏一块盘，容量利用率高 | (n - 1) × S |
| RAID 6 | 4 | 类似 RAID 5，但双校验；允许同时坏两块盘 | (n - 2) × S |
| RAID 10 | 4 | RAID 1 + RAID 0 组合：先镜像再条带；性能和冗余兼得 | (n / 2) × S |

Linux 提供了两种 RAID 实现方式：

- **硬件 RAID**：由 RAID 控制器处理，操作系统看到的是单一的虚拟磁盘
- **软件 RAID（mdadm）**：由 Linux 内核的 md（Multiple Device）子系统管理

```bash
# 查看软件 RAID 信息
cat /proc/mdstat

# mdadm 基本操作
sudo mdadm --detail /dev/md0          # 查看 RAID 详情
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1  # 创建 RAID 1
```

### 6.3 磁盘性能测试

在部署存储系统之前（尤其是数据库服务器），了解磁盘的实际性能参数是规划的基础。

```bash
# 安装测试工具
sudo apt install -y hdparm fio

# hdparm：简单的顺序读写测试
sudo hdparm -Tt /dev/sda
# -T：测试缓存读取（纯内存性能）
# -t：测试磁盘读取（实际磁盘性能）

# 输出示例：
# /dev/sda:
#  Timing cached reads:   12340 MB in  1.99 seconds = 6210.45 MB/sec
#  Timing buffered disk reads: 1502 MB in  3.00 seconds = 500.23 MB/sec

# fio：灵活的综合 I/O 测试（业界标准工具）
# 随机读取测试
fio --name=randread --ioengine=libaio --direct=1 --bs=4k \
    --size=1G --rw=randread --numjobs=1 --runtime=30 \
    --group_reporting --filename=/tmp/fio-test

# 随机写入测试（在挂载的文件系统上执行）
fio --name=randwrite --ioengine=libaio --direct=1 --bs=4k \
    --size=1G --rw=randwrite --numjobs=1 --runtime=30 \
    --group_reporting --filename=/mnt/data/fio-test
```

### 6.4 磁盘健康监控 —— S.M.A.R.T.

**S.M.A.R.T.（Self-Monitoring, Analysis and Reporting Technology，自我监测、分析与报告技术）** 是现代磁盘内置的健康监测系统。它可以预测磁盘故障，让你在磁盘彻底损坏之前替换它。

```bash
# 安装 smartmontools
sudo apt install -y smartmontools

# 查看磁盘是否支持 S.M.A.R.T.
sudo smartctl -i /dev/sda

# 查看完整的 S.M.A.R.T. 数据
sudo smartctl -a /dev/sda

# 关键指标：
#   Reallocated_Sector_Ct    - 重新分配的坏扇区数（>0 要警惕）
#   Current_Pending_Sector   - 当前待处理的坏扇区
#   Offline_Uncorrectable    - 离线无法修复的扇区
#   Power_On_Hours           - 磁盘运行总时长

# 快速自检
sudo smartctl -t short /dev/sda
# 查看结果（等待约 2 分钟）
sudo smartctl -l selftest /dev/sda
```

### 6.5 UUID 与 LABEL——为何推荐使用 UUID 而非设备路径

```bash
# 思考：以下两个挂载命令有什么不同？

# 方式 A：使用设备路径
sudo mount /dev/sdb1 /mnt/data

# 方式 B：使用 UUID
sudo mount -U "12345678-abcd-..." /mnt/data

# 答案：
# /dev/sdb1 是内核按探测顺序分配的，在两个场景中不可靠：
#   1. 添加/移除磁盘后，设备字母可能改变
#   2. 换了 SATA 端口或 USB 端口后，字母也可能改变
#
# UUID 是格式化时写入文件系统超级块的，与磁盘物理位置无关，永不变
# （除非重新格式化）

# 如何在脚本中使用 UUID：
DISK_UUID=$(sudo blkid -s UUID -o value /dev/sdb1)
echo "建议在 /etc/fstab 中使用：UUID=$DISK_UUID"
```

### 6.6 创建 swap 文件（替代 swap 分区）

在云服务器和现代 Linux 系统中，使用 swap 文件比 swap 分区更灵活，可以随时调整大小而无需重新分区。

```bash
# 第 1 步：创建 4 GiB 的空文件
sudo fallocate -l 4G /swapfile
# 或使用 dd（更慢但兼容性更好）
# sudo dd if=/dev/zero of=/swapfile bs=1M count=4096

# 第 2 步：设置正确的权限（只允许 root 读写，安全要求）
sudo chmod 600 /swapfile

# 第 3 步：格式化为 swap
sudo mkswap /swapfile

# 第 4 步：启用 swap
sudo swapon /swapfile

# 第 5 步：验证
sudo swapon --show
free -h

# 第 6 步：设置开机自动启用（编辑 /etc/fstab）
echo "/swapfile  none  swap  sw  0  0" | sudo tee -a /etc/fstab

# 第 7 步：调整 swappiness（可选，值 0-100，越低越少用 swap）
sudo sysctl vm.swappiness=10
# 持久化：
echo "vm.swappiness=10" | sudo tee -a /etc/sysctl.conf
```

### 6.7 磁盘配额——限制用户/组的磁盘使用

```bash
# 1. 安装配额工具
sudo apt install -y quota

# 2. 修改 fstab，添加 usrquota,grpquota 选项
# UUID=...  /home  ext4  defaults,usrquota,grpquota  0  2

# 3. 重新挂载
sudo mount -o remount /home

# 4. 创建配额文件
sudo quotacheck -cugm /home

# 5. 启用配额
sudo quotaon /home

# 6. 为用户设置配额
sudo edquota -u username
# 编辑 soft/hard limits for blocks and inodes

# 7. 查看配额使用情况
sudo repquota /home
```
