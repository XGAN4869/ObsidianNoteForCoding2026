# 第32章：Gin 面试宝典与总复习

## 32.1 知识体系回顾

```
Gin 知识体系
├── 基础
│   ├── *gin.Engine（引擎）、*gin.Context（上下文）
│   ├── gin.Default() = New() + Logger + Recovery
│   └── r.Run(":8080")
├── 路由
│   ├── GET/POST/PUT/DELETE/PATCH → CRUD 对应
│   ├── r.Group("/api") 路由分组（嵌套，中间件）
│   ├── :id（路径参数）、*path（通配）
│   ├── c.Query() / c.DefaultQuery() 查询参数
│   └── Radix Tree（基数树）→ 高性能
├── 参数绑定与验证
│   ├── ShouldBindJSON / ShouldBindQuery / ShouldBindUri
│   ├── ShouldBind（自动选择）vs MustBind
│   ├── 标签：json / form / uri / header
│   └── binding:"required,min=3,email" 验证
├── 响应
│   ├── c.JSON / c.XML / c.YAML / c.String / c.HTML
│   ├── c.File / c.FileAttachment 文件下载
│   └── 统一响应 {code, message, data}
├── 中间件（洋葱模型）
│   ├── c.Next() → 传递控制权
│   ├── c.Abort() → 中止后续
│   ├── c.Set/Get → 跨中间件数据传递
│   ├── Logger + Recovery + CORS + Auth + 限流
│   └── 范围：全局 / 分组 / 路由级
├── 配套能力
│   ├── JWT 认证（golang-jwt）
│   ├── Session（gin-contrib/sessions）
│   ├── Swagger（swaggo）
│   ├── 文件上传（FormFile + SaveUploadedFile）
│   └── HTML 模板（LoadHTMLGlob + c.HTML）
└── 生产部署
    ├── 优雅关闭（signal.Notify + srv.Shutdown）
    ├── 超时控制（ReadTimeout/WriteTimeout）
    ├── Docker + Nginx
    └── 健康检查 /health
```

## 32.2 高频面试题 30 题

### 基础题

**Q1：`gin.Default()` 和 `gin.New()` 的区别？**
> Default = New + Logger + Recovery。Default 开箱即用，New 纯净无中间件。

**Q2：`c.Next()` 和 `c.Abort()` 的作用？**
> Next 将控制权传给下一个处理器。Abort 阻止后续处理器执行，但当前函数的后续代码仍会执行（需要 return）。

**Q3：Gin 的路由为什么快？**
> 基于 Radix Tree（基数树），匹配时间 O(路径长度)，与路由数量无关。httprouter 做了零内存分配优化。

**Q4：ShouldBind vs MustBind 的区别？**
> ShouldBind 返回 error 让你处理，MustBind 自动返回 400。推荐 ShouldBind。

**Q5：如何实现参数验证？**
> binding 标签（required/min/max/email/url）+ 自定义 validator.RegisterValidation。

### 中间件题

**Q6：中间件的洋葱模型是什么？**
> 请求从外到内经过中间件前置 → Handler → 从内到外经过中间件后置。如同剥洋葱。

**Q7：如何实现 JWT 认证中间件？**
> 从 Authorization 头取 Bearer Token → jwt.Parse → 提取 claims → c.Set("user_id") → c.Next()。失败则 c.AbortWithStatusJSON(401)。

**Q8：CORS 是什么？如何处理？**
> 浏览器同源策略限制跨域请求。服务端设 Access-Control-Allow-Origin 等响应头 + 处理 OPTIONS 预检请求。

### 实战题

**Q9：如何实现优雅关闭？**
> signal.Notify 监听 SIGINT → srv.Shutdown(ctx) → 等已有请求处理完 → 关闭资源。

**Q10：项目目录结构怎么组织？**
> main.go + config/ + models/ + handlers/ + middlewares/ + routes/ + response/

## 32.3 场景设计题

**场景1：设计博客系统 API 路由**
```
POST   /api/v1/register
POST   /api/v1/login
GET    /api/v1/articles?page=1&tag_id=1
GET    /api/v1/articles/:id
POST   /api/v1/articles        [Auth]
PUT    /api/v1/articles/:id     [Auth]
DELETE /api/v1/articles/:id     [Auth]
POST   /api/v1/articles/:id/comments [Auth]
```

**场景2：防止接口被刷**
> 限流中间件（IP + 接口级别，令牌桶算法），验证码，用户行为分析。

**场景3：用户登录态保持**
> JWT（无状态，适合 API）+ Refresh Token。或 Session + Redis（适合传统 Web）。
