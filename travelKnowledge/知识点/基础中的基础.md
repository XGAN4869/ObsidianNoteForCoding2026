## reactive / ref111

| 特性       | `ref`                                            | `reactive`                                                                   |
| :------- | :----------------------------------------------- | :--------------------------------------------------------------------------- |
| **适用类型** | 原始值 (number, string, boolean) 和 对象               | **仅对象** (包括数组、Map、Set 等复杂类型) <br>why？因为底层return new Proxy...，Proxy 只能代理上面的内容 |
| **访问方式** | `.value` 访问/修改值                                  | 直接访问/修改属性                                                                    |
| **底层实现** | 包装成一个带有 `.value` 属性的对象，用 `Proxy` 拦截 `.value` 的读写 | 直接用 `Proxy` 包装目标对象本身                                                         |
| **解构问题** | 解构会失去响应性                                         | 解构会失去响应性 (`...` 扩展运算符也会)                                                     |
| **内部转换** | `reactive` 内部如果遇到 `ref`，会自动解包 (unwrap)           |                                                                              |
- reactive/ref的目的是让被定义变量本身活起来，而不是监听变量内部属性是否有变化来变化。比如 const profile = reactive({ name: accountStore.accountName })，它只在初始化时读取一次 store。解构失去响应性
	```bash
	reactive 的响应性来自 Proxy。
	
	直接访问 state.name：
	会走 Proxy get，所以有响应性。
	
	解构 const { name } = state：
	只是在那一刻复制了 state.name 的值。
	
	后面访问 name：
	访问的是普通变量，不再走 Proxy get。
	
	所以：
	不会 track，不会收集依赖，也就不会响应式更新。
	```

## computed / watch
1. computed 只能存在组件里
它是组件专属API，只依附 setup 组件环境，脱离组件就用不了
作用：依托组件内变量，算出新值，给模板渲染用，只负责取值，不负责做事
2. watch 不绑定组件
只要拿到响应式变量，随便在哪都能写
自定义指令、工具函数、独立JS文件、仓库里全都能用
作用：变量一变，立刻执行一段逻辑、操作DOM、发请求、改样式
3. 对应你权限场景
 
- 权限指令是独立DOM逻辑，不属于某个组件，写不了computed
- 只需要监听Pinia权限数组，数组一改就删按钮/显示按钮
- 这种脱离组件、监听变量执行动作，只能用watch
 
4. 最简区别
 
- computed：组件内算值，给页面显示
- watch：任意地方监听值变化，执行行为
- computed + v-model 使用场景
	`computed.get` 负责把数组里的 checked 状态转换成 radio-group 能识别的选中 id；`computed.set` 负责把 radio-group 新选中的 id 写回数组里的 checked 状态。

## Promise 基础用法
```js
// 返回Promise的登录接口
function loginApi() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const ok = false;
      if (ok) resolve({ token: "xxx" });
      else reject(new Error("账号错误"));
    }, 1000);
  });
}

// 链式调用
loginApi()
  .then(res => console.log("登录成功", res))
  .catch(err => console.log("失败", err))
```

## store 和 localStorage

- 一般项目的做法
	登录 token：uni storage 持久化
