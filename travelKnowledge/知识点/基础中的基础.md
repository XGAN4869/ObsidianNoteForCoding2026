## reactive / ref111

| 特性       | `ref`                                            | `reactive`                                                                   |
| :------- | :----------------------------------------------- | :--------------------------------------------------------------------------- |
| **适用类型** | 原始值 (number, string, boolean) 和 对象               | **仅对象** (包括数组、Map、Set 等复杂类型) <br>why？因为底层return new Proxy...，Proxy 只能代理上面的内容 |
| **访问方式** | `.value` 访问/修改值                                  | 直接访问/修改属性                                                                    |
| **底层实现** | 包装成一个带有 `.value` 属性的对象，用 `Proxy` 拦截 `.value` 的读写 | 直接用 `Proxy` 包装目标对象本身                                                         |
| **解构问题** | 解构会失去响应性                                         | 解构会失去响应性 (`...` 扩展运算符也会)                                                     |
| **内部转换** | `reactive` 内部如果遇到 `ref`，会自动解包 (unwrap)           |                                                                              |
- reactive/ref的目的是让被定义变量本身活起来，而不是监听变量内部属性是否有变化来变化。比如 const profile = reactive({ name: accountStore.accountName })，它只在初始化时读取一次 store。解构失去响应性
	```bash
	reactive 的响应性来自 Proxy。
	
	直接访问 state.name：
	会走 Proxy get，所以有响应性。
	
	解构 const { name } = state：
	只是在那一刻复制了 state.name 的值。
	
	后面访问 name：
	访问的是普通变量，不再走 Proxy get。
	
	所以：
	不会 track，不会收集依赖，也就不会响应式更新。
	```
