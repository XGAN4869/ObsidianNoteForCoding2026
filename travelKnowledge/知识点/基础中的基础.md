## reactive / ref

| 特性       | `ref`                                                | `reactive`                                                                   |
| :------- | :--------------------------------------------------- | :--------------------------------------------------------------------------- |
| **适用类型** | 原始值 (number, string, boolean) 和 对象                   | **仅对象** (包括数组、Map、Set 等复杂类型) <br>why？因为底层return new Proxy...，Proxy 只能代理上面的内容 |
| **访问方式** | `.value` 访问/修改值                                      | 直接访问/修改属性                                                                    |
| **底层实现** | 包装成一个带有 `.value` 属性的**对象**，用 `Proxy` 拦截 `.value` 的读写 | 直接用 `Proxy` 包装目标对象本身                                                         |
| **解构问题** | 解构会失去响应性                                             | 解构会失去响应性 (`...` 扩展运算符也会)                                                     |
| **内部转换** | `reactive` 内部如果遇到 `ref`，会自动解包 (unwrap)               |                                                                              |
- reactive/ref的目的是让被定义变量本身活起来，而不是监听变量内部属性是否有变化来变化。比如 const profile = reactive({ name: accountStore.accountName })，它只在初始化时读取一次 store。解构失去响应性
	```bash
	reactive 的响应性来自 Proxy。
	
	直接访问 state.name：
	会走 Proxy get，所以有响应性。
	
	解构 const { name } = state：
	只是在那一刻复制了 state.name 的值。
	
	后面访问 name：
	访问的是普通变量，不再走 Proxy get。
	
	所以：
	不会 track，不会收集依赖，也就不会响应式更新。
	```

## computed / watch
- computed 
	- 注意事项：只能存在组件里。它是组件专属API，只依附 setup 组件环境，脱离组件就用不了
	- 作用：依托组件内变量，算出新值，给模板渲染用，只负责取值，不负责做事
	- 底层详解

2. watch 不绑定组件
[响应式 API：核心 | Vue.js](https://cn.vuejs.org/api/reactivity-core#watch)
只要拿到响应式变量，随便在哪都能写
自定义指令、工具函数、独立JS文件、仓库里全都能用
作用：变量一变，立刻执行一段逻辑、操作DOM、发请求、改样式
3. 对应你权限场景
 
- 权限指令是独立DOM逻辑，不属于某个组件，写不了computed
- 只需要监听Pinia权限数组，数组一改就删按钮/显示按钮
- 这种脱离组件、监听变量执行动作，只能用watch
 
4. 最简区别
 
- computed：组件内算值，给页面显示
- watch：任意地方监听值变化，执行行为
	- ```js
	  //这里不能写 getters 函数式，ref本身不变的,改的是 ref 里面的 value 
		watch(activePath, () => {  
		  console.log('activePath', activePath.value)  
		},{immediate:true})
		
	//或者改成这种
	//这里不能写 getters 函数式，ref本身不变的  
		watch(  
		  () => activePath,  
		  () => {  
		    console.log('activePath', activePath.value)  
		  },  
		  { immediate: true, deep: true },  
		)
	  ```

## defineModel
你的疑问很关键，这里确实容易搞混。先直接说答案：

```js
const startDate = defineModel('startDate', { default: '' });
// 这一行是完全正确的，且等同于 emit('update:startDate', innerStart.value)
startDate.value = innerStart.value;
```

**用 `defineModel` 时，直接赋值就是合法的，它就是触发 `emit` 的语法糖。**
`defineModel` 是 Vue 3.4+ 引入的编译宏。它在编译后会生成：

1. 一个 **props** 叫 `startDate`
    
2. 一个 **emit** 事件叫 `update:startDate`
    
3. 一个 **ref**（就是你拿到的 `startDate`）

## await/async
- 需要等待该 async 函数完成的时候，用 `await`  当作暂停器，比如某个数据必须先拿到。
```js
async function login(remember, options) {
  const res = await loginApi(...)
  // ...
  await getSystemInfo()   // 没 await，这里异步跑了，但不管它
  // 立即继续执行后面的 remember 逻辑
  // login 函数返回了
}
```
