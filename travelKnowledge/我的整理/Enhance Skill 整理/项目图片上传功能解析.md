## 先看总流程

这个项目的图片上传不是直接把图片传给业务接口，而是走一套更常见的“COS 直传”流程：

1. 页面先让用户选择图片，拿到本地临时路径或浏览器 `File` 对象。
2. 前端生成一个云端文件路径，也就是 `fileKey`。
3. 前端调用后端 `fileKeyPost`，让后端返回 COS 临时密钥。
4. 前端用腾讯云 COS SDK 把图片直接传到 COS。
5. 上传成功后，前端调用 `fileCreate`，让后端登记这个文件。
6. 业务提交时，只把 `fileKey` 或 fileKey 数组交给业务接口。

可以把它记成一句话：

> 先选图，生成 fileKey，拿临时密钥，传 COS，登记文件，最后业务表单只提交 fileKey。

相关 API 在这里：

- `travel-web/packages/api/src/apis/organization.js:41`：`fileKeyPost`，向后端申请 COS 临时密钥。
- `travel-web/packages/api/src/apis/organization.js:44`：`fileCreate`，上传成功后登记文件。
- `travel-web/packages/api/src/apis/workerManagement.js:30`：`fileKeyPostTemp`，临时工头像使用。
- `travel-web/packages/api/src/apis/workerManagement.js:33`：`fileCreateTemp`，临时工头像使用。

## 这个 function 是干嘛的：`uploadRequestMethod`

代表文件：

- `travel-web/sites/uniapp/src/packageOther/meeting/index.vue:557`
- `travel-web/sites/uniapp/src/packageOther/feedback/index.vue:134`
- `travel-web/sites/uniapp/src/packageApproval/audit/index.vue:386`

它是给 `t-upload` 组件用的自定义上传函数。用户点上传后，`t-upload` 会把选中的文件传进来，真正上传逻辑由这个函数接管。

### 它接收什么数据

它接收 `files`，可能是数组，也可能是单个文件对象。代码会先统一取第一个文件：

```js
const file = Array.isArray(files) ? files[0] : files
const filePath = file?.tempFilePath || file?.path || file?.url || ''
```

小白可以这样理解：上传组件给你的东西不一定长得完全一样，所以先把它整理成“一个文件”和“一个文件路径”。

### 它返回什么结果

成功时返回类似：

```js
return {
  status: 'success',
  response: { url: uploaded.url, fileKey: uploaded.fileKey },
}
```

这个返回值是给 `t-upload` 看的，告诉组件“这次上传成功了”，同时把图片地址带回去用于预览。

### 它中间做了哪几步

1. 从 `files` 里取图片路径。
2. 校验路径是否存在。
3. 校验图片大小，一般限制 5MB。
4. 显示 `上传中...`。
5. 调用 `createMeetingPhotoFile` / `createFeedbackPhotoFile` / `createEvidenceFile`。
6. 把返回的 `fileKey` 存到业务表单状态里。
7. 把返回的 `url` 存到 `uploadFiles`，用于页面预览。
8. 成功 toast，失败时清空状态。
9. `finally` 里关闭 loading。

## 这个 function 是干嘛的：`createXxxPhotoFile`

代表文件：

- `travel-web/sites/uniapp/src/packageOther/meeting/index.vue:271`：`createMeetingPhotoFile`
- `travel-web/sites/uniapp/src/packageOther/customer-complaint/ComplaintDialog.vue:601`：`createComplaintPhotoFile`
- `travel-web/sites/uniapp/src/pages/profile/setting.vue:196`：`createEmployeePhotoFile`
- `travel-web/sites/uniapp/src/packageApproval/audit/index.vue:357`：`createEvidenceFile`

这一类函数是真正的“上传主流程”。它不负责 UI，也不负责表单提交，只负责把一张本地图片变成一个云端文件。

### 它接收什么数据

它接收一个本地图片路径：

```js
async function createMeetingPhotoFile(filePath = '') {
  // filePath 是微信小程序本地临时路径，比如 wxfile://...
}
```

头像、反馈、会议纪要、审批凭证都是这个思路。

### 它返回什么结果

它一般返回：

```js
return {
  fileKey,
  url: fileInfo?.url || fileInfo?.fileUrl || fileInfo?.filePath || cosUrl,
}
```

`fileKey` 是提交给后端业务接口保存的核心字段；`url` 是页面预览用的完整图片地址。

### 它中间做了哪几步

1. 调用 `generateFileKey(filePath)` 生成云端路径。
2. 调用 `fileKeyPost({ fileKey, bizType })` 获取临时密钥。
3. 判断后端有没有返回 `credentials`。
4. 整理 COS 需要的临时密钥字段。
5. 调用 `putObjectToCos` 上传到 COS。
6. 调用 `fileCreate({ fileKey, bizType })` 登记文件。
7. 返回 `fileKey` 和预览 `url`。

这里最值得模仿的是职责分离：上传主流程只关心“文件怎么上传”，不掺杂按钮、表单、页面跳转。

## 这个 function 是干嘛的：`putObjectToCos`

代表文件：

- `travel-web/sites/uniapp/src/packageOther/meeting/index.vue:249`
- `travel-web/sites/uniapp/src/packageOther/feedback/index.vue:84`
- `travel-web/sites/uniapp/src/packageOther/customer-complaint/ComplaintDialog.vue:546`
- `travel-web/sites/web/src/pages/finance/index.vue:606`
- `travel-web/sites/web/src/pages/complaint/components/communicateDialog.vue:263`

这个函数只做一件事：把图片传到腾讯云 COS。

### 它接收什么数据

uniapp 小程序端接收：

```js
{
  credentials, // 临时密钥
  fileKey,     // 云端路径
  filePath,    // 本地临时文件路径
}
```

PC Web 端接收：

```js
{
  credentials, // 临时密钥
  fileKey,     // 云端路径
  rawFile,     // 浏览器 File 对象
}
```

### 它返回什么结果

它返回一个 Promise。成功就 `resolve(data)`，失败就 `reject(error)`。

### 它中间做了哪几步

1. 用临时密钥创建 COS 实例。
2. 指定 `Bucket`、`Region`、`Key`。
3. 小程序端传 `FilePath`。
4. Web 端传 `Body: rawFile`。
5. COS 回调成功就 resolve，失败就 reject。

小程序端常见写法：

```js
cos.postObject({
  Bucket: COS_CONFIG.BUCKET,
  Region: COS_CONFIG.REGION,
  Key: fileKey,
  FilePath: filePath,
}, callback)
```

Web 端常见写法：

```js
cos.putObject({
  Bucket: COS_CONFIG.BUCKET,
  Region: COS_CONFIG.REGION,
  Key: fileKey,
  Body: rawFile,
}, callback)
```

区别很好记：小程序是本地临时路径，所以用 `FilePath`；浏览器是文件对象，所以用 `Body`。

## 小白应该怎么模仿

以后你要在项目里新增一个图片上传功能，可以按这个固定顺序写：

1. 准备状态：`uploadFiles`、`uploadLoading`、业务字段里的 `fileKey`。
2. 准备配置：`COS_CONFIG`，至少包含 `BIZ_TYPE`、`PATH`、`BUCKET`、`REGION`。
3. 写 `generateFileKey`：生成唯一云端路径。
4. 写 `getResponseData`：兼容接口返回格式。
5. 写 `putObjectToCos`：只负责传 COS。
6. 写 `createXxxFile`：负责 `fileKeyPost -> COS上传 -> fileCreate`。
7. 写 `uploadRequestMethod`：负责 UI 上传入口、校验、loading、更新状态。
8. 写 `handleUploadRemove`：清空 fileKey 和预览文件。
9. 业务提交时只提交 `fileKey`，不要提交本地临时路径。

## 示例代码

示例代码仅供参考，需要你手动复制到项目中。

```js
// 1. 统一管理上传配置，后面所有上传函数都从这里取值
const COS_CONFIG = {
  BIZ_TYPE: 'demo_image',
  PATH: 'demo/image',
  get BUCKET() {
    return accountStore.bucketName || 'ims-saas-dev-1310497727'
  },
  get REGION() {
    return accountStore.cosRegion || 'ap-guangzhou'
  },
}

// 2. 页面状态分两类：预览给页面看，fileKey 给接口提交
const uploadFiles = ref([])
const imageKey = ref('')
const uploadLoading = ref(false)

function generateFileKey(filePath = '') {
  const ext = String(filePath).split('?')[0].split('.').pop() || 'jpg'
  const timestamp = Date.now()
  const random = Math.floor(Math.random() * 10000)
  return `travel/${COS_CONFIG.PATH}/${timestamp}_${random}.${ext}`
}

function getResponseData(response) {
  return response?.code === 200 && response?.data !== undefined
    ? response.data
    : response?.data ?? response
}

function putObjectToCos({ credentials, fileKey, filePath }) {
  return new Promise((resolve, reject) => {
    const cos = new COS({
      SecretId: credentials.tmpSecretId,
      SecretKey: credentials.tmpSecretKey,
      SecurityToken: credentials.sessionToken,
      StartTime: Number(credentials.startTime),
      ExpiredTime: Number(credentials.expiredTime),
    })

    cos.postObject({
      Bucket: COS_CONFIG.BUCKET,
      Region: COS_CONFIG.REGION,
      Key: fileKey,
      FilePath: filePath,
    }, (err, data) => {
      if (err) reject(err)
      else resolve(data)
    })
  })
}

async function createDemoImageFile(filePath = '') {
  const fileKey = generateFileKey(filePath)

  // 先向后端申请临时密钥，避免把永久密钥写死在前端
  const tempKeyData = getResponseData(await fileKeyPost({
    fileKey,
    bizType: COS_CONFIG.BIZ_TYPE,
  }))

  const credentials = tempKeyData?.credentials
  if (!credentials) throw new Error('获取COS临时密钥失败')

  await putObjectToCos({
    credentials: {
      ...credentials,
      startTime: tempKeyData.startTime,
      expiredTime: tempKeyData.expiredTime,
    },
    fileKey,
    filePath,
  })

  // COS 上传成功后，再通知后端登记这个文件
  const fileInfo = getResponseData(await fileCreate({
    fileKey,
    bizType: COS_CONFIG.BIZ_TYPE,
  }))

  return {
    fileKey,
    url: fileInfo?.url || `https://${COS_CONFIG.BUCKET}.cos.${COS_CONFIG.REGION}.myqcloud.com/${fileKey}`,
  }
}

async function uploadRequestMethod(files) {
  const file = Array.isArray(files) ? files[0] : files
  const filePath = file?.tempFilePath || file?.path || file?.url || ''
  if (!filePath) return Promise.reject(new Error('文件路径无效'))

  uploadLoading.value = true
  try {
    const uploaded = await createDemoImageFile(filePath)
    imageKey.value = uploaded.fileKey
    uploadFiles.value = [{ ...file, url: uploaded.url }]

    return {
      status: 'success',
      response: uploaded,
    }
  } finally {
    uploadLoading.value = false
  }
}
```

## 举一反三

这类上传函数一般都按这个固定套路：

- 先校验：有没有文件、是不是图片、大小是否超限。
- 再准备：生成 `fileKey`，准备 `bizType`。
- 再申请：调用后端拿 COS 临时密钥。
- 再上传：调用 COS SDK。
- 再登记：调用 `fileCreate`。
- 最后更新页面状态：预览 URL 给用户看，`fileKey` 给业务接口提交。

适合抽成公共函数的内容：

- `getResponseData`
- `generateFileKey`
- `putObjectToCos`
- `buildCosImageUrl`
- 图片大小校验

适合保留在页面里的内容：

- `bizType` 和路径目录，因为每个业务不同。
- 上传成功后写入哪个表单字段。
- 提交接口需要 `JSON.stringify([fileKey])`、逗号字符串还是单个 fileKey。
- 是否必须上传图片。

## 一句话总结

项目里的图片上传核心套路是：前端不把图片交给业务接口，而是先用临时密钥直传 COS，拿到 `fileKey` 后再把 `fileKey` 作为业务数据提交。
