## 三、理解这次处理的真实业务模块

现有文件：

```text
C:\Project\travel\travel-web\packages\enums\src\constant\common.js
```

里面的 `NormalDisableEnum` 定义了“正常／禁用”两种状态。本讲直接导入这份数据，不再写一份相同业务数据。

依赖与执行过程：

```text
Webpack 配置（由 Node 执行）
  → 定位 sites/web/src/webpack-stage1.js
  → 追踪它导入的 packages/enums/src/constant/common.js
  → 把所需模块组织成 dist-webpack-stage1/main.js

浏览器打开 webpack-stage1.html
  → 加载 dist-webpack-stage1/main.js
  → 执行 DOM 操作，显示状态列表
```

这里有两个执行环境：Node 执行构建配置，浏览器执行生成的业务脚本。Webpack 扫描和处理模块时，不会因为源码里写了 DOM 操作，就在构建阶段替浏览器渲染页面。

## 五、写入口：复用真实 OA 枚举

新增文件：

```text
C:\Project\travel\travel-web\sites\web\src\webpack-stage1.js
```

```javascript
import { NormalDisableEnum } from '../../../packages/enums/src/constant/common.js';

const app = document.querySelector('#app');

if (!app) {
  throw new Error('页面缺少 #app 挂载节点');
}

const title = document.createElement('h1');
title.textContent = 'OA 状态选项：Webpack 构建验证';

const list = document.createElement('ul');

for (const item of Object.values(NormalDisableEnum)) {
  const row = document.createElement('li');
  row.textContent = `${item.label}：${item.value}`;
  list.appendChild(row);
}

app.replaceChildren(title, list);
console.log('本次使用的 OA 枚举：', NormalDisableEnum);
```

此时先使用明确的相对路径，下一讲再引入别名和 workspace 包入口。三个 `../` 从 src 向上依次到 web、sites、仓库根目录。

阅读时画出：这个入口依赖谁？被导入的枚举又有没有其他 import？Webpack 不是默认复制 src 下全部文件，而是从入口建立模块依赖关系；额外复制资源等行为由其他配置决定。

## 六、写第一份配置，并解释每一项

新增文件：

```text
C:\Project\travel\travel-web\sites\web\build\webpack.stage1.cjs
```

```javascript
const path = require('node:path');

const webRoot = path.resolve(__dirname, '..');

module.exports = {
  context: webRoot,
  mode: 'development',
  entry: './src/webpack-stage1.js',
  output: {
    path: path.resolve(webRoot, 'dist-webpack-stage1'),
    filename: 'main.js',
    clean: true,
  },
  devtool: false,
};
```

- [ ] **为什么是 `.cjs`：** 当前 package.json 声明了 `type: module`；这里明确使用 CommonJS 配置，所以使用 `.cjs`，以支持 require、module.exports 和 __dirname。Webpack 配置也可以写成 ESM，本讲先选一种。
- [ ] **path / __dirname：** 这是 Node 的路径工具和当前配置文件所在目录，不是浏览器 API。
- [ ] **webRoot：** 配置放在 build 下，所以向上一层得到 sites/web。
- [ ] **context：** 明确 entry 等相对请求解析的基础目录，减少对执行命令位置的隐含依赖。
- [ ] **entry：** 从哪个模块开始追踪依赖。本例不是直接加载 OA 的 main.js，后者会立即牵涉 Vue、样式、SVG、环境变量等后续配置。
- [ ] **output.path：** 构建输出的绝对目录；本例独立于原来的 Vite dist。
- [ ] **output.filename：** 本轮生成的主要 JS 文件名。
- [ ] **clean：** 构建前清理这个专用输出目录的旧产物；不要把 output.path 改成源码目录。
- [ ] **mode：** 本轮使用开发默认设置，便于观察产物，不进行生产性能评测。
- [ ] **devtool：** 暂时关闭 Source Map，让本轮更容易观察普通构建产物；后续单独学习错误映射。

配置中没有 Loader / Plugin，是因为本轮只有普通 JS 与静态枚举，不需要额外格式转换或 HTML 生成。

## 九、常见错误先按层定位

- **找不到 webpack：** 检查安装是否成功、过滤的包名是否正确；使用本讲的 pnpm exec 命令。
- **require is not defined：** 检查配置是否为 `.cjs`，以及是否把 CommonJS 写进了当前 ESM 包中的 `.js` 文件。
- **Can't resolve：** 查看报错指向 entry 还是入口里的 import；分别核对 context 和相对路径。
- **构建成功但页面空白：** 先看脚本路径与浏览器控制台，再检查 #app；不要先改 Webpack 的优化参数。
- **改了源码页面没变化：** 检查是否重新构建、浏览器是否打开了本讲的 HTML，以及引用的是不是新产物。
