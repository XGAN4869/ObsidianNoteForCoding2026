# IMS Router 从零开发交付需求书

## 1. 项目背景与目标

IMS Router 是面向阿里官方 Model Router 客户的账号与运营管理系统。系统由杭州算能矩阵科技有限公司负责，杭州算能矩阵科技有限公司由杭州效果科技有限公司全资持股，持股比例 100%。

本需求书用于交给新的研发团队从 0 开发第一版 IMS Router。交付目标不是复刻当前仓库结构，而是让团队基于清晰业务规则自行完成工程搭建、前后端实现、上游对接、权限隔离和验收闭环。

第一版产品目标：

- 为运营人员提供普通用户开户、启禁用、软删除、余额管理、API Key 管理、模型观测、账单查询和审计追溯能力。
- 为普通用户提供登录、账号维护、余额查看、API Key 自助管理、模型服务查看、账单查询导出和浏览器直连 Model Router 的文本对话能力。
- 复用 Model Router 的部门、API Key、余额、模型、用量、调用记录和账单能力，不在本地重复建设模型管理、计费、账单或推理系统。
- 保证管理端和用户端身份隔离，保证普通用户只能访问自己绑定的上游部门数据。

技术要求：

- 后端必须使用 Java。
- 前端必须使用 Vue 与 TDesign。
- 后端框架、前端工程组织、数据库设计、接口路径、部署方式和测试框架由承接团队自行设计，但必须满足本文的业务、权限、安全和验收要求。

## 2. 系统边界与非目标

### 2.1 系统定位

IMS Router 只负责账号与运营管理，不负责大模型推理本身。普通用户真正调用大模型时，使用自己的 Model Router API Key 直接访问 Model Router。

IMS Router 可以保存本地账号、用户与上游部门映射、操作审计等管理所需数据；但余额、API Key、模型列表、用量、调用记录和账单等业务结果，必须以 Model Router 实时返回为准。

### 2.2 第一版范围

第一版必须包含：

- 管理端超级管理员和运营管理员登录。
- 管理端后台账号管理。
- 管理端普通用户创建、查询、启用、禁用和软删除。
- 普通用户与 Model Router 部门的一一绑定。
- 管理端查看和删除 Model Router 部门。
- 管理端只读查看 Model Router 模型、用量和 API 调用记录。
- 管理端按普通用户管理 Model Router API Key。
- 管理端对普通用户部门余额进行人工充值、人工扣减和余额流水查询。
- 管理端跨用户账单查询、详情查看和导出。
- 用户端普通用户登录、退出和修改密码。
- 用户端查看自己的余额、API Key、模型服务、用量、API 调用记录和账单。
- 用户端自助创建、查看、复制和删除自己的 API Key。
- 用户端账单导出。
- 用户端文本对话页面，浏览器使用用户选择的 API Key 直连 Model Router。
- 敏感操作审计。

### 2.3 非目标

第一版不得实现：

- 用户自助注册、邀请注册、成员体系、组织架构或子账号体系。
- 自定义角色、菜单权限或按钮权限。
- 模型上架、下架、编辑、删除、定价、计费规则或路由策略管理。
- 本地价格加成、本地计费、账单修改、人工调账、退款、提现、发票或在线支付。
- IMS Router 后端大模型推理接口、中转接口、代理接口或对话内容存储。
- 用量、账单、调用记录、余额和 API Key 的本地权威副本。
- API Key 禁用入口、禁用状态或本地模拟禁用逻辑。
- 在本地保存 API Key 明文。

## 3. 角色与权限

### 3.1 角色定义

系统包含三类角色：

- 超级管理员：管理端身份，可以管理后台账号，也可以管理普通用户、部门、API Key、余额、账单和审计。
- 运营管理员：管理端身份，可以管理普通用户、部门、API Key、余额、账单和审计，但不能管理后台账号。
- 普通用户：用户端身份，只能管理和查看自己绑定部门下的数据。

后台管理员账号与普通用户账号是两套独立身份域。普通用户不能登录管理端，管理员身份也不能直接当作普通用户使用。

### 3.2 权限规则

权限必须由后端校验，前端隐藏入口不能替代鉴权。

超级管理员必须可以：

- 登录管理端。
- 管理后台账号，包括创建、启用、禁用、重置密码和查看列表。
- 执行运营管理员拥有的全部业务能力。

运营管理员必须可以：

- 登录管理端。
- 创建、查看、启用、禁用和软删除普通用户。
- 查看和删除 Model Router 部门。
- 查看模型列表、用量监控、用量明细和 API 调用记录。
- 按普通用户创建、查看、复制和删除 API Key。
- 查询余额、人工充值、人工扣减和查看余额变更流水。
- 查询、查看详情和导出账单。
- 查看审计记录。

运营管理员不得：

- 创建、禁用、启用或重置后台管理员账号。
- 修改后台管理员角色。

普通用户必须可以：

- 登录用户端。
- 修改自己的密码。
- 查看自己的余额、模型服务、用量、API 调用记录和账单。
- 创建、查看、复制和删除自己的 API Key。
- 导出自己的账单。
- 选择自己的 API Key 和可用模型发起文本对话。

普通用户不得：

- 查看、导出或操作其他用户的数据。
- 指定或篡改用户 ID、部门 ID 来越权访问数据。
- 访问管理端能力。

## 4. 核心业务对象关系

普通用户与 Model Router 部门是一一绑定关系：

- 一个 IMS Router 普通用户只能绑定一个 Model Router 部门。
- 一个 Model Router 部门只能绑定一个 IMS Router 普通用户。
- 一个 Model Router 部门可以拥有多个 API Key。
- 一个 Model Router 部门拥有一个余额。
- 余额、API Key、用量、调用记录和账单均归属于上游部门。

IMS Router 本地负责维护普通用户账号与上游部门的绑定关系。所有面向普通用户的数据查询和操作，后端必须从当前登录身份找到其绑定部门，再调用 Model Router；不得把前端提交的用户标识或部门标识作为最终授权依据。

普通用户被禁用或软删除后，不能继续登录用户端。若 Model Router 支持部门可用状态同步，应按其实际能力同步处理；若上游不支持某项状态能力，不得在 IMS Router 中伪造 API Key 禁用状态或虚假部门状态。

## 5. 管理端需求

### 5.1 登录与会话

- 管理端只允许超级管理员和运营管理员登录。
- 被禁用的后台账号不得登录。
- 已登录账号被禁用后，后续受保护操作必须被拒绝。
- 登录失败提示不得暴露账号是否存在、密码是否正确或系统内部异常细节。

### 5.2 后台账号管理

仅超级管理员可以使用后台账号管理。

必须支持：

- 查看后台账号列表、角色、状态和更新时间。
- 创建超级管理员或运营管理员。
- 启用、禁用后台账号。
- 重置后台账号密码。
- 记录相关审计。

### 5.3 普通用户管理

超级管理员和运营管理员均可使用普通用户管理。

必须支持：

- 按账号、昵称、状态等条件查询普通用户。
- 查看用户基本资料、绑定部门、状态、余额摘要和创建时间。
- 创建普通用户，并完成本地账号、上游部门和部门余额限流能力的建立。
- 修改用户资料，并同步更新对应上游部门名称和备注。
- 禁用用户，使其不能登录，并按 Model Router 实际支持能力处理上游部门状态。
- 重新启用用户，使其恢复登录资格，并按 Model Router 实际支持能力恢复上游部门状态。
- 软删除用户，使其默认不出现在正常用户列表中，但保留历史账单、余额流水关联和审计记录。

开户必须满足：

- 用户账号唯一。
- 用户昵称与备注可以用于生成或更新上游部门展示信息。
- 本地账号、上游部门绑定和必要的余额配置全部成功后，才算开户成功。
- 任一步骤失败时，不得展示开户成功，也不得产生可正常登录但无法绑定上游部门的用户。

### 5.4 Model Router 部门管理

管理端必须支持查看 Model Router 部门树。

部门管理规则：

- 部门树实时从 Model Router 获取，不以本地数据作为权威来源。
- 管理端可以删除上游部门。
- 管理端不提供单独新增部门入口；新增部门通过普通用户开户流程触发。
- 删除部门必须以上游明确成功为准。
- 删除部门不自动删除本地普通用户账号和历史审计。
- 删除已绑定用户的上游部门后，该用户后续余额、API Key、用量和账单查询可能失败，系统应按上游错误给出清晰提示。

### 5.5 模型观测

管理端必须支持只读查看 Model Router 相关观测数据：

- 模型列表。
- 用量概览。
- 模型用量列表。
- 模型用量明细。
- API 调用记录。

模型观测规则：

- 数据实时来自 Model Router，不在本地保存为权威数据。
- 管理端可以按用户、部门、API Key、模型、模型类型和时间范围等条件筛选，具体筛选项以上游实际支持能力为准。
- API 调用记录只展示观测字段，例如请求标识、部门、API Key 掩码、模型、状态、Token、图片或视频数量、耗时和时间。
- 不得展示、返回或保存请求体、响应体、提示词、模型回复或对话内容。
- 不得提供模型新增、编辑、删除、定价、计费规则或路由策略入口。

### 5.6 API Key 管理

管理端必须支持按普通用户管理其绑定部门下的 Model Router API Key。

必须支持：

- 查询 API Key 列表。
- 创建 API Key。
- 查看或复制完整 API Key。
- 删除 API Key。

API Key 管理规则：

- 创建 API Key 时，管理端选择普通用户；后端根据该用户绑定部门调用 Model Router，不得信任前端直接提交的部门作为授权依据。
- API Key 列表只能展示掩码或预览信息，不得返回完整明文。
- 完整 API Key 只能在创建、查看或复制时从 Model Router 实时取得并短暂返回。
- 完整 API Key 不得写入本地数据库、缓存、日志、异常信息、审计详情、测试快照或前端持久化存储。
- 查看或复制 API Key 明文前，应有明确确认或二次确认交互。
- 删除 API Key 必须以上游明确成功为准。
- Model Router 当前不支持 API Key 禁用时，IMS Router 不得提供禁用入口，不得维护本地禁用字段，也不得模拟禁用状态。

### 5.7 余额管理

管理端必须支持对普通用户绑定部门进行余额管理。

必须支持：

- 查看用户当前余额。
- 查看上游余额变更流水。
- 人工充值。
- 人工扣减。

余额管理规则：

- 当前余额实时来自 Model Router。
- 人工充值和人工扣减必须选择用户、填写大于零的金额，并允许填写业务备注。
- 充值或扣减必须调用 Model Router 的余额交易能力。
- 只有上游明确返回成功后，才能展示操作成功。
- 上游失败时不得在界面伪造余额变化。
- IMS Router 不单独生成本地充值流水；余额流水以 Model Router 查询结果为准。
- 本地审计只记录操作人、目标、金额、结果、时间和错误摘要，不记录敏感凭证。

### 5.8 账单管理

管理端必须支持跨用户账单运营。

必须支持：

- 按用户、部门、时间范围及上游支持的账单条件筛选。
- 查看账单列表。
- 查看账单详情。
- 导出账单。

账单管理规则：

- 列表、详情和导出均实时调用 Model Router。
- 页面展示和导出结果的筛选口径必须一致。
- 管理员不得修改上游账单金额、计费项、币种或状态。
- 上游不可用时，应提示查询或导出失败，不得返回伪造账单。

### 5.9 审计记录

管理端必须能查看关键操作审计。

至少审计：

- 后台账号创建、启用、禁用、角色设置和密码重置。
- 普通用户创建、启用、禁用、软删除和密码重置。
- Model Router 部门删除。
- 人工充值和人工扣减。
- API Key 创建、查看明文、复制明文和删除。
- 账单导出。

审计内容至少包含操作者、操作对象、操作描述、成功状态、失败原因摘要、客户端信息和操作时间。审计内容不得包含密码、会话凭证、上游访问凭证或 API Key 明文。

## 6. 用户端需求

### 6.1 登录与账号

普通用户账号只能由管理员创建，第一版不开放自助注册。

用户端必须支持：

- 普通用户登录。
- 退出登录。
- 修改自己的密码。
- 查看自己的账号信息。

用户账号规则：

- 被禁用或软删除的用户不得登录。
- 已登录用户被禁用或软删除后，后续受保护操作必须被拒绝。
- 用户不得提交或修改自己的上游部门 ID。
- 若允许用户修改会影响部门展示的信息，后端必须同步更新其绑定的 Model Router 部门展示信息。

### 6.2 概览与余额

用户端必须支持查看当前用户自己的余额。

余额规则：

- 余额实时读取当前用户绑定的 Model Router 部门。
- 用户不得查看或指定其他用户、其他部门的余额。
- 上游余额查询失败时，应明确提示失败，不得展示伪造余额。

### 6.3 API Key 自助管理

用户端必须支持普通用户管理自己部门下的 API Key。

必须支持：

- 查看自己的 API Key 列表。
- 创建新的 API Key。
- 查看或复制完整 API Key。
- 删除自己的 API Key。

用户端 API Key 规则：

- 列表只展示掩码或预览信息，不展示完整明文。
- 完整 API Key 只能在用户主动创建、查看或复制时短暂展示。
- 完整 API Key 只允许保留在当前页面内存中，用于展示、复制或本次浏览器直连 Model Router。
- 关闭展示弹窗、切换页面、刷新页面或退出登录后，不应继续保留完整 API Key。
- 完整 API Key 不得写入本地数据库、缓存、日志、审计详情、浏览器本地存储或全局状态持久化。
- 用户只能删除自己的 API Key。
- 删除结果以上游返回为准。
- 不提供 API Key 禁用入口或本地禁用状态。

### 6.4 模型服务

用户端必须支持只读查看当前绑定部门可用的模型服务。

必须支持：

- 查看当前部门可用模型列表。
- 查看当前部门用量概览。
- 查看当前部门模型用量列表和明细。
- 查看当前部门 API 调用记录。

模型服务规则：

- 后端必须根据当前登录用户确定绑定部门，不得接收或信任前端提交的用户或部门作为授权依据。
- 如果上游部门配置了可用模型范围，后端必须强制按该范围过滤。
- 模型列表、用量和调用记录实时来自 Model Router。
- API 调用记录只展示观测字段，不返回请求体、响应体、提示词、模型回复或对话内容。
- 用户端不得提供模型新增、编辑、删除、定价、计费规则或路由策略入口。

### 6.5 账单

用户端必须支持普通用户查看和导出自己的账单。

必须支持：

- 按时间范围和上游支持条件筛选自己的账单。
- 查看账单列表。
- 查看账单详情。
- 导出当前筛选范围内的账单。

账单规则：

- 账单实时来自 Model Router。
- 用户只能查询和导出自己绑定部门的账单。
- 页面展示和导出结果的筛选口径必须一致。
- 用户不得修改账单金额、币种、计费项或状态。

### 6.6 文本对话

用户端必须提供文本对话页面，用于让用户测试自己的 API Key 和可用模型。

文本对话规则：

- 用户必须从自己部门下的 API Key 中选择一个 Key。
- 用户必须从自己部门可用模型列表中选择一个模型。
- 对话请求由浏览器直接请求 Model Router 开放对话能力。
- IMS Router 后端不得新增推理、中转、代理或请求内容存储接口。
- 对话仅支持文本消息。
- 对话应支持流式展示模型回复。
- 对话历史只保存在当前页面内存中。
- 刷新页面、关闭页面、退出登录或清空对话后，对话历史即丢失。
- 对话内容不得写入本地数据库、缓存、日志、审计详情、浏览器本地存储或导出文件。
- 完整 API Key 仅用于本次浏览器请求，不得写入持久化状态。

## 7. Model Router 对接边界

Model Router 是以下数据和能力的权威来源：

- 部门树。
- 部门删除。
- 部门余额。
- 余额交易。
- 余额变更流水。
- API Key 创建、列表、查看、复制和删除。
- 模型列表。
- 用量概览。
- 模型用量列表和明细。
- API 调用记录。
- 账单列表、详情和导出所需数据。
- OpenAI 兼容文本对话能力。

对接规则：

- 所有上游能力必须以官方文档或实际联调结果为依据，不得臆造接口、字段或状态。
- 上游明确不支持的能力，不得在 IMS Router 本地模拟成已支持能力。
- 改变上游状态的操作，只有在上游明确成功后才能向用户展示成功。
- 查询类数据应实时从上游获取；如为了页面体验做短时缓存，缓存不得被描述或使用为权威数据，并必须避免敏感信息落地。
- 上游返回失败、超时或不可识别结果时，系统应提示当前数据获取失败。
- 错误提示应便于定位问题，但不得包含上游访问凭证、API Key 明文、密码或会话凭证。

## 8. 安全、审计与数据隔离

### 8.1 身份隔离

- 管理端和用户端必须使用独立登录入口和独立身份校验。
- 后端必须区分管理员身份和普通用户身份。
- 管理员不能因为拥有管理端权限就绕过用户端登录直接成为某个普通用户。
- 普通用户不能访问任何管理端能力。

### 8.2 用户数据隔离

- 普通用户所有查询、导出和写操作都必须限制在其绑定部门内。
- 后端必须从当前登录身份推导部门，不得信任前端提交的用户或部门作为授权依据。
- 篡改请求参数、导出条件或页面路由，不得访问其他用户余额、API Key、用量、调用记录或账单。

### 8.3 敏感信息保护

不得在以下位置保存或输出 API Key 明文、密码、会话凭证或上游访问凭证：

- 本地数据库。
- 缓存。
- 系统日志。
- 异常信息。
- 审计详情。
- 测试快照。
- 前端本地存储。
- 前端全局持久化状态。
- 导出文件。

第一版要求后台管理员密码和普通用户密码以明文形式保存在各自账号数据中；即使按此要求保存密码，也不得把密码返回给前端页面、写入日志、写入审计或出现在异常信息中。

API Key 明文只能在创建、查看或复制等用户主动触发的场景短暂返回。列表、详情列表、审计、日志和导出均不得包含完整 Key。

## 9. 异常处理规则

系统必须对以下场景给出明确、可理解的失败提示：

- 登录失败。
- 账号被禁用或删除。
- 权限不足。
- 用户未绑定上游部门。
- 上游部门不存在或已被删除。
- Model Router 请求失败、超时或返回不可识别结果。
- API Key 创建、查看、复制或删除失败。
- 余额查询、充值或扣减失败。
- 用量、调用记录或账单查询失败。
- 账单导出失败。
- 文本对话请求失败。

异常处理要求：

- 不得用伪造数据、静态假数据或未标识的历史数据冒充实时结果。
- 不得把内部堆栈、数据库错误、上游凭证、密码或 API Key 明文暴露给前端用户。
- 对于已提交上游的状态变更操作，应以上游最终明确结果为准。
- 对于用户可重试的失败，应保留用户已输入的非敏感内容，避免重复填写。

## 10. 验收标准

项目交付时，至少满足以下验收标准：

1. 超级管理员可以管理后台账号；运营管理员访问后台账号管理能力时被拒绝。
2. 超级管理员和运营管理员均可管理普通用户、部门、API Key、余额、账单和审计。
3. 管理员创建普通用户后，本地普通用户与唯一 Model Router 部门建立一一绑定；绑定失败时不得产生可正常使用的用户。
4. 普通用户只能登录用户端，管理员只能登录管理端，两套身份域互不混用。
5. 普通用户只能查看和操作自己绑定部门的余额、API Key、模型服务、用量、调用记录和账单；篡改用户或部门参数不能越权。
6. 用户被禁用或软删除后不能继续登录；历史账单关联、余额流水和审计记录仍可追溯。
7. 管理端可以查看 Model Router 部门树并删除部门；页面不提供单独新增部门入口。
8. 管理端可以只读查看模型列表、用量概览、模型用量、模型用量明细和 API 调用记录；不提供模型管理、定价、计费规则或路由策略入口。
9. 用户端可以只读查看自己部门可用模型、用量、模型用量明细和 API 调用记录。
10. API 调用记录不展示、不返回、不保存请求体、响应体、提示词、模型回复或对话内容。
11. 管理端和用户端均可创建、查看、复制和删除 API Key；均不提供禁用入口或本地禁用状态。
12. API Key 明文不会出现在数据库、缓存、日志、异常、审计详情、测试快照、浏览器本地存储或导出文件中。
13. 充值或扣减成功后，Model Router 余额正确变化，并能从上游余额流水中查询到结果；上游失败时页面不展示虚假余额。
14. 管理员可以跨用户查询、查看详情和导出账单；普通用户只能查询、查看详情和导出自己的账单。
15. 页面账单和导出账单使用相同筛选口径。
16. Model Router 不可用时，页面明确提示获取失败，不展示伪造或未标识的过期数据。
17. 关键管理操作、充值、扣减、API Key 明文查看或复制、删除和账单导出均可在审计记录中追溯。
18. 审计记录不包含密码、会话凭证、上游访问凭证或 API Key 明文。
19. 用户端文本对话由浏览器使用用户选择的 API Key 和模型直接请求 Model Router，IMS Router 后端没有推理、代理、中转或对话内容存储接口。
20. 文本对话历史只存在当前页面内存中，刷新、关闭、退出或清空后即丢失。
21. 后端使用 Java 实现，前端使用 Vue 与 TDesign 实现。
22. 交付文档、页面文案和系统说明中涉及公司主体时，使用“杭州算能矩阵科技有限公司”；涉及股权关系时，使用“杭州效果科技有限公司全资持股，持股比例 100%”。

## 11. 交付建议

- 第一阶段：完成管理端和用户端登录、两套身份域、角色权限和基础页面框架。
- 第二阶段：完成普通用户开户、上游部门绑定、用户启禁用和软删除。
- 第三阶段：完成 API Key、余额和审计闭环，重点验证敏感信息不落地。
- 第四阶段：完成模型观测、调用记录、账单查询和导出。
- 第五阶段：完成用户端文本对话，确保浏览器直连 Model Router，后端不参与推理链路。
- 第六阶段：完成越权测试、上游失败测试、敏感信息扫描和最终验收。

每个阶段都应先保证后端权限与数据隔离正确，再完成前端页面体验。不得只依赖前端隐藏入口实现安全控制。
