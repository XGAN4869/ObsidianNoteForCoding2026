# 分享与海报前端方案

> A2 技术决策：维护状态归属、数据链路、实现选择与可行性证据。业务规则、运行规则、行为验收及业务未决项只引用[需求评审](../详情与互动需求评审与最小决策树.md)；整体边界见[方案总览](../详情前端方案.md)。
>
> 客户端只做 App-Plus／App-vue；外部链接增加独立分享预览网页，不开发完整 H5 客户端或微信小程序端。
> 对应 M8 海报生成、图片分享与保存，M9 外部链接卡片、App 内好友分享与口令。用户已确认产品方向，具体契约与技术候选仍待验证；本轮仅整理文档。

## 1. 数据放哪里（状态归属表）

| 需要记住的信息 | 由谁管理 | 保留范围与清理时机 |
| --- | --- | --- |
| 主分享面板开关、笔记 ID 与分享元信息 | 页面局部状态 | 以笔记和请求批次隔离，旧准备结果不覆盖当前笔记 |
| 站内收件人选择、发送状态与客户端消息 ID | 分享流程局部状态；消息归私信模块 | 同次重试复用消息 ID；会话与持久化消息不复制到分享 Store |
| 海报模板、素材、生成进度与导出结果 | 局部海报流程 | 生成批次隔离；换笔记或模板时使旧结果失效并释放资源 |
| 海报预览与第二目标面板 | 页面局部状态 | 明确当前输出为纯图片；分享／保存失败保留可重试预览 |
| 微信调用状态与实际可证明事件 | 局部渠道适配 | 每次调用绑定笔记、输出类型与操作标识，不推断对方已收到 |
| 收藏状态 | 沿用同一笔记互动共享状态候选 | 复用 M4 的状态与清理边界，不另存一份收藏 |
| 网页公开预览与下载配置 | 服务端分享预览接口及独立预览页 | 仅返回允许公开的字段；失效、私密与清理按服务端状态处理 |

## 2. 模块之间传什么（数据链路）

### 2.1 主面板：笔记链接卡片

笔记 ID → API 获取可分享元信息与 HTTPS 分享地址 → 主面板选择微信好友／朋友圈 → uni.share 的链接卡片 → 接收方点击后进入分享预览网页。

预览页 → 读取允许公开的笔记摘要 → “查看更多” → 尝试打开 App 或按实际环境引导下载。不是把完整详情页面改成 H5 端；Web 预览和 App 深链是独立承接能力，详见 Q-10a。

### 2.2 App 好友：站内笔记消息

主面板选择“App 好友” → 选择可接收对象并确认 → 私信模块发送笔记卡片消息 → 服务端校验并持久化 → 会话与未读信息更新 → 对方收到后点击进入 App 详情。

前端提交所需语义为“收件人／会话、笔记 ID、客户端消息 ID”。服务端生成真实消息 ID，校验双方关系、拉黑／私信限制及笔记可见性，并构造合法卡片元信息。上述为所需契约示意，不是已存在 API 或字段声明。

消息卡片只承载笔记引用和允许显示的摘要；打开时重新校验内容状态。重试依赖消息幂等契约，不另建一条绕过私信系统的发送通道。

### 2.3 海报：先生成，再选图片去向

笔记素材与海报模板 → 生成器导出图片 → 统一转换为有效本地文件 → 海报预览与第二目标面板 → 微信好友／朋友圈纯图片分享，或保存相册。

链接卡片、站内消息卡片和海报图片使用不同输出类型，不能因共用一个面板状态而串用参数。海报上的二维码即使可扫描，图片消息本身也不变为链接卡片。

## 3. 开发时怎么选（技术决策）

### 3.1 两层面板与渠道调用

主面板保留原五项并增加“App 好友”。排列方式建议为好友区＋操作区，不为强行放入一行而固定按钮宽度；布局待设计确认。海报生成成功后再呈现第二目标面板，入口候选见需求评审 SH-05。

| 入口／输出 | 技术处理 |
| --- | --- |
| 主面板微信好友的笔记链接 | uni.share，provider 为 weixin，scene 为 WXSceneSession，type 为 0；组装 href、标题、封面与摘要 |
| 主面板朋友圈的笔记链接 | 同为 type 0，scene 为 WXSceneTimeline；展示由微信承载，不能保证与聊天卡片长得相同 |
| 海报分享给微信好友 | uni.share，type 为 2，scene 为 WXSceneSession；传本次海报图片 |
| 海报分享到朋友圈 | uni.share，type 为 2，scene 为 WXSceneTimeline；不附加笔记链接卡片 |
| 海报保存相册 | uni.saveImageToPhotosAlbum，传有效本地文件；授权拒绝或失败与生成结果分开 |
| App 好友分享 | 调消息 API／已有私信 SDK 的业务封装；与 uni.share 无关 |
| 复制口令 | API 准备可解析口令，uni.setClipboardData；成功后局部反馈，关闭默认 toast |
| 收藏／取消收藏 | 调 M4 同一业务动作，校准同一共享状态 |

当前没有“更多”系统分享入口，uni.shareWithSystem 不进入本期必需路径。微信 SDK 需在自定义基座或独立测试安装包中配置验证，不能把提供商列表当作已安装微信的证据。

官方依据：[分享 API](https://uniapp.dcloud.net.cn/api/plugins/share.html)、[剪贴板 API](https://uniapp.dcloud.io/api/system/clipboard.html)、[保存图片](https://uniapp.dcloud.net.cn/api/media/image.html#saveimagetophotosalbum)。微信分享不能可靠判断真实分享成功或取消，因此只回传可证明的调用事件。

### 3.2 海报生成选型：不限定手写 Canvas

| 候选 | 实现方式 | 当前取舍 |
| --- | --- | --- |
| 现成模板库 lime-poster | 以结构和样式描述图片、文本与二维码，由库布局并输出图片；底层使用 Canvas | 推荐先做小原型，减少手写坐标；不把作者兼容表当项目实测 |
| 手写 Canvas | 自行处理绘制、换行、裁切、二维码与导出 | 固定简单海报可用；复杂版式需自行维护布局，不作为先定方案 |
| App 原生视图截图 | 独立海报视图渲染后，使用 App 原生截图或合适的原生扩展导出 | 保留候选；plus.webview.draw 主要截取可视区域，不能假设支持任意长图或所有原生控件 |
| 服务端生成 | 后端根据模板和业务数据渲染图片，App 下载后预览、保存、分享 | 需要服务端出图服务；是否采用依据一致性、延迟和维护成本验证，不预设新增服务 |

推荐先验证 [lime-poster 作者文档](https://ext.dcloud.net.cn/plugin?id=24357)。作者声明支持 Vue 3 与 App-vue，提供文本、图片和二维码布局；这些是选型线索，不是当前项目已兼容的证据。本轮不安装依赖、不升级工具链，不承诺采用该库或与小红书内部实现相同。

关键输出边界：该库文档说明导出结果可为 base64 data URL，不能因方法名含 TempFilePath 就视为真实文件路径。App 适配层需落为本地文件后，再交给保存或图片分享 API。若开启 renderjs，还需单独验证本地图、网络资源加载与导出限制，不能只按性能宣传直接开启。

海报数据与版式分离；版式消费项目令牌并明确导出坐标换算，预览区域自适应，不把导出分辨率写成页面组件固定宽度。视频笔记使用封面、首期模板和二维码内容均仍是设计建议，见 Q-10c。

原生截图依据：[Webview.draw](https://www.html5plus.org/doc/zh_cn/webview.html#plus.webview.WebviewObject.draw)。其 Android 支持存在 Canvas 和部分原生控件无法截取的限制，需用独立海报视图验证，不直接截图整个详情页面。

### 3.3 App 好友选择与消息一致性

1. 建议先提供“最近会话＋互关好友”，按消息模块资格过滤；单人确认后发送为候选，是否多选见 Q-10b。
2. 优先复用私信消息传输、持久化、重连补拉和未读链路；若尚未接通，作为分享依赖，先用同契约 Mock 验证，不从本页另建 WebSocket 系统。
3. 为笔记卡片定义业务消息类型。可用消息服务的自定义消息承载，但具体 IM 实现未选，不因本轮需求自动引入 uni-im 或第三方 SDK。
4. 一次发送使用稳定客户端消息 ID；响应丢失时按幂等契约核实或重试，禁止重复落消息。
5. 接收端按消息类型展示笔记卡片，点击按 note ID 进入详情并校验最新权限；已删或无权限按 M11 占位，不能复活旧摘要与正文。
6. 消息服务确认、送达与已读分别记录。是否发送附言、一次发给多人、群聊和发送后是否跳转会话，均未默认纳入。

本轮源码依据：[消息页](../../../src/pages/message/index.vue)目前仅有公共导航；已有设计稿提到的聊天能力尚不能视为已实现。

### 3.4 分享预览网页与测试下载

按用户补充，外部卡片地址进入一个分享预览页，供微信内浏览；“查看更多”引导 App。服务端提供裁减后的预览数据，不先返回完整内容再靠样式遮挡；私密、删除或无权限状态不输出可用旧内容。

建议先展示封面、作者、标题与摘要，视频只展示封面；具体截断与媒体范围见 Q-10a。链接与海报二维码使用相同受控分享地址，但卡片点击与扫码分别验证。

App 未上架不影响独立公开网页提供预览。对外测试需配置可下载的安装包或测试分发入口：Android 为 APK，不是 Windows 的 EXE；iOS 可考虑 TestFlight，具体账号、构建与邀请条件按苹果要求落实。当前没有可用地址就显示真实测试状态，不编造下载链接。

微信内下载或唤起受环境限制：提供必要的外部浏览器操作提示，实际是否成功以目标设备验证；不得用超时判断可靠检测“未安装”，也不承诺安装后自动恢复原笔记，需要独立验证路由／口令恢复。

参考：[Android 安装引导](https://www.pgyer.com/doc/view/androidStep)、[Apple TestFlight](https://developer.apple.com/cn/testflight/)。

| TV-S01 | 模板生成器与本地文件适配 | 当前工具链可导出清晰完整图片；中文换行、网络／本地图、二维码和重复生成正确 | 一张真实笔记海报小原型，验证导出数据格式、落盘、预览、保存和微信发送 | lime-poster 为优先候选，尚未安装或运行 |
