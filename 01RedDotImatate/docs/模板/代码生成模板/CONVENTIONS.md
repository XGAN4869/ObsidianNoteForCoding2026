# Composables 书写规范

以当前 `useCursorFeed.ts` 的组织方式和学习用注释为参考；不修改参考文件及用户已有注释。本文约束后续新增的 composable。

## 文件顺序

1. import。
2. 输入、输出类型及配置项：分别说明调用方传入什么、函数返回什么。
3. 必要的内部辅助函数。
4. `useXxx` 主函数：状态 → 派生状态（确有需要时）→ 内部逻辑 → 公开方法 → return。

## 注释格式

- `//!`：标记关键约定、状态分区或公开方法。
- `//!! 重点:`：只标记会影响理解的核心约束，不到处使用。
- `/** 前 ... */`：标记前端提供的数据，例如分页请求参数。
- `/** 后 ... */`：标记后端返回的数据，例如经 API 模块适配后的分页结果。
- `前`、`后` 表示前后端数据来源，不表示函数执行前后或函数输入输出。普通函数的参数、返回值分别写“输入”“输出”，不套用这两个标记。
- `// hooks 配置项`：说明外部依赖和配置。
- 核心方法内部使用 `//1.`、`//2.` 连续标出真实执行步骤，同时解释这一步为什么需要。
- 公开方法使用 `//! 暴露1：用途`，编号不重复。
- 保留用户的原始注释；逻辑发生变化时说明原因，并只更新直接相关的说明。

## 实现要求

- 一个 composable 只处理一件事；模板、页面文案、TDesign 结构和样式由组件负责。
- 只定义实际需要的参数、状态和返回值；不提前加入缓存、版本号、重置方法或通用错误体系。
- 多个含义不同的参数用对象传递；避免调用处出现不易辨认的布尔参数组合。
- 禁止 `any`；DOM 查询回调等不受控数据在必要的边界检查，不能拿错误尺寸继续布局。
- 列表整体替换时优先 `shallowRef`；普通状态使用 `ref`；纯计算放到 utils。
- 异步步骤用 `async/await`；需要清理临时状态时用 `finally`。只在能处理错误的地方捕获，避免层层兜底。
- 尺寸计算统一使用实际 px；展示尺寸继续由 tokens 中的 rpx 和自适应布局决定。

## 最小结构示意

```ts
import { shallowRef } from 'vue'

/** 输入：调用方传入本次需要处理的数据。 */
export interface XxxInput {
  id: string
}

/** 输出：返回调用方真正需要的结果。 */
export interface XxxResult {
  id: string
}

export function useXxx() {
  //状态
  const items = shallowRef<XxxInput[]>([])

  //! 暴露1：执行当前职责
  async function execute(input: XxxInput[]): Promise<XxxResult[]> {
    //1. 根据实际流程补充步骤和原因，不为了编号拆分无意义函数。
    items.value = input
    return input
  }

  return { items, execute }
}
```
