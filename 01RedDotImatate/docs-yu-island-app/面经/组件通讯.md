# 组件通讯

## 组件事件不会「穿透」

`emit` 是子组件向**直接父组件**发通知，只能被父组件模板上的 `@事件名` 收到，不会自动继续往上冒。

```vue
<!-- NoteNavbar.vue 内部 -->
<t-button @click="select('visibility')">谁可以看</t-button>
```

```ts
function select(action: 'share' | 'visibility' | 'remove'): void {
  if (action === 'share') emit('share')
  else if (action === 'visibility') emit('visibility')
  else emit('remove')
}
```

```vue
<!-- 直接父组件 pages/note/index.vue -->
<NoteNavbar :author="author" @visibility="visibilitySheet = true" />
```

如果中间还隔一层组件，事件就停在中间那层。想继续往上，中间层要自己再 `emit` 一次：

```vue
<!-- NoteNavbar 里把 AppNavbar 的 left 转成自己的 back -->
<AppNavbar @left="emit('back')" />
```

### 和 DOM 冒泡的区别

原生点击（`@click`、`@tap`）会沿 DOM 树往上冒，组件根节点也参与，所以看起来像「穿过了组件」。但 `share`、`visibility` 这种**自定义事件名不会冒泡**，只能靠 `emit` 一层层接。两套机制不要混为一谈。

## props / emit / v-model / defineModel 怎么选

先看数据往哪边走：

| 场景 | 用什么 |
| --- | --- |
| 父组件把数据给子组件显示 | `props` |
| 子组件只通知父组件「发生了某件事」 | `emit` |
| 父子都要读写同一个值 | `v-model` |
| 在子组件里实现 `v-model` | `defineModel` |

`v-model` 本身就是 `emit` 的语法糖：

```vue
<Child v-model="visible" />
<!-- 等价于 -->
<Child :modelValue="visible" @update:modelValue="visible = $event" />
```

`defineModel` 则是 Vue 3.4 起在子组件里声明这个 model 的写法：

```vue
<!-- 子组件 -->
<script setup lang="ts">
const visible = defineModel<boolean>({ default: false })
</script>

<template>
  <t-button @click="visible = true">打开</t-button>
</template>
```

子组件赋值，父组件的 `visible` 同步更新。项目 Vue 锁在 `3.4.21`，可以直接用。

### 判断标准

- **有值要双向同步**：显示/隐藏、输入内容、选中项 → `v-model` + `defineModel`。
- **只是通知动作**：点了分享、要删除、要打开某个面板 → `emit`，状态留在父组件。
- **子组件自己的 UI 状态**：菜单展开、局部 loading → 子组件内部 `ref`，不暴露给父组件。

### 为什么「打开面板」不用 v-model

面板真正渲染在父页面里，子组件不需要知道它开着还是关着，它只负责「用户点了这个菜单项」这个动作。用 `v-model` 等于把父组件的状态借给子组件，子组件却只写不读，语义反而绕。

同一个菜单里，`share`、`remove`、`back` 都没有值可绑，只能 `emit`；单独把 `visibility` 换成 `v-model`，一个组件两套写法，不如统一。

`defineModel` 和 `defineEmits` 可以并存，需要时混用没问题，只是这里没必要。
