# 删除笔记前端方案

> A2 技术决策：维护状态归属、数据链路、实现选择与可行性证据。业务规则、运行规则、行为验收及业务未决项只引用[需求评审](../详情与互动需求评审与最小决策树.md)；整体边界见[方案总览](../详情前端方案.md)。
>
> 对应单元：M10 作者确认 → 删除结果 → 返回与缓存同步。删除后的首页同步按[点赞与收藏方案的简单做法](02-点赞与收藏.md#3-首页怎么回显)处理：成功后往共享状态记一笔已删，首页显示时把卡片从列表和缓存里移除，同列后续卡片上移，不重新测量高度。作者详情菜单显示“分享／谁可以看／删除笔记”，其中删除笔记使用红色破坏性入口。

## 1. 数据放哪里（状态归属表）

| 需要记住的信息 | 由谁管理 | 保留范围与清理时机 |
| --- | --- | --- |
| 作者权限、确认框与进行中请求 | 页面局部 computed／ref | 取消、完成或离开时结束相应操作 |
| 详情菜单入口与可见范围入口显隐 | 页面局部 computed，依据当前详情的 author.self | 非作者不显示删除和“谁可以看”；切换笔记或账号时重新计算，不以本地缓存权限兜底 |
| 已删除标记 | 按笔记 ID 的共享状态（与点赞收藏共用） | 删除成功后记一笔；首页取走后清空 |
| 来源页面与恢复锚点 | 沿用来源页面的导航与位置状态 | 有来源返回；无来源按已确认规则处理 |
| 相关业务缓存 | 各自持有者按 ID 更新或失效 | 只处理相关缓存，不复制或清空全部 Feed |

## 2. 模块之间传什么（数据链路）

作者权限 → TDesign 二次确认 → API 删除 → 成功／明确已删／明确失败／未知结果 → 共享状态与相关缓存 → 停止媒体、返回或安全出口。

详情作者菜单 → 点击“删除笔记” → 二次确认与进行中锁；点击“谁可以看”属于独立的可见范围流程，不得复用删除确认或在删除失败时改变 visibility。菜单入口显隐只由当前详情的作者权限派生，服务端仍是最终权限边界。

接口最终校验权限。删除成功前不提前移除详情。返回首页时按笔记 ID 从列表和本地缓存里移除卡片，同一列后续卡片上移，具体做法见[点赞与收藏方案第 3、4 节](02-点赞与收藏.md#3-首页怎么回显)。

## 3. 开发时怎么选（技术决策）

### 3.1 契约前提与操作边界

- 删除入口只由当前详情的作者权限决定；非作者不显示。
- 点删除后先二次确认，取消或关掉确认框都不发请求。
- 确认后调删除接口；请求期间不重复提交，也不提前把详情藏掉。
- 接口成功或明确返回“已删除”后：停媒体，往共享状态记一笔已删，然后按来源返回。
- 接口失败：留在详情，提示原因。
- 结果不明确：不当作成功，先核实内容状态再决定。
- 有来源页就返回来源页并恢复位置；没有来源按约定走安全出口。

删除说明、30 天范围及无历史页出口仍由需求评审维护；本方案不自行选择跳转地址。多端并发下“明确已删”必须有契约依据，不能把其他失败当作成功。

### 3.2 详情菜单与删除动作

1. 作者详情菜单固定保留“分享”“谁可以看”“删除笔记”；“删除笔记”使用破坏性红色样式，非作者不渲染该入口。
2. 点击删除后进入二次确认；取消、遮罩关闭或系统返回均保留详情，不产生删除请求。
3. 确认后获得进行中锁，连点不重复提交；请求期间不提前移除标题、作者、正文、媒体或互动。
4. 删除成功或服务端明确返回“已删除”后，停止媒体并标记当前笔记不可读，再按来源返回；失败保留详情并只反馈有依据的原因；结果未知先核实，不直接当作成功。
5. 可见范围面板的三档规则和即时生效说明维护在[详情与媒体方案](01-详情与媒体.md#34-作者菜单与可见范围)，删除方案只消费其最终权限结果。

### 3.3 删除后的提交边界

1. 仅有效操作结果可提交；成功或明确已删后停止媒体，并标记共享状态。
2. 首页按笔记 ID 移除卡片：内存列表和本地缓存各删一条，同一列后续卡片上移；不重新测量高度。
3. 各场景采用占位还是移除由需求评审 BR-09、BR-10 和 Q-04、Q-12 决定，实现衔接见[占位方案](06-删除后占位.md)。
4. 有来源页则按来源返回并恢复锚点；无来源按 Q-11 的最终规则选择出口。
