# 点赞与收藏前端方案

> 对应单元 M4。本文替换之前的候选方案，只记录已确认的简单做法：详情页正常调接口、不加锁；把最终状态记到一个按笔记 ID 的共享状态里；首页重新显示时取走并回显。

## 1. 一句话方案

详情页点赞、收藏、评论点赞都直接调接口，不锁按钮、不排队。接口成功后，把这条笔记的最新状态记下来；首页每次重新显示时把记录取走，改掉首页列表和本地缓存。

## 2. 详情页做什么

- 点赞、收藏、评论点赞各自独立调用，互不等待，不锁按钮。
- 每次接口成功，记一笔：笔记 ID + 最新的点赞状态、点赞数、收藏数。
- 接口失败不记。按钮失败后怎么恢复原样，是详情页自己的展示逻辑，不影响首页。
- 评论点赞不会改变首页卡片上的任何内容，不用记。
- 接口成功就记，不用等退出页面。这样从消息页、用户页等入口打开详情再切回首页，也能回显。

## 3. 首页怎么回显

首页在 `onShow` 时（[index.vue](../../../src/pages/index/index.vue)）取走所有记录，对发现流和关注流各应用一次，然后清空记录。

- 列表里找得到这张卡片：换掉卡片上的红心、点赞数、收藏数。
- 找不到：直接丢弃。说明首页还没加载到它，或者它本来就不在首页列表里；之后网络返回的数据本来就是最新的。
- 删除笔记：把卡片从首页列表和本地缓存里去掉，同一列下面的卡片往上挪。

应用改动只改现有列表，不重新请求、不改滚动位置。

## 4. 为什么不用重新测量高度

首页卡片的高度只由三块决定（[HomeNoteCard.vue](../../../src/pages/index/feed/components/HomeNoteCard.vue)）：

| 部分 | 高度 |
| --- | --- |
| 封面 | 永远是 3:4 的框 |
| 标题 | 最多两行 |
| 底部一行 | 固定高度 |

点赞、收藏只改红心颜色和数字，这三块都没变，所以卡片高度不变。

删除笔记不需要量高度，只需要算位置：同一列后续卡片上移「被删卡片高度 + 卡片间距」，是加减法。

只有标题或封面真的变了（比如以后做编辑笔记），才需要单独量那一张卡片的高度。点赞、收藏、删除都不需要。

## 5. 本地缓存怎么写

首页本地缓存只存第一页，30 分钟内有效（[cache.ts](../../../src/pages/index/feed/utils/cache.ts)）。

- 回显时只改缓存里找得到的那一条，找不到就跳过。
- 保留原来的保存时间，不刷新 30 分钟有效期，避免把旧数据伪装成刚拉的新数据。

## 6. 不做的事

- 不锁按钮、不做请求排队、不做操作版本号。
- 不做跨页的乐观覆盖和回滚队列：首页回显只认接口成功后的最终结果。
- 不做详情页退出时的统一上报：接口成功就记，不用等退出。
- 连点时接口可能乱序返回，这是在详情页按钮层处理的事，不在首页回显层解决。
