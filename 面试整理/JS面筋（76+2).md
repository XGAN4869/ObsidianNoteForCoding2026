# 一、数据类型

#### 补充：JS常见的数据结构

1. Array 数组：一块连续的内存空间，保存的数据个数在分配内存的时候就是确定的。使用在 - 待办事项列表、购物清单等地。

   1. O(1)，索引直接访问，无需遍历查找，是数组的核心优势

   2. 连续存储，本身不自带排序功能

2. Stack 栈：栈是一种遵循先进后出（LIFO）原则的有序集合。

3. Queue 队列：队列遵循先进先出（FIFO）原则

4. 链表（Linked List)

   1. 和数组一样也是一种列表，数组的效率相对偏低，可以考虑用链表代替数组

   2. 链表几乎可以用在任何可以使用一堆数组的情况，但是如果需要随机访问，还是数组比较好

5. 字典

   1. 以键-值对 存储数据的数据结构，JS中的 Object 类就是以字典的形式设计的。

6. 散列表（哈希表）

   1. 在散列表上插入、删除和取用数据非常快

   2. VS：如果你用数组/链表 存储数据，想找到其中一个数据，需要从头遍历，因为不知道这个数据存储到了数组的哪个位置。

   3. 散列表 数组的长度是预设好的，所有元素根据该元素对应的键，保存在数组的特定位置，这里的键是类型的概念

   4. 使用散列表存储数组时，通过一个散列函数将键映射为一个数字，这个数字的范围是0\~散列表.length。

   5. 即使使用一个高效的散列函数，依然存在两个键映射为同一个值的可能性，这种现象叫碰撞

#### 2. 数据类型检测的方式有哪些

* **（1）typeof （基本数据类型/其中数组、对象、null都会被判断为object，其他判断都正确。）Symbol可以的**

  ```javascript
  console.log(typeof 2);               // number
  console.log(typeof true);            // boolean
  console.log(typeof 'str');           // string
  console.log(typeof []);              // object    
  console.log(typeof function(){});    // function
  console.log(typeof {});              // object
  console.log(typeof undefined);       // undefined
  console.log(typeof null);            // object
  ```



* **（2）instanceof 引用数据类型/构造函数（不能判断基本数据类型，因为本质是找原型链）**

  `instanceof`可以正确判断对象的类型，**其内部运行机制是判断在其原型链中能否找到该类型的原型**。**<span style="color: rgb(36,91,219); background-color: inherit">（说白了就是原型链上的都成立）</span> <u><span style="color: rgb(36,91,219); background-color: inherit"> ⭐x instanceof A：A.prototype在x的原型链上。也就是右侧构造函数A的原型有没有出现在左侧x 的原型链上</span></u>**

  ```javascript
  console.log(2 instanceof Number);                    // false
  console.log(true instanceof Boolean);                // false 
  console.log('str' instanceof String);                // false 

  console.log([] instanceof Array);                    // true
  console.log(function(){} instanceof Function);       // true
  console.log({} instanceof Object);                   // true
  ```

  可以看到，`instanceof`**只能正确判断引用数据类型**，而不能判断基本数据类型。`instanceof` 运算符可以用来测试一个对象在其原型链中是否存在一个构造函数的 `prototype` 属性。

* **（3）⭐ constructor 一是判断数据的类型，二是对象实例通过 `constrcutor` 对象访问它的构造函数。**

  ```javascript
  console.log((2).constructor === Number); // true
  console.log((true).constructor === Boolean); // true
  console.log(('str').constructor === String); // true
  console.log(([]).constructor === Array); // true
  console.log((function() {}).constructor === Function); // true
  console.log(({}).constructor === Object); // true
  ```

  需要注意，如果创建一个对象来改变它的原型，`constructor`就不能用来判断数据类型了：

  这里是因为Fn.prototype在 = new Array的时候，里面的prototype指向了Array，这是constructor属性为空，Fn会顺着原型链找到有constructor的prototype进入，并用Array.prototype.constructor 拿到Array

* **（4）Object.prototype.toString.call()**

  `Object.prototype.toString.call()` 使用 Object 对象的原型方法 toString 来判断数据类型：

  ```javascript
  var a = Object.prototype.toString;

  console.log(a.call(2));         // [object Number]   —— 数字类型
  console.log(a.call(true));      // [object Boolean]  —— 布尔类型
  console.log(a.call('str'));     // [object String]   —— 字符串类型
  console.log(a.call([]));        // [object Array]    —— 数组类型
  console.log(a.call(function(){})); // [object Function] —— 函数类型
  console.log(a.call({}));        // [object Object]   —— 普通对象
  console.log(a.call(undefined)); // [object Undefined] —— undefined
  console.log(a.call(null));      // [object Null]     —— null
  ```

  同样是检测对象obj调用toString方法，obj.toString()的结果和Object.prototype.toString.call(obj)的结果不一样，这是为什么？

  ```javascript
  // 1. Object.prototype.toString —— 返回 "[object Type]"
  Object.prototype.toString.call({}); // "[object Object]"

  // 2. Array.prototype.toString —— 被重写为：返回元素拼接的字符串
  Array.prototype.toString.call([1,2,3]); // "1,2,3"
  // 3. Function.prototype.toString —— 被重写为：返回函数体字符串
  Function.prototype.toString.call(function(){}); // "function(){}"
  // 4. Number.prototype.toString —— 被重写为：返回数字字符串
  Number.prototype.toString.call(123); // "123"
  // 5. Boolean.prototype.toString —— 被重写为：返回 "true"/"false"
  Boolean.prototype.toString.call(true); // "true"
  // 6. String.prototype.toString —— 被重写为：返回字符串本身
  String.prototype.toString.call("str"); // "str"
  ```

  这是因为toString是Object的原型方法，而Array、function等**类型作为Object的实例，都重写了toString方法**。不同的对象类型调用toString方法时，根据原型链的知识，调用的是对应的重写之后的toString方法（function类型返回内容为函数体的字符串，Array类型返回元素组成的字符串…），而不会去调用Object上原型toString方法（返回对象的具体类型），所以采用obj.toString()不能得到其对象类型，只能将obj转换为字符串类型；

因此，在想要得到对象的具体类型时，应该调用Object原型上的toString方法。也就是用Object.prototype.toString.call(obj)绕过原型链，直接调用最原始的版本！

#### 6. 为什么0.1+0.2 != 0.3，如何让其相等

在开发过程中遇到类似这样的问题：

```javascript
let n1 = 0.1, n2 = 0.2
console.log(n1 + n2)  // 0.30000000000000004
```

这里得到的不是想要的结果，要想等于0.3，就要把它进行转化：

```javascript
(n1 + n2).toFixed(2) // 注意，toFixed为四舍五入
```

`toFixed(num)` 方法可把 Number 四舍五入为指定小数位数的数字。

为什么会出现这种问题？因为计算机在计算0.1+0.2的时候，将其转换成了二进制数的和①，而两个数的二进制都是无限循环的数，

①\[在二进制数中是没有0.1的，0.1和0.2是多个二进制数的和]

0.1 = 1/16 + 1/32 + 1/256 + 1/512 + ...

0.2 = 1/8 + 1/64 + 1/128 + 1/1024 + ...（0.2 也有自己的二进制循环）

#### 9. typeof null的结果是什么，为什么(跳过，目前的水平无法理解）

typeof null 的结果是Object。

在 JavaScript 第一个版本中，所有值都存储在 32 位的单元中，每个单元包含一个小的 **类型标签(1-3 bits)** 以及当前要存储值的真实数据。类型标签存储在每个单元的低位中，共有五种数据类型：

```javascript
000: object   - 当前存储的数据指向一个对象。
  1: int      - 当前存储的数据是一个 31 位的有符号整数。
010: double   - 当前存储的数据指向一个双精度的浮点数。
100: string   - 当前存储的数据指向一个字符串。
110: boolean  - 当前存储的数据是布尔值。
```

如果最低位是 1，则类型标签标志位的长度只有一位；如果最低位是 0，则类型标签标志位的长度占三位，为存储其他四种数据类型提供了额外两个 bit 的长度。



有两种特殊数据类型：

* undefined的值是 (-2)(30)(一个超出整数范围的数字)；

* null 的值是机器码 NULL 指针(null 指针的值全是 0)



那也就是说null的类型标签也是000，和Object的类型标签一样，所以会被判定为Object。

#### 14. ⭐ JavaScript 内部用于将对象转换为原始值（Primitive）的抽象操作？

* `ToPrimitive` 是 ECMAScript 规范中定义的内部操作，它接收一个对象和一个可选的“预期类型”提示（`hint`），并返回一个原始值（string、number、boolean、symbol、bigint 等）。它决定了对象在需要原始值时的行为。

  ```javascript
  // 你写了一段代码
  let obj = {}
  let result = obj + 1
  console.log(result)  // 结果是 "[object Object]1"
  ```

* 核心方法：ToPrimitive: 是一个拆箱的过程，它需要知道拆谁，拆成什么类型（期望转换成number还是stirng。而valueOf和toString之所以能返回数字和字符串是因为这俩方法在基本类型中被重写过，参考下图👇发现几乎大家都有valueOf，这样就不会从原型链找Object.prototype.valueOf了，因为这个就是返回对象本身。

  * 而辅助拆箱的工具是 valueOf() \[通常是返回对象的数字表示] 和toString() \[返回对象的字符串表示] 这两个内部工具<u>[因为都被重写过]</u>.

  * ⭐Object.prototype上的toString()和Object.prototype.valueOf()
    这俩原型链上最原始的方法，如下

    * `Object.prototype.toString()` 返回 `"[object Type]"`

    * &#x20;const obj = { foo: 1 }; obj.valueOf() === obj || 返回一个对象

  * ⭐从右侧我们可以看出来基本类型基本身上都有valueOf()方法，所以不需要去原型链\[Object.prototype.valueOf]上找valueOf

  * 补充知识：JS调用valueOf方法将对象转换成基本类型值很少自己去调用valueOf方法，遇到基本类型值的对象时，JS会自动调用该方法

    * 强制数字类型转换和强制基本类型转换会优先调用valueOf

    * 强制字符串转换会优先调用toString

  * 所以，JS是弱类型语言，当原酸涉及不匹配的类型时，允许隐式类型转换而不是抛出错误。

#### 1. let、const、var的区别

* **块级作用域：**&#x5757;作用域由 `{ }`包括，块级作用域解决了ES5中的两个问题：

  ```java
  var a = 1        // window.a = 1 ✅
  let b = 2        // window.b = undefined ❌

  // 情况2：块级作用域
  {
    var c = 3      // window.c = 3 ✅（穿透了）
    let d = 4      // window.d = undefined ❌
  }
  ```

  * 补充知识全局环境：验证方法 -- 看 this 是否等于 window全局环境/global模块作用域

  ```javascript
  // var：没有死区

  let b = 2
  ```

* **const指针指向：**&#x6C;et和const都是ES6新增的用于创建变量的语法。 let创建的变量是可以更改指针指向（可以重新赋值）。但const声明的变量是不允许改变指针的指向。

#### 1. 对原型、原型链的理解

在JavaScript中是使用构造函数来新建一个对象的，每一个构造**函数**的内部都有一个 prototype 属性，它的属性值是一个对象，这个对象包含了可以由该构造函数的所有实例共享的属性和方法。当使用构造函数新建一个对象后，在这个对象的内部将包含一个指针，这个指针指向构造函数的 prototype 属性对应的值，在 ES5 中这个指针被称为对象的原型。一般来说不应该能够获取到这个值的，但是现在浏览器中都实现了 **proto** 属性来访问这个属性，但是最好不要使用这个属性，因为它不是规范中规定的。ES5 中新增了一个 Object.getPrototypeOf() 方法，可以通过这个方法来获取对象的原型。

当访问一个对象的属性时，如果这个对象内部不存在这个属性，那么它就会去它的原型对象里找这个属性，这个原型对象又会有自己的原型，于是就这样一直找下去，也就是原型链的概念。原型链的尽头一般来说都是 Object.prototype 所以这就是新建的对象为什么能够使用 toString() 等方法的原因。

# 四、异步编程

### 🔴 考察很多

#### 1. 对Promise的理解

* 放在 executor 里，是因为“这次任务成功还是失败，以及传什么结果”，必须在执行任务的时候决定

* 为什么值要放在 executor 里决定：因为每个 Promise 的任务结果都不一样。

* 放在 executor 外面的 .then，是因为“这个结果以后要怎么被别人接收和使用”，属于后续消费逻辑。then可以放外面，因为then不是生产结果是消费结果

##### 📌 一句话总结

**Promise 是一个构造函数**，**接收一个执行器函数executor**，**返回一个实例promise对象**。实例有 pending/resolved/rejected 三种状态，状态一旦确定就不可改变。通过 resolve/reject 改变状态，通过 then 注册回调（微任务），解决了回调地狱问题。

![](images/JS面筋（76+2\)-image-28.png)

##### 📌 关键机制

* 构造函数立即执行：`new Promise()` 时，传入的函数会立即执行

* 状态改变：通过 `resolve()` 和 `reject()` 改变状态

* 回调注册：用 `.then()` 为状态改变注册回调：把函数存起来 -- 成功的res，失败的rej

* 回调执行：then 的回调是微任务，在本轮事件循环末尾执行



##### 什么是 Promise？

Promise 是异步编程的解决方案，是一个容器，保存着未来才结束的异步操作结果。它是一个对象，可以获取异步操作的消息。

##### &#x20;三种状态

* Pending（进行中）- 初始状态

* Fulfilled/Resolved（已成功）

* Rejected（已失败）

##### 两个过程

* Pending → Resolved（成功）

* Pending → Rejected（失败）
  一旦状态改变，就永久凝固，不会再变

##### 核心特点

1. 状态不受外界影响 - 只有异步操作结果能决定状态

2. 状态一旦改变就不会再变 - 任何时候添加回调都能得到结果（不同于事件）

##### &#x20;缺点

1. 无法取消

2. 不设回调，内部错误不会反应到外部，所以要.then去接收错误信息

3. Pending 状态时无法得知进展到哪个阶段

#### 2. Promise的基本用法

* **(1)创建Promise对象**

  ```javascript
  const promise = new Promise(function(resolve, reject) {
    // ... some code
    if (/* 异步操作成功 */){
      resolve(value);
    } else {
      reject(error);
    }
  });
  ```

  **一般情况下都会使用`new Promise()`来创建promise对象，但是也可以使用`promise.resolve`和 `promise.reject`这两个方法：**

  * **Promise.resolve**

    `Promise.resolve(value)`的返回值也是一个promise对象，可以对返回值进行.then调用，代码如下：

    ```javascript
    Promise.resolve(11).then(function(value){
      console.log(value); // 打印出11
    });
    ```

    `resolve(11)`代码中，会让promise对象进入确定(`resolve`状态)，并将参数`11`传递给后面的`then`所指定的`onFulfilled` 函数；

    创建promise对象可以使用`new Promise`的形式创建对象，也可以使用`Promise.resolve(value)`的形式创建promise对象；

  * **Promise.reject**

    `Promise.reject` 也是`new Promise`的快捷形式，也创建一个promise对象。代码如下：

    ```javascript
    Promise.reject(new Error(“我错了，请原谅俺！！”));
    ```

    就是下面的代码new Promise的简单形式：

    ```javascript
    new Promise(function(resolve,reject){
       reject(new Error("我错了，请原谅俺！！"));
    });
    ```

    下面是使用resolve方法和reject方法：

    ```javascript
    function testPromise(ready) {
      return new Promise(function(resolve,reject){
        if(ready) {
          resolve("hello world");
        }else {
          reject("No thanks");
        }
      });
    };
    // 方法调用
    testPromise(true).then(function(msg){
      console.log(msg);
    },function(error){
      console.log(error);
    });
    ```

    上面的代码的含义是给`testPromise`方法传递一个参数，返回一个promise对象，如果为`true`的话，那么调用promise对象中的`resolve()`方法，并且把其中的参数传递给后面的`then`第一个函数内，因此打印出 “`hello world`”, 如果为`false`的话，会调用promise对象中的`reject()`方法，则会进入`then`的第二个函数内，会打印`No thanks`；

* **(2)Promise方法**

  Promise有五个常用的方法：then()、catch()、all()、race()、finally。下面就来看一下这些方法。

  1. **then()**

     当Promise执行的内容符合成功条件时，调用`resolve`函数，失败就调用`reject`函数。Promise创建完了，那该如何调用呢？

     ```plain&#x20;text
     promise.then(function(value) {
       // success
     }, function(error) {
       // failure
     });
     ```

     `then`方法可以接受两个回调函数作为参数。第一个回调函数是Promise对象的状态变为`resolved`时调用，第二个回调函数是Promise对象的状态变为`rejected`时调用。其中第二个参数可以省略。

     `then`方法返回的是一个新的Promise实例（不是原来那个Promise实例）。因此可以采用链式写法，即`then`方法后面再调用另一个then方法。

     当要写有顺序的异步事件时，需要串行时，可以这样写：

     ```javascript
     let promise = new Promise((resolve,reject)=>{
         ajax('first').success(function(res){
             resolve(res);
         })
     })
     promise.then(res=>{
         return new Promise((resovle,reject)=>{
             ajax('second').success(function(res){
                 resolve(res)
             })
         })
     }).then(res=>{
         return new Promise((resovle,reject)=>{
             ajax('second').success(function(res){
                 resolve(res)
             })
         })
     }).then(res=>{
         
     })
     ```

     那当要写的事件没有顺序或者关系时，还如何写呢？可以使用`all` 方法来解决。

  2. **catch()**

     Promise对象除了有then方法，还有一个catch方法，该方法相当于`then`方法的第二个参数，指向`reject`的回调函数。不过`catch`方法还有一个作用，就是在执行`resolve`回调函数时，如果出现错误，抛出异常，不会停止运行，而是进入`catch`方法中。

     ```javascript
     p.then((data) => {
          console.log('resolved',data);
     },(err) => {
          console.log('rejected',err);
          }
     ); 
     p.then((data) => {
         console.log('resolved',data);
     }).catch((err) => {
         console.log('rejected',err);
     });
     ```

  3. **all()**

     `all`方法可以完成并行任务， 它接收一个数组，数组的每一项都是一个`promise`对象。当数组中所有的`promise`的状态都达到`resolved`的时候，`all`方法的状态就会变成`resolved`，如果有一个状态变成了`rejected`，那么`all`方法的状态就会变成`rejected`。

     ```javascript
     javascript
     let promise1 = new Promise((resolve,reject)=>{
             setTimeout(()=>{
            resolve(1);
             },2000)
     });
     let promise2 = new Promise((resolve,reject)=>{
             setTimeout(()=>{
            resolve(2);
             },1000)
     });
     let promise3 = new Promise((resolve,reject)=>{
             setTimeout(()=>{
            resolve(3);
             },3000)
     });
     Promise.all([promise1,promise2,promise3]).then(res=>{
         console.log(res);
         //结果为：[1,2,3] 
     })
     ```

     调用`all`方法时的结果成功的时候是回调函数的参数也是一个数组，**这个数组按顺序保存着每一个promise对象`resolve`执行时的值。**

  4. **race()**

     `race`方法和`all`一样，**接受的参数是一个每项都是`promise`的数组，但是与`all`不同的是，当最先执行完的事件执行完之后，就直接返回该`promise`对象的值\[只返回一个]**。如果第一个`promise`对象状态变成`resolved`，那自身的状态变成了`resolved`；反之第一个`promise`变成`rejected`，那自身状态就会变成`rejected`。

     ```javascript
     let promise1 = new Promise((resolve,reject)=>{
             setTimeout(()=>{
            reject(1);
             },2000)
     });
     let promise2 = new Promise((resolve,reject)=>{
             setTimeout(()=>{
            resolve(2);
             },1000)
     });
     let promise3 = new Promise((resolve,reject)=>{
             setTimeout(()=>{
            resolve(3);
             },3000)
     });
     Promise.race([promise1,promise2,promise3]).then(res=>{
             console.log(res);
             //结果：2
     },rej=>{
         console.log(rej)};
     )
     ```

     那么`race`方法有什么实际作用呢？**当要做一件事，超过多长时间就不做了，可以用这个方法来解决**：

     ```javascript
     Promise.race([promise1,timeOutPromise(5000)]).then(res=>{})
     ```

  5. **finally()**

     `finally`方法用于指定不管 Promise 对象最后状态如何，都会执行的操作。该方法是 ES2018 引入标准的。

     ```javascript
     promise
     .then(result => {···})
     .catch(error => {···})
     .finally(() => {···});
     ```

     上面代码中，不管`promise`最后的状态，在执行完`then`或`catch`指定的回调函数以后，都会执行`finally`方法指定的回调函数。

     下面是一个例子，服务器使用 Promise 处理请求，然后使用`finally`方法关掉服务器。

     ```javascript
     server.listen(port)
       .then(function () {
         // ...
       })
       .finally(server.stop);
     ```

     `finally`方法的回调函数不接受任何参数，这意味着没有办法知道，前面的 Promise 状态到底是`fulfilled`还是`rejected`。这表明，`finally`方法里面的操作，应该是与状态无关的，不依赖于 Promise 的执行结果。`finally`本质上是`then`方法的特例：

     ```javascript
     promise
     .finally(() => {
       // 语句
     });
     // 等同于
     promise
     .then(
       result => {
         // 语句
         return result;
       },
       error => {
         // 语句
         throw error;
       }
     );
     ```

     上面代码中，如果不使用`finally`方法，同样的语句需要为成功和失败两种情况各写一次。有了`finally`方法，则只需要写一次。

#### 1. ⭐new操作符的实现原理

```javascript
function objectFactory() {
  let newObject = null;
  //shift() 方法从数组中删除第一个元素，并返回该元素的值 | 
  let constructor = Array.prototype.shift.call(arguments);
  let result = null;
  // 判断参数是否是一个函数
  if (typeof constructor !== "function") {
    console.error("type error");
    return;
  }
  // 新建一个空对象，对象的原型为构造函数的 prototype 对象
  newObject = Object.create(constructor.prototype);
  // 将 this 指向新建对象，并执行函数
  result = constructor.apply(newObject, arguments);
  // 判断返回对象
  let flag = result && (typeof result === "object" || typeof result === "function");
  // 判断返回结果
  return flag ? result : newObject;
}
// 使用方法
objectFactory(构造函数, 初始化参数);
```

* new操作符的实现步骤如下：先设置原型 --> 再绑定 this --> 最后执行构造函数

  * ⭐所以new 的过程其实就是用到了 **<span style="color: rgb(36,91,219); background-color: inherit">Object.create 去连接原型链</span>** + 然后用 **<span style="color: rgb(36,91,219); background-color: inherit">apply/call 让实例 a 使用构造函数 A 的初始化代码</span>**

  ```javascript
  // new 的底层实现
  function myNew(Constructor, ...args) {
      // 1. 创建空对象，原型指向 Constructor.prototype
      // ⭐ 这里就是用 Object.create 连接原型链！
      const obj = Object.create(Constructor.prototype);
      
      // 2. 执行构造函数，把 this 绑定到新对象
      const result = Constructor.apply(obj, args);
      
      // 3. 如果构造函数返回对象，就返回那个对象；否则返回新对象
      return result instanceof Object ? result : obj;
  }

  // 使用
  function Person(name) {
      this.name = name;
  }

  const p1 = new Person('张三');
  const p2 = myNew(Person, '张三');  // 完全等价

  console.log(p1.__proto__ === Person.prototype);  // true
  console.log(p2.__proto__ === Person.prototype);  // true
  ```

  * （1）首先创建了一个新的空对象（比如 temp = {}，对象有一个独立的内存地址0x100）

    * P.S. 此时的temp的constructor是 A 吗？不存在，空对象无自身属性

  * （2）设置原型链：（这一步实际上是用Object.create()的方式创建的）

    * 设置原型，将对象的原型设置为函数的 prototype 对象。将temp 的 \[\[prototype]] 内部属性，让 \_\_proto\_\_ 访问）立即指向构造函数的 prototype 属性

    * 此时 temp 还没有自己的任何属性，知识一个 “空壳”，但原型链已经连好了

      * 此时的 temp 的 constructor 是 A: .constructor 不是自身的属性，而是通过原型链访问的属性。`A.prototype.constructor`。

      * 如果原型链上的 A.prototype 被重写，会丢失默认的 constructor 属性（新对象的{}的constructor指向Object）

  * （3）绑定 this ，<span style="color: rgb(36,91,219); background-color: inherit">于是立即执行了构造函数</span>（有了 this 才能为这个新对象添加属性）

    * [核心逻辑：<span style="color: rgb(36,91,219); background-color: inherit">JS 引擎调用 A.call(temp,...args) &lt;-- this 指向改变的关键</span>](https://ocn7xcch75ib.feishu.cn/wiki/Im0UwDaSsiU5OXkXb2mc2ABWnKh?fromScene=spaceOverview#share-QO5sddfN6o2qNDxx5nTcF2rqn1e)

      * 这行代码把构造函数 A 的 this 强制绑定到 temp 对象（内存地址0x100）

      * 然后执行 A 的函数体（例如 this.name = name）

    * 此时 this 才指向新的对象 temp，所有的 this.xxx 操作都是在修改 temp 本身

  * （4）返回新对象

    * 判断函数的返回值类型，如果是值类型，返回第一步创建的新对象。如果是引用类型，就返回这个引用类型的对象。如果没有 return 对象，返回 temp

  * ⭐上面代码的顺序不能颠倒：比如2和3的顺序不能颠倒，因为某些构造函数（如 class）严重依赖原型链（如 super()的调用）如果3在2上，那么构造函数会立即执行

#### 3. 什么是 DOM 和 BOM?

* BOM是老大，DOM是下属

  > 1. DOM 的最根本的对象 document(DOM的根) 对象也是 BOM 的 window(BOM核心) 对象的子对象
  >
  > 2. window 对象是顶级对象。它代表整个浏览器窗口（或者标签页）。
  >
  > 3. document 对象只是 window 对象下的一个属性

* 关系图

  如果你想操作浏览器本身（比如如何获取网址）用window.location。

  如果你想操作网页内容（比如改文字）,你可以通过window.document去找到具体的HTML元素。因为 document 太昌勇了，我们通常直接写document.getElementById，但本质上有window.xxx

1. DOM（文档对象模型）

   你可以把它想象成： 网页的“内部结构图”或“操作手册”。

   **它关注的是文档内容本身**

   具体来说： 当浏览器加载一个HTML页面时，它会把你写的所有标签（比如 \<div>、\<p>、\<a>）**<u>转换成一个由节点组成的树状结构</u>**。这个树就是DOM。

   它的作用： 让我们可以通过JavaScript（或者其他语言）来读取、修改、删除或添加这个**树上的任何一个节点**。比如，改变一段文字的颜色、弹出一个隐藏的对话框、动态添加一个列表项，都是通过操作DOM来实现的。

2. BOM（浏览器对象模型）

   浏览器这个“应用程序”的“控制面板”。

   **它关注的是浏览器环境本身。**

   浏览器本身也是一个程序，**它有地址栏、历史记录、屏幕尺寸、弹出新窗口的能力等。**&#x42;OM就是把这些和浏览器相关，但又不直接属于页面内容的功能，封装成一系列对象。

   它的作用： 让我们可以**通过JavaScript来控制浏览器的行为**。比如，获取浏览器窗口的宽度、跳转到一个新的网址、弹出提示框、获取用户的操作系统信息等。

#### 6. JavaScript为什么要进行变量提升，它导致了什么问题?

##### 什么是变量提升？

```javascript
console.log(a);  // undefined（不会报错）
var a = 1;
```

##### 解析阶段/执行阶段

* 解析阶段（创建执行上下文）-- 将变量、函数声明提前记录，**<span style="color: rgb(36,91,219); background-color: inherit">变量赋值为undefined，函数整体可用</span>**

* 执行阶段：按照代码顺序执行，到变量赋值语句时才赋值

  ```javascript
  // 解析阶段：var a;  a = undefined
  // 执行阶段：
  console.log(a);  // undefined
  a = 1;           // 此时才赋值为1
  ```

##### 为什么设计变量提升？

* 提高性能：

  * 解析阶段一次性统计变量/函数，为函数生成预编译代码（压缩、优化）

  * 执行时直接分配栈空间，无需重复解析

* 容错性强：

  ```javascript
  a = 1;
  var a;
  console.log(a);  // 1（没有提升会报错）
  ```

##### 带来的问题

* **⭐变量覆盖**

  ```javascript
  ⭐ var 关键字，规则是：变量声明是在编译阶段处理的，和执行阶段（是否进入 if 语句）无关。
  全局 tmp：存储在全局执行上下文的变量环境中。
  局部 tmp：存储在函数 fn 的执行上下文的变量环境中。
  除非局部没有tmp，局部的位置才会

  var tmp = new Date();
  function fn() {
      //var tmp <-- 声明被提升到这里，值为 undefined。
      console.log(tmp);  // undefined（内层tmp提升覆盖外层）
      if (false) {
          var tmp = 'hello world'; //JS引擎看到这里有 var 就 有个 tmp = undefined了↑
      }
  }

  fn();  // undefined
  ```

* 循环变量泄露

  ```javascript
  var tmp = 'hello world';

  for (var i = 0; i < tmp.length; i++) {
      console.log(tmp[i]);
  }

  console.log(i);  // 11（i成为全局变量，未销毁）
  ```

let 和 const 不存在变量提升，可以形成暂时性死区（TDZ）

```javascript
    console.log(tmp);  // ReferenceError（TDZ）
    let tmp = 'hello'; 
}
```

##### （2）Map 和 Set 这两种强引用简述

* ⭐首先：强引用 和 弱引用  是什么？

  强引用（Map/Set/普通对象）：只要引用存在，对象永不回收：强引用只要对象可以达到（reacheable)，那么JS的GC无法自动回收，所以强引用必须主动 map.delete("key") 或 map = null 才可以。

  弱引用（WeakMap/WeakSet）：对象若无其他强引用，GC可自动回收 -- 不阻止垃圾回收

  ```javascript
  let obj = { name: "小明" };
  let map = new Map();
  map.set(obj, "这是小明的数据"); // Map 对 obj 持有强引用

  obj = null; // 断开 obj 的强引用
  // 但 Map 内部仍持有 { name: "小明" } 的强引用 → 对象不会被 GC 回收！
  除非你手动 delete,buran zheg duixiang {name:'小明'} 依然存在于内存中

  ```

  ```javascript
  let obj = { name: "小红" };
  let weakMap = new WeakMap();
  weakMap.set(obj, "这是小红的数据"); // WeakMap 对 obj 的键是弱引用

  obj = null; // 断开 obj 的强引用
  // 此时 { name: "小红" } 对象无其他强引用 → 下次 GC 运行将被回收
  // WeakMap 中对应的键值对自动消失，无需手动删除！
  ```

#### 9. JavaScript脚本延迟加载的方式有哪些?

阻塞的原因：当我们说"**阻塞页面解析**"，指的是：浏览器在解析HTML（构建DOM树）时，如果遇到\<script>标签，**会停下来**去加载并执行JavaScript，执行完后再继续解析HTML。这会导致页面显示延迟。

```xml
<!-- 普通script：会阻塞页面 -->
<script src="large.js"></script>
<p>这段文字要等large.js加载执行完才能显示</p>
```

* defer 属性：给 js 脚本添加 defer，会让脚本的加载与文档的解析同步执行，然后在文档解析完成后再执行脚本文件，这样就能使页面渲染不被阻塞 | 且多个defer脚本会按照顺序执行。

  ```xml
  <!-- 示例 -->
  <script defer src="1.js"></script>  <!-- 下载不阻塞 -->
  <script defer src="2.js"></script>  <!-- 下载不阻塞 -->
  <p>这段文字会立即显示，不等脚本</p>
  <!-- HTML解析完成后，先执行1.js，再执行2.js -->
  ```

* Async：使脚本异步加载，不会阻塞页面解析，当脚本加载完成后立即执行js脚本，但是如果文档没有解析完成同样会阻塞，多个async脚本的执行顺序是不可预测的，一般不会按照代码的顺序依次执行

  ```javascript
  <script async src="script.js"></script>
  <!-- 示例 -->
  <script async src="1.js"></script>  <!-- 下载不阻塞，但下载完就执行 -->
  <script async src="2.js"></script>  <!-- 可能比1.js先执行 -->
  <p>如果1.js先下载完，它会先执行（可能阻塞页面）</p>
  ```

* 动态创建 DOM 标签方式：可以对文档的加载事件进行监听，当文档加载完成后再动态地创建script标签来引入 js 脚本

* setTimeout 延迟方法，让定时器延迟加载js脚本文件

* 让JS最后加载：将 js 脚本放在文档的底部，来使 js 脚本尽可能的在最后加载执行

#### 12. ES6模块与CommonJS模块有什么异同?

ES6 Module和CommonJS模块的区别：&#x20;

* CommonJS是对模块的**浅拷贝**，ES6 Module是对模块的引用，**即ES6 Module只存只读，不能改变其值，也就是指针指向不能变，类似const**；<-- 难怪都爱用 ⭐ES6

* import \[ES6模块的语法] 的接口是read-only（只读状态），不能修改其变量值。 即不能修改其变量的指针指向，但可以改变变量内部指针指向，可以对commonJS对重新赋值（改变指针指向），但是对ES6 Module赋值会编译报错。&#x20;

  ```javascript
  // commonjs.js
  let count = 1;
  let user = { name: '张三', age: 25 };

  function add() {
      count++;
      user.age++;
  }

  module.exports = { count, user, add };

  // main.js
  const obj = require('./commonjs.js');

  console.log(obj.count);  // 1
  console.log(obj.user.age); // 25

  obj.add();  // 修改源模块的值

  console.log(obj.count);  // 1（⚠️ 基本类型没变）
  console.log(obj.user.age); // 26（✅ 对象内部变了）

  // 甚至可以重新赋值
  obj.count = 100;  // ✅ 可以修改（这是拷贝来的副本）
  obj.user = { name: '李四' }; // ✅ 可以修改
  ```

ES6 Module和CommonJS模块的共同点：&#x20;

* CommonJS和ES6 Module都可以对引入的对象进行赋值，即对对象内部属性的值进行改变。

#### 13. 如何判断一个对象是否属于某个类?

* 第一种方式，使用 instanceof 运算符来判断构造函数的 prototype 属性 是否出现在对象的原型链中的任何位置。

* 第二种方式，通过对象的 constructor 属性来判断，对象的 constructor 属性指向该对象的构造函数，但是这种方式不是很安全，**因为 constructor 属性可以被改写**。

* 第三种方式，如果需要判断的是某个**内置的引用类型**的话，可以使用 Object.prototype.toString() 方法配合 call 来打印对象的\[\[Class]] 属性来进行判断。

  * 为什么需要用call？因为很多对象可能重写了 toString 方法，需要用 call 强制调用原始的 Object.prototype.toString：

  ```javascript
  // 基础用法
  console.log(Object.prototype.toString.call([]));  
  // "[object Array]"

  console.log(Object.prototype.toString.call({}));  
  // "[object Object]"

  console.log(Object.prototype.toString.call(new Date()));  
  // "[object Date]"
  ```

#### 14. for...in 和 for...of 的区别

* for… in **会遍历对象的整个原型链**，性能**非常差不推荐使用 || 仅限对象**

  ```typescript
  const object = { a: 1, b: 2, c: 3 };

  for (const property in object) {
    console.log(`${property}: ${object[property]}`);
  }

  // Expected output:
  // "a: 1"
  // "b: 2"
  // "c: 3"
  ```

* for…of 是ES6新增的遍历方式，允许遍历一个含有iterator接口的数据结构（数组、对象等）并且返回各项的值，和ES3中的for…in的区别如下，且**for…of 只遍历当前对象不会遍历原型链；**

  * **for…of 遍历获取的是对象的键值，for…in 获取的是对象的键名；**

  * 对于数组的遍历，for…in 会返回数组中所有可枚举的属性(包括原型链上可枚举的属性)，**for…of 只返回数组的下标对应的属性值；**

  ```c++
  const array1 = ["a", "b", "c"];

  for (const element of array1) {
    console.log(element);
  }

  // Expected output: "a"
  // Expected output: "b"
  // Expected output: "c"
  ```

**总结：**&#x66;or...in 循环<u>主要是为了遍历对象</u>而生，不适用于遍历数组（也不适用map）；**<span style="color: rgb(36,91,219); background-color: inherit">for...of 循环可以用来遍历数组、类数组对象，字符串、Set、Map 以及 Generator 对象。</span>**

#### 17. Unicode、UTF-8、UTF-16、UTF-32的区别?

* Unicode：字符集（字典--文字数字对应表），给每个字符唯一的编号，是一种标准

* UTF-8/16/32：上面那种标准下衍生出的编码规则（存储格式），决定如何存储这些编号

* 面试常见问题：

  1. UTF-8 为什么最流行？

     1. 兼容 ASCII, 英文内容（HTML/CSS/JS) 占优

     2. 无字节序问题，适合网络传输

  2. 中文用哪个好？

     1. UFT-8：中文占3字节

     2. UTF-16：中文占2字节

     3. 纯中文场景是UTF-16适合

  3. UTF-16 的代理对机制

     1. 基本平面（U+0000 - U+FFFF）：2字节

     2. 辅助平面（U+10000以上）：拆成两个2字节（代理对）

#### 19. escape,encodeURI,encodeURIComponent的区别

* 消除代码运行的不安全之处，保证代码运行的安全；

* 为未来新版本的 Javascript 做好铺垫。

只要函数参数使用了默认值、解构赋值、或者扩展运算符，那么函数内部就不能显式设定为严格模式，否则会报错

#### 24. 如何使用for...of遍历对象

for…of是作为ES6新增的遍历方式，允许遍历一个含有iterator接口的数据结构（数组、）并且返回各项的值，普通的对象用for..of遍历是会报错的。

如果需要遍历的对象是类数组对象，用Array.from转成数组即可。

```javascript
var obj = {
    0:'one',
    1:'two',
    length: 2
};
obj = Array.from(obj);
for(var k of obj){
    console.log(k)
}
```

如果不是类数组对象，就给对象添加一个\[Symbol.iterator]属性，并指向一个迭代器即可。

```javascript
//方法一：
var obj = {
    a:1,
    b:2,
    c:3
};
//这是 Symbol 键，如果是字符串键的话就加""
obj[Symbol.iterator] = function(){
        var keys = Object.keys(this);
        var count = 0;
        return {
                next(){
                        if(count<keys.length){
                                return {value: obj[keys[count++]],done:false};
                        }else{
                                return {value:undefined,done:true};
                        }
                }
        }
};

for(var k of obj){
        console.log(k);
}


// 方法二
var obj = {
    a:1,
    b:2,
    c:3
};
obj[Symbol.iterator] = function*(){
    var keys = Object.keys(obj);
    for(var k of keys){
        yield [k,obj[k]]
    }
};

for(var [k,v] of obj){
    console.log(k,v);
}
```

#### 25. ajax和axios的区别（看不太懂说实话）

##### 什么是 Ajax？

概念： Asynchronous javascript and xml 不是一种技术，而**是一种思想或者模式**

核心：它的底层依赖于浏览器提供的 XMLHttpRequest (XHR) 对象

特点：通过 XHR 实现网页的**局部刷新，无需重新加载整个页面**

注：我们常说的用jQuery的$.ajax，其实是对原生 XHR 的封装

缺点：

* 本身是针对MVC编程，不符合前端MVVM浪潮

* 不符合关注分离的原则

* 基于事件异步模型不够友好

##### Fetch

fetch号称是Ajax的替代品，在ES6时代出现的，使用了ES6中的promise对象。Fetch是基于promise设计的。Fetch的代码结构比ajax简单很多。**fetch不是ajax的进一步封装，而是原生js，没有使用XMLHttpRequest对象**。

etch的优点：

* 语法简洁，更加语义化

* 基于标准 Promise 实现，支持 async/await

* 更加底层，提供的API丰富（request, response）

* 脱离了XHR，是ES规范里新的实现方式

fetch的缺点：

* fetch只对**网络请求报错，对400，500都当做成功的请求，服务器返回 400，500 错误码时并不会 reject，只有网络错误这些导致请求不能完成时，fetch 才会被 reject。**

* fetch默认不会带cookie，需要添加配置项： fetch(url, {credentials: 'include'})

* fetch不支持abort，不支持超时控制，使用setTimeout及Promise.reject的实现的超时控制并不能阻止请求过程继续在后台运行，造成了流量的浪费

* fetch没有办法原生监测请求的进度，而XHR可以



##### Axios

Axios 是一种基于Promise封装的HTTP客户端，其特点如下：

* 浏览器端发起XMLHttpRequests请求

* node端发起http请求

* 支持Promise API

* 监听请求和返回

* 对请求和返回进行转化

* 取消请求

* 自动转换json数据

* 客户端支持抵御XSRF攻击

#### 1. 对象创建的方式有哪些？

* 字面量/Object 构造函数 <-- 表达式

  * Let obj = {name:'a;}  let obj = new Object()

* 工厂模式

  * 方式：用函数封装创建细节，返回新的对象

  * 优点：解决代码重复

  * 缺点：无法识别对象类型（不知道对象是谁的实例，都是Object）

  ```javascript
  // 工厂函数：专门用来生产对象
  function createPerson(name, age, job) {
      // 1. 创建一个新对象（原材料）
      const obj = {};
      
      // 2. 添加属性和方法（加工）
      obj.name = name;
      obj.age = age;
      obj.job = job;
      obj.sayName = function() {
          console.log('我的名字是：' + this.name);
      };
      
      // 3. 返回对象（出厂）
      return obj;
  }

  // 使用工厂生产对象
  const person1 = createPerson('张三', 25, '工程师');
  const person2 = createPerson('李四', 30, '设计师');

  person1.sayName(); // 我的名字是：张三
  person2.sayName(); // 我的名字是：李四

  console.log(person1); // {name: "张三", age: 25, job: "工程师", sayName: ƒ}
  ```

* 构造函数模式

  * 方式：用 new 调用函数

  * 优点：解决了类型识别问题（通过 constructor 或 instanceof）

  * 缺点：方法不能复用（每个实例上的同名方法都是不同的函数对象，浪费内存）

* 原型模式

  * 方式：将属性和方法都挂载到构造函数的 prototype 上

  * 优点：解决了方法复用的问题

  * 缺点：**引用值属性会被所有实例共享**，所以不适合放引用类型的属性，且无法传参初始化

    ```javascript
    function Person() {}

    // 把属性都放在原型上
    Person.prototype = {
        constructor: Person,
        name: '默认名字',
        hobbies: ['读书', '跑步']  // 这是一个引用类型（数组）
    };

    const p1 = new Person();
    const p2 = new Person();

    // p1 修改自己的爱好
    p1.hobbies.push('打游戏');

    console.log(p1.hobbies); // ['读书', '跑步', '打游戏']
    console.log(p2.hobbies); // ['读书', '跑步', '打游戏']  <-- p2 也被改了！
    ```

* 组合模式

  * 方式：引用值共享 - 把属性放在构造函数里，方法放在原型上。解决了上面的问题

  * 优点：不启用共享属性了，让每个实例都有自己的属性

* 动态原型模式

  * 方式：将原型初始化逻辑放到构造函数内部，通过检查方法是否存在来决定是否挂载原型方法

  * 优点：解决了组合模式的封装问题，视觉上更紧凑

  ```javascript
  function Person(name, hobbies) {
      // 构造函数内定义实例属性 —— 解决了引用值共享的问题！
      this.name = name;
      this.hobbies = hobbies || ['读书', '跑步'];

      // 动态添加原型方法（仅在第一次调用时添加）
      if (typeof this.sayName !== 'function') {
          Person.prototype.sayName = function() {
              console.log(this.name);
          };
      }
  }

  const p1 = new Person('张三', ['读书', '跑步']);
  const p2 = new Person('李四', ['游泳', '跑步']);

  p1.hobbies.push('打游戏');

  console.log(p1.hobbies); // ['读书', '跑步', '打游戏']
  console.log(p2.hobbies); // ['游泳', '跑步']  <-- 没被影响，因为 hobbies 在实例上
  ```

* 寄生构造函数模式

  * 方式：类似工厂模式，它看起来像构造函数（用了 `new`），但实际上和工厂模式一样，返回的是自己构造的新对象，导致 `instanceof` 失效。

  * 用途：在不修改原构造函数的前提下，为对象添加额外方法（例如给Array 添加一个特殊方法）

  * 缺点：同样无法识别对象类型

  ```javascript
  function SpecialArray() {
      // 当调用 SpecialArray(1, 2, 3, 4) 时
      // arguments 就是：{ 0: 1, 1: 2, 2: 3, 3: 4, length: 4 }
      console.log(arguments); // Arguments(4) [1, 2, 3, 4]
      
      // 1. 创建空数组
      const arr = new Array();  // arr = []
      
      // 2. 关键步骤：把 arguments 里的所有参数添加到 arr
      // arguments 是 [1, 2, 3, 4]
      arr.push.apply(arr, arguments);//this 指向arr本身
      // 等价于：arr.push(1, 2, 3, 4)
      // 现在 arr = [1, 2, 3, 4]
      
      // 3. 添加 sum 方法
      arr.sum = function() {
          // this 指向 arr 本身，因为之后我们调用方法，也是用arr.sum()
          return this.reduce((prev, curr) => prev + curr, 0);
      };
      
      return arr;
  }

  const arr = new SpecialArray(1, 2, 3, 4);
  ```

#### 2. 对象继承的方式有哪些？⭐（你好好理解理解，挺好玩估计和ES6底层有关）

##### （1）第一种是以原型链的方式来实现继承

但是这种实现方式存在的缺点是，在包含有引用类型的数据时，会被所有的实例对象所共享，容易造成修改的混乱。还有就是在创建子类型的时候不能向超类型传递参数。

```javascript
// 超类型
function Parent() {
    this.hobbies = ['读书', '跑步'];  // 引用类型
}
Parent.prototype.sayHi = function() {
    console.log('你好');
};

// 子类型
function Child() {}

// 原型链继承：将父类的实例赋值给子类的原型
Child.prototype = new Parent();

const child1 = new Child();
const child2 = new Child();

child1.hobbies.push('游戏');

console.log(child1.hobbies); // ['读书', '跑步', '游戏']
console.log(child2.hobbies); // ['读书', '跑步', '游戏']  ❌ 被共享了

// 无法向父类传参
const child3 = new Child('张三'); // 参数传不进去
```

##### （2）第二种方式是使用借用构造函数的方式

这种方式是通过在子类型的函数中调用超类型的构造函数来实现的，这一种方法解决了不能向超类型传递参数的缺点，但是它存在的一个问题就是无法实现函数方法的复用，并且超类型原型定义的方法子类型也没有办法访问到。

```javascript
function Parent(name) {
    this.name = name;
    this.hobbies = ['读书', '跑步'];
}
Parent.prototype.sayHi = function() {
    console.log('你好');
};

function Child(name) {
    // 借用构造函数：调用父类构造函数
    Parent.call(this, name);  // 可以传参了！
}

const child1 = new Child('张三');
const child2 = new Child('李四');

child1.hobbies.push('游戏');
console.log(child1.hobbies); // ['读书', '跑步', '游戏']
console.log(child2.hobbies); // ['读书', '跑步']  ✅ 属性独立了

child1.sayHi(); // ❌ 报错：child1.sayHi is not a function
// 无法访问父类原型上的方法

// 每个实例都有自己的方法副本（如果有方法定义在构造函数内）
function ParentWithMethod(name) {
    this.name = name;
    this.sayHi = function() {  // 方法定义在构造函数内
        console.log('你好' + this.name);
    };
}
function ChildWithMethod(name) {
    ParentWithMethod.call(this, name);
}
const c1 = new ChildWithMethod('张三');
const c2 = new ChildWithMethod('李四');
console.log(c1.sayHi === c2.sayHi); // false ❌ 方法无法复用
```

##### （3）组合继承

组合继承是将原型链和借用构造函数组合起来使用的一种方式。通过借用构造函数的方式来实现类型的属性的继承，通过将子类型的原型设置为超类型的实例来实现方法的继承。这种方式解决了上面的两种模式单独使用时的问题，但是由于我们是以超类型的实例来作为子类型的原型，所以调用了两次超类的构造函数，造成了子类型的原型中多了很多不必要的属性。

```javascript
function Parent(name) {
    this.name = name;
    this.hobbies = ['读书', '跑步'];
    console.log('Parent 构造函数被调用');
}
Parent.prototype.sayHi = function() {
    console.log('你好，我是' + this.name);
};

function Child(name, age) {
    Parent.call(this, name);  // 第1次调用 Parent
    this.age = age;
}

// 第2次调用 Parent
Child.prototype = new Parent();  // ❌ 多余的调用
Child.prototype.constructor = Child;

const child = new Child('张三', 18);
// 控制台输出：
// Parent 构造函数被调用  (第1次：new Parent() 设置原型时)
// Parent 构造函数被调用  (第2次：new Child() 内部调用)

console.log(child.name);  // '张三' (来自实例)
console.log(child.age);   // 18

// Child.prototype 上有一份多余的属性
console.log(Child.prototype.name);  // undefined (因为没传参)
console.log(Child.prototype.hobbies); // ['读书', '跑步'] (多余的)
```

##### （4）第四种方式是原型式继承

原型式继承的主要思路就是基于已有的对象来创建新的对象，实现的原理是，向函数中传入一个对象，然后返回一个以这个对象为原型的对象。这种继承的思路主要不是为了实现创造一种新的类型，只是对某个对象实现一种简单继承，ES5 中定义的 Object.create() 方法就是原型式继承的实现。缺点与原型链方式相同。

```javascript
// 原型式继承的核心实现
function object(o) {
    function F() {}
    F.prototype = o;
    return new F();
}

// 或者直接用 ES5 的 Object.create
const person = {
    name: '默认姓名',
    hobbies: ['读书', '跑步'],
    sayHi: function() {
        console.log('你好');
    }
};

// 基于 person 对象创建新对象
const person1 = object(person);
const person2 = Object.create(person);  // 两种方式等价

person1.name = '张三';
person1.hobbies.push('游戏');

console.log(person1.name);  // '张三' (实例属性)
console.log(person2.name);  // '默认姓名' (原型上的)
console.log(person2.hobbies); // ['读书', '跑步', '游戏'] ❌ 引用被共享

// 简单继承，无需定义构造函数
const child = Object.create(person, {
    age: {
        value: 18,
        writable: true,
        enumerable: true
    }
});
console.log(child.name);  // '默认姓名' (来自原型)
console.log(child.age);   // 18 (自己的属性)
```

##### （5）第五种方式是寄生式继承

寄生式继承的思路是创建一个用于封装继承过程的函数，通过传入一个对象，然后复制一个对象的副本，然后对象进行扩展，最后返回这个对象。这个扩展的过程就可以理解是一种继承。这种继承的优点就是对一个简单对象实现继承，如果这个对象不是自定义类型时。缺点是没有办法实现函数的复用。

```javascript
// 寄生式继承的核心函数
function createAnother(original) {
    const clone = Object.create(original);  // 创建副本
    clone.sayHi = function() {  // 扩展：添加方法
        console.log('你好，我是' + this.name);
    };
    clone.introduce = function() {
        console.log('我的爱好有：' + this.hobbies.join('、'));
    };
    return clone;
}

const person = {
    name: '默认姓名',
    hobbies: ['读书', '跑步']
};

const person1 = createAnother(person);
person1.name = '张三';

const person2 = createAnother(person);
person2.name = '李四';

person1.sayHi();  // 你好，我是张三
person1.introduce(); // 我的爱好有：读书、跑步

// 问题：方法无法复用
console.log(person1.sayHi === person2.sayHi); // false ❌ 每个实例都有自己的方法副本

// 引用类型仍然会被共享
person1.hobbies.push('游戏');
console.log(person2.hobbies); // ['读书', '跑步', '游戏'] ❌ 还是共享
```

##### （6）第六种方式是寄生式组合继承

组合继承的缺点就是使用超类型的实例做为子类型的原型，导致添加了不必要的原型属性。寄生式组合继承的方式是使用超类型的原型的副本来作为子类型的原型，这样就避免了创建不必要的属性

```javascript
// 寄生组合继承的核心函数
function inheritPrototype(Child, Parent) {
    // 创建父类原型的副本
    const prototype = Object.create(Parent.prototype);
    // 修正 constructor 指向
    prototype.constructor = Child;
    // 设置子类的原型
    Child.prototype = prototype;
}

function Parent(name) {
    this.name = name;
    this.hobbies = ['读书', '跑步'];
    console.log('Parent 构造函数被调用');
}
Parent.prototype.sayHi = function() {
    console.log('你好，我是' + this.name);
};

function Child(name, age) {
    Parent.call(this, name);  // 只调用1次 Parent
    this.age = age;
}

// 关键：使用寄生组合继承
inheritPrototype(Child, Parent);

// 还可以继续在子类原型上添加方法
Child.prototype.sayAge = function() {
    console.log('我' + this.age + '岁');
};

const child1 = new Child('张三', 18);
const child2 = new Child('李四', 20);
// 控制台输出：Parent 构造函数被调用 (只调用1次)
// Parent 构造函数被调用 (只调用1次)

child1.hobbies.push('游戏');
console.log(child1.hobbies); // ['读书', '跑步', '游戏']
console.log(child2.hobbies); // ['读书', '跑步']  ✅ 属性独立

child1.sayHi();   // 你好，我是张三  ✅ 方法复用
child2.sayHi();   // 你好，我是李四
child1.sayAge();  // 我18岁

// 验证原型链
console.log(child1 instanceof Child);   // true
console.log(child1 instanceof Parent);  // true
console.log(Child.prototype.constructor === Child); // true

// 原型上没有多余的属性
console.log(Child.prototype.hasOwnProperty('name')); // false ✅
console.log(Child.prototype.hasOwnProperty('hobbies')); // false ✅
// 只有方法在原型上
console.log(Child.prototype.hasOwnProperty('sayAge')); // true
```

* 总结：寄生组合继承是 JavaScript 中最理想的继承方式，它：

* ✅ 属性独立（借用构造函数）

* ✅ 方法复用（原型链）

* ✅ 只调用一次父类构造函数（寄生）

* ✅ 原型链干净，没有多余属性（组合）

* ✅ 保持了 instanceof 的正常工作

* 这也是 ES6 `class` 继承的底层实现原理。

#### P.S. 补充串行/并行/并发/同步异步

##### 串行 Serial

1. 任务按顺序执行，依赖前一个任务的结果

2. 机制：执行上下文栈（单线程顺序执行代码）

3. 示例：普通函数调用（如 functionA(); functionB();）必须等 functionA 执行完才能执行 functionB

##### 并行 Parallel

1. 多个任务在物理上同时进行（依赖多线程/多进程）

2. 机制：Web Worker（独立线程）或 Node.js 子进程（独立进程）

3. 示例：主线程处理 UI, Worker 线程计算大数据，两者同时运行

##### 并发 Concurrency

1. 任务在宏观上交替执行（单线程通过事件循环切换任务）

2. 机制：事件循环（Event Loop）+ 任务队列（宏任务/微任务）

3. 示例：setTimeout 回调（宏任务） 与 Promise.then （微任务）在主线程空闲时交替执行。

##### 同步 Synchronous

1. 阻塞主线程，必须等待任务完成后才能继续执行后面的代码

2. 机制：执行上下文栈（直接压入栈执行）

3. 示例：alet()、for()循环（阻塞线程直到执行完毕）

##### 异步 Asynchronous&#x20;

1. 异步点发起任务后，不阻塞主线程在后台执行，等到执行完毕，回调函数被放入任务队列 （宏队列/微队列）等待主线程空闲时执行。fetch(url).then(response => {// 回调进入微任务队列，主线程空闲时执行})

2. 机制：任务队列（宏任务。微任务队列）+ 事件循环

3. 示例：setTimeout（宏任务）、Promise（微任务）、fetch（网络请求）

#### 1. 对闭包的理解

* 闭包&#x662F;**<u>指一个函数能够访问并记住其词法作用域（lexical scope）外的变量</u>**，即使这个函数在它的外部作用域之外执行。

* 创建方式：在一个函数内创建另一个函数，内部函数可以访问外部函数的局部变量

* 闭包的本质：

  1. 闭包保持对变量的引用，而不是对固定内存地址的引用

  2. 引用而非值：闭包记住了外部词法环境的引用，不是单单是值引用！

  3. 作用域链的词法/静态绑定：函数的作用域链在函数定义时就已经确定，而不是在调用时确定。

* 闭包两大用途

  * ✅访问内部变量：使我们在函数外部能够访问到函数内部的变量。通过使用闭包，可以通过在外部调用闭包函数，从而在外部访问到函数内部的变量，可以使用这种方法来创建私有变量。

  * ✅ 延长变量生命周期：使已经运行结束的函数上下文中的变量对象继续留在内存中，因为闭包函数保留了这个变量对象的引用，所以这个变量对象不会被回收。

  * ✅ 常用于数据封装、私有变量、函数工厂等场景

    ```javascript
    function outer() {   
        let count = 0; // 外部变量   
        return function inner() { // 闭包（inner 能访问 count）     
            count++;     
            return count;   
        }; 
    }  
    //outer()只执行了一次，返回了 inner 函数
    const counter = outer();//只赋值一次outer()
    //下面这个都是调用inner()
    console.log(counter()); // 1
    console.log(counter()); // 2
    ```

### 🔴 考察很多

#### 1. 浏览器的垃圾回收机制

##### 什么是内存泄露

只要程序提出要求，操作系统或者运行时（runtime）就必须供给内存。

对于持续运行的服务进程（demo），必须及时释放不再用到的内存，否则，内存占用越来越高，轻则影响系统性能，重则导致进程崩溃。

也就是说，**不再用到的内存，如果没有及时释放，就叫做内存泄露（memory leak）**

##### JS重的垃圾回收机制

浏览器的 javaScript 具有自动垃圾回收机制（GC: Garbage Collection） ，也就是执行环境会负责管理代码执行过程中使用的内存，其原理是：**垃圾收集器会定期（周期性）找出那些不再继续使用的变量，然后释放其内存。**

但是这个过程不是实时的，因为开销比较大并且GC时会停止响应其他操作，所以垃圾回收器会按照固定的事件间隔周期性执行

不再使用的变量也就是生命周期结束的变量，当然只可能是局部变量，全局变量的生命周期直至浏览器卸载页面才会结束。

局部变量只在函数的执行过程中存在，而在这个过程中会为局部变量在栈或堆上分配相应的空间，以存储它们的值，然后在函数中使用这些变量，直至函数结束，**而闭包中由于内部函数的原因，外部函数并不能算是结束。**

```javascript
function fnl() {
  var obj = { name: "zhangsan", age: 10 };
}
function fn2() {
  var obj = { name: "zhangsan", age: 10 };
  return obj; //这里return出来了，就不会被释放
}
var a = fn1();
var b = fn2();

```

当函数 fn1 被调用时，会进入 fn1 的执行环境，并开辟一块内存来存储对象 { name: 'zhangsan', age: 10 }。当函数调用结束后，执行环境退出，这块内存就会被 JavaScript 引擎中的垃圾回收器自动释放。

而在 fn2 被调用的过程中，返回的对象被全局变量 b 引用，因此该对象依然被保持，不会被释放。

这里就出现了一个问题：如何判断哪些变量是“不再有用的”？

垃圾收集器必须跟踪变量的使用情况，对于不再有用的变量进行标记，以便在适当的时机回收其占用的内存。标记无用变量的策略因实现方式不同而有所区别，通常有两种主要策略：

* **标记清除（较为常用的垃圾回收方式）**

  * 垃圾回收器运行时，会给存储在内存中的所有变量都加上标记（这是初始状态，假设所有变量都是待回收的）。

  * 然后，它会去掉**环境中的变量：全局变量**（如 window.name、globalVar）,**当前正在执行的函数里的局部变量**（函数还没执行完）以及**被环境中的变量引用的变量：比如闭包这种通过上面的变量能间接访问到的变量**的标记 。这一步是关键，它标记出所有“存活”的、仍在使用的变量。

  * 此时，仍然持有标记的变量（即没有被步骤2“去掉标记”的变量），就被认为是准备删除的变量。因为它们已经无法从环境中访问到了。

  * 最后，垃圾回收器销毁那些带标记的值，回收它们占用的内存

  ```javascript
  1. 垃圾回收在运行的时候就会给存储在内存中的所有变量加上标记（当然，可以使用任何标记方式）
  2. 它会去掉环境中的闭包/还未执行完的变量（环境中的变量以及被环境中的变量引用的变量的标记）
  3. 最后仍然持有的变量就是待删除的变量
   function test(){
       var a = 10; //被标记，进入环境
       var b = 20; //被标记，离开环境
   }
   test(); //执行完毕后，a,b 又被标记为离开环境，被回收

  ```

* 引用计数（不常用）

#### 2. 哪些情况会导致内存泄漏

以下四种情况会造成内存的泄漏：

* **意外的全局变量：**&#x7531;于使用**未声明的变量（没用let/var/const）**，而意外的创建了一个全局变量，而使这个变量一直留在内存中无法被回收。

* **被遗忘的计时器或回调函数：**&#x8BBE;置了 setInterval 定时器，而忘记取消它，如果循环函数有对外部变量的引用的话，那么这个变量会被一直留在内存中，而无法被回收。

  ```javascript
  let data = {
    name: 'test',
    array: new Array(1000000) // 占用大量内存
  };

  // 设置了定时器，但没有清理
  setInterval(() => {
    console.log(data.name); // 定时器持续引用 data
  }, 1000);

  // data 因为被定时器引用，即使不需要了也无法被回收
  ```

* **脱离 DOM 的引用：**&#x83B7;取一个 DOM 元素的引用，而后面这个元素被删除，由于一直保留了对这个元素的引用，所以它也无法被回收。

  ```javascript
  // 获取 DOM 元素引用
  let button = document.getElementById('myButton');
  let parent = document.getElementById('parent');

  // 移除 DOM 元素
  parent.removeChild(button);
  // 或者
  document.body.innerHTML = '';

  // 但 button 变量仍然引用着这个 DOM 元素
  // 导致 DOM 元素无法被垃圾回收
  button = null; // 需要手动释放引用
  ```

* **闭包：**&#x4E0D;合理的使用闭包，从而导致某些变量一直被留在内存当中。

  ```javascript
  function outer() {
    let largeData = new Array(1000000).fill('data'); // 大数组
    
     // 只返回需要的数据，而不是整个 largeData  
     let neededValue = largeData.length;
     
    function inner() {
      // 这个函数引用了 largeData
      console.log(largeData.length); //可以尽量只返回需要的数据来减少引用
    }
    
    // 返回 inner 函数，并且长时间持有
    return inner;
  }

  // 获取 inner 函数，但 largeData 无法被回收
  let fn = outer();

  // 即使不需要 largeData 了，它仍然存在
  // 因为 fn 保持着对它的引用

  // 使用完后，将引用置为 null
  fn = null; // largeData 现在可以被垃圾回收了
  ```





# 十一、事件循环的理解

事件循环是什么？：是实现单线程非阻塞的方法。

JS中，所有的任务都可以分为

**（1）异步 = 发起一个任务后不用等它完成，可以继续做其他事，任务完成后会通知你。【比如api处理，比如ELMessage组件的Promise处理，其实是一个性质——&#x20;**&#x8F93;入过程是同步的，异步性体现在 “等待用户确认 / 取消”**】**

**（2）同步：必须等上一步完成才能做下一步（排队）**

（3）so:为什么JS是单线程的但是可以异步：**JavaScript自己（主线程）是单线程的，但它的运行环境（浏览器/Node.js）是多线程的！--所以异步的过程不只是JS执行的，中间会有浏览器/NodeJS的配合**

![](images/JS面筋（76+2\)-image-41.png)

![](images/JS面筋（76+2\)-image-42.png)

事件循环的执行流程如下：

1. **执行同步代码**（所有同步任务按顺序执行完）

2. **清空微任务队列**（执行 `Promise.then`、`queueMicrotask` 等微任务）

3. 每**执行一个宏任务**（例如 `setTimeout` 回调），然后回到步骤 2，检查有没有微任务，有的话就执行，循环往复。

作者：东望

链接：https://juejin.cn/post/7487998346838179879

来源：稀土掘金

从上面我们可以看到，同步任务进入主线程，即主执行栈，异步任务进入任务队列，主线程内的任务执行完毕为空，会去任务队列读取对应的任务，推入主线程执行。上述过程的不断重复就事件循环

#### 宏任务 & 微任务

执行优先级：**微队列 > 宏队列**

##### 微任务：**定义** ：微任务是异步任务中优先级较高的任务队列，通常由 JavaScript 引擎直接处理

其实正如🍔佬所说，promise本身不是异步的，只是

* Promise 的 then/catch/finally 回调

* MutationObserver 回调

* Object.observe（已废弃：Proxy 对象替代）

* async/await 中的 await 后面的代码

微任务会在当前宏任务执行完后立即执行，不会等到下一个事件循环

##### **宏任务：定义** ：宏任务是异步任务中优先级较低的任务队列，通常由浏览器或 Node.js 的运行环境提供支持

* DOM 事件回调（如click, input 等事件触发后，对应的回调函数会被加入宏队列）

* script（外层的同步代码标签）

* ajax 回调

* 定时器回调（setTimeout/setInterval）

* requestAnimationFrame

* I/O 队列（文件读写等）



##### Async & await

.then和await其实都是为了成功拿到相应的数据，.then 是 "你完成后通知我"（回调模式） await 是 "我等你完成后继续"（同步写法模式）

.then 只是注册回调，从不阻塞 | await（阻塞当前函数）

1. **Promise的目的是更好地处理异步请求的结果，通过then，catch，finally，await...**

2. [**https://blog.csdn.net/weixin\_45811256/article/details/123638582**](https://blog.csdn.net/weixin_45811256/article/details/123638582)

3. `async` 函数默认返回 `resolved` Promise，但通过 `throw` 或返回 `rejected Promise` 也能返回 `rejected` Promise。

![](images/JS面筋（76+2\)-FpgYbBGigoT0fuxGpzDcKK2un4c.png)

4. 那么要想获取到async 函数的执行结果，就要调用promise的then 或 catch 来给它注册回调函数

###### await：是then的语法糖，await的写法让异步代码看起来像同步的

**await会"阻塞"它所在的async函数，但释放了JavaScript主线程去执行其他代码！**

1. 如果它等到的是一个Promise对象，await就忙起来了，它会阻塞函数后面的代码，等着Promise对象resolve/reject，然后得到resolve/reject的值，作为await表达式的运算结果。

2. 如果 await 等待的是一个非 Promise 对象，那么V8 会隐式地将该对象包装成一个已经 resolve 的 Promise 对象.

# 十二、JS本地存储

#### 1. 方式

##### Javascript 本地缓存的方法主要有以下四种

* **独立机制 cookie**（兼容性好，可设置过期时间，但每次请求都会携带（所以有被窃取的风险），影响性能

  * 定义：Cookie，类型为「小型文本文件」，指某些网站为了辨别用户身份而储存在用户本地终端上的数据。是为了解决 HTTP无状态导致的问题。

  * 作为一段一般不超过 4KB 的小型文本数据，它由一个名称（Name）、一个值（Value）和其他几个用于控制 cookie 有效期、安全性、使用范围的可选属性组成。但是 cookie 在每次请求中都会被发送，如果不适用 HTTPS 对其进行加密，保存的信息很容易被窃取

  * Cookie的使用如下：

    ```javascript
    document.cookie = '名字 = 值'
    ```

    如果要删除cookie，可以给cookie设置一个过期事件

* Web Storage

  * **localStorage**（H5的新方法，数据不会过期

    * 特点

      * 生命周期：持久化的本地存储，除非主动删除数据，**<span style="color: rgb(36,91,219); background-color: inherit">否则数据永远不过时</span>**

      * 当本页操作（增删改）了 localStorage 的时候，本页不会触发 storage 事件，但是别的页面会触发 storage 事件

      * 大小：5M（跟浏览器厂商有关系）

      * localStorage 本质上是对字符串的读取，如果存储内容多的话会消耗内存空间导致页面卡

      * **受同源策略限制**（浏览器的安全机制，用于限制不同源的网页脚本对当前王爷资源的访问，防止恶意网站窃取数据）

        * 源（Origin）由 协议、域名、端口 组成，这仨都相同才是同源

        * 主要**限制跨域读取**Cookie、LocalStorage等存储数据，跨域发送AJAX请求（需要通过CORS等机制的允许）跨域操作DOM（如iframe嵌套不同源页面时无法访问其内容）

    * 关于 localStorage 的使用

      无法像 cookie 一样设置过期时间

      只能存入字符串，无法直接存对象

      ```javascript
      设置
      localStorage.setItem('username', 'cfangxu');
      获取
      localStorage.getItem('username')
      获取键名
      localStorage.key(0) // 获取第一个键名
      删除
      localStorage.removeItem('username')
      一次性清除所有存储
      localStorage.clear()
      ```

  * **sessionStorage**（关闭会话数据丢失）

    * sessionStorage 和 localStorage 使用方法基本一致，唯一不同的是生命周期，一旦页面（会话）关闭，sessionStorage 将会删除数据

![](images/JS面筋（76+2\)-IMG_1772513070833.png)

* **扩展 indexedDB** （存量大的数据）

  * 是一种低级API，用于客户端存储大量结构化数据（包括，文件/blobs）虽然上面的web Storage 对存储量较少的数据有用，但存储量更大的结构化数据，用indexedDB 比较好


以上 sessionStorage 和 localStorage 不会自动把数据发给服务器，仅仅在本地保存。而cookie 的数据会自动传递到服务器，服务端也可以写 cookie。

##### 区别：

关于 cookie、sessionStorage、localStorage 三者的区别主要如下：

* 存储大小：cookie 数据大小不能超过 4k, sessionStorage 和 localStorage 虽然也有存储大小的限制，但比cookie 大得多

* 有效时间：**localStorage 存储持久数据**，浏览器关闭后数据不丢失 除非主动删除数据：sessionStorage 数据在当前浏览器窗口关闭后自动删除; cookie 设置的 cookie 过期时间之前一直有效，即使窗口或浏览器关闭。

* 数据与服务器之间的交互方式，cookie数据会自动传递到服务器，服务端也可以写 cookie 到客户端：sessionStorage 和 localStorage 不会自动把数据发送给服务器



##### 针对不同场景的选择：

* 标记用户与跟踪用户行为的情况，推荐用 cookie

* 适合长期保存在本地的数据（令牌），推荐用 localStorage (localStorage就是存本地且数据不会过期

* 敏感账号一次性登录，推荐用 sessionStorage（因为关闭会话会丢失

* **存储大量数据的情况**、在线文档（富文本编辑器）保存编辑历史的情况，推荐使用 indexedDB

# 十三、什么是防抖和节流？有什么区别？如何实现？

#### 1. 是什么？

* 浏览器的 resize、scroll、keypress、mousemove 等事件在触发时，会不断地调用绑定在事件上的回调函数，极大的浪费了资源，降低了前端的性能

* 为了优化体验：采用防抖 debounce 和 节流 throttle 来减少调用频率

#### 2. 定义

* 节流：n 秒内只运行一次，若在 n 秒内重复触发，只有一次生效

  ```javascript
  function throttled1(fn, delay = 500) {
      let oldtime = Date.now()
      return function (...args) {
          let newtime = Date.now()
          if (newtime - oldtime >= delay) {
              fn.apply(null, args)
              oldtime = Date.now()
          }
      }
  }
  ```

  ```javascript
  function throttled2(fn, delay = 500) {
      let timer = null
      return function (...args) {
          if (!timer) {
              timer = setTimeout(() => {
                  fn.apply(this, args)
                  timer = null
              }, delay);
          }
      }
  }
  ```

* 防抖：n 秒后再执行该事件，若再n 秒内被重复触发，则重新计时

  ```javascript
  function debounce(func, wait) {
      let timeout;

      return function () {
          let context = this; // 保存this指向
          let args = arguments; // 拿到event对象

          clearTimeout(timeout)
          timeout = setTimeout(function(){
              func.apply(context, args)
          }, wait);
      }
  }
  ```

        * 垂直滚动 scrollTop>0

   ![](images/JS面筋（76+2\)-image-48.png)

   ```javascript
   function isElementInViewport(el) {
       const rect = el.getBoundingClientRect()
       return (
           rect.top >= 0 &&  // 元素顶部在视口内或下方
           rect.bottom <= (window.innerHeight || document.documentElement.clientHeight)  // 元素底部在视口内或上方
       )
   }
   ```

3. Intersection Observer

```javascript

const isTopVisible = rect.top >= 0 && rect.top <= windowHeight;
```
