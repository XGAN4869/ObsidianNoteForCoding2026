## 编程范式大全

| 编程范式          | 核心思想              | 代表性语言 / 特性          |
| ------------- | ----------------- | ------------------- |
| 面向过程（POP）     | 按步骤组织程序，关注执行过程    | C                   |
| **面向对象（OOP）** | 将数据和行为组织成对象       | Java、C++            |
| 函数式编程（FP）     | 通过函数组合、不可变数据处理问题  | Haskell、Java Lambda |
| 声明式编程         | 描述想要什么结果，而不是具体怎么做 | SQL、React 部分思想      |
| 逻辑式编程         | 通过事实和规则推导结果       | Prolog              |
https://github.com/Snailclimb/JavaGuide/issues/431
👆面向过程开发一般比面向对象开发性能好，但是不利于管理，比如不封装对象而是直接写过程

## equals 和 ==
== 引用，和 Object 的 equals  方法是一样的
String 重写了 Object 的 equals()，为比较值
## 封装
- 隐藏内部状态
- 提供公共方法
- 保护数据安全
## 继承
- 子类对象包含由父类声明的实例状态，`private` 成员不会被子类继承
- 子类可以拥有自己属性和方法，即子类可以对父类进行扩展
- 子类可以用自己的方式实现父类的方法

## 多态
- 父类的引用指向子类的实例
- 运行时动态绑定
- 方法重写实现

## 强制类型转换
- 向上转型，大/宽类型接收小/窄类型。子类引用的对象转换为父类类型，安全，但只能用 father方法
- 向下转型，小类型接收大类型引用。必须确认它原本就是小类型，否则运行时报错。
- 但 Father 声明的对象永远是 Father 类型的，同理 Son 也是【类型定了之后不变】
```java
Father father = new Son(); //Father 类型：Son对象 给 Father类型用，因为 Son extends Father，编译期不会出问题

father.eat();  // 可以
father.play(); // 编译报错

//case1
Son son = (Son) father //可以，本身就是 Son 对象，自然可以转

//case2
Father father1 = new Father();
Son son1 = (Son) father1 //Son 类型：本身不是 Son 对象，无法转：编译不报错运行报错

```



## interface接口 和 abstract类
- 特点
	- 不能实例化
	- 都可以写 abstract method，没有实体，必须由子类实现
- 区别：
	- 接口强调约束，abstract 类用于代码复用，强调所属关系
	- 类:接口=1对多，接口：接口=多对多
	- 接口中的成员变量：public static final 必须！
	- default 接口新增，可以不重写实现方法

## 深拷贝浅拷贝
浅拷贝只会复制当前对象的字段值；引用类型字段复制的是引用地址，不会递归创建子对象，因此两个对象的引用成员指向同一个子对象。
